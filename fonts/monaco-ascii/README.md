# Monaco ASCII デザイン用画像

添付された `Monaco_Linux.ttf` の字形を、そのままPNGに展開したデザイン参照。
対象は印字可能なASCIIの **U+0020〜U+007E、95文字**。SPACEも1枚に含め、空白の透明画像として保存した。制御文字U+0000〜U+001FとDEL（U+007F）は字形を持つ文字ではないため対象外。

- `glyphs/U0020.png`〜`glyphs/U007E.png`: 文字ごとの1024×1024 RGBA PNG。黒い字形、透明背景。字形以外の線やラベルはない。
- `ascii-overview.png`: 全95文字の一覧。コードポイント、青いベースライン、薄い左右の送り幅ガイド付き。
- `glyphs.json`: 文字とファイルの対応、元フォントのglyph名・送り幅・左サイドベアリング、画像上の字形範囲と描画設定。

全画像は768pxの同じ文字サイズ、左の原点x=282、ベースラインy=745で描画。字形を個別に拡大縮小・中央寄せ・切り抜きしていないので、文字の大きさ、幅、上下位置を相互比較できる。元フォントは等幅で、ASCIIの送り幅は1229/2048em（描画時460.875px）。

再現用の入力は、この会話の添付 `Monaco_Linux.ttf`。ファイルのSHA256は `glyphs.json` に記録した。Pillow 11.1.0 / FreeTypeで元フォントを直接描画した画像であり、生成画像ではない。元TTFは複写・変更していない。

検証: 95文字すべてのcmap対応とPNG生成、SPACE以外の字形が空でないこと、画像端で切れていないこと、共通サイズ・原点・ベースラインを確認。一覧画像を目視確認。
