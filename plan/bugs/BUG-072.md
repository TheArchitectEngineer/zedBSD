# BUG-072: zedBSD が FAT32 に書いた directory・file の metadata が仕様に合わない（`..`、FSInfo、日時）

Bug ID: `BUG-072`
Reproduction: reproduced（QEMU、WS073 の agent、BUG-071 の確認の中。既存の不具合）
Disposition: resolved（2026-09-27、ws073-p012）
Date: 2026-09-27
Source: ws073-p010（BUG-071 の確認）
Owner: WS073

## 期待と観測

期待: zedBSD が FAT32 の volume に directory と file を作った後、host の `fsck.fat -n` が誤りを出さず、mtools が正しい日時を出す。

観測（データは正しい、`cmp` 一致）:

1. 「Invalid '..' entry in the second slot」: 最上位の directory の `..` に root の cluster（2）を書く（仕様は 0）。
   `fat_raw_initialize_directory()` と rename の `fat_raw_update_dotdot`。
2. 「Free cluster summary wrong」: FSInfo の空き cluster 数を保っていない。
3. 新しい entry の作成・更新の日時が 0（mtools で 1980-00-00 0:00、不正な日付）。

## 次の手

ws073-p012 で直す（BUG-071 の p010 の後）。詳細は WS073 の phase。

## 解決（2026-09-27、ws073-p012）

- `..` は親が root なら 0（`fat_raw_dotdot_cluster()`）。FSInfo の空き数を mount ごとに table から数えて commit ごとに増減し、sync で書く。
  新しい record と size の変わった file に日時を書く（`fat_raw_stamp_record()`）。
- 確認の中で見つけた 4 つ目も直した: `sync(2)` が kernel の持つ boot の FAT（`/boot`・`/boot/esp` の bind の先の private な mount）を sync しなかった。
- 試験: `plan/ws073/tests/fat-metadata.sh`（guest と host）で `fsck.fat -n` clean・日付が当日。amd64 の ESP と rpi4 の firmware の FAT に zedBSD が
  書いた後 `plan/ws073/tests/fat-compare.py` で clean・loader と firmware の file は不変、boot test PASS。[ws073-p012](../ws073/phase012/phase.md)。
