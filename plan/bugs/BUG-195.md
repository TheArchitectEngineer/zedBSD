# BUG-195: 実機 5330 で DSDT が読めず（AML の stack の予算を超える）、ACPI の namespace が無い。native の touchpad・I2C が付かずスクロールできない

Reproduction: reproduced（実機 5330、UAT 2026-10-05 午後、image uat-0505c = main ee2f8c7f）
Disposition: tracking（優先度: 高）
Discovery: 2026-10-05 午後 UAT。ユーザー「タッチパッドはスクロールなどができていない。」→ Q1 が 5330（10.0.30.3、ユーザーの許可）の dmesg を読んだ
Handling: WS049（ACPI の AML の解釈器）・WS159（native の touchpad）。担当 P1（最優先）

## 観測（dmesg、`plan/uat/2026-10-05pm/dmesg.txt`）

```
lpss-i2c: attach failed while powering on (3)        ← 2 回（EINVAL）
input: /dev/input/event0: PC/AT PS/2 mouse           ← touchpad は PS/2 の互換の mouse のまま（スクロール無し）
ACPI: AML nests deeper than the stack budget
ACPI: DSDT Dell Inc stopped at offset 0x22177 (error 28)   ← E2BIG
acpi: the DSDT did not load (error 28)
acpi: attachment failed (error 28)
```

`/dev/input` は event0（PS/2 mouse）・event1（PS/2 keyboard）だけ。I2C-HID の touchpad は付いていない。

## 以前の実機

2026-10-04 の UAT（`plan/uat/2026-10-04/dmesg.txt`）でも DSDT は読めていない（`stopped at offset 0x1c89b (error 13)`）。今回は 0x22177 まで進み、別の理由（stack の予算、`src/drivers/acpi/acpi-kern.c` の `STACK_BUDGET` 8 KiB、`aml-eval.c` の `drv_acpi_stack_check`）で止まった。つまり実機では ACPI の namespace が一度も揃っておらず、namespace に頼る物（LPSS の I2C の `_PS0` と I2cSerialBus・GpioInt、I2C-HID の touchpad、蓋・電源ボタン・AC・電池の事象、LPS0、S0 idle）は実機で働いていない見込み。QEMU では DSDT が小さく通る。

## 調べる点

- 5330 の DSDT（取り出し済み、host の試験の入力）を host の AML の harness で読み、0x22177 で stack の予算を超える経路（入れ子の深さ、各 frame の大きさ）を測る。`drv_acpi_stack_deepest()`。
- 予算 8 KiB が小さいのか（kernel の thread の stack の大きさとの関係）、frame が大きいのか（LTO の inline で再帰の frame が膨らむ）、入れ子を再帰でなく明示の stack にすべきか。
- lpss-i2c の `attach failed while powering on (3)` は namespace が無いことの結果か、別の原因か。
- 直した後の確認: host で 5330 の DSDT が全部読める、QEMU の回帰、実機で touchpad の event と I2C-HID の attach（UAT）。
