# BUG-192: mount 中の USB の記憶装置を抜いても disk が残り、事象が出ない

Reproduction: reproduced（QEMU、T1-139）
Disposition: scheduled（優先度: 標準、ベータ1 の WS132 の受け入れに関わる）
Discovery: 2026-10-05 未明 T1-139（ws132-p004 の p004-guest.sh の step 5）、P2 の解析
Handling: WS132（ws132-p004 の step 5）、kernel の USB storage と disk の層。担当 P1（q712 の後）

## 観測

mount 中の FAT の stick を QMP の device_del で抜くと、volumed の一覧に `VOLUME id=sda state=mounted … path=/media/USBSTICK` が残り、/media/USBSTICK も残る（2 回とも）。

## 解析（P2、2026-10-05）

`src/drivers/usb/usb-storage.c` の `storage_detach` は、disk が使われている（mount 中）と `disk_gone_if_idle` が EBUSY を返して detach が失敗する。USB の core の REMOVE の事象（`usb.c` の `post_device_event`）は detach が成功して device を解放した後にしか出ない。そのため disk は LIVE のまま残り、DISK と USB のどちらの事象も来ず、/dev/sda も見えたままで、volumed は抜去を知れない。

## 直しの案

物理的に抜かれた（port が切れた）mount 中の disk は、detach の時に media を退役させ（`partition_retire_media` の類で fs の I/O を ENXIO/EIO にする）、DISK REMOVE（または media の喪失の事象）を出し、unmount の後に disk を解放する。volumed は USB の事象も購読するよう直してある（abb0d09c）ので、kernel が disk を消すか media を退役させれば、次の走査で force unmount と rmdir が働く。

## 再調査の契機

kernel の直しの後に T1 で p004-guest.sh の step 5。

## 修正（2026-10-05 P1 generation17）

- 抜去の detach（USB の core の `destroy_device` → `detach_interfaces`、`DRV_USB_DETACH_FORCE`）で disk が使われている（mount 中）時:
  - `src/kern/disk.c` の新しい `disk_media_gone`: medium を revoke し（`disk_media_revoke`、以後の I/O と open は ENXIO）、その device の live な partition と device 自身の DISK REMOVE を system の事象に一度だけ出す（`d_media_gone_posted`、registry の lock の外で、pin した disk に対して）。disk は registry に残り、idle になった時の `disk_media_retire` で外れる。
  - `src/drivers/usb/usb-storage.c` の `storage_detach`: disk の除去（`disk_gone_if_idle`、medium が revoke 済みなら `partition_retire_media`）が EBUSY で、抜去で、まだ revoke していない時に `disk_media_gone`。detach は EBUSY で失敗し、USB の core が周期の root の走査でやり直す（`destroy_device` の「A failed destroy leaves DISCONNECTING set; periodic root scans then retry」）。volumed が force unmount した後のやり直しで、revoke 済みの medium が retire され、disk が解放され、USB の REMOVE が出る。
  - 判断は純粋な `storage_removal_decide`（`include/drivers/usb/usb-storage-removal.h`）にし、host で試す。FORCE の無い detach（抜去でない）は revoke しない。
- volumed の側: DISK の事象で走査し、revoke された `/dev/sda1` は open が ENXIO なので候補にならず、一覧から消えて force unmount と rmdir が働く（volumed の変更は無し）。
- 確認: amd64 の vmunix（CI の config）成功、warning 0、kernel include check PASS。`sh plan/ws132/tests/run-host-storage-removal.sh`（ASan・UBSan）7 checks ok: mount 中の抜去で revoke と post が一度、mount 中のやり直しは待つ（二度目の post なし）、unmount の後に retire と解放、idle の抜去はすぐ解放、FORCE 無しは revoke しない、他の拒否は待つ。style-check は変えた所に指摘 0（usb-storage.c は 98 → 97、disk.c は増えない）。
- 範囲外で残す: 他の理由（card reader の media の交換）で revoke された medium の retire は、今も REMOVE を出さない（既存の挙動）。
- QEMU: T1 に `plan/ws132/tests/p004-guest.sh` の step 5 を依頼（Q1 経由）。
