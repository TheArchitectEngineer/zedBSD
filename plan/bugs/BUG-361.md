# BUG-361: NVIDIA RTX 2070（nvrtx）で Notes が起動しない（nvrtx の Vulkan の executor に stencil の format と test が無い）

- 状態: fixed（2026-10-30 P5 q1692-i01、実機で確かめた、branch `agent/p5-ws243` 48f21726b、main に未 merge）。reproduced（実機、2026-10-30 P5 q1692-i01）。登録: 2026-10-30 Q1（ユーザー「NVIDIA RTXを使っているときにNotesアプリが起動できるか確認し、できなければ対応しておいてください。」）
- 再現: 10.0.10.3 の RTX 2070、kernel 3605640992（main＋WS243＋試験の入力の注入）、machine の userland の `/bin/notes`（cksum 2430934716）。出力は `NOTES TABLET seat` の後 `notes: stencil format failed (-11)` で終わり、窓は出ない（KWL FAILED 0、kernel の失敗 0）。記録 `build/ws243/q1692-n1`（P5 の worktree）。
- 原因: Notes の renderer（`userland/desktop/notes/render.c` の `render_stencil_format`）は線の塗りに stencil の format（D24_UNORM_S8_UINT・D32_SFLOAT_S8_UINT・S8_UINT・D16_UNORM_S8_UINT のどれかで optimal の DEPTH_STENCIL_ATTACHMENT）が要る。nvrtx の executor は depth を D32_SFLOAT だけ持ち stencil が無い（`src/drivers/gpu/nvrtx/vk/` の vk-device.c の format の表、vk-pipeline.c が stencilTestEnable を拒む、exec-push.c が STENCIL_TEST を常に false、vk-target.c が depth の attachment を D32_SFLOAT に限る）。i915・amdrdna・Venus は stencil を持つ。
- 直す方針: nvrtx の中で D24_UNORM_S8_UINT（zeta の Z24S8）を depth-stencil の attachment として出し、image・view・render pass の stencil の aspect、load の clear、pipeline の stencil の状態（front・back の op・compare・mask・ref、dynamic state）を 3D の method に（Mesa nvk の値を参照）。HAL は変えない。
- 担当: P5（q1692-i01）。
- 2026-10-30 P5（q1692-i01）: 直しと確かめ。
  - 直し（nvrtx の中、HAL は変えない、48f21726b）: D24_UNORM_S8_UINT を depth-stencil の attachment として出す（vk-device.c の format の表、vk-resource.c の image・view、
    vk-target.c の render pass と stencilLoadOp）。3D の depth target は S8Z24（exec-push.c）、two-sided の stencil test（front・back の op は D3D の値＝VkStencilOp+1、
    function は OGL、ref・compare mask・write mask）、stencil だけの clear（SET_STENCIL_CLEAR_VALUE と CLEAR_SURFACE の stencil の bit）、pipeline の stencil の state
    （vk-pipeline.c）、clear の値の stencil（vk-record.c）。値は Mesa 25.0.7/26.2.6 の cl9097.h・nvk_cmd_draw.c（nvk_flush_ds_state）・nil_formats.csv。
  - 実機で分かった 2 つ目の原因: Turing は S8Z24 の depth target の page に PTE の kind S8Z24（0x03、Mesa の dev_mmu.h と nil の tu102_choose_pte_kind）を求め、kind 0 のままでは
    「3D-Z KIND Violation」（GPC 0〜2、RC type 13）で channel が止められた（`build/ws243/q1692-n2`）。→ stencil の image を page の境・page の大きさにし（vk-memory.c の
    requirements と bind、4 KiB）、最初に depth target として使う時にその page の PTE を同じ VA のまま kind S8Z24 で書き直す（vk-execute.c → vk-node.c
    `nvrtx_vk_memory_kind` → work.c `nvrtx_work_remap_vram` → mmu.c `nvrtx_mmu_gr_entries_vram_kind`）。image の破棄で pitch の kind に戻す。
