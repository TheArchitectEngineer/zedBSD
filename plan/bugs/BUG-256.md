# BUG-256: 5330 の USB-C（TC1）に DP の monitor を挿すと DP-alt には入るが AUX が全部 timeout し、表示されない

- 状態: reproduced（実機 5330、2026-10-08 ユーザー「USB-C DPを接続しましたが、ディスプレイは表示されませんでした。」） / scheduled
- 証拠: [kernel-5330.log](BUG-256/kernel-5330.log)（kernel は P2 の ws113-p011 の build、cksum 1836440229、main の WS051 p004a・p004b・p005a を含む）

## 観察（Q1、SSH）

- 挿すと `hpd: long hpd on DDI D: detecting`、`hpd TC1 connected=1 (DDI D)`、`TC1: mode none -> dp-alt`（FIA lanes 4）→ Type-C の port は DP-alt に入る。
- その後 `i915: vbt: i915: edp [err] i915: vbt: %s: not done (status 0x%08x)` が 32 行（AUX の転送が DONE にならない。log の書式の文字列がそのまま出ている（%s・%08x が展開されない）のも別の不具合）→ `DP-ext TC1: disconnected (step receiver capabilities, rc -16)`、`probe N held the port in dp-alt mode (FIA lanes 4), none after it`。6 回の retry で同じ、`HPD-EVENT DP-1 ... disconnected -> disconnected`。
- 2026-10-07 の M-3（Linux）の正解値は **TC2（DDI E、DP-2）** で採った。今回ユーザーが挿したのは **TC1（DDI D、DP-1）**。
- 疑い（未確認）: TC1 の AUX の channel の対応（VBT の aux_ch）・AUX_USBC1 の power well・TC1 の AUX の register の番地、または TC の AUX の timeout の扱い。log の書式の展開の不具合も直す。

## 次

- i915（WS051）の担当が TC1 の AUX の経路を読んで直す。ユーザーにもう一方の USB-C の口（TC2）でも試してもらうと切り分けになる。

## TC2 でも同じ（2026-10-08 ユーザー「TC2でつなぎましたが変わりませんでした。」）

- 起動時: `TC2: declared (DDI E, legacy 0, AUX channel 4)`、`TC2: PHY mode tbt (ready 1, owned 0, live none)`、`DP-ext TC2: bound (DDI E, AUX channel 4, VBT max rate 810000 lanes 4)`。
- 挿すと `hpd: long hpd on DDI E: detecting`、`hpd TC2 connected=1`、`TC2: mode none -> dp-alt` → AUX の `not done` が続き `DP-ext TC2: disconnected (step receiver capabilities, rc -16)`（TC1 と同じ）。
- → port に依らない TC の AUX の経路の問題（Linux（M-3）では同じ TC2 で DPCD・EDID が読めた）。AUX の失敗の log の行に `edp` の接頭が付く → TC の AUX の転送が eDP の AUX の hook（channel・power domain・register）を使っている疑い（p004b の D7 の「DPCD の routing を object ごとの aux_emit に」と p004a の aux.c の Type-C の分岐の食い違いも）。
- 証拠: [kernel-5330-tc2.log](BUG-256/kernel-5330-tc2.log)。
