# BUG-312: 起動の時に root の UFS が壊れていると read-only で mount され、fsck して rw にしない

- 状態: reproduced（実機、ユーザー）/ scheduled（2026-10-14 Q1、P2）
- 発見: 2026-10-14 夜、Pi 4（10.0.30.2）で WS236 の試験の kernel が止まった後、電源を入れ直すと root が RO で mount されていた。ユーザー「Pi4はイメージが壊れてROマウントになっていたので、書き直して起動しました。」「RO mountは動作中に壊れたらRO remountならわかりますが、ブート時にROなのは使いづらいです。fsckしてRWにするべき、というバグフィックスはできそうですか？」
- 期待: 起動の時に root（と他の UFS）が clean でなければ、mount の前に fsck（または journal の replay と修復）をして、直せたら rw で mount する。直せない時だけ RO にして、理由と回復の手順を画面と log に出す。
- 関連: BUG-307・BUG-308（UFS の journal）、WS072（UFS の format の lease）。
