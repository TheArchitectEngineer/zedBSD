# BUG-202: 5330 の実機で起動の途中に fatal「scheduler queue underflow」（最初の SCI の直後）

Reproduction: reproduced（ユーザー、実機 5330、2026-10-05 夜、1 回）
Disposition: tracking
Discovery: 2026-10-05 夜 ユーザー（image build/uat-0505g、main bf5d1a39、sha256 7ded4823…5faa2339）
Handling: 未定（まず画面で読めるようにする: [WS174](../ws174/ws.md) の safe boot、または text の boot の image）

## 観測

ユーザー「イメージを実機で起動したら、カーネルの起動の途中でpanicしたとみられますが、グラフィカルブートなのでわかりません。」QEMU の boot-test（T1-212 (2)）は PASS。

## 候補（未確認）

今日 main に入った kernel の変更で、QEMU では出ず実機で出る物: WS130 p002 の IPv6 の核（network の worker の 1 秒ごとの起床、装置の record）、WS168 p002 の syscall の入口の検め、WS161 の hidraw・smartcard、ACPI の BUG-195〜197 の直し、BUG-198 の overlay の inode の表。

## 2026-10-06 ユーザーの実機の結果（uat-0506b、Ctrl+Shift の safe boot）

画面の最後:
```
acpi: first SCI handled
fatal: src/kern/sched.c:1839: scheduler queue underflow
```
`queue_remove()` で count が 0 の queue から thread を外した（queue の整合が壊れた）。ACPI の SCI の thread（`src/drivers/acpi/acpi-kern.c` の event thread）が最初の SCI を処理した直後。QEMU では SCI が来ないか形が違うので出ない見込み。今日の SCI・GPE・EC・電源ボタンの変更（BUG-195〜197、WS049 p007、WS132 p008、WS052 p006 S0 idle）と、sched の変更（76282484 ほか 2026-10-05）が候補。Reproduction: reproduced（実機、safe boot で読めた）。
