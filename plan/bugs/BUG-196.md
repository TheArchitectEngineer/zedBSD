# BUG-196: 実機 5330 で電源ボタンを押すと、ただちに電源が切れる

Reproduction: reproduced（実機 5330、UAT 2026-10-05 午後、image uat-0505c = main ee2f8c7）
Disposition: tracking（優先度: 高）
Discovery: 2026-10-05 午後 UAT。ユーザー「ACPIについて、電源ボタンを押すと、ただちに電源が切れてしまいました。」
Handling: WS049（ACPI の有効化）・WS132（電源ボタンの事象）。[BUG-195](BUG-195.md) と同じ根の見込み。担当 P1

## 期待

電源ボタンの短押しは SCI の固定の事象（PM1 の PWRBTN_STS）として kernel が受け、`/dev/system` の POWER の事象で Keiland に渡す（ws132-p001 の D1: dialog 無しで S0 idle、今は記録だけ）。電源が切れるのは 4 秒以上の長押し（firmware の強制の off）だけ。

## 見込みの原因

同じ起動の dmesg（`plan/uat/2026-10-05pm/dmesg.txt`）で `acpi: the DSDT did not load (error 28)`・`acpi: attachment failed (error 28)`。ACPI の attach が失敗すると、OS が ACPI の mode に入らない（FADT の SMI_CMD に ACPI_ENABLE を書かない、PM1_CNT の SCI_EN が立たない、PM1_EN の PWRBTN_EN を立てない）。SCI_EN が 0 の legacy の mode では、Intel の PCH は電源ボタンの押下で直ちに S5 に落ちる（または SMM の既定の処理が off にする）。

## 調べる点

- DSDT が読めない時でも、固定の hardware の ACPI の有効化（FADT・SMI_CMD・PM1 の register、AML は要らない）だけは行い、電源ボタンの固定の事象を受けられるようにする（DSDT の失敗と分ける）。
- BUG-195 の直しの後に、実機で短押しが事象になり電源が切れないこと（UAT）。

## 直し（2026-10-05、P1 generation18）

BUG-195 の直しで DSDT が読めれば `start_events()` が走り ACPI の mode に入る。それに加え、DSDT が読めない時も固定の hardware だけは
有効にする: `drv_acpi_attach()` は load の失敗で `start_fixed_hardware()` を呼び（`start_events()`: FADT の SMI_CMD に ACPI_ENABLE、
SCI、電源・sleep ボタンの固定の事象を `/dev/system` の POWER へ）、それから error を返す（`src/drivers/acpi/acpi-kern.c`）。
host: `--power-button` で `FIXED power-button` が出る（5330 の table、namespace あり）。namespace の無い経路は kernel の中だけ（host の
harness は `acpi-kern.c` を使わない）で、build（warning 0）まで。実機は次の UAT。
