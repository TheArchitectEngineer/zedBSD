# BUG-143: IME の確定のたびに 500 ms を超えて止まり、compositor が IME を迂回する

Reproduction: reproduced（P4 / q604、QEMU Venus。p005 より前から）
Disposition: scheduled（ws095-p015、P2、2026-10-04）
Discovery: ws095-p005 / q604。Enter で確定するたびに `ZWL IME bypass after_ms=500` が出て、その間の key は IME を通らず app へ直に行く。原因の見当: 確定のたびの利用者の辞書の保存（`ja-user.c` の fsync と rename）が QEMU の UFS で遅い（BUG-135 と関係の可能性）。直し方の案: 保存を key の経路の外（後回し・別 thread）へ。実機では未計測。

2026-10-03 user（優先度と依存）: 優先。ユーザーの観察:「テキストエディットアプリにおいてIMEを通さなくてもすべての文字入力が500msの遅延があるように思う」→ IME の確定の時だけでなく、Text Editor の通常の入力の遅延も調べる。

## 対応（2026-10-03、q643、P1）

handling: [ws095-p014](../ws095/phase014/phase.md)。

- **IME の確定の止まり（直した）:** 確定で学んだ時の `ja_user_save`（全体を書き、fsync、rename）が key の経路の中で同期だった。`ja_user_save_later` で
  書き込みを専用の thread に移した（text は key の経路で作り、新しい物が待ちを置き換え、辞書を閉じる時に最後の書き込みを待つ）。host-engine 208 PASS、
  keiland-ime の build は warning 0。
- **Text Editor の直接入力の遅れ（未特定）:** 直接入力では key は IME を通らない。Text Editor の loop・libkeiui・libwayland・WSI を読んで 500 ms の待ちは
  見つからなかった（近い周期は cursor の点滅 530 ms）。「あ」のまま打っていたなら上の修正で消える。`plan/ws095/tests/latency-bug143.sh` で QEMU の
  数字（Text Editor と Terminal、日本語の確定直後）を T1 に依頼した。結果で次を決める。実機（5330）は未計測。

2026-10-03 T1-024（QEMU、参考値）: key から画面の変化まで median/max ms: textedit-direct 337/416、terminal-direct 311/321、textedit-japanese 335〜446。Text Editor と Terminal で同じ程度 → Text Editor に固有の遅れは QEMU では見えない（VNC の撮影の遅れを含む）。IME の確定の止まりは ws095-p014 で直した。直接入力の 500 ms の原因は未特定、実機（S2）で確かめる。

2026-10-04 user「BUG-143は、辞書の保存は遅延させ、入力が3分以上ないときにファイル保存、みたいな運用にして回避しましょう。」→ 確定のたびの辞書の保存（fsync）をやめ、入力が 3 分以上無い時（と終了の時）に保存する。handling: ws095-p015（P2）。

## 対応（2026-10-04、q652、P2）

handling: [ws095-p015](../ws095/phase015/phase.md)。

- **辞書の保存:** 確定では保存しない（未保存の印だけ）。keiland-ime に届いた最後の key から 3 分で engine の `save`（writer thread、event loop は待たない）、
  終了（接続の終わり・SIGTERM・SIGHUP・SIGINT）で未保存の分を書く。host-engine 220 PASS、keiland-ime の zedBSD・Linux の build は warning 0。
- **Text Editor の key ごとの描画:** card の角丸の全画素の合成が key のたびの `te_draw` の大半だった。clip の中だけ・角の無い行の速い経路・同じ画素の結果の再利用で、
  host の 1920x1080 で 25 → 3.8 ms（画素は同じ）。500 ms を説明する量ではなく、直接入力の遅れの原因は未特定（実機の present の経路を測る）。
- QEMU の確認は T2 に依頼（latency-bug143.sh、step 4 を追加）。実機は未実施。
