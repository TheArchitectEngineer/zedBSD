### 原因の絞り込みと緩和（WS075 の agent、2026-09-28）

- 計測（`submit.c` の CSB の誤りの報告、`worker.c` の要求の失敗の報告）を入れた run では CSB の誤りも worker の 10 s の
  timeout も出ない。GPU の engine は止まっていない（compositor の submit は停止の間も続く）。
- 止まるのは GPU core（`drivers/gpu/gpu.c`）の job の **reservation** の期限（`CONFIG_GPU_JOB_RESERVATION_MS` 10 s）: ある
  session の job が reserve されたまま commit されず、期限で session が失敗 → GPU core が i915 に isolate を求める →
  i915 の `drv_i915_worker_engine_recover()` が未実装（ENOTSUP）→ device 全体の fault（`device fault 5`）→ compositor を含む
  全 session が DEVICE_LOST。
- 止まった session は、場面の最初の Vulkan の client `wltest`（`plan/ws031/tests/zdesktop/run-wlkill.sh`: 描画中に 6 s で
  SIGKILL する試験）と見られる: hang はいつも wlkill の後に次の client（mview・Files・egltest）が接続する頃で、isolate の
  報告は「reserved 1」の slot 1 つ（i1-files2）。描画中に kill された client の reserve 済みで未 commit の job が、close で
  取り消されず期限まで残る、が仮説（GPU core と libvulkan の reserve → wire の submit の間の kill）。未確認。
- 緩和（i915、`worker.c`）: `drv_i915_worker_engine_recover()` を実装。engine で今走っていない session の要求（reserve 済み・
  queue・worker の run list の未着手）をその error で終え、その session だけを isolate する（今走っている要求は reset が要る
  ので、従来どおり ENOTSUP で device fault）。worker は走らせている要求を `current` に持つ。
- 結果（実機、`/home/awe/zedBSD-rpi4/build/ws075-bug077/`）: egl-d1（緩和の前、計測のみ）は再現して compositor 停止。緩和の後
  egl-d2・i1-files1・i1-zdesktop は再現せず、**i1-files2 で再現し、session 5 だけが isolate され compositor は生き残った**
  （`i915: engine 0: session 5 isolated (... reserved 1 ...)`）。
- 残り: reserve のまま残る job の原因（GPU core の close の取り消し、または libvulkan）。isolate の後は compositor の 1 frame の
  GPU 時間が 7 ms から 30〜50 ms に増えた（i1-files2。原因は未調査）。

## 原因と修正（WS075 の agent、2026-09-28）

**原因: close の循環待ち。** client が GPU_JOB_RESERVE の後、COMMIT の前に殺される（`run-wlkill.sh` の wltest の SIGKILL）と、
reserve 済みで未 commit の job が残る。`gpu_close()`（`src/drivers/gpu/gpu.c`）は:

1. `gpu_session_fail_locked(ENODEV, graceful)` で reserve の completion を論理的に終える（`job_deadline` は 0、期限では落ちない）。
2. `commands->drain()`: i915 の drain は `pending_requests` が 0 になるまで待つ。reserve の request は `pending_requests` に数える
   （`job.c`）ので、戻らない。
3. GPU core は reserve を backend の cancel で取り下げるのを、stop_poll が idle を証明した後（`gpu_session_reclaim()`）にだけ行って
   いた。i915 の stop_poll（`reset.c`）も reserve を pending に数えるので idle にならない。

close の thread は drain で止まり、monitor の thread の stop が `CONFIG_GPU_JOB_STOP_MS`（10 s）の期限で escalate する →
isolate（緩和の前は engine_recover の未実装 → device fault → compositor を含む全 session が DEVICE_LOST）。isolate が reserve の
request を EIO で終えると drain が戻り、close が続く。観測の「isolate の報告が reserved 1」「isolate の直後に `session 5 closed while
quarantined`」「wlkill の約 10 s 後、次の client の接続の頃に停止」と合う。前の節の「reservation の期限（10 s）」は誤りで、効いて
いたのは close の後の stop の期限。

**修正（GPU core、404830b4）:** `gpu_session_reclaim()` が失敗した session の未 commit の reserve を backend の cancel（definite
nonacceptance）で取り下げる。job action の pin（`job_action`・observer）を取るので、進行中の commit・cancel とは競合しない。
呼ぶ所: `gpu_close()` の drain の前（close と競合する ioctl は無い）と、stop_begin の直後（期限で失敗した生きた session も）。
取り下げたとき `gpu: close withdrew N uncommitted job reservation(s)` を log へ。未 commit の reserve は native の仕事ではない
（libvulkan の reserve → wire の submit → commit のうち、wire の submit の batch は別の request として pending に数えられ、drain と
stop はそれを待つ）。i915 の engine_recover の緩和（`worker.c`）は他の原因の停止のために残す。

**確認:**
- host: `plan/ws014/tests/run-gpu-supervision-test.sh` に「reserved close」の場面（i915 のように stop_poll と drain が reserve を
  pending に数える backend で、commit の前に close）。修正の前は abort、後は PASS。gpu-job・fence・sharing・scanout 等の GPU core の
  host 試験も PASS。
- 実機（修正の後、wlkill を含む場面）: `build/ws075-bug077/fix-files1`・`fix-files2`・`fix-files3`（zdesktop-files 9/9）、
  `fix-zdesktop1`（zdesktop 6/6）、`build/ws075-p005/fix-egltest1`〜`3`（egltest の場面、compositor は最後まで動く）。**7 run で停止・
  isolate・device fault なし**（修正の前: zdesktop-files 4 回中 2 回、ほか egl-d1・r1-zdesktop・i1-files2）。log が全部取れた 5 run に
  `withdrew` の行は無い（kill が reserve と commit の間に当たらなかった）。競合の窓を実機で狙って当てた run は無く、修正の効きは host の
  場面で確かめた。画面 `build/ws031-shots/ws075-bug077-20260928-fix-{files1,files2,files3,zdesktop1}-sheet.png`。
- isolate の後の compositor の GPU 時間の増加（7 → 30〜50 ms）: isolate が起きなくなったので調べていない。isolate が再び起きたときに見る。
