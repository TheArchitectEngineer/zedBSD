# BUG-181: Browser: URL が窓の幅より長い時、URL バーをポイントすると窓の title bar をはみ出して描かれる

Reproduction: reproduced（実機）
Disposition: tracking（優先度: 標準）
Discovery: 2026-10-04 夜 ad-hoc UAT-3（実機 Latitude 5330、image `build/uat-3/hdd-image.img` sha256 ada4492e…、main efe846a、[uat.md の uat-3](../uat.md)）
Handling: WS074（Browser、Codex の担当）／browser の shell（`userland/desktop/browser/`）の title bar の URL 欄

## 観測

ユーザー「ブラウザでタイトルバーで、URLが長すぎてウィンドウ幅より長いときに、URLバーをポイントするとウィンドウタイトルバーをはみ出して描画される（バグ）」

## 次

hover の時の URL 欄の展開（全文の表示）の幅を title bar（窓の幅）で clip していない疑い。 WS074（Browser）は Master で「Codex が担当」（このセッションの担当の外）。担当はユーザーが決める。

## 2026-10-05 午後 UAT（実機 5330、uat-0505c = main ee2f8c7）

ユーザー「ブラウザでURLが長いときにタイトルバーをはみ出してテキスト範囲選択が描画されます。前回指摘のバグが完全には直っていないようです。」

- 長い URL の欄で、**文字の範囲の選択（選択の地）** が title bar の外にはみ出して描かれる。この ticket には直しの記録が無い（Disposition は tracking のまま）。ユーザーは一部が直ったと見ている（はみ出しが選択の描画に残る）ので、文字は欄の枠で切られていても、選択の矩形の clip が欠けている見込み。
- 担当: title bar の入力欄の描画（BUG-177 で compositor の title bar の入力欄が IME を受けるようにした所）か browser の shell。Q1 が割り当てる（Browser の WS074 は Codex の担当なので、compositor の側の欄なら P2）。

## 修正（2026-10-05、P2 g15、q758）

- 原因: Browser の Location は compositor の title bar の breadcrumb の control（`browser/shell/titlebar.c`、`KEILAND_CONTROL_BREADCRUMB`）で、編集中は compositor の欄（`wayland/titlebar-shell.c` の `shell_draw_field_text`）が描く。文字は欄の幅（`glass_draw_text` の width）で切っていたが、**選択の地（tint）の矩形は欄の幅で切っておらず**、長い URL を選ぶと title bar の外まで描かれた。
- 直し: 選択の両端の x を欄の幅に収めてから描く（search の欄・breadcrumb の欄の両方がこの関数）。browser の側の変更は無し。
- 残り（別の改善、今回は扱わない）: 長い文字列の欄は先頭から描くので、cursor が欄の右の外にある時に cursor と末尾が見えない（横の scroll が無い）。
- 試験: `plan/ws099/tests/bug181-guest.sh`（T1、titlebar-probe の search の欄で長い文字・Ctrl+A・drag の選択、PNG を目で見る）。build: zedBSD の `bin/wayland` warning 0、style-check は変更前と同じ件数（4、既存）。未実施: QEMU（T1）、実機の Browser（UAT）。
