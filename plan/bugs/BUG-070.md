# BUG-070: USB HID keyboard の driver が keypad・Num Lock・Print Screen・Scroll Lock・Pause・102nd・Menu の key を出さない

Bug ID: `BUG-070`
Reproduction: reproduced（QEMU、amd64 の lean zdesktop guest、qemu-xhci の usb-kbd に QMP の input-send-event で `num_lock`、1/1）
Disposition: resolved（2026-09-27、ws073-p011）
Date: 2026-09-27
Source: [ws035-p078](../ws035/phase078/phase.md)（XKB keymap の試験）
Owner: 未定（WS073 の候補。driver は `src/drivers/usb/usb-hid.c`）

## 期待と観測

期待: USB の keyboard の HID usage 0x46（Print Screen）、0x47（Scroll Lock）、0x48（Pause）、0x53（Num Lock）、0x54〜0x63（keypad の
/ * - + Enter 1〜9 0 .）、0x64（102nd の `<>`）、0x65（Application = Menu）が evdev の KEY_SYSRQ・KEY_SCROLLLOCK・KEY_PAUSE・
KEY_NUMLOCK・KEY_KP*・KEY_102ND・KEY_COMPOSE として `/dev/input/eventN` に出る。

観測: QMP で `num_lock` を押しても zdesktop の client（`/bin/seat-probe`）に key が届かない（Caps Lock は届く）。
`keyboard_code()`（`src/drivers/usb/usb-hid.c`）の表に上の usage が無く、KEY_RESERVED になる（コードを読んで確認）。

## 影響

keypad で数字を打てない、Num Lock を使えない。zdesktop の XKB keymap（p078）はこれらの key を持つが、実際には届かない。

## 次の手

`keyboard_code()` に上の usage を足し、QMP の `kp_7`・`num_lock` 等で evdev の code を確かめる（`plan/ws035/tests/zdesktop-p078.sh` の
Num Lock の段を戻す）。

## 解決（2026-09-27、ws073-p011）

`keyboard_code()` に Linux の HID の表と同じ code を足し、`include/uapi/input.h` に定義を足した（日本語の keyboard の key も）。QMP の
`input-send-event` で 31 中 28 の key が期待の code で届く（修正前は 2）。QEMU の usb-kbd が標準の usage を送らない `menu`・`f13`・`f24` は実機で
確かめる（未実施）。`plan/ws073/tests/keys-host.py`・`evdev-keys.c`。[ws073-p011](../ws073/phase011/phase.md)。
