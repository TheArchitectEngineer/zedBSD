# BUG-321: Latitude 5330 で i915 の初期化の途中に kernel が止まる（`invalid kernel allocation free`、回帰）

- 状態: reproduced（ユーザー、5330 実機、2026-10-15）/ scheduled（P1、BUG-320 の後）
- 発見: 2026-10-15 ユーザー「5330でi915がフリーズするリグレッションを確認しました。P1でPiの修正が終わったらi915をP1で修正してください。」（画面の写真、chat。image の版は未確認＝ユーザーに聞く）
- 画面（写真から Q1 が読んだ）: login prompt の後に i915 の P3 の行が続く: `xc step=D0 DMC load queued (path=i915/adlp_dmc.bin, work_submitted=1)`、`i915: firmware /lib/firmware/i915/adlp_dmc.bin: loaded (79088 bytes)`、`i915: P3 modeset/flip workqueues: modeset=1 flip=1`、`i915: dmc worker: proceeding to load`、`i915: Forcing SAGV disable: mask 0x10b`、`i915: P3 intel_bw_init: obj=3 sagv_forced=1 qgv=0x4 psf=0x6 mask=0x10b pcode=0 sagv_status=1`、`i915: PCIID cached: ven=0x8086 dev=0x46a8 rev=0x0c subsys=1028:0b02 | live: …`、`i915: P3 intel_init_quirks: dev=0x46a8 subsys=1028:0b02 quirk_mask=0x0 hooks=0 …`。その後、複数の CPU の出力が混ざった行に `…rn/entry.c:269: invalid ker…`（= `src/kern/entry.c:269` の `HAL_FATAL("invalid kernel allocation free")`、kernel の大きな確保の free に確保されていない pointer が渡った）と `fault`・`call`・`ffffffff8…` の stack の番地（読み取れる断片: `ffffffff8901358`、`ffffffff80219…155c`、`80218f89`、`…8205368`）。
- 読み（未確認）: i915 の初期化（DMC の worker・modeset/flip の workqueue・bw_init・quirks の頃）か並行する仕事で、kernel_free の二重の解放か誤った pointer。最近の i915 の変更（WS237 の Gen9 の安全化 63d0532b0 は Gen9 だけの道、5330 は Gen12 の ADL-P）や他の main の変更との関係は未調査。
