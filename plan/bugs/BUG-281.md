# BUG-281: QEMU の guest で SSH の session（slirp の TCP）が約 1〜2 分止まって戻ることがある

Reproduction: reproduced（QEMU、間欠、T1-513 と T1-515）
Disposition: tracking
Discovery: 2026-10-10 P1 の T1-513・T1-515 の解析
Handling: 未定（kernel の TCP か virtio-net・slirp の経路。BUG-222 の USB LAN とは別の interface）

## 観測

- T1-513（1bb9ab24e より前の image）: tcp-receive-speed の run で fetch の出力が `Connection to 127.0.0.1 closed by remote host.`、約 120 s。直後の SSH と次の run は通った。
- T1-515: lan-hotplug の counters の SSH の呼び出し `ifconfig ue1` が空のまま約 60 s（timeout）止まった。2 回に 1 回。
- T1-516 の受信 6 回（filter-dump つき）では再現しなかった。

## 次

再現の時の採取（host の slirp 側の capture、guest の netstat・ifconfig の数、kernel の TCP の timer の状態）を試験に足す。T1-515 の試験は空の返事を 3 回まで取り直す形にした（6ed93d24d）。

## 2026-10-14 関係の疑い（T1-597、P2 の解析）: 起動の直後に SSH の接続が命令を走らせずにすぐ閉じる

- 同じ物とは断定しない（BUG-281 は止まってから戻る、こちらは止まらずにすぐ閉じる。ssh の status は 255 と推測、LogLevel=ERROR で何も出ない）。
- T1-597（QEMU、tree 24208099f、config-amd64-users.mk）で、`guest.py wait` が通った後の約 1 分、admin-p026 と user-commands-guest の request が guest に届かず空の答えで FAILED。guest の /var/log/messages には最初の 2 行と、約 1 分後からの行だけ。証拠: T1 の worktree の build/review/t1-597/（admin-run2.txt・uc-run2.txt・out2b/messages.txt）。
- 試験の側は ssh の 255 を 3 秒ごとに最大 90 秒取り直す形にした（842c58a82、`ssh-retries: N` を出す）。再試験（T1-600）で N が 0 でなければここに足す。
