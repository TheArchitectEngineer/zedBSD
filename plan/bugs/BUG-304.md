# BUG-304: raw の block device への write が 512 B ごとに disk_write を呼び、4 KiB の line を毎回書く（約 8 倍の書き込み）

- 状態: reproduced（QEMU、T1-609 の QMP の wr_bytes）/ scheduled（2026-10-14 Q1、P2）。2026-10-14 P2 が直した（commit 738edbe23、QEMU は未確認、T1 の確かめ待ち）
- 発見: ws231-p001 の T1-609（AHCI）。32 MiB の `dd of=/dev/sda` で QMP の wr_bytes が 256 MiB。P2 の解析: `src/kern/devfs.c` の `block_pwrite_data()` が sector ごとに `disk_write()` を呼び、write-through の disk で `buf_write_context()` が 4 KiB の cache の line を毎回書く（65536 × 4 KiB = 256 MiB）。line の最初の部分の書き込みは line を読む（32 MiB の rd）。NVMe・USB も同じはず。
- 直し方の案: `block_pwrite_data()`・`block_pread_data()` で整列した複数の sector をまとめて `disk_write()`・`disk_read()` に渡す。
- 関連: WS231、installer の image の dd。

## 直し（2026-10-14 P2、branch agent/p2-ws215、base main 078b388fd、commit 738edbe23）

- `src/kern/devfs.c`: `block_pread_data()`・`block_pwrite_data()` の loop の先頭で、位置が sector に揃っていて 1 sector 以上残るなら、揃った完全な sector の並び（run、最大 `DEVFS_BLOCK_IO_RUN_BYTES` = 1 MiB）を caller の buffer から直に 1 回の `disk_read()`・`disk_write()`（claim のある raw の予約では `disk_read_direct()`・`disk_write_direct_claimed()`）に渡す。新しい helper `devfs_block_io_run()`。揃っていない頭と尾の部分 sector だけが今までの sector の bounce（読み・混ぜ・書き）を通る。完全な 1 sector を 0 で埋めた bounce で書く枝は run の経路に入ったので消えた。
- 一貫の根拠（source を読んで）:
  - 分割: run は `buf_write_context()`・`buf_read()` に入り、line の境界に揃った 2 line 以上は `transfer_run()` → `disk_transfer_progress_context()` → `disk_transfer_direct()` が `d_max_transfer_blocks` で分ける。claim の経路は `disk_transfer_direct()` が直に分ける。devfs は分割を持たない。
  - partition の境界: 範囲は前と同じ `devfs_block_io_range_prepare()` で partition の `d_block_count` に切られ、`disk_resolve_range()`・`bio_admit()` が leaf の範囲に写して確かめる（前と同じ）。
  - buffer cache との一貫: cache の経路は前と同じく buf を通るので mount と raw が同じ block を触っても同じ line を見る（cache 済みの line は line ごとの経路、cache に無い揃った line は transfer_run が line を確保して書く）。claim の経路は前と同じく書く前に `buf_invalidate()` で範囲の clean な line を捨てる。範囲全体の `backing_mutation_begin_disk()` も前と同じ。
  - DMA: AHCI・NVMe の driver は自分の bounce に memcpy する（`pci-ahci.c` の 2724 行付近・`pci-nvme.c` の 4596 行付近）ので、caller の buffer の整列は要らない（filesystem も任意の buffer で多 block を渡している）。
  - 失敗の報告: run の途中の失敗は、その run より前の byte 数を返す（何も済んでいなければ error）。前は sector の単位だった短い write の報告が run の単位（最大 1 MiB）に粗くなる。
- 期待: `dd of=/dev/sdN bs=64k` の 64 KiB の write は 1 回の `disk_write(…, 128 sector)` → write-through の disk では 16 line の transfer_run 1 回 → 32 MiB で wr_bytes ≈ 32 MiB、line の読み込み（rd）は無し。**`dd` の既定の bs=512 のままの write は 1 sector の run なので line ごとの経路のまま（前と同じ 8 倍）**。直すなら cache の側の作り（部分 line の write を line 全体で書かない）が要り、この BUG の範囲外。
- 確かめ（P2、host）: `make ZEDBSD_CONFIG=config/ci/config-amd64.mk BUILD=build/bug304 build/bug304/vmunix -j16` rc 0、warning 0、`amd64 vmunix check: PASS`（BUG-305 の直しを含む）。使い捨ての host 試験（scratchpad、commit しない）: devfs.c から `devfs_block_io_range_prepare`・`devfs_block_io_piece`・`devfs_block_io_run` を抜き出し、新しい loop と同じ形の model を 512・4096 B の sector で 3000 回ずつ乱数の offset・長さ（0〜3 MiB）で書き読みし、byte 単位の参照と一致、部分 sector の経路に完全な sector が来ないこと、64 KiB の揃った write が 1 回の disk の呼び出しになること、2 つ目の run の失敗で 1 MiB を返すこと、ENOSPC を確かめた（ASan・UBSan、PASS）。QEMU は未実施。

### T1 への確かめの依頼の文（T1-610 の AHCI の再試験と一緒に流せる）

image: branch agent/p2-ws215 の 738edbe23 以降（Q1 の merge の後は main）、`plan/tools/guest/test-image.sh plan/ws231/tests/config-amd64-ahci.mk build/<名前>`。QEMU は T1-609・T1-610 と同じ q35、64 MiB の raw を `-device ide-hd,bus=ide.0,drive=sata0`、加えて 64 MiB の raw の NVMe `-drive if=none,id=nv1,file=<img>,format=raw -device nvme,serial=nv1,drive=nv1`。判定は SSH と QMP だけ（console・serial の log は使わない）。

1. **AHCI の wr_bytes**: `dd if=/dev/urandom of=/tmp/a bs=1M count=32` の後、QMP `query-blockstats` の sata0 の wr_bytes・rd_bytes を取り、`dd if=/tmp/a of=/dev/sda bs=64k`、もう一度取る。合否: wr_bytes の差が 32 MiB に近い（33554432 以上、36 MiB 未満）、rd_bytes の差が 1 MiB 未満。続けて `dd if=/dev/sda of=/tmp/b bs=64k count=512; cmp /tmp/a /tmp/b` が一致。
2. **NVMe の wr_bytes**: 同じ手順を nv1（guest の /dev/nvme1n1、名前は `ls /dev/nvme*` で確かめる）に。合否: wr_bytes の差が 32 MiB に近い（前の T1-609 の見立てでは ~256 MiB だった）、cmp が一致。
3. **部分 sector**: `printf abc | dd of=/dev/sda bs=1 seek=1000 conv=notrunc` の後 `dd if=/dev/sda bs=512 skip=1 count=1 | od -c | head -2` で offset 1000（sector 1 の 488 byte 目）に `a b c` があり、`cmp` で /tmp/a の他の byte が変わっていないこと（`dd if=/dev/sda of=/tmp/d bs=64k count=512; cmp -l /tmp/a /tmp/d | wc -l` が 3 以下）。
