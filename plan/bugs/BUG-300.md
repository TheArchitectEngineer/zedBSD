# BUG-300: Video Player のスライダーが、再生の終わりで 50% くらいの位置に止まる

- 状態: reproduced（実機 5330、ユーザー） / tracking
- 発見: [ws202-p013](../ws202/ws.md) の 5330 の UAT（ユーザー、2026-10-13）。ユーザー「動画プレーヤーアプリのスライダーは、ビデオの再生が終わっても50%くらいの位置で、スケールあるいは認識されている再生時間がおかしいようでした。それは動画プレーヤーのバグかも。」
- 期待: 再生の終わりでスライダーが右端（100%）に来る。
- 観察: 再生は終わりまで進むが、スライダーは約 50% の位置。UAT の判定は OK（ユーザー）で、この不具合は p013 を止めない。
- 疑い（未調べ）: Video Player がスライダーの全長に使う長さ（container の duration・`end_us`、ws202-p004）と、表示に使う pts の単位・時刻の基準（D29 の空の entry の時刻の消費、edit list・trim）の食い違い。約 2 倍なので、timescale の取り違えや音と映像の track の長さの取り違えもありうる。
- 再現の材料: ws202-p013 の image（libavcodec 無しの `plan/ws202/tests/config-media.mk`）、どの file で見たかは未記録（ユーザーに聞くか、WS202 の試験の stream で全部見る）。
- 関連: [WS202](../ws202/ws.md)（p004 の `end_us`、p010 の時刻、p011 の Video Player）、WS122（動画の player）。

## 2026-10-13 夜: 原因と直し（Q1、bug-analyzer の解析）

- 原因: `userland/desktop/videoplayer/main.c` の「終わり」の遷移で `VP_ENDED` にする時に clock の anchor（`media.clock_time`）を今の clock に固定していなかった。`vp_media_clock()`（media.c）は再生中でない時 anchor をそのまま返すので、終わった瞬間にスライダーと時刻が「最後に Play で再開した位置か seek した位置」（どちらも無ければ 0:00）へ戻る。途中で Pause→Play か seek をすると、その位置（約半分なら約 50%）に見える。libmedia の engine（engine.c の ENDED）と Music（play.c）は固定している。
- 調べで外れた候補: container の timescale（mediafile の duration 6.25 s・各 track の end_us は正しい）、AAC の長さ（298000 frame = 6.208 s）、clock の単位（48000）、映像の pts。ユーザーの動画で host の probe で確かめた。
- 直し（Q1、main の checkout）: ENDED にする前に anchor を終わりの clock（長さの方が大きければ長さ）にする。Video Player の amd64 の build（config/current-uat.mk、BUILD=build/q1-bug300）warning 0。host 試験は無し（UI の main.c だけ）。
- 未確認: ユーザーが UAT で途中に Pause・seek をしたか（していなければ症状は 0% のはずで、別の原因が残る）。QEMU・実機の確かめは T1（短い file で途中に Space 2 回 → 終わりでスライダーが右端・時刻が「長さ / 長さ」、触らずに終わり → 右端、ENDED の後の Left で終わり −10 s へ）。
- 状態: 直しを入れた、確かめ待ち（tracking のまま）。

## 2026-10-13 夜: 2 回目の解析（bug-analyzer）

- 一時停止・seek 無しで「終わりで約 50%」になる決定的な経路は code からは見つからなかった。除外した候補: container の長さ・timescale、AAC の rate（AAC-LC 48000 Hz・298000 frame）、clock の単位（AUDIO_RATE 48000）、heard の単位（audiod の read_position は stream frame、delay も換算、device は stereo）、audiod の delay（約 85 ms）、映像の pts（ctts 有り）、mp4 の interleave、slider の描画（widgets.c:500-504）、Space が UI に渡る、resize・F11。clock が半分の速さなら映像も遅れて終わりでは 100% になるので、50% は「heard が約 3.1 s で止まる」か「anchor が 3.1 s」しか無い。
- 別の実在の不具合: audiod の heard は client が書き終わると read − delay で凍る（mix.c:296-305、10-12 の acfb78a27 からの退行）→ Video Player の clock が音の終わりの約 85 ms 手前で止まり、最後の picture が due にならず ENDED に到達しない（main.c:803-811）。device が 48000 でない時は補間が最後の 1 frame を消費せず played_out も偽。→ player の側の直しを bug-fixer に（audiod の直し: ring が空で draining でない間は heard を時刻で read まで進める、は案として残す）。
- 残る仮説（5330 でだけ起きる実行時の条件）: (1) 音が鳴っていなかった・stream が lost（AUDIO open error・AUDIO lost）(2) 5330 の GPU decode が遅く音の ring が枯れて heard が凍り、picture ring が満杯で reader が待ち音を書かない膠着 (3) 途中の Space。
- 切り分け: 調査用の CLOCK の log 行（time_ms・heard・written・consumed・pictures・late・eof・state、1 秒ごと）を足した Video Player を 5330 で、ユーザーの動画（repo の外の build/bug300/、5330 の kei の home に scp、image や tests/ には入れない）で何も押さずに最後まで再生し、log を回収する（T1）。
- ユーザーの許可（2026-10-13）: 動画を 5330 の kei の home に scp して使ってよい（repo・image・tests には入れない、試した後は 5330 から消す）。


## 2026-10-13 夜: player の側の直し（bug-fixer）

- 直した所（`userland/desktop/videoplayer/main.c` だけ、audiod は触らない）:
  - 新しい `vp_played_out()`: 再生中・reader が eof・seek の要求なしの時だけ「音が出きった」と判定する。音ありは `read + 1 >= written`（rate の補間が最後の 1 frame を消費しない分を許す）、または eof の後に heard の位置が `VP_END_STALL_US`（0.5 s）動かなければ出きった。音なしは従来どおり clock が長さに達したら。
  - `vp_draw`: 出きったら残りの picture を全部 due と見なして（`vp_media_take` に `HUGE_VAL`）最後の 1 枚まで出し、picture が空なら ENDED。heard が delay（約 85 ms）手前で凍るので、`clock >= picture_time` の条件は外した。ENDED の時の anchor の固定（2a7e09cd9、長さの方が大きければ長さ）はそのまま。
  - 調査用の log（残してよい軽い行）: 再生中に 1 秒ごと `CLOCK time_ms=… heard=… written=… consumed=… pictures=… late=… eof=… out=… state=…`（heard = `vp_audio_clock_position`、written = `vp_audio_write_position`、consumed = `vp_audio_read_position`、out = 上の判定）。
- build: `ZEDBSD_CONFIG=config/current-uat.mk make BUILD=build/bf-bug300 build/bf-bug300/bin/videoplayer`（-Wall -Wextra -Werror）warning 0。host 試験は無し（UI の main.c の static 関数だけ）。
- 未確認（T1・5330）: (1) 何も押さずに最後まで再生 → ENDED に達し、スライダーが右端・時刻が「長さ / 長さ」（以前は最後の picture が due にならず ENDED に届かないことがありえた）。(2) device の rate が 48000 でない時も ENDED に達する。(3) 途中で Space 2 回・seek の後も終わりで右端。(4) 5330 でユーザーの動画（repo の外の `build/bug300/user-video.mp4`）を何も押さずに再生し、CLOCK の行で heard が約 3.1 s で止まるか（50% の残る仮説の切り分け）。
- audiod の直しの案（今回は入れない、他の client にも効く）: ring が空で draining でない間は heard を時刻で read まで進める（mix.c:296-305 の `audiod_played_store`）。

## 2026-10-13 夜: 再生中の停止の直し（bug-fixer、案 1）

- 原因の確かめ（host）: ユーザーの動画の chunk の並び（stsc・stco、repo の外の写しを読んだだけ）は「映像 10 frame（約 417 ms）→ AAC 20 frame（約 427 ms）」の交互が 30 回。reader は映像の chunk の 10 packet を decode し切るまで次の音の chunk を読まない。picture の ring（8）＋待っている 1 枚が、時計（heard、書いた音の終わりより audiod の delay 約 85 ms 手前で止まる）から先の chunk の残りの picture を入れきれないと、reader は `media_picture` で ring の空きを待ち、音を書かず、heard が止まり、picture が due にならない膠着になる。decoder の出す遅れ（reorder の深さ）が小さいほど起きやすい（packet を送るのに先に出す picture が多い）。
- どちらにしたか: **案 1**（音と映像の待ちを分ける）だけ。理由: (a) 膠着の元（reader が映像の待ちで音を書かない）を直接除く。音は途切れず、時計は音のまま。(b) 案 2（音が枯れたら monotonic で時計を進める）は、この file では chunk ごとに音が枯れて途切れ、音が戻った時には時計が先にあるので、音を捨てるか A/V がずれる。直しが大きく（underrun の判定・anchor の合わせ直し・遅れた音の捨て方）、音の途切れが毎秒起きる再生は正しくない。(c) 変えるのは media.c の reader だけで、時計・window・audio は変えない。
- 直した所（`userland/desktop/videoplayer/media.c` だけ）:
  - 映像の packet は読んだ順に上限つきの queue（`MEDIA_PACKETS` 128 個・`MEDIA_PACKET_BYTES` 64 MiB、container の bytes は次の read で無効になるので写す）に入れ、音の packet はその場で decode して音の ring に書く。
  - ring が満杯の時、decode した picture は reader が 1 枚だけ持ち（`held`）、`media_picture` は待たずに `MEDIA_FULL` を返す。毎回の read の前に `media_video_pump` が「持っている picture → decoder の出す物 → queue の次の packet」の順に ring の空きの分だけ進める（picture の順は保つ）。送った packet は、その後の drain が終わるまで queue に残す（decoder が bytes を後で読む場合も、以前の「次の read まで有効」と同じ保証）。
  - queue も満杯の時だけ reader は ring の空きを待つ（以前の待ちと同じ。交互でない特殊な file ではここで以前と同じく待つ）。file の終わりは queue の最後の印（NULL の送り）で映像の decoder を drain し、映像が全部 ring に入ってから音の decoder を drain して `eof` にする（以前と同じ順）。seek と close は queue と持っている picture を捨てる。
  - 前の直し（2a7e09cd9 の ENDED の anchor、2690a1d2e の `vp_played_out` と CLOCK の log、main.c）はそのまま。
- build: `ZEDBSD_CONFIG=config/current-uat.mk make -j16 BUILD=build/bf2 build/bf2/bin/videoplayer`（-Wall -Wextra -Werror）warning 0、`git diff --check` OK。
- host の試し（commit しない、使い捨て）: media.c を host で stub（交互の file 10/20・6.25 s、reorder の遅れ N の映像の decoder、0.5 s の音の ring で heard が consumed の 4096 frame 手前・枯れると止まる sink、window の take の loop、4 倍速）と link。直す前の media.c: N=0 で clock 0.000 s・N=2 で clock 0.341 s のまま `pictures=8 eof=0 written=consumed`（5330 の CLOCK と同じ形）で止まる、N=3・6 は通る。直した media.c: N=0・1・2・3・6 の全部で eof に達し 148/150 枚まで出る（残りの 2 枚は音の終わりの約 85 ms の凍り、main.c の `vp_played_out` が扱う部分で、この試しの window には無い）。ASan・UBSan で N=2 も無事。
