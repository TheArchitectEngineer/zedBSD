# BUG-184: Settings で WiFi をオンにした後、オフにしようとクリックすると Scan のボタンが押され、オフにならない

Reproduction: reproduced（実機）
Disposition: tracking（優先度: 高）
Discovery: 2026-10-04 夜 ad-hoc UAT-3（実機 Latitude 5330、image `build/uat-3/hdd-image.img` sha256 ada4492e…、main efe846a、[uat.md の uat-3](../uat.md)）
Handling: WS089（Settings の Wi-Fi の頁）

## 観測

ユーザー「同じ動作で、SettingsでWiFiをオンにしたあと、オフにしようとクリックすると、Scanボタンが反応して押されたことになり、オフボタンは押されたことにならない」

## 次

オンになった後に頁の配置（Scan のボタンの出現・行の追加）が変わり、hit の判定の矩形が描画と食い違っている、またはオンの直後の再配置の前の座標で click を判定している疑い。switch と Scan のボタンの矩形を確かめ、配置が変わった時に hit の表を作り直す。 修正は P3（Bug の修正の担当）の Queue（q700）で。QEMU の確認は T1（AX211 が無い QEMU では networkd の模擬か RTL8822BU の USB passthrough）、実機は次の UAT。

2026-10-04 夜: ユーザーの要望で Scan のボタンを無くす（[ws089-p021](../ws089/phase021/phase.md)）。この Bug は p021 と一緒に直す（hit の判定の食い違いの根も確かめる）。

## ws089-p021 での扱い（2026-10-05、q703-i01 P2 generation14）

Scan のボタンは p021 で無くした。hit の判定の食い違いは無かった（Wi-Fi の頁の switch と Scan の矩形は重ならず、press・release は同じ frame の hit の表で引く）。根は、頁が 20 秒ごとに出す Settings 自身の scan の要求が一つだけの要求の枠を占め、その間の off が slot で待ち、見出しが「Searching...」になっていたこと。scan は要求の枠の外（`kl_system_network_set_scanning`）に移した。確認は p021 の試験（settings-p021.sh、T1）と UAT。詳細は [ws089-p021](../ws089/phase021/phase.md)。
