# BUG-315: OLED（Wacom 056a:8191）の multi-touch で compositor の edge の gesture が不安定

- 状態: reproduced（実機、ユーザー）/ tracking（2026-10-15 Q1、担当は未割当）
- 発見: 2026-10-15 ユーザー（BUG-313 の 2 回目の直しの後、T1-649）「マルチタッチにはなったのですが、操作がかなり怪しいです。画面端のスワイプでなくても仮想デスクトップ送りができていますし、上端からのスワイプダウンが認識されないですし、なんだか不安定です。」
- 環境: Pi 4、1280x720、13.3 インチの OLED の USB の touch panel（contact-count-maximum=10、10 slots）、BUG-313 の 2 回目の kernel（2f072ff41）。
- 症状: (1) 端からでない swipe で仮想 desktop が切り替わる。(2) 上端からの swipe down（Wiseview、BUG-270）が効かない。(3) 全体に不安定。
- 候補（未確認）: (a) `userland/desktop/wayland/touch.c` の群の規則（KWL_EDGE_GROUP_MS 以内の 2 本以上で、外側の 1 本が KWL_EDGE_GROUP_BAND の中なら残りはどこでも edge の swipe、BUG-267）が、この panel の 2 本指の操作で誤って当たる。(b) touch の座標の範囲（abs の max）と画面の 1280x720 の対応が合わず、端の判定がずれる（panel の native は 1024x600 の可能性）。(c) BUG-313 の event4（keyboard の collection の main device）が残っている影響。
- 次: T1 が abs の範囲・`fingers down at once`・compositor の log を集める（T1-649 の続き）。それから担当を決める。
- 関連: BUG-313、BUG-267、BUG-270、WS079、WS217。
- 2026-10-15 ユーザーの追試: 「1本指スワイプで仮想デスクトップ送りができてしまいました。」（画面の中ほどからの 1 本指の短い swipe）→ 群の規則（a）では説明できない。端の判定に使う座標がずれている（b）の見込みが強い: 中ほどの指が端の band の中と判定されている。
- 2026-10-15 ユーザー（中央と四隅を tap、T1 が event4・event5 を od で記録中）:「タッチは正常にクリックとして認識されていないことがわかりました。状態を持つスワイプに化けています。」→ 指を離したこと（release）が compositor に届いていない見込み（kernel の tip switch・contact count・slot の解放、または compositor の up の扱い）。座標の範囲は X 0..16383、Y 0..9599（16:10）、画面は 1280x720（16:9）。
- 2026-10-15 P2（BUG-313 の 3 回目と同じ round、kernel の release の経路の確認、host だけ）:
  - 8191 の touch の report（13、54 byte）は Finger が 10 個と Contact Count で、1 report に 10 本。hybrid にはならない（[BUG-313](BUG-313.md) の 3 回目の解読、fixture `plan/bugs/BUG-313/wacom-8191-if0.rdesc`）。
  - kernel の state machine（`src/drivers/generic/hid-touch.c`）に、この descriptor で次の 3 つの終わり方を host で通した。どれも slot に `ABS_MT_TRACKING_ID -1` を出し、最後の指で `BTN_TOUCH 0` を出す。
    - Contact Count 1 で Tip Switch 0。
    - Contact Count 0 の frame。
    - 2 本のうち 1 本が Tip 0（残りは触ったまま）、次に残りが Tip 0。
  - これは `plan/ws143/tests/hid-input-host-test.sh` の `check_8191_release` として固定した（PASS）。
  - kernel の原因は見つからず、直しは無い。
  - 残る kernel の側の可能性は 2 つ。どちらも T1 の event5 の生の記録で判定する。
    - (1) panel が離した時の report（Tip 0 か Contact Count 0）を出さずに黙る。Linux の hid-multitouch は Win8 の device にこれを見込んで、100 ms で指を離す（MT_QUIRK_STICKY_FINGERS）。zedBSD には無い。
    - (2) Contact Count が report の Finger の数（10）より大きい値で来る。frame が閉じず、次の count>0 の report は lift なしで書かれる。
  - 記録の見方は 2 つ。
    - event5 に `ABS_MT_TRACKING_ID -1`（type 3 code 57 value -1）と `BTN_TOUCH 0`（type 1 code 330 value 0）が tap ごとに出ていれば、kernel は離しを出しており、原因は compositor（`userland/desktop/wayland/touch.c`）の側。
    - 出ていなければ、生の report（`usbhid.dump=1` の `usb-hid-report:` の行）で (1)・(2) を P2 が見る。
- 2026-10-15 T1-649 の event5 の解読（T1、results-20261015-t1-649-650.md）: 各 tap は ABS_MT_TRACKING_ID -1・BTN_TOUCH 0・SYN で終わる（kernel の release は正しい）。tap は 0.07〜0.15 s、slot 0・1。X は左右の端で 0・16383。**Y は宣言の最大 9599 に対し約 6446 を超えない**（下端の tap が 5000〜6445）、上端は 1〜78。→ 原因は compositor の側（`userland/desktop/wayland/touch.c`）の見込み: 短い tap の扱い（状態を持つ swipe に化ける）と、Y の範囲（画面の下 1/3 に届かない）。
- 2026-10-15 ユーザー（3 回目の kernel の Pi）:「Pi4のタッチは改善していませんでした。シングルスワイプで仮想デスクトップが切り替わります。」→ 想定どおり（直しは compositor の側、P2 が作業中で未 merge）。
