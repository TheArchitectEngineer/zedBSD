# BUG-083: rtld の dlopen が /usr/lib の package の library を開けない

Bug ID: `BUG-083`
Reproduction: reproduced（QEMU の guest、ws074-p017）
Disposition: scheduled（ws074-p017 の中で修正、2026-09-28 main の判断）
Date: 2026-09-28
Source: WS074 p017（OpenSSL の dlopen）
Owner: WS074

## 観測

`src/rtld/rtld.c` の dlopen（dlopen_bare_name）は `/lib/<name>` だけを開き、/lib 以外の絶対 path を断り、/usr/lib を探さない。
DT_NEEDED の解決（open_search）は /lib → /usr/lib を探し、package の library は /usr/lib にあると注記している。そのため
`dlopen("libcrypto.so")` が OpenSSL の package の /usr/lib/libcrypto.so を見つけられず "shared object not found" になる。

また「読み込み済み」の判定は `objects[i].path+5` と bare name を比べ、"/lib/" の接頭辞を前提にするので、DT_NEEDED で /usr/lib から
読んだ library を dlopen で二重に読みうる。

## 修正の方針

1. bare name の dlopen は /lib に無ければ /usr/lib を探す（DT_NEEDED と同じ順）。任意の絶対 path は今のまま断る。
2. 読み込み済みの判定は basename で比べる。
rtld の確認と boot test で検証する。
