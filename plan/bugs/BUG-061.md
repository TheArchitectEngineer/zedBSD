# BUG-061: devfs で `lstat("/dev/fd/N")` が開いた directory そのものを返し、`du /dev` が /dev/fd/4 で directory の loop と言って 1 で終わる

## 観測

lstat は symbolic link（`/dev/fd/N` → 開いた file）として答えるべき。今は開いた directory の stat を返す。

## 次の手

devfs の /dev/fd の lstat を WS067（/dev/fd）の実装に合わせて直す。

## 解決（2026-09-27、ws073-p001）

Linux の `/proc/self/fd` と同じく、link をたどらない問い合わせ（lstat・`fstatat(AT_SYMLINK_NOFOLLOW)`・readlink・readdir の型）では
`/dev/fd/N`・`/dev/stdin` などを symbolic link として見せる。target は開いた file の path（directory は上への walk、他は name cache と devfs の走査）、
名前の無いものは `pipe:[N]` など。たどる stat・open は従来どおり。修正前は `find /dev` が `/dev/fd/3: directory cycle`、`du /dev` が 1。
修正後は両方 0、回帰試験 `plan/ws073/tests/devfd-link.c` 20 件 PASS、boot test PASS。
