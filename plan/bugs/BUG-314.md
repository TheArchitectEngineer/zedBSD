# BUG-314: Pi 4 で compositor が GPU への submit の EIO で終わり、session が出直した

- 状態: unknown（1 回観察、再現の手順なし）/ tracking（2026-10-15 Q1）
- 発見: 2026-10-15 ユーザー「今コンポジタが再起動しましたが、あなたがやりました？」。Q1・担当は誰もその時 Pi の compositor・再起動を操作していない（T3 は local の QEMU だけ）。
- 環境: Pi 4、BUG-313 の試験の kernel（P2、touch の修正の途中）、OLED の touch panel を接続、BT の試験（BUG-311）の後。
- 観察（Pi の /var/log/messages、Q1 が ssh で）:
  - `00:04:18 wayland[24]: KWL FAILED site=compose_draw errno=5 operation=submit result=-4`、同じ秒に `operation=acquire`、`site=park errno=42 thread=cursor step=stop`
  - `00:04:33 sessiond[23]: login kei on the graphical seat (password)`（session の出直し）
  - dmesg に V3D の fault・reset・hang の行は無い（`v3d: vk: capset declares H.264 video decode` だけ）。
- 推測（未確認）: kernel が submit に EIO を返した理由が log に出ていない。V3D の job の失敗、または device の喪失（seat の変化）。WS236 の video の capset が on の kernel であることも候補。
- 次: 再び起きたら時刻と直前の操作（touch・video・BT）を控え、V3D の submit の EIO の経路に理由の log を足す。
- 2026-10-15 P3（ws236-p006、agent/p3-ws236 9c1595a71、merge 待ち）: submit の ioctl の EIO は `runtime_ready`・`bcm2711_render_worker_submit` の admission の拒否（session の stop・engine の uncertain・not ready・fault）で、どちらも log を出していなかった。EIO を返す submit の道（render-worker.c の submit・job reserve/commit/capacity、render-runtime.c の command、vulkan-queue.c の queue submit/execution）に `v3d: EIO at <site>: <reason> (N more refusals …)` を 1 秒に最大 1 行足した（判定は不変、build warning 0）。再発時はこの行で理由が分かる。
- 関連: BUG-313、BUG-311、WS236。
