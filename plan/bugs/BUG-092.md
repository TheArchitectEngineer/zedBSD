# BUG-092: graphical な起動で sessiond が /dev/gpu0 の現れる前に始まり、console の login に落ちる

Bug ID: `BUG-092`
Reproduction: reproduced（5330 の i915、ws075-p013）
Disposition: resolved（2026-09-28、ws035-p113。demo の image の `greeter_gpu` の回避は削除）
Date: 2026-09-28
Source: ws075-p013（H4）
Owner: WS035

## 観測

sessiond が i915 の `/dev/gpu0` の公開（約 1 秒後）より前に始まり、`SESSIOND CONSOLE reason=no-display errno=6`（ENOENT）で console の login に落ちる。
Venus では GPU が先に現れるので出なかった。

## 次の手

sessiond が GPU の driver の attach の途中なら上限付きで `/dev/gpu0` を待つ（GPU の無い機械では console の login を遅らせない）。
demo の image の `greeter_gpu`（120 秒待つ）をこの修正に置き換える。

## 修正（2026-09-28、ws035-p113）

- kernel: sysctl `hw.gpu.attaching`（uint32、`HW_GPU_ATTACHING`、`include/uapi/sysctl.h`）= driver が attach したが GPU の node を
  まだ公開していない（または諦めていない）device の数。`kern_gpu_attach_begin()`/`kern_gpu_attach_end()`（`src/kern/sysctl.c`、atomic で
  0 未満にならない）。i915 は PCI の attach（init より前）の `drv_i915_device_schedule_start()` で数え、node の公開
  （`drv_i915_publish()` の `drv_gpu_register()` の成功）、start の失敗・終わり、start の worker の作成の失敗、pending のままの stop で
  1 回だけ外す（`drv_i915_device_attach_settled()`、start registry の lock の下の `attach_counted`）。HAL は変えていない。
- sessiond（`userland/desktop/sessiond/main.c`）: `/dev/gpu0` が無いとき `hw.gpu.attaching` を読み、0（または sysctl が無い）なら
  もう一度だけ見てすぐ console へ。0 でない間は 100 ms ごとに見直し、最大 15 秒待つ（超えたら `SESSIOND DISPLAY timeout` を log して console）。
  待った時は `SESSIOND DISPLAY waited_ms=N` を log。
- demo の image: `plan/ws075/demo/greeter_gpu`・`greeter-gpu.sh`・`rc.conf` を削除し、`build-demo-image.sh` は base の rc.conf を使う。

## 確認

- 実機（5330 の i915 の passthrough、`build/b091/` の demo の image、回避なし）: sessiond.log `SESSIOND DISPLAY waited_ms=300` →
  `SESSIOND START` → greeter が HDMI の 1920x1280 に出た（`build/ws075-shots/bug092-greeter-hdmi-no-workaround.png`、scanout の buffer）。
- QEMU（GPU の無い q35、同じ image、login=graphical）: sessiond.log は `SESSIOND CONSOLE reason=no-display errno=6` の 1 行だけ（待ちの行
  なし = 待っていない）、boot test PASS（`build/ws075-shots/bug092-qemu-nogpu-console-login.png`）。
