# BUG-122: compositor が落ちた後、greeter が 3 回失敗して文字の console に落ちる

Bug ID: `BUG-122`
Reproduction: reproduced（5330 の passthrough、2026-09-30、BUG-117 の compositor の終了の後。QEMU の Venus でも ws099-p010 で再現）
Disposition: resolved（ws099-p010、2026-09-30、QEMU。5330 は未確認）
Date: 2026-09-30
Source: ws075-p025 の報告
Owner: WS099（sessiond・greeter の起こし直し）

## 観測

BUG-117 で compositor が終わった後、greeter が 3 回続けて失敗し、文字の console に落ちた。デモ中に compositor が落ちたとき、graphical の
login に戻れず console が見える。GPU の lease の返しと次の compositor の起動の順、または起こし直しの間隔の問題と見ている（推測）。

## 次にすること

compositor を意図して落とす試験（kill）で再現し、greeter の起こし直しの失敗の理由を sessiond の log で見る。

## 再現（ws099-p010、QEMU の Venus、criteria の image）

- session の compositor を kill -9 → sessiond は greeter を起こし、greeter は出る（ここは失敗しない）。
- greeter の compositor を、出るたびにすぐ kill -9 する（落ち続ける compositor の形）→ 3 回目で `SESSIOND CONSOLE reason=greeter-failed failures=3`、
  文字の console の login（`plan/ws099/tests/bug122-recovery.sh` が直しの前の image で FAIL）。
- 原因（sessiond の方針）: 起動から 20 秒以内に終わった greeter を失敗と数え、3 回続くと 1 秒ずつの待ちの後に console に戻す。5330 では
  BUG-117 の後の greeter が `ZWL EXIT error=21`（EOPNOTSUPP、`display.c` の display の問い合わせか GPU の能力）で 3 回続けて終わった。
  GPU が回復するまでの時間に対して、3 回・1 秒の待ちは短すぎる。5330 で EOPNOTSUPP が出た理由（i915 の状態）は QEMU では再現できない。

## 直し（ws099-p010）

- `userland/desktop/sessiond/main.c`: console に戻すまでの失敗を 6 回にし、待ちを 1・2・4・8・16 秒に伸ばした（合わせて約 31 秒）。
  `SESSIOND GREETER retry failures= delay=` を log に出す。
- `userland/desktop/sessiond/greeter.c`: 失敗のたびに greeter の log（`/var/log/greeter.log`）の最後の `ZWL EXIT` の行（無ければ最後の行）を
  `SESSIOND GREETER failed reason="…"` として sessiond の log に写す（次に 5330 で起きたとき理由が残る）。
- 確認（QEMU）: `bug122-recovery.sh` PASS（session の compositor の kill の後に greeter、greeter の compositor の 5 回続けての kill の後も console に
  落ちず greeter が出る、kei が login できる）。直しの前の image では FAIL。

## 再検討

5330 で再び起きたら、sessiond の log の `SESSIOND GREETER failed reason=` で理由を見て、GPU（i915）の回復の側を直す（WS099 の L2、WS075）。
