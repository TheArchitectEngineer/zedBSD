# BUG-107: system 全体の socket の上限（32）が小さく、SSH の並列の session が ENFILE で失敗する

Bug ID: `BUG-107`
Reproduction: reproduced（QEMU、ws073-p030 の SSH の負荷）
Disposition: resolved（2026-09-29、[ws073-p034](../ws073/phase034/phase.md)、QEMU で確認。実機は未実施）
Date: 2026-09-29
Source: ws073-p030 のサブエージェントの報告
Owner: WS073（ws073-p034）

## 観測

`include/kern/net/socket.h` の `SOCKET_MAX 32U` が system 全体の socket の数の上限。SSH の session を 6 本並列にすると、sshd と
sshd-session が `socketpair: Too many open files in system`（ENFILE、`src/kern/net/socket.c` の `socket_create`）で失敗し、その後
OpenSSH の PerSourcePenalties が host からの接続を一時的に締め出す。静かな guest で socket は 9 個、SSH の session 1 つで約 3〜4 個。
デスクトップ（Wayland の client、networkd、audiod 等の unix socket）でも上限に近づく可能性がある。

## 直し方（案）

固定の配列を動的な割り当て（または大きな上限と process ごとの上限）にする。

## 修正と確認（2026-09-29、[ws073-p034](../ws073/phase034/phase.md)）

- `SOCKET_MAX` 1024（socket の実体は既に 1 つずつ割り当て。上限は guard）。raw ICMP・packet・route は stack の snapshot（32）で配るので、
  family ごとの上限 `SOCKET_BROADCAST_MAX` 32 を作成の時に検査（ENFILE）。TCP の timer は socket の数に合わせて snapshot を割り当てる。
- QEMU: Venus の guest で zdesktop ＋ client 44（socket 100）が全て描画（修正前は約 10 枚で止まり SSH も不通）。同じ guest で socketpair 200 ＋ TCP 60、
  SSH 10 本並列で失敗 0。
- 別の限界（未修正、起票を依頼）: unix の listen の backlog が 16 に clamp され、満ちると connect が待たずに EAGAIN。一斉に 40 の client を起こすと失敗する。
