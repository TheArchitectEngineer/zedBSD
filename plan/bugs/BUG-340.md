# BUG-340: VF2 の実機で SD の 32 block の読みが data CRC の誤りで失敗し、/sbin/init が起動しない

- 状態: reproduced / resolved（2026-10-20 ユーザーの VF2 の実機: `dw-mmc: no sample phase reads at 49500000 Hz` → `card clock down to 24750000 Hz` の後に init が起動し `init: system running`。修正 f82741ef7。49.5 MHz で通らない理由は未解明、IDMAC との違いは未確認）
- 発見: ユーザーの VF2 の UAT（`build/uat/vf2/native-dtb.img`、`bootefi ${kernel_addr_r} ${fdt_addr_r}` で mainline の v1.3b の DTB）。ユーザーが貼った serial の log（判定には使わない、手がかり）: SD は `dw-mmc: mmcblk0 SDXC card SA128 …`、`bus 4-bit, 49500000 Hz, high speed`、`vf2-mmc: sample phase 0, sysreg 9c field 0`。GPT と partition の読み、root の mount まで成功。init の exec で `dw-mmc: read of 32 blocks at 137472 failed (5, status a4), try 1〜3` → `exec: load ELF failed for /sbin/init (5)`。
- status 0xa4 の読み（DW MMC の RINTSTS、推測）: bit 2 CMD_DONE・bit 5 RXDR・bit 7 DCRC（data CRC の誤り）。小さい読みは通り、大きい読みで CRC の誤り → 49.5 MHz の high speed で sample の phase 0 が合っていない見込み。
- 同じ log で動いた物: 4 CPU、PLL・clock、SD の card detect、PCIe0 の VL805 の xHCI と USB hub、PCIe1 は link down、DMAC、PWMDAC、`powervr: BXE 36.50.54.182 at 396000000 Hz, ALIAS OK`、Ethernet en0（YT8531、`link up 1000 Mbps full duplex`）、root の mount。
- 別の気づき: `dc8200: no-go (power domain off)`（U-Boot が GOP を出しているのに PD_VOUT が off と読めた。読み方の誤りか、GOP の scanout が DC8200 でない可能性。WS277 p002 で調べる）。
- 関係: WS256 p014（SD）、WS277 p002。
- 2026-10-20 追記（Q1、P1 q1359 の調べ 6512d3381）: 「別の気づき」の原因は U-Boot。vendor の U-Boot（starfive-tech/u-boot JH7110_VisionFive2_devel）の DC8200 の video の driver（sf_vop.c、DM_FLAG_OS_PREPARE）が ExitBootServices の dm_remove_devices_flags(DM_REMOVE_ACTIVE_ALL) で plane・panel を 0、reset、clock を止め、PMU の domain 4（VOUT）を off にする。ユーザーの目視「カーネルがブートした瞬間に、GOPのスキャンアウトは止まってるように見えましたね。」と合う。zedBSD の PD の読みは正しい。直し: PD_VOUT が off で loader の framebuffer がある時は WS277 p005 の自前の点灯（bootfb の memory をそのまま scanout、1920x1080@60）に入る。


## 修正（2026-10-20 P2、q1358-i01。実機は未確認）

- status の読み（確かめた）: `DW_MMC_RAW_STATUS`（0x044、RINTSTS）の bit。OpenBSD `sys/dev/fdt/dwmmc.c`（SDMMC_RINTSTS_*）と Linux v6.12 `drivers/mmc/host/dw_mmc.h`（SDMMC_INT_*）で一致: bit 2 = CMD_DONE、bit 5 = RXDR（受信 FIFO が閾値）、bit 7 = DCRC（data CRC の誤り）。0xa4 = CMD_DONE | RXDR | DCRC。DRTO（bit 9）・SBE（bit 13）・EBE（bit 15）・FRUN（bit 11）は立っていない → card は応答し data も来たが CRC が合わない = sample の時期の誤りの見込みが強い。
- 既定の phase（Linux から）: mainline v6.12 と vendor（`~/visionfive-linux`、vf2-6.12.y-devel 4cecf169f38e）の `dw_mmc-starfive.c` は UHS_REG_EXT（0x108）の bit 20:16（STARFIVE_SMPL_PHASE、32 段）だけを持ち、tuning（`dw_mci_starfive_execute_tuning`）は UHS の CMD19 の時だけ。high speed（`cap-sd-highspeed`、ciu 50 MHz の bypass）では phase を書かず、firmware/reset の値（VF2 では 0）のまま走る。drive phase の field を Linux はこの slot に設定しない。よって「正しい既定」は Linux と同じく firmware の値のままとし、既定は変えない。dts（`jh7110-common.dtsi` の `&mmc1`: max-frequency 100 MHz、assigned 50 MHz、bus-width 4、cap-sd-highspeed、pinctrl の drive-strength 12・slew-rate 0）も zedBSD の読みと同じ。Linux で動く理由は未解明（Linux は IDMAC、zedBSD は PIO。PIO が原因かは未確認）。
- 入れた fallback（`src/drivers/mmc/dw-mmc.c` の `adapt_bus()`・`tune_sample_phase()`）: run が DCRC・SBE・EBE で失敗し、card を transfer state に戻せたら、1 段ずつ bus を変えて次の try へ進む。
  1. 読みで、glue が phase の hook を渡していれば、失敗した run を phase 0〜31 で読み直し（各 phase の後 1 ms 待つ、Linux の `mdelay(1)` と同じ）、通る phase の最長の連続の中央を取る（Linux の execute_tuning の手順）。log `dw-mmc: sample phase N (phases a-b read)`。
  2. 通る phase が無い、書きの誤り、hook が無い、または phase を変えた後も失敗したら、card clock を default speed（49.5 MHz → 24.75 MHz）へ下げる。card は high speed mode のままで、低い clock は規格上許される。log `dw-mmc: data errors at high speed, card clock down to 24750000 Hz`。
  3. default speed で失敗するものは従来どおり 3 try で EIO。
- glue（`src/drivers/platform/visionfive2/vf2-mmc.c`）: firmware の phase を読んで渡し、`set_sample_phase()`（0x108 の bit 20:16 だけ書き換え）を hook にする。`include/drivers/mmc/dw-mmc.h` の config に `sample_phase`・`sample_phase_count`・`set_sample_phase`・`phase_context`、card info に `sample_phase`・`slowed` を足した（HAL の API ではない）。
- 確認: build（VF2 `config/ci/config-visionfive2.mk`・riscv64-virt `config/ci/config-riscv64-virt.mk`、`vmunix`、warning 0）。host 試験 `plan/ws256/tests/dw-mmc/run.sh`（driver・phase・no-hook・glue の 4 つ、全部 PASS）。足した case: fake の controller が bypass の clock で phase 10〜20 以外の CMD18 に DCRC を返す → 32 block の読みが通り phase 15 になる／どの phase も通らない → 24.75 MHz で通り phase は 0 に戻る／hook 無し → 1 回の失敗で 24.75 MHz に下がって通る。
- 未実施: VF2 の実機（`dw-mmc: sample phase …` か `card clock down` の log の後に /sbin/init が起動するか）。実機で確かめるまで resolved にしない。
