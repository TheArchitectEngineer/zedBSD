# BUG-301: RTL8822BU の CCMP の解読が MAC header を 24 byte 固定で読み、QoS の data（26 byte）で外れる疑い

- 状態: unknown（source の読みの観察、実機では未再現） / tracking
- 発見: ws004-p039（P2、2026-10-13）の WLAN の driver の共通化の調べ。物理の試験は通っている。
- 観察: RTL8822BU の driver の CCMP の解読は header の長さを 24 byte 固定で扱う。QoS の data frame（QoS Control の 2 byte で 26、4 address で 32）では CCMP の header・PN の位置がずれ、解読か replay の確かめが外れるはず。AX211 は header の長さを計算している。core の wlan_l2_parse_data は RTL 式の MIC の trailer を前提にしている（AX211 は 8 byte を足して合わせている）。core に channel_frequency の写しが 2 つ。
- 疑問: 物理の試験（WPA2 の AP への接続・通信）は通っているので、hardware が解読しているか、受けの path で QoS の header を外しているか、QoS の AP で試していない可能性。
- 次: P2 が source で確かめ、外れるなら header の長さを計算する直し（AX211 と同じ）。
- 関連: [WS004](../ws004/ws.md) p039、RTL8822BU（userland の外、src/drivers）。
