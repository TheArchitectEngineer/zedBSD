# BUG-311: Raspberry Pi 4 の onboard の WiFi と Bluetooth が立ち上がらない（firmware の tag 0x38041 not supported で WL_ON・BT_ON を操作できない）

- 状態: reproduced（実機、T1-628）/ scheduled（2026-10-14 Q1、P2。ユーザーの UAT「PiのイメージでWiFiとBluetoothが使えていないようなので、configやDTBの確認をお願いします。」）
- 観察（Pi 4、kernel 947617b 系の WS236 の試験の kernel、結果 plan/agents/T1/results-*-t1-628 と ledger の T1-628）:
  - WiFi: `rpi4-wifi: WL_ON was level 1 (0)` → GPIO 34〜39 を ALT3 → `rpi4-sdio: host specification 2, capabilities 00000000 (0 MHz)` → `rpi4-firmware: tag 38041 not supported` → `rpi4-wifi: WL_ON not driven low (21)` → `bcm43455: chip did not power up (21)` → `onboard Wi-Fi not published (21)`。wlan0 無し。
  - BT: `rpi4-bt: BT_ON was level 1` → GPIO 30〜33 → PL011 → `rpi4-firmware: tag 38041 not supported` → `BT_ON not driven low (21)` → `controller did not come up (21)`。`bt show` は no-controller。
  - firmware の file（brcm・cypress）と config.txt（disable-bt・enable_uart 無し）、DTB（ws232-p004 で確認）は揃っている。
- 推測（Q1）: WL_ON・BT_ON は Pi 4 の GPIO の expander にあり、firmware の mailbox の tag 0x00038041（GPIO の状態の設定）で操作する。firmware が「not supported」を返す（または driver が応答を誤って読む）ので電源の line を下げられない。GPIO の番号（expander の 128+N）、tag の引数の形、応答の code の読み方、firmware の版（start4.elf 3d301dd9）を確かめる。0x38041 の前に 0x38043（GPIO の設定）が要るかも。
- `rpi4-sdio: capabilities 00000000 (0 MHz)` も気になる（EMMC の capabilities が 0）。
- 関連: WS206（RPi4 の WiFi）、WS215（BT）、ws232-p004。
