# BUG-357: kernel が先頭の 4 台の disk しか partition を調べず、boot の stick が 5 台目以降だと「VFS initialization failed (6)」で止まる

- 状態: closed（2026-10-29 Q1 の判定）。修正の後 QEMU で 8 台の disk を std 5 回・Venus 3 回起動し毎回 SSH、`physical disks=8`、stick が 5 台目の回も起動。
- 発見: 2026-10-29 bug-analyzer（BUG-356 の解析、WS307 p011 の QEMU）。
- 該当: `src/kern/vfs.c:67` の `#define PHYSICAL_DISK_MAX 4U` と `vfs_scan_physical_disks()`（1431 行付近）の loop が `disk_at()` の順に 4 台まで。`src/kern/platform/pcat.c` の `wait_for_boot_disk()` は全 disk から boot の FAT を見つけるのに、VFS は 5 台目以降を調べない。
- 観測（7 台の disk、std VGA、Venus 無し）: kernel の log の buffer に `vfs: native boot disk=none physical disks=4`、scan は nvme0n1・nvme1n1・sda・sdb の 4 台だけで boot の stick は 5 台目の sdc、`vfs: boot0 selector resolution failed (error 6)`、`VFS initialization failed (6); entering idle.`。USB の列挙の順で結果が変わる。
- 直す方針: 4 台の上限を外し全ての whole disk を調べる（上限を上げるか配列を動的に）。少なくとも boot の FAT（または handoff）の disk を必ず含め、飛ばした disk は log に出す。
- 確かめる試験: std VGA と Venus のそれぞれで 7 台の disk（`build/bug356/run.py alls … std`・`allv … venus`）を何度か起動し毎回 SSH が上がる、stick が 5 台目以降の順でも起動する。

## 修正（2026-10-29 fix-bug356、状態の判定は Q1）

- 直した事（commit 8000e2484、branch agent/fix-bug356）: `src/kern/vfs.c` の `PHYSICAL_DISK_MAX 4U` を外し、`vfs_scan_physical_disks()` は `disk_at()` が NULL を返すまで全ての whole disk を集める。配列は registry と同じ `DISK_MAX`（80）の大きさで `.vfs_bss` に置く（小さな port の stack を使わない）。入らない disk があれば `vfs: <name> not scanned: more than 80 disks` と数を log に出す。`vfs: native boot disk=… physical disks=N` の行の書式は変えていない。
- 確かめた事:
  - build: amd64 の vmunix rc 0・warning 0。他の platform の vmunix（config-rpi4・riscv64-virt・m68k-virt・armv7-virt・pcat・riscv32-virt・ppc64-pseries、各 `BUILD=build/k-<名>`）全て rc 0・warning 0。
  - QEMU（判定は SSH、guest の中の dmesg で順を見た）: 7 台の追加 disk（nvme・k4・SATA 3 台を 1 つの ahci・USB 2 台を 2 つ目の xhci、boot の stick を入れて 8 台）で std VGA 5 回・Venus 3 回の 8 回とも SSH が上がり ue0=10.0.2.15、毎回 `physical disks=8` と 8 台の scan、boot0 は毎回解決。stick が 5 台目（sdc）の回は std 1・Venus 2、3 台目（sda）の回は std 1・Venus 1（残りの std 2 回は順を記録していない）。
- 未実施: 実機。scan の数の host 試験（kernel の disk の registry に依るので書かなかった。上の QEMU の dmesg で確かめた）。
