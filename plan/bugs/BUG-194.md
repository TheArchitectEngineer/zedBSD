# BUG-194: Terminal を全画面にすると戻る方法が無い。F11 で全画面にも戻すこともできない（compositor が全画面から戻る操作を持っていない）

Reproduction: reproduced（実機 5330、UAT 2026-10-05 午後）
Disposition: tracking
Discovery: 2026-10-05 午後 UAT（実機 Latitude 5330、image は 12 時の uat-0505c の見込み）
Handling: Terminal（app）と compositor（WS099、全画面の扱い）。担当は Q1 が割り当てる

## 観測（ユーザー）

「Terminalは全画面にすると戻るキーがみつからなかった。F11で戻れない。しかも、F11で全画面にもできない。バグです。そもそも全画面はゲーム用の機能で、コンポジタを無効にしてスキャンアウトを占有するものです。全画面から戻るキー操作は、コンポジタが持っておく必要があります。ここはコンポジタのバグにもします。」

## 期待（ユーザーの方針）

- 全画面はゲーム用の機能で、compositor の合成を止めて scanout を占有する物。
- **全画面から戻る key の操作は compositor が持つ**（app に任せない）。app が応答しなくても、利用者は compositor の key で全画面から戻れる。
- F11 で全画面に入る・戻る（少なくとも Terminal で。compositor の側の key で戻れること）。

## 調べる点

- Terminal がどの操作で全画面になったか（menu か、title bar の button か、gesture か）と、Terminal の F11 の扱い（key を受けていない、または処理が無い）。
- compositor の全画面（xdg_toplevel の set_fullscreen、direct scanout）で、compositor が奪う key（例: F11、Super+↑/↓、Esc の長押しなど）の設計。WS099 の窓の操作・WS142 の key の割り当てとの整合。
- 決める key（compositor が全画面から戻す操作）は、ユーザーの確認が要る（案を出す）。
