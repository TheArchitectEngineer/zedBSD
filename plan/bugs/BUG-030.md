期待: `plan/tools/boot-test.sh`（`BOOT_MODE=uefi-usb`、QEMU の xHCI に usb-storage）で、root の image を読み取り error なしに起動する。

```

loop0: read block=9456 count=16 flags=0 error=42
```

## 原因と修正（2026-09-30、[ws073-p041](../ws073/phase041/phase.md)）

- **guest の xHCI の event の取りこぼしではない。** xHCI の driver に入れた診断（時間切れの cancel の直前の event ring・IMAN・USBSTS・ERDP と、cancel 中の
  request に届いた completion code）は毎回 `pending-events=0`、Stop Endpoint の後の completion は 26（Stopped）residual=13 で、controller（QEMU）が
  その TD をまだ実行中だった。
- QEMU の trace（`-trace enable=usb_msd_*,usb_xhci_xfer_*,usb_xhci_ep_*,scsi_req_*`）で、時間切れの command は 6 回とも **tag 0x13f の
  SYNCHRONIZE CACHE(10)**（data 無し）。QEMU の usb-storage は `s->req`（scsi-disk の `blk_aio_flush` = host の image の `fdatasync`）が終わるまで CSW の
  packet を ASYNC で保持し、5 秒を超えて guest の Stop Endpoint → `scsi_req_cancel` になる。
- 起動時だけ出る理由: `guest.py`・`boot-test.sh` は起動の直前に image を複写する（build の directory は ext4 で reflink が効かず 2.2 GB の実複写）。
  host の page cache の dirty page を guest の最初の方の flush が全部待つ。起動の後の丸読みは flush を出さないので出ない。TCG/KVM の差ではなく
  host の書き戻しの遅さ（並列の QEMU、他の I/O）で決まる。
- 修正: `src/drivers/usb/usb-storage.c` の BOT の段（CBW・data・CSW）の timeout を command で決める（`bot_stage_timeout()`）。`BOT_TIMEOUT_MS` 5000 →
  30000、SYNCHRONIZE CACHE は `BOT_FLUSH_TIMEOUT_MS` 60000（Linux の sd の慣例）。command 全体の予算は段の 3 倍のまま。
- 修正後: 同じ条件で TCG 4 回中 4 回 error 0（trace で tag 0x13f の flush が `usb_msd_cmd_complete` まで届く）、boot test PASS。
- 受け入れ（別の担当）: TCG・KVM で各 20 回以上 error 0、丸読み・usb-net・keyboard の回帰（p041 の「試験の担当への引き継ぎ」）。通れば resolved。
- 残: UAS（`usb-uas-disk.c`）の 5000 ms も同じ問題を持ちうる（未再現）。

## 受け入れの試験（2026-09-30、途中、[ws073-p041](../ws073/phase041/phase.md) の「受け入れの試験の結果」）

- 修正後: TCG 2 本並列で trace なし 40 回・`usb_msd_*` の trace 付き 35 回、usb-storage の error 0（修正前の kernel は同じ条件で 40 回中 7 回）。KVM の組と
  boot test は wrap up で未実施。まだ resolved にしない。

## 受け入れの試験（2 回目、2026-09-30、[ws073-p041](../ws073/phase041/phase.md)）

- KVM 2 本並列 × 20（丸読み 1 回）: SSH と丸読み（2216689664 bytes）は 40/40。usb-storage の error が 1 回: `BOT data dir=in error=42`（READ の data の

  flush の待ち（この bug の原因、`pending-events=0`・completion 26）ではなく、[BUG-116](BUG-116.md) と同じ guest の event の取りこぼし。再試行で回復した。
