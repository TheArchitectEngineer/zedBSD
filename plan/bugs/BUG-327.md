# BUG-327: 5330 で zedBSD の USB の stick からの小さな読み込みが 1 回 30〜54 ms 待つ（起動が遅い）

- 状態: reproduced（5330 の実機の記録 1 回）/ tracking
- 発見: 2026-10-16 P2（WS253 起動の時間）、P1 が取った 5330 の記録（main 8666f25a6）の `hw.diskstats`: sda の read_ops=1693、read_bytes=33 MB、read_ns=92.2 s（平均 54 ms）。QEMU の USB の stick は平均 0.68 ms、NVMe は 0.40 ms。dd で 10 MB を続けて読むと 0.56 s で速いので、小さな読み込みを 1 回ずつ待つ所が遅い。
- 影響（推定、5330 での切り分けは T1 の測定の後）: compositor の glyphs-fonts 1.5 s、compositor が動き出すまでの約 2.5 s（page-in）、late の service、kernel→init の一部。
- 範囲: usb-storage・xHCI の driver の側。2026-10-16 ユーザー「USB driverが遅いのは、起動が遅い問題を解決しているサブエージェントで処理してくだしあ。」→ WS253 の範囲に入れ、P2 が直す（q1221-i04）。
- 関連: [WS253](../ws253/ws.md)
- 2026-10-16 ユーザーの見立て:「USB stickが古くてNANDフラッシュが劣化して遅くなっているかもしれないです。」→ 切り分け: 同じ stick を 5330 の Linux の側から小さな読み込み（4 KiB の direct I/O を散らして数百回、読むだけ）で測る。Linux でも 1 回数十 ms なら stick の劣化、Linux で速ければ zedBSD の usb-storage・xHCI の側。T1 の次の 5330 の回で相乗り。
- 2026-10-16 T1-703 の切り分け: stick は劣化していない。5330 の Linux から同じ stick（TransMemory 58.2G）を direct I/O で 4 KiB のランダム読み 300 回 = 平均 0.43 ms（image の範囲 0.36 ms）、連続 99〜196 MB/s。zedBSD の diskstats は 1 回あたり約 28〜34 ms（T1-703 の 2 回）。→ zedBSD の usb-storage・xHCI の側の待ち。出力 /home/awe/zedBSD-worktrees/t1/build/t1703-out/usb-read.txt。
