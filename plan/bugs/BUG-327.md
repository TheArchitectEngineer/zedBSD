# BUG-327: 5330 で zedBSD の USB の stick からの小さな読み込みが 1 回 30〜54 ms 待つ（起動が遅い）

- 状態: reproduced（5330 の実機の記録 1 回）/ tracking
- 発見: 2026-10-16 P2（WS253 起動の時間）、P1 が取った 5330 の記録（main 8666f25a6）の `hw.diskstats`: sda の read_ops=1693、read_bytes=33 MB、read_ns=92.2 s（平均 54 ms）。QEMU の USB の stick は平均 0.68 ms、NVMe は 0.40 ms。dd で 10 MB を続けて読むと 0.56 s で速いので、小さな読み込みを 1 回ずつ待つ所が遅い。
- 影響（推定、5330 での切り分けは T1 の測定の後）: compositor の glyphs-fonts 1.5 s、compositor が動き出すまでの約 2.5 s（page-in）、late の service、kernel→init の一部。
- 範囲: usb-storage・xHCI の driver の側。2026-10-16 ユーザー「USB driverが遅いのは、起動が遅い問題を解決しているサブエージェントで処理してくだしあ。」→ WS253 の範囲に入れ、P2 が直す（q1221-i04）。
- 関連: [WS253](../ws253/ws.md)
- 2026-10-16 ユーザーの見立て:「USB stickが古くてNANDフラッシュが劣化して遅くなっているかもしれないです。」→ 切り分け: 同じ stick を 5330 の Linux の側から小さな読み込み（4 KiB の direct I/O を散らして数百回、読むだけ）で測る。Linux でも 1 回数十 ms なら stick の劣化、Linux で速ければ zedBSD の usb-storage・xHCI の側。T1 の次の 5330 の回で相乗り。
- 2026-10-16 T1-703 の切り分け: stick は劣化していない。5330 の Linux から同じ stick（TransMemory 58.2G）を direct I/O で 4 KiB のランダム読み 300 回 = 平均 0.43 ms（image の範囲 0.36 ms）、連続 99〜196 MB/s。zedBSD の diskstats は 1 回あたり約 28〜34 ms（T1-703 の 2 回）。→ zedBSD の usb-storage・xHCI の側の待ち。出力 /home/awe/zedBSD-worktrees/t1/build/t1703-out/usb-read.txt。
- 2026-10-16 ユーザー「P2はQEMUでテストをお願いします。実機は他のチケットに回します。」→ P2 の確認は QEMU だけ、実機の確認は修正の後に別のチケット。

- 2026-10-16 P2（q1221-i04、WS253）: 1 command の時刻の内訳を出す計測を足した（既定は off）。`sysctl hw.usb.trace=1`（root、HW_USB_TRACE_STORAGE）で、usb-storage の command ごとに kernel の log に 1 行 `usb-storage-trace: sda op=28 lba=… blocks=… error=… queue_us=Q total_us=T xfer1=S/E/W xfer2=S/E/W xfer3=S/E/W`。xferN は BOT の CBW・data・CSW の順の各 transfer（data の無い command は 2 つ）、S は USB core が controller に渡してから xHCI が transfer event を取るまで（device と controller と割り込み）、E は event から USB core が終わりを出すまで（driver）、W は終わりから待つ thread が見るまで（起床）、queue_us は device の lock を待った時間、total_us は lock を取ってから終わりまで。時計は monotonic の counter（ns）。実装: `include/uapi/sysctl.h`（HW_USB_TRACE 10）、`src/kern/sysctl.c`（hw.usb.trace、`kern_usb_trace()`）、`src/drivers/usb/usb.c`（URB の時刻 submitted・event・completed、`drv_usb_trace_*`、`drv_usb_urb_trace_*`）、`src/drivers/pci/pci-xhci.c`（transfer_claim で event の時刻）、`src/drivers/usb/usb-storage.c`（command ごとの記録と 1 行）。
- 2026-10-16 P2 の QEMU の確認（USB の stick の boot、qemu-xhci）: MSI で 1 command 約 0.40〜0.52 ms（S は CBW 85〜205 µs・data 80〜270 µs・CSW 73〜88 µs、E 約 25 µs、W 0〜11 µs）、`-global qemu-xhci.msi=off -global qemu-xhci.msix=off` の INTx でも約 0.37〜0.50 ms。QEMU では 5330 の約 30 ms は再現しない（QEMU の usb-storage は即座に答え、throttle は 1 transfer の遅れを真似られない）。5330 での読み方: S が大きければ device・controller・割り込みの到着、E が大きければ完了の処理の遅れ（command の gate などで遅らされた drain）、W が大きければ待つ thread の起床、queue_us が大きければ command の取り合い。5330 の確認は別の ticket（2026-10-16 ユーザー「P2はQEMUでテストをお願いします。実機は他のチケットに回します。」）。5330 の dmesg では stick（30de:6545）は port 15 の SuperSpeed、xHCI（00:14.0）は MSI。USB3 の LPM（PORTPMSC）は zedBSD が設定しない（既定の無効）。
