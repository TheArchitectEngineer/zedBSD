# BUG-082: sync と process の終了の競合で kernel panic（invalid shared VM reverse mapping）

Bug ID: `BUG-082`
Reproduction: reproduced（WS073 の agent、full guest image、QEMU）
Disposition: scheduled（WS073、修正途中: plan/bugs/BUG-082-wip.patch）
Date: 2026-09-28
Source: WS073（BUG-075 の試験中）
Owner: WS073

## 観測

full guest image の UFS root で、通常の dd・cat と `sync` を process の終了と競わせると
`fatal: src/kern/vmspace.c:742: invalid shared VM reverse mapping` で止まる。gdbstub の stack:
mount_sync_all → vm_object_sync_mount_buffer → sync_inode_buffer → vm_object_sync_range_buffer → vmspace_object_page_revoke。

## 原因（WS073 の解析）

sync は mount の object の map された page を全て revoke する。vmspace_destroy() は refcount が 0 になった後に region ごとに
mapping を外し、region の間で metadata の lock を離す。その間に revoke が vm_tryref に失敗する mapping を見つけて HAL_FATAL する。
BUG-075 の変更より前からある。

## 修正の方針

revoke は HAL_FATAL の代わりに lock を離して yield し、終わりかけの space が mapping を外すのを待って再試行する（vmspace.c）。
WS073 で検証中。

## 経過（2026-09-28、ws073-p020、wrap up）

- 再現: [sync-exit.sh](../ws073/tests/sync-exit.sh)（[bug082.sh](../ws073/tests/bug082.sh)）。修正前は 1 回目で上の fatal。
- 同じ競合の 2 つ目: copy-on-write の fault が予約（BUSY）した mapping を revoke が見て `vmspace.c:768 shared VM reverse mapping changed while pinned`。
  fault は writeback が持つ page を待つので、revoke が単に待つと相互に待つ。
- patch（未 commit、`BUG-082-wip.patch`）: 終わりかけの space を yield で待つ、BUSY の mapping を fault の wait queue で待つ、fault は page が
  writeback 中なら予約を返して pin で待つ、revoke の最後の vmspace の参照を reaper へ。fatal は消えたが 30 回中 27 回の後に sync と cat の hang。
- 次の手: phase020 の再開の手順（hang の thread の stack を gdbstub で読む）。
