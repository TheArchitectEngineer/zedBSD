# BUG-317: Pi 4 で main の kernel が起動 54 秒で停止（namei の context->lock で cpu0 が割り込み off のまま 14 秒 spin）

- 状態: reproduced（実機 1 回、ユーザーの写真）/ scheduled（2026-10-15 Q1、bug-analyzer で解析）
- 発見: 2026-10-15 ユーザー（写真 `build/review/bug317-pi-stall.webp`）「Pi4です」。T1 が T1-653（WS236 p006）で入れた main の kernel（T1 の worktree の build/t1-653/ci、main 44eee26c5 以降）。
- 画面: `zedBSD stall watch: spins with interrupts off (seen by cpu0)`、uptime 53.862s、`cpu0 STOPPED tick -14.001s irq-off -14.000s at 000d0c74 < 000ac554`、chain `000936d0 00091ca4 000d0ba4 000d0ca0 000ac554 000ff44c`。cpu1〜3 は動いている（cpu3 は irq-off の時に d57c4 < 126f80）。
- 記号（Q1、build/t1-653/ci/kernel.elf）: d0c74 = spin_lock_irqsave+0x1c、ac554 = namei_path_flags_at+0xf8（`src/kern/namei.c` の `spin_lock_irqsave(&context->lock)`）、ff44c = sys_stat_path_call+0x160、d57c4 = sched_yield+0x24、126f80 = drv_usb_urb_wait_reusable+0x8c、936d0 = arm64_watch_self_check、91ca4 = hal_cpu_current、d0ba4 = spin_trylock。
- 読み（未確認）: stat の namei が process の context->lock を取れず、持ち主が離さない（lock の取りこぼし・二重の取得・持ったまま眠る・別 CPU の持ち主が止まっている）。kernel log の最後は BT（BUG-311 r6 の bluetoothd）と touch の行。
- 関連: WS236（同じ kernel）、BUG-311、BUG-313・315。
