# BUG-190: タップダウン（触れて押した瞬間）が全ての UI の要素で押下として効かない（右上の音量の slider はダブルタップでのスライドだけ動く）

Reproduction: reproduced（実機）
Disposition: tracking（優先度: 高）
Discovery: 2026-10-04 夜 ad-hoc UAT-3（実機 Latitude 5330、image `build/uat-3/hdd-image.img` sha256 ada4492e…、main efe846a、[uat.md の uat-3](../uat.md)）
Handling: WS099（compositor の入力の変換・touch と pointer）・WS081（touch）・libkeiland の UI の部品

## 観測

ユーザー「右上のサウンドボリュームメニューで、ダブルタップでスライドするとうまくいくが、タップダウンの操作が効かない。と思ったら、すべてのUI要素でタップダウンが効かない。タップダウンはクリック押下と同じ扱いにするべきと思います。」

## 仕様（ユーザー）

タップダウン（指が触れて押した瞬間）は、マウスのボタンの押下（press）と同じ扱いにする。全ての UI の要素（slider・button・list・title bar など）で。触れたまま動かせば drag、離せば release（click）。

## 次

- 入力の device を確かめる（touchscreen の touch の down か、タッチパッドの tap か）。Q1 の読み: 「ダブルタップでスライド」が効くのはタッチパッドの tap-and-drag（2 回目の down で press になる）で、1 回目の down が press にならない（tap は離した時に click を合成する）形の疑い。touchscreen なら compositor の touch → pointer の変換が down で press を出していない疑い。
- [BUG-166](BUG-166.md)（タッチパッドの仕様: 押し込み＋タップドラッグ）、[BUG-178](BUG-178.md)（title bar のタッチのドラッグ）、[BUG-188](BUG-188.md)（AP の一覧のシングルタップ）、[BUG-182](BUG-182.md)（Browser のタップ）と同じ根の可能性が高い。入力の変換を 1 か所で直し、全部をまとめて確かめる。
- 修正は P3 の q700（窓の操作・タッチの束）。QEMU は T1（タッチの注入）、実機は UAT。

## 調べたこと（2026-10-05 P1 generation17 / q700-i01）

- 5330 の dmesg（`plan/uat/2026-10-04/dmesg.txt` の 52 行と 360 行）: タッチパッドは `input: /dev/input/event0: PC/AT PS/2 mouse`、`i8042: mouse id=0 packet=3`（3 byte の標準の packet。wheel の knock 200,100,80 も通らない）。touchscreen は無い。tree に I2C-HID と Intel LPSS（DesignWare）I2C の driver は無い（`src/drivers` に無い）。
- 経路: firmware の tap は PS/2 の packet の bit 0（左 button）の on/off になる。`src/drivers/platform/pcat/ps2-8042.c` の `consume_byte`/`publish_sample` が packet ごとに変わった button を `EV_KEY BTN_LEFT` として出し、packet ごとに `SYN_REPORT` を出す。motion が overflow した packet は捨てるが、button の状態は次の packet で差分として出る。compositor の `input.c` の `apply_frame` は report ごとに、まず motion、次に button の順で `zwl_seat_button` へ素通しする。tap を click に変換する所も、press を遅らせる所も compositor には無い。
- 2026-10-05 ユーザー:「PS/2でもタップダウンもイベントとして取れているように見えました。」→ firmware の press と release が compositor の UI（slider・title bar）でどう扱われるかを、実機の evdev の記録で確かめる必要がある。見る点: タップの press と release の間隔、同じ report に来るか、tap-and-hold で press が続くか。採る手順は Q1 に送る。
- native の touchpad（I2C-HID、2 本指のスクロール、押し込み）は WS159 へ（2026-10-05 ユーザー）。
- 2026-10-05 ユーザーの方針「既存BUGはいったん保留して、新規実装を進める」で保留。
