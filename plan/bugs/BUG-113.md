# BUG-113: 手前の窓を閉じた後、残った窓に keyboard の focus が戻らない

Bug ID: `BUG-113`
Reproduction: reproduced（QEMU の Venus、ws095-p004 の guest の試験）
Disposition: resolved（ws035-p137、2026-09-30: zdesktop の不具合ではなく、試験が残るはずの窓も kill していた）
Date: 2026-09-29
Source: ws095-p004 のサブエージェントの報告
Owner: WS035（zdesktop の focus）

## 観測

guest の試験で、手前の窓を閉じた後、残った窓に keyboard の focus が戻らなかった。試験は新しい窓を出して進めた。意図した動き（focus を
click まで誰にも渡さない）か、不具合かは未確認。一般の desktop では、閉じた窓の次に上にある窓へ focus を移す。

## 再検討

WS035 の次の区切り。WS094（desktop の icon）の「focus は desktop を click したときだけ移す」の設計と合わせて決める。

## 解決（ws035-p137、2026-09-30）

- zdesktop は、手前の窓が閉じると同じ desktop の次に上の窓へ focus を移す（`zwl_schedule` の `front_surface = zwl_top_window()` と `zwl_seat_focus`）。
  `plan/ws035/tests/zdesktop-p137.sh`（QEMU の Venus、変更前の image）で、client の終了・close button のどちらでも残った窓が enter と key を受け、
  別の desktop の窓は受けないことを確かめた（PASS）。compositor の source の変更なし。
- 観測の原因（推定、ws095 の試験の code から）: `plan/ws095/tests/ime-p004.sh` は `ps -A -o pid,args | grep "[i]me-probe"` の全ての process を
  kill しており、残るはずの窓（最初の probe）も閉じていた。guest の `ps` の args は引数を出さない（`/bin/popup-probe` だけ）ので、引数で
  process を選ぶ書き方も効かない。pid（`$!`）で kill するのがよい。
- WS094 への引き継ぎ: desktop の surface（ws094-p002）は `zwl_top_window` の候補から外すこと（focus は click したときだけ）。
