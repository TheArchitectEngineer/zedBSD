# BUG-109: userland の `sqrt`・`sqrtf` が software の実装への call で遅い

Bug ID: `BUG-109`
Reproduction: reproduced（ws035-p129 の計測）
Disposition: resolved（2026-09-29、[ws073-p037](../ws073/phase037/phase.md)、WS035 のエージェント）
Date: 2026-09-29
Source: ws035-p129 のサブエージェントの報告
Owner: WS073（実施は WS035 のエージェント）

## 観測

userland は `-ffreestanding -fno-builtin` で build するので、`sqrtf`・`sqrt` は毎回 libc の software の平方根（`src/libc/math/sqrt.c`、WS076）への
call になる。Kei の印の描画（`artwork/mark.c`）が約 570 万回呼んで 1.4 秒かかっていた（p129 で呼ぶ回数を減らして回避）。icon の描画
（`atan2f`・`sinf`・`cosf`）等、他の描画も遅い見込み。

## 直し方（案）

amd64 の `sqrtss`・`sqrtsd`、arm64 の `fsqrt` は IEEE 754 の正しく丸めた平方根なので、libm の `sqrt`・`sqrtf`（と `sqrtl` の要る範囲）を
arch ごとの命令にする（WS076 の「正しく丸める」の方針と両立する）。header で inline にするかは、`-fno-builtin` の下での呼び出しの形を見て決める。

## 解決（2026-09-29、[ws073-p037](../ws073/phase037/phase.md)）

- `src/libc/math/sqrt.c`: amd64（`__SSE2__`）は `sqrtsd`・`sqrtss`、arm64（`__ARM_FP`）は `fsqrt`。kernel・i386・sparc64・m68k は整数の平方根のまま。
  特殊な値・errno は C で先に扱い、不正確な根の `FE_INEXACT` は根の 2 乗の誤差なしの検査で立てる（libc の例外は software）。header の inline 化は
  しない（`-fno-builtin` の下で呼ぶ側は libc の call のまま）。
- 証拠: host の WS076 の libm の試験の出力が変更前と全行同じ、変更前の sqrt.c との bit・errno・例外の比較（`plan/ws073/tests/p037/run-sqrt-compare.sh`）
  PASS、guest の libm の試験 PASS、guest の `sqrtf` 1 回 347.5 → 220.5 ns、Kei の印（p129 の前の mark.c）1415 → 961 ms、boot test PASS。arm64 は build だけ。
- 残り（別の件）: 1 回の残りの約 205 ns は `feraiseexcept` の TLS の参照（`__tls_get_addr` が毎回 syscall）。p037 の「分かったこと」。
