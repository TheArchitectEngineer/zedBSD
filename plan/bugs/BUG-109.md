# BUG-109: userland の `sqrt`・`sqrtf` が software の実装への call で遅い

Bug ID: `BUG-109`
Reproduction: reproduced（ws035-p129 の計測）
Disposition: scheduled（WS035 のエージェント）
Date: 2026-09-29
Source: ws035-p129 のサブエージェントの報告
Owner: WS073（実施は WS035 のエージェント）

## 観測

userland は `-ffreestanding -fno-builtin` で build するので、`sqrtf`・`sqrt` は毎回 libc の software の平方根（`src/libc/math/sqrt.c`、WS076）への
call になる。Kei の印の描画（`artwork/mark.c`）が約 570 万回呼んで 1.4 秒かかっていた（p129 で呼ぶ回数を減らして回避）。icon の描画
（`atan2f`・`sinf`・`cosf`）等、他の描画も遅い見込み。

## 直し方（案）

amd64 の `sqrtss`・`sqrtsd`、arm64 の `fsqrt` は IEEE 754 の正しく丸めた平方根なので、libm の `sqrt`・`sqrtf`（と `sqrtl` の要る範囲）を
arch ごとの命令にする（WS076 の「正しく丸める」の方針と両立する）。header で inline にするかは、`-fno-builtin` の下での呼び出しの形を見て決める。
