Bug ID: `BUG-031`
Reproduction: reproduced（QEMU、間欠、1 回）
Disposition: tracking（2026-09-27 に修正を入れた。確認は部分的で、解決とは言わない）

## 期待と観測・影響

期待: kernel の message は 1 行ずつ、他の message と混ざらずに画面に出る。

観測（boot test が撮った画面。serial log ではない）: 画面の先頭の 3 行で、`usb-hid:` の行と `vfs:`（`sda partition ...`・interface の行）の行が文字ごとに交互に混ざった。

```
usb-hid: vevenfs: sda pt devicea rutsibt0i odne v1i cset=a2rt i=0000000nte0r:0fa
c0000800e=0 endpo data=000i00nt=81000:0 re0p00n0r8t0-0b ybtles=o8c
nterfacevfs:  sd0 ca plasasr t0i3t/i0o1n/ 012  dsrtarit=v0er00=u00s0b-h0id0:
```

2 回目: q402 の boot test（`build/boot-test-amd64-q402/login.png`、先頭の 5 行）。他の起動（q395・q397・q398・q399・q401 の boot test）では見ていない。二つの thread（CPU）が同時に console へ書き、行の単位の排他が無いように見える（未検証）。

影響: 起動時の message が読めなくなることがある。動作には影響しない（login prompt に届いた）。

## 調べたこと

- なし（記録だけ）。この Phase の変更（libedit の規約の書き直し）は kernel の出力と関係が無い。

## 再開の条件

kernel の console・log の出力を扱う WS で。受け入れ案: USB と storage の probe が並ぶ起動を 20 回撮って、行が混ざらない。

## 原因と修正（2026-09-27、WS073）

- 原因（コードで確認）: `kern_log_write()`（`src/kern/klog.c`）は ring への追加だけを `klog_lock` で守り、console への写し
  （`kernel_putc` を 1 文字ずつ、と debug console）は lock の外だった。二つの CPU が同時に log を書くと、文字ごとに混ざる。
- 修正（commit a06266db）: 1 つの record を console へ写す間、その CPU が `klog_mirror_owner`（CPU 番号 + 1）を持つ。他の CPU は待つ
  （上限 `KLOG_MIRROR_SPIN_MAX` の回数。止まった CPU が他の全ての出力を止めないため）。同じ CPU の入れ子（割り込み）は待たずに出す。
  lock の順位（rank）には入らない（log はどの lock の下でも呼ばれ、console は文字ごとに自分の lock を取る）。
- 確認（QEMU、amd64、`plan/ws073/tests/console-mix.sh`）: USB から 15 回起動し、SSH が上がった後の画面の kernel の行を `dmesg` の record
  （80 桁に切ったもの）と比べた: 混ざった行 0（2 回は SSH が上がらず比べていない。原因は未確認で、[BUG-036](BUG-036.md) の列挙の失敗と同じ見込み）。ただし画面に
  残るのは最後の約 30 行で、以前混ざった起動の途中の行は多くの場合もう見えない。修正の前の同じ試験での発生率も測っていない。
  解決とするには、起動の途中の画面（例えば USB の probe の直後）を撮る試験で 20 回混ざらないことを見る。
