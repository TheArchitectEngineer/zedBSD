# BUG-115: zdesktop-p072 の試験で、最初の client（wlshm a）の接続が setup errno=5 になる

Bug ID: `BUG-115`
Reproduction: reproduced（QEMU の Venus、ws094-p002 の回帰。main の compositor でも同じ）
Disposition: resolved（ws099-p003、2026-09-30）
Date: 2026-09-30
Source: ws094-p002 のサブエージェントの報告
Owner: WS035（zdesktop）

## 観測

`plan/ws035/tests/zdesktop-p072.sh` で、最初の client（wlshm a）が接続の setup で errno=5（EIO）になり FAIL する。WS094 の変更を入れない
main の compositor に入れ替えても同じく FAIL するので、WS094 とは無関係の既存の問題。compositor の変化（WS035 p129〜p137、WS095 の IME の
global、WS089 の preferences）のどれかで試験の前提が崩れたか、compositor の不具合かは未確認。

## 再検討

WS035 の次の区切り。まず p072 の試験の期待が古いのか、compositor の不具合かを切り分ける。

## 2026-09-30 ws099-p001 の切り分け

- **原因は試験の待ち方**。p072 は compositor を起こして `sleep 4` の後に wlshm を起こす。ws094 が使った古い image（`build/ws035-sq/hdd-image.img`）では
  compositor の起動に 6 秒以上かかり、wlshm は socket が無いうちに接続して EIO になった。同じ image で 12 秒待てば接続して描く。
- 今の main の image では再現しない（起動は約 3 秒、4 秒の待ちに対する余裕は約 1 秒）。compositor の不具合ではない。
- 直し方: `sleep 4` を socket か `ZWL READY` を待つ形にする（ws099-p003）。

## 2026-09-30 解決（ws099-p003）

`plan/ws035/tests/` の 42 本・43 箇所の固定の `sleep N` を、compositor の log に `ZWL READY` が出るのを最大 15 秒待つ形に置き換えた。BUG-115 の条件
（古い image）で p072 が PASS、今の image で C9 の回帰 9 本が PASS。他の WS の試験（`plan/tools/titlebar/`・`plan/tools/files/`・
`plan/ws079/tests/`・`plan/ws089/tests/` など）にも同じ固定の待ちが残る（F-062）。
