# BUG-186: Settings で新しい AP の鍵を入力した後、Connecting… の間も鍵の入力欄が出たままで、Connected で消える

Reproduction: reproduced（実機）
Disposition: tracking（優先度: 標準）
Discovery: 2026-10-04 夜 ad-hoc UAT-3（実機 Latitude 5330、image `build/uat-3/hdd-image.img` sha256 ada4492e…、main efe846a、[uat.md の uat-3](../uat.md)）
Handling: WS089（Settings の Wi-Fi、BUG-160 の行の中の鍵の欄）・system bar の menu も確かめる

## 観測

ユーザー「Settingsで、新しいAPにパスワードを入力したあと、Connecting...の最中にもパスワード入力欄が表示されたままで、Conectedでようやく消える。この動作は、入力を確定してConnectingにするときにパスワード入力欄を消すべきと思う。」

## 次

仕様（ユーザー）: 鍵の入力を確定（Join・Enter）して Connecting にする時点で、鍵の入力欄を消す。失敗した時は [BUG-187](BUG-187.md) の失敗の表示を出し、もう一度入力できるようにする（欄を出し直す）。 修正は P3 の q700（BUG-183・185 と同じ Wi-Fi の状態の経路）。QEMU の確認は T1（RTL8822BU の USB passthrough か networkd の模擬）、実機は次の UAT。

## 保留（2026-10-05 未明、q703-i01 P2 generation14。ユーザーの方針「既存BUGはいったん保留して、新規実装を進める」）

- 未着手（差分なし）。読んだこと: Settings の鍵の欄（`key_ssid` と `key`）は save_key の要求を送る時に `key.text` を使い、成功（`network_join_outcome`）まで閉じない。要求が slot で待つ間も鍵は欄に残る。
- 再開点（設計）: 確定（Join・Enter）の時に鍵を join の側の buffer へ移して欄を閉じ（行は Connecting...）、送った後に buffer を消す。失敗した時は同じ AP の欄を空で出し直し、失敗の文をその下に出す。system bar の menu の鍵の欄も同じか確かめる。
- 追記（2026-10-05、p021 の host 試験で見つけた）: 鍵の欄で save_key が slot で待つ間に、別の AP の join が成功で答えられると、`network_join_outcome` が欄と鍵を消し（`se_field_clear`）、待っていた save_key は空の鍵で送られる（library が EINVAL で断る）。上の設計（確定の時に鍵を join の側へ移す）で一緒に直る。
