# BUG-245: docked の X の窓（glxtest）で bar の close（×）を押しても閉じない（`KWL GLASS close` が出ない）

- 状態: reproduced（QEMU、T1-340・T1-341、WS178 の前の main でも同じ） / tracking
- 発見: plan/tools/x11/x11-p004.sh の段 3（2026-10-07）

## 観察

- glxtest を docked にした後、bar の × を (1252, 17) で押しても glxtest と x11server が残る。compositor の log に `KWL GLASS close` が無く、最後は `dock … via=double-click buttons=1252,1218,1184`・`resized … docked=1`。xserver の log にも close の行が無い。
- P1 の読み（2026-10-07）: × は x≈1251・y≈22 にあり座標は合う。shell.c の press の経路で bar_press（5517、close は 5546〜5550）より前の handler（830〜895: home・media・IME の印・volume・network・menu・apps-bar・titlebar の各 *_button）が press を取っている疑い。試験は直さない（事象を隠す）。

## 次

- T1-343 で click の前後の /tmp/zdesktop.log の全行（KWL MENU・APPS・TITLEBAR・HOME ほか）を採る → compositor の bar の担当（P2）が直す。

## 原因と修正（2026-10-07 P2）

- 原因: T1-343 の log（`KWL CORNER press source=pointer x=1252 y=17` の直後に `KWL CORNER cancel reason=unarmed`）のとおり、右上の corner の swipe（corner.c、Notes）の範囲（右端と上端から 28 px）に docked の窓の bar の × がある（1280 幅で × の中心は x=1252）。kwl_glass_button は corner を bar の処理より先に呼ぶので、mouse の press を corner が取り、release で unarmed として捨て、bar_press（close）まで届かなかった。P1 の読みの bar の各 handler（830〜895）ではない。
- 修正: shell.c に `kwl_glass_bar_control_at`（bar が描かれ、docked の窓があり、点が bar の close・restore・minimize の箱の中なら 1）を足し、corner.c の `kwl_corner_contact_begin` は source が mouse（KWL_CONTACT_POINTER）でその点が bar の control の上なら press を取らない。指（touch）と pen は今までどおり swipe を始める（右上の swipe の入口を残す）。
- 確かめ: zedBSD の compositor（`build/ws181/bin/wayland`）と Linux の Keiland の build は warning 0。QEMU は未（x11-p004 の段 3 を T1 で）。見込み: × の press は corner を素通りし、keyboard・band（touch だけ）・Home・status（docked の時は左へずれる）・arrange・menu・apps-bar・titlebar を通って bar_press の BUTTON_CLOSE に届き `KWL GLASS close` が出る。
