# BUG-074: FAT で `rm -r DIR` が 1 つおきに entry を飛ばし "Directory not empty" で失敗する

Bug ID: `BUG-074`
Reproduction: reproduced（QEMU、WS073 の agent、ws073-p015 の作業中。swap file の有無に関係なし）
Disposition: resolved（ws073-p016、2026-09-27、QEMU で確認。実機は未実施）
Date: 2026-09-27
Source: ws073-p015
Owner: WS073

## 期待と観測

期待: 走査の途中で entry を消しても、消していない entry はちょうど 1 回ずつ返る（POSIX の readdir）。`rm -r DIR` が成功する。

観測: FAT で f1〜f6 の directory に `rm -r` すると f1・f3・f5 だけ消え、f2・f4・f6 が残り "Directory not empty"。tmpfs では通る。

## 原因（agent の見込み）

FAT の readdir が位置を生きている entry の数で数えるので、走査中の unlink で次の entry が見えない位置へずれる。`/boot/bootN`・`/boot/esp`
の利用に影響。

## 次の手

WS073 で FAT の readdir の cookie（位置）を entry の物理的な位置にする Phase を p015 の後に。

## 修正と検証（ws073-p016）

[ws073-p016](../ws073/phase016/phase.md) を見よ。readdir の位置を directory の record の番号にし（`fat_raw_readdir()` の `start`・`next`）、ESP と 512 B・4 KiB cluster の FAT で `plan/ws073/tests/fat-rmr.sh` 9 件 PASS（6 個・300 個と部分木の `rm -r`、消した後の `ls`）。
