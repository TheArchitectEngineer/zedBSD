# BUG-198: amd64 の kernel が大きさの上限（AMD64_KERNEL_MAX_BYTES 16 MiB）の手前で、余りが約 440 KiB しか無い

Reproduction: reproduced（link の大きさ、2026-10-05 P1）
Disposition: scheduled（2026-10-05 Q1: P1 82b354a4 で amd64 の overlay の inode の表（約 3 MiB）を起動時の確保に。製品の kernel の余りは 544 KiB → 3712 KiB。boot の確認は T1-192。上限はいつでも外してよい（ユーザー））
Discovery: 2026-10-05 P1（q762、i915 の試験の kernel「all」が link できない件の調べ）
Handling: kernel の image の配置（bootloader の `amd64-kernel-image.h`・linker の assert・`src/hal/amd64/image.c`・handoff の検証）か、kernel の大きな .bss の配列。担当 P1

## 観測

試験を含まない kernel が約 15.9〜16.0 MiB で、上限 16 MiB（W^X の leaf の表 8 つ、2 MiB 単位）まで約 440 KiB。そのうち .bss が 13.7 MiB: vfs_bss 5.3 MiB、kernel_heap 4 MiB、overlay_inodes 3.2 MiB、CPU ごとの descriptor の状態 2 MiB、klog・cache_hash・files・pty_pairs が各 約 0.5 MiB。試験の組は約 1.4 MiB を足す（72b64d3e で組を分けて全部 link するようにした）。数百 KiB 大きくなると製品の kernel も link できなくなる。

## 直しの案

(1) 上限を上げる（W^X の leaf の表を増やす。bootloader・linker・HAL の実装・handoff の検証、UEFI と BIOS の boot の試験）、または (2) 大きな .bss の配列を起動時の確保に移す。`include/hal/hal.h` は変えない見込み（変えるなら止めて報告）。

## 直し（2026-10-05 P1 generation19、q764）

`src/drivers/fs/overlayfs.c`: amd64 では overlay の inode の表（`OVERLAY_INODE_MAX` 4096、約 3 MiB）を .vfs_bss の静的な配列から、
`drv_overlayfs_init()` で filesystem の type を登録する前に `kern_calloc()`（物理の page の連続した run）で確保する形にした。登録に失敗したら返す。
type は表と一緒にしか登録されないので、overlay の inode の処理は表が在ることを前提にできる（NULL の確かめは足さない）。大きさ・上限・振る舞いは同じ。
他の機械（pcat・pc98・rpi4 など）は .vfs_bss の静的な配列のまま（小さな機械では 3 MiB の連続した物理 memory が実行時に取れないことがある）。
generation18 が書きかけた差分を元に、到達しない NULL の確かめを除き、注釈を直した。上限（AMD64_KERNEL_MAX_BYTES）は変えていない。

確認:
- build（warning 0）: amd64 の製品と試験の組 10 個（上の表）、`config/ci/config-pcat.mk`・`config-pc98.mk`・`config-rpi4.mk` の kernel（overlayfs.c を含む。
  他の機械の `overlay_inodes_storage` は前と同じ大きさで .vfs_bss に在る）。
- host 試験: `plan/ws001/tests/credential-vfs-overlay-fault-host-test.mk` は変更の前の main でも link できない（`mount_at` など 4 つの未定義）、
  `directory-fsync-host-test.mk` は `build/driver-fragments/` の生成物が要る。どちらも今の直しとは別の古さで、overlay の振る舞いの host 試験は流せていない。
- QEMU の UEFI と BIOS の boot（login まで）: **未実施**、T1 に依頼（Q1 経由）。

残り: 上限を外す（下の「ユーザーの記録」）は今は要らない。試験の組が再び窮屈になったら選ぶ。

## ユーザーの記録（2026-10-05 夕）

ユーザー「カーネルの16MBの制限は、15-16MBホールを意識したもので、でもabove 16MBにロードして回避して、もう制限にしておく必要はないはずですね。いつでも制限を外してよいことを記録してください。」→ 16 MiB は ISA の 15〜16 MiB の hole を意識した値で、kernel を 16 MiB より上に置いて避けているので、今は制限である必要が無い。**いつでも外してよい**（広げる時は amd64-kernel-image.h の AMD64_KERNEL_MAX_BYTES・vmunix.ld の ASSERT・space.c の system_kernel_pt の数・image.c・handoff-validation.c を揃え、UEFI と BIOS の boot を確かめる）。試験の組が窮屈になったら、.bss の移し替えより先にこちらを選んでよい。
