# BUG-198: amd64 の kernel が大きさの上限（AMD64_KERNEL_MAX_BYTES 16 MiB）の手前で、余りが約 440 KiB しか無い

Reproduction: reproduced（link の大きさ、2026-10-05 P1）
Disposition: scheduled（P1、q764、優先度を下げた: 製品の kernel は余り 3.7 MiB）
Discovery: 2026-10-05 P1（q762、i915 の試験の kernel「all」が link できない件の調べ）
Handling: kernel の image の配置（bootloader の `amd64-kernel-image.h`・linker の assert・`src/hal/amd64/image.c`・handoff の検証）か、kernel の大きな .bss の配列。担当 P1

## 観測

試験を含まない kernel が約 15.9〜16.0 MiB で、上限 16 MiB（W^X の leaf の表 8 つ、2 MiB 単位）まで約 440 KiB。そのうち .bss が 13.7 MiB: vfs_bss 5.3 MiB、kernel_heap 4 MiB、overlay_inodes 3.2 MiB、CPU ごとの descriptor の状態 2 MiB、klog・cache_hash・files・pty_pairs が各 約 0.5 MiB。試験の組は約 1.4 MiB を足す（72b64d3e で組を分けて全部 link するようにした）。数百 KiB 大きくなると製品の kernel も link できなくなる。

## 直しの案

(1) 上限を上げる（W^X の leaf の表を増やす。bootloader・linker・HAL の実装・handoff の検証、UEFI と BIOS の boot の試験）、または (2) 大きな .bss の配列を起動時の確保に移す。`include/hal/hal.h` は変えない見込み（変えるなら止めて報告）。

## 測り直し（2026-10-05 P1 generation19）

製品の config（config.mk）の kernel は 12.38 MiB（余り 3.7 MiB）、config-test-hw.mk の試験無しは 12.47 MiB。generation18 の「約 440 KiB」は vkprobe の config（試験の基盤を含む）での値で、製品の kernel はまだ余裕がある。差し迫ってはいないので優先度を下げる（Q1）。試験の組の kernel（vke2 で 16300 KiB）が窮屈なことは残る。
