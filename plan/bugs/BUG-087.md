## 調べた結果（2026-09-28、ws073-p025）

原因を code と小さな Makefile で確認: rootfs の tree の rule は `$(ZEDBSD_PACKAGE_FILES)` を parse の時（`$(call)`）に展開し、stage の無い
新しい build ではこの `$(wildcard)` が空。同じ make で stage ができても最初の rootfs に resource の header は入らない（次の make で直る）。
修正案（rootfs の recipe で一覧を展開し、clang の一覧は `find`）は `BUG-087-wip.patch` に置いた（未適用・未検証）。試験
[bug087.sh](../ws073/tests/bug087.sh) と再開の手順は phase に。

## 観測

`userland/packages/lang/clang/Makefile` の `ZEDBSD_CLANG_RESOURCE_HEADERS` は clang の stage への `$(wildcard)` で、make の parse の時に読む。新しい checkout の最初の image に clang の resource の header が欠けうる。

## 次の手

新しい checkout で 1 回の make の image に resource の header が入るか確かめ、欠けるなら遅延の一覧か stage の manifest から作る。


## 適用（2026-09-28、main）

`BUG-087-wip.patch` を適用した（Makefile の rootfs の recipe は package の file を recipe の実行の時に展開、clang の header の一覧は stage を使う時に find）。desktop の image の build が通り、`build/ws035-sq/rootfs/usr/lib/clang/23/include/stddef.h` がある。boot test PASS。新しい checkout の 1 回目の build での再現試験（bug087.sh）は未実施。
