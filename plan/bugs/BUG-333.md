# BUG-333: Pi 4 の USB の touchscreen で 1 本指のスワイプが 2 本指のスワイプとして扱われる

- 状態: resolved（2026-10-17、93bb1db8c。ユーザー「Pi4でもうまく利用できることを確認しました。」）
- 発見: 2026-10-17 ユーザー「1本指のスワイプが2本指スワイプで認識されています。この点を調査できますか。サブエージェントでお願いします。」
- 機器: USB の HID の touchscreen（usb0 device 4、interface 0、contact-count-maximum=10、report 54 byte、10 slots。interface 1 は vendor の report で attach 失敗、interface 2 は mouse の emulation で非公開）。/dev/input/event2 HIDTOUCH Touchscreen。
- 手がかり: dmesg に `hid-input: usb0/port1/device4/interface0 touch: 2 fingers down at once (of 10 slots)`。1 本指で 2 つの contact が down になっている見込み（contact count・tip switch・slot の扱い、hybrid の report mode の扱い）。
- 担当: q1238。
- 2026-10-17 6:00 Q1: 原因を特定。panel は数え上げの最初の GET_DESCRIPTOR(Device) で ID を選ぶ。Linux と Windows は wLength 64 を full-speed で 64 byte の EP0 に出し、panel の 8 byte の packet が short packet になって 8 byte で終わる → panel は Goodix 27c6:8191 を名乗る。zedBSD は wLength 8・EP0 8 byte → panel は Wacom 互換 056a:8191（中央 1/3 の帯の写し）を名乗る。5330 の Linux の usbmon（build/review/pi4/usbmon-5330-linux2.txt）と zedBSD の control の記録（usb.ctltrace=1、build/review/pi4/zedbsd-5330-ctltrace.txt）を並べて確かめた。5330 の zedBSD で usb.first64=1 → 27c6:8191、無し → 056a:8191 を交互に確かめた。Input Mode・SET_IDLE・MS OS descriptor・2 回目の port reset・reset の後の待ちは関係なし。
- 直し（opt-in の boot の語 usb.first64=1）: usb.c の最初の要求を 64 byte に、pci-xhci.c で full-speed の EP0 を 64 から始める（Linux と同じ）。これで 5330・Pi 4 の他の機器（Intel BT、Logitech の receiver）も数え上げに成功。未確認: 27c6 の時の X の範囲（ユーザーの drag）、既定にするか（全部の USB 機器の数え上げが変わる）。
- 実験の boot の語（既定 off）: usb.ctltrace=1、usb.winreset=1、usb.resetwait=1、usbhid.nomode=1、usbhid.msos=1、usbhid.idle=1。
- 2026-10-17 6:2x（ユーザー）:「了解です、ではいったん仕様として受け止めます。デフォルトでUSBの挙動にマージしてほしいです。カーネルオプションは不要です」→ 1 本指の端の swipe は仕様（BUG-267）。最初の要求を 64 byte・full-speed の EP0 を 64 から始める形を既定にした（boot の語は無し）。実験の boot の語（ctltrace・winreset・resetwait・usbhid の probe）は外した。Pi 4 で既定の kernel の起動で 27c6:8191、hub・Logitech の receiver・Apple の keyboard も数え上げ ok。amd64・rpi4・pcat の build は warning 0。未実施: QEMU の起動の回帰、5330 での既定の kernel（電池切れで未確認）。
- 2026-10-17 T1-707（QEMU）: d31e4955a で amd64 の UEFI・NVMe と USB の stick の起動、pcat の起動で login、qemu-xhci の usb-kbd・usb-tablet・usb-storage・usb-net が全部 configured・enumeration failed 0・入力の event も出る、旧版と USB の行は同じ → PASS。QEMU の HID は high-speed で、full-speed の道は usb-net だけで通った。pcat の USB の機器は未実施。
