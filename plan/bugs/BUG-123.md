# BUG-123: desktop-probe が `--timeout-s=3` の後に終わらないことがある（ack の後で止まる）

Bug ID: `BUG-123`
Reproduction: reproduced（QEMU の Venus、単独で 5 回中 2 回、2026-09-30）
Disposition: resolved（ws073-p044、2026-09-30。QEMU で確認、5330 の実機は未実施）
Date: 2026-09-30
Source: ws094-p006 の報告
Owner: WS073（ws073-p044）

## 観測

`plan/ws094/tests/desktop-guest.sh` の restart の手順で、試験の client `desktop-probe` が `--timeout-s=3` の後に終わらず、log は ack の後で止まる
（gone・exited・start-limit の行が出ない）。p002 で 1 回、p006 で 2 回続けて。単独で 5 回起こすと 2 回止まり 3 回は再現しない。WS094 の Files の
変更とは無関係と見ている。原因（probe の loop、libwayland-client、libc か kernel の poll・時刻）は未調査。timeout 付きの poll が時間切れで
戻らない kernel の不具合なら、他の app にも効く恐れがある。

## 原因と修正（ws073-p044、2026-09-30）

詳細は [ws073-p044](../ws073/phase044/phase.md)。

- kernel の poll は正しい: guest で poll の時間切れを 1000 回単位（pipe・unix・3 s・probe の loop・相手の close）で試し、遅れ・早戻り・偽の
  readiness は 0。
- 止まった probe を guest の lldb で見ると `wl_display_dispatch_queue` の中の poll（時間切れ無し）で待っていた。zedBSD の libwayland-client の
  `wl_display_dispatch_queue` は、その queue の event を 1 つ dispatch するまで待ちと読みを繰り返していた（標準は 1 回読んで返す）。
  compositor からの data が default の queue の event を含まない時（delete_id など）、probe は自分の `--timeout-s` の loop に戻らない。
- 修正: 標準と同じ 1 回の待ちと読みに（`userland/desktop/libwayland/client.c`）。host の回帰試験 `plan/ws073/tests/wayland-dispatch-once.sh`
  （修正前は FAIL、修正後 PASS）。Venus の guest の restart の手順: 修正前 7 回中 2 回 FAIL、修正後 18 回 PASS。
- 影響: poll の時間切れの後に `wl_display_dispatch` を呼ぶ形の client 全て（probe 類、ime など）が、同じ条件で止まりえた。
