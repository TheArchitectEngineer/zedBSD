# BUG-111: PDF Viewer で key の repeat が dispatch の前に発火し、矢印等が 2 回効くことがある

Bug ID: `BUG-111`
Reproduction: reproduced（2026-09-29、QEMU の Venus の guest、PDF Viewer の直す前の build で 4 回の押下が 5 回の zoom に）
Disposition: resolved（2026-09-29、PDF Viewer と Text Editor を直した。QEMU で確認、実機は未実施）
Date: 2026-09-29
Source: ws091-p002 のサブエージェントの報告
Owner: WS079（PDF Viewer）

## 観測

imageview は PDF Viewer の型を写して作った。key の repeat を event の dispatch の前に発火させる作りのため、重い処理で main loop が止まっている間に、
key の release を読む前に repeat が発火し、矢印や Home が 2 回効いた。imageview は repeat を dispatch の後だけにし、切り替えの key は repeat
しないようにして直した（ws091-p002）。PDF Viewer（`userland/desktop/pdfviewer/`）も同じ作りなので、同じ症状が出うる（未確認）。Notes 等、
同じ型の他の app も確かめる。

## 調べた範囲（2026-09-29、サブエージェント、worktree `bug111-keyrepeat`、branch `wt/bug111`）

client の側で key を repeat する app（`repeat_key` を持つもの）の main loop を見た:

| app | repeat の呼び方 | 判定 |
| --- | --- | --- |
| PDF Viewer（`userland/desktop/pdfviewer/`） | wait の timeout を決める時に `pv_window_repeat()` を呼ぶ（期限なら repeat を queue に押す）→ dispatch | **当てはまる**。直した |
| Text Editor（`userland/desktop/textedit/`） | 同じ（`te_window_repeat()` を dispatch の前に） | **当てはまる**。直した |
| Files・Settings・Terminal | dispatch の後だけ（timeout は `repeat_at` から計算） | 当てはまらない |
| imageview | ws091-p002 で直した形 | 手本 |
| Notes・mview・libkeiland の chooser | client の repeat を持たない（`repeat_info` を受けるだけ） | 当てはまらない |

## 原因

main loop が重い処理（大きな拡大の raster で数秒）で止まっている間に key の press と release が compositor から届く。次の周回で、wait の
timeout を決める `*_window_repeat()` が repeat の期限（press から 400 ms）を過ぎたのを見て repeat を queue に押し、その後の dispatch で
初めて release を読む。押した key が 2 回効く。

## 修正

- PDF Viewer・Text Editor: repeat を押さない `*_window_repeat_wait()` で timeout を決め、repeat は dispatch（release を読む）の後だけに押す
  （imageview の直しと同じ）。
- PDF Viewer: repeat の event に印（`pv_event.repeat`）を付け、開く・閉じる・切り替える・確かめる key（Ctrl+O・W・Q・E・0、F9、Home、End、Enter、
  Escape）は repeat を無視する（imageview と同じ考え）。key の log の行 `KEY key=… modifiers=… repeat=…` を足した（試験の interface）。
- Text Editor は WS092 のエージェントが作業中（その worktree に textedit/main.c の未 commit の変更がある）。こちらの変更は main.c の 2 か所と
  window.c・window.h の関数 1 つだけ。merge で衝突し得る。
