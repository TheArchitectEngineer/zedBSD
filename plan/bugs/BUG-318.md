# BUG-318: Pi 4 で音声のある mp4 が Video Player で進まない（音声の時計が 0 のまま、絵が 1 枚目で止まり slider が動かない）

- 状態: reproduced（Pi 4 実機、2026-10-15 Q1）/ scheduled（P1、2026-10-15 ユーザー「この問題をサブエージェントP1に引き継いでください。」）。原因が分かり直した（P1、2026-10-15）。T2 の実機の確かめ待ち
- 発見: 2026-10-15 ユーザー「PiのホームにVideo.mp4を置きました。動画プレーヤで再生できませんでした。」「デコードはできているようですが、スムースに動画再生できませんでした。スライダーが動きません。」
- 環境: Pi 4（kei@10.0.30.2）、kernel main 2597b86（ユーザーの build、Bluetooth の driver は off）、/home/kei/Video.mp4（1920x1080 H.264＋AAC-LC、6.25 秒、6586020 byte）。
- Q1 の再現（ssh、`XDG_RUNTIME_DIR=/run/user/1000 WAYLAND_DISPLAY=wayland-0 /bin/videoplayer --timeout-s=15 /home/kei/Video.mp4`）:
  - `MEDIA backend=vulkan-video codec=h264`、`MEDIA backend=libmedia codec=aac-lc`、OPENED error=0、PRESENTED。
  - `VIDEOPLAYER CLOCK time_ms=0 heard=0 written=24000 consumed=0 pictures=8 …` が 15 秒ずっと同じ。`FRAMES shown=1`、`DONE reason=timeout shown=1`。
  - 音声の書き込みは 24000 frame で止まり、consumed・heard が 0 のまま → 時計（音声で進む）が 0 → 絵は 1 枚目、slider も動かない。decode は 8 枚の先読みで止まる（kernel の video は正常、WS236 p006 の実機の結果）。
- 音声のない試験の mp4（plan/ws236/tests/*-1080p30-10s.mp4）は時計が進む（約 15 fps、shown 76・late 224、こちらは WS236 の速さの残り）。
- Pi の状態: `service list` で audiod は running（pid 7）、`/dev/dsp0` を audiod が開いている（fuser）、`/run/audiod.sock` あり。dmesg は `rpi4-audio: PWM1 at fe20c800, DMA channel 4, irq 116, clock 54000000 Hz` だけ（`DMA error` の行は無い）。/var/log/messages に audiod の行は無い。
- 経路の候補（未確認）: videoplayer → libkeiland の audio stream（kl_audio_stream）→ compositor → libkeiland-backend-zedbsd → audiod → /dev/dsp0 → rpi4-audio（PWM1・DMA ch4）。どこで消費が止まるかを切り分ける。
- 関連: WS236（Pi の Vulkan Video）、WS202（libmedia）、WS191（再生の音を libkeiland の audio stream へ）、BUG-300（スライダー）、src/drivers/platform/rpi4/rpi4-audio.c。

## P1 の切り分けと原因（2026-10-15）

1. userland を外す: audiod を止め（`service stop audiod`、後で start）、`/dev/dsp0` に直接書く小さな probe（scratch、tree に入れない）を流した。write 方式は `GET_OSPACE` の transferred が 0 のまま write が詰まり、mmap 方式は `GET_OPTR` が trigger の時の lead（8192）から進まない → kernel の rpi4-audio で DMA が進んでいない。videoplayer・compositor・audiod は原因ではない（audiod は mmap 方式で、frontier は DMA の割り込みでだけ進む）。
2. 一時の register の dump を足した kernel（main 8688da9 + diag、tree には入れない）を Pi に置いて読んだ: DMA は ACTIVE、TI・CB・SRC・DST（0x7e20c818）は正しく、ENABLE 0x7fff、DEBUG に error 無し。ただし CS が `DREQ_STOPS_DMA`（PWM の DREQ が落ちたまま）、LEN が 0x2000 から 11〜13 word だけ減って止まる。PWM は CTL 0x2121・STA 0x700（FIFO は空でも満杯でもない、STA1/STA2 は 1）、CM_PWMCTL 0x91（SRC 1 = 54 MHz の oscillator・ENAB・BUSY）、DIV 0x1000（DIVI 1）、GPFSEL4 0x64（GPIO 40・41 が ALT0）。→ PWM が FIFO を読まない。
3. 同じ boot の中で clock の divisor を変えて 2 ms の間の DMA の進みを測った: DIVI 1（range 1125）は 8 byte しか進まない（止まっている）、DIVI 2（563）・3（375）・4（281）はどれも進む。DIVI 2 の kernel で `videoplayer --timeout-s=15 /home/kei/Video.mp4` は CLOCK が 0→5312 ms と進み heard・consumed が増え、FRAMES shown=64（late=85、WS236 の decode の速さの残り）。音声の無い `ws236/baseline-1080p30-10s.mp4` も shown=69 で時計が進む（diag の kernel、P1 の観察）。

**原因**: `src/drivers/platform/rpi4/rpi4-audio.c` が PWM の clock を oscillator ÷1（DIVI 1）で動かしていた。Pi 4 ではこの設定で clock manager は BUSY（動作中）を示すのに PWM が FIFO を読まず、DREQ が上がらないので DMA が最初の数 word で止まり、割り込みも frontier も進まない。ws207-p002 の実機の確かめ（T1 依頼）は未実施のままだった。

**直し**: `CM_PWM_DIVISOR` 2（27 MHz）。range は 48 kHz で 563（実際 47,957 Hz、−0.09%）、44.1 kHz で 612（44,118 Hz、+0.04%）。DIVI 3 なら 48 kHz が 375 でちょうどだが duty の段が減るので 2 を選んだ。dsp の framework・audiod は変えていない。

確かめ（P1、host）: `make -j16 BUILD=build/p1/rpi4 ZEDBSD_CONFIG=config/ci/config-rpi4.mk build/p1/rpi4/vmunix` rc 0・warning 0・`arm64 vmunix check: PASS`、`plan/tools/style-check.py` 指摘 0、`plan/ws207/tests/run-rpi4-audio-ring-test.sh` all PASS ×2。直しの kernel そのものの実機の確かめは T2（Q1 経由）。音が jack から出るか、左右の順（`AUDIO_RIGHT_FIRST`）はユーザーの耳の確認（未実施）。

Pi の状態: `/boot/boot0/vmunix` は元の kernel（main 2597b86 のユーザーの build、`/root/vmunix.bug318-orig` と同じ）に戻した。次の reboot まで diag の kernel が動いている。

### T2 への依頼の案

- kernel: 直しの commit で `make -j16 BUILD=build/<dir> ZEDBSD_CONFIG=config/ci/config-rpi4.mk build/<dir>/vmunix`。Pi 4 の `/boot/boot0/vmunix` に置いて reboot（元は `/root/vmunix.bug318-orig`）。
- 試験: (1) dmesg に `rpi4-audio: PWM1 at fe20c800, DMA channel 4, irq 116, clock 54000000 Hz`、`rpi4-audio: DMA error` が無い。(2) `XDG_RUNTIME_DIR=/run/user/1000 WAYLAND_DISPLAY=wayland-0 /bin/videoplayer --timeout-s=15 /home/kei/Video.mp4`: CLOCK の time_ms・heard・consumed が増え続け、FRAMES shown が 30 以上。(3) 同じ形で `/home/kei/ws236/baseline-1080p30-10s.mp4`（音声無し）: shown が 30 以上（回帰）。
- 合否: (1)〜(3) が全部なら PASS。音が出るかはユーザー。
