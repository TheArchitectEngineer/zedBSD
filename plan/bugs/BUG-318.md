# BUG-318: Pi 4 で音声のある mp4 が Video Player で進まない（音声の時計が 0 のまま、絵が 1 枚目で止まり slider が動かない）

- 状態: reproduced（Pi 4 実機、2026-10-15 Q1）/ scheduled（P1、2026-10-15 ユーザー「この問題をサブエージェントP1に引き継いでください。」）
- 発見: 2026-10-15 ユーザー「PiのホームにVideo.mp4を置きました。動画プレーヤで再生できませんでした。」「デコードはできているようですが、スムースに動画再生できませんでした。スライダーが動きません。」
- 環境: Pi 4（kei@10.0.30.2）、kernel main 2597b86（ユーザーの build、Bluetooth の driver は off）、/home/kei/Video.mp4（1920x1080 H.264＋AAC-LC、6.25 秒、6586020 byte）。
- Q1 の再現（ssh、`XDG_RUNTIME_DIR=/run/user/1000 WAYLAND_DISPLAY=wayland-0 /bin/videoplayer --timeout-s=15 /home/kei/Video.mp4`）:
  - `MEDIA backend=vulkan-video codec=h264`、`MEDIA backend=libmedia codec=aac-lc`、OPENED error=0、PRESENTED。
  - `VIDEOPLAYER CLOCK time_ms=0 heard=0 written=24000 consumed=0 pictures=8 …` が 15 秒ずっと同じ。`FRAMES shown=1`、`DONE reason=timeout shown=1`。
  - 音声の書き込みは 24000 frame で止まり、consumed・heard が 0 のまま → 時計（音声で進む）が 0 → 絵は 1 枚目、slider も動かない。decode は 8 枚の先読みで止まる（kernel の video は正常、WS236 p006 の実機の結果）。
- 音声のない試験の mp4（plan/ws236/tests/*-1080p30-10s.mp4）は時計が進む（約 15 fps、shown 76・late 224、こちらは WS236 の速さの残り）。
- Pi の状態: `service list` で audiod は running（pid 7）、`/dev/dsp0` を audiod が開いている（fuser）、`/run/audiod.sock` あり。dmesg は `rpi4-audio: PWM1 at fe20c800, DMA channel 4, irq 116, clock 54000000 Hz` だけ（`DMA error` の行は無い）。/var/log/messages に audiod の行は無い。
- 経路の候補（未確認）: videoplayer → libkeiland の audio stream（kl_audio_stream）→ compositor → libkeiland-backend-zedbsd → audiod → /dev/dsp0 → rpi4-audio（PWM1・DMA ch4）。どこで消費が止まるかを切り分ける。
- 関連: WS236（Pi の Vulkan Video）、WS202（libmedia）、WS191（再生の音を libkeiland の audio stream へ）、BUG-300（スライダー）、src/drivers/platform/rpi4/rpi4-audio.c。
