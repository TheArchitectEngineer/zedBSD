# BUG-073: swap・loop の claim のある FAT で cluster が buffer cache の line（4 KiB）より小さいと volume 全体が EBUSY で固まる

Bug ID: `BUG-073`
Reproduction: reproduced（QEMU、amd64 native の ESP（FAT32、512 B cluster）。WS073 の agent）
Disposition: resolved（ws073-p015、2026-09-27、QEMU で確認。実機は未実施）
Date: 2026-09-27
Source: ws073-p015（backing claim の試験）
Owner: WS073
Fix: [ws073-p015](../ws073/phase015/phase.md)

## 期待と観測

期待: swap file・loop の claim のある FAT で、claim の外の file の作成・読み・mkdir・swapoff ができ、claim の file だけが書けない。

観測（修正前）: `swapon boot0:swapfile` の後に `echo > /boot/boot0/new.txt` が EBUSY、以後その FAT の ls・cat・mkdir・swapoff が
reboot まで EBUSY。ws073-p014 の「ESP の swapfile の試験が 300 秒で timeout」もこれと見られる。p009 以降の pcat の `/boot`（BOOT、
2 KiB cluster に rootfs.img・data.img・swapfile）でも起こりえた。

## 原因

buffer cache の line は 1 page（4 KiB）で、512 B・2 KiB の cluster は 1 つの line に複数入る。claim された file（swap・loop）の最後の
cluster と隣の file の cluster が同じ line に入ると、`writeback_line()`（`src/kern/buf.c`）が line 全体を書こうとし、`mutation_reserve()`
（`src/kern/backing-claim.c`）が「他の claim の範囲に触れる」として EBUSY で断る。その line は BUF_ERROR・dirty のまま残り、FAT の engine の
1 sector の cache も書けずに残るので、後の全ての操作が同じ EBUSY を返す。

## 修正（ws073-p015）

- `backing_claim_find_extent_owner(disk, block, count, except, &owner)`: 書き手の claim（`except`）以外の claim の公開された extent が範囲に
  触れるかを返す。
- `writeback_line()`: 他の claim が line に触れるときは `writeback_line_runs()` で claim の外の block の連なりだけを、連なりごとに
  `backing_mutation_begin_disk_filesystem()` の guard を取って書く。claim の block は所有者が device に直接書くので、line の写しは書かない。
  書いた後の line は VALID を外し、次の読み手が device から読み直す。触れないときは従来どおり line 全体（`writeback_line_whole()`）。
- 保護は弱めていない: 書く全ての block は従来どおり registry が判定し、claim の block を書くのは所有者だけ（試験で、swap file・rootfs.img・
  data.img への追記・その場の書き込み・truncate・rm・mv・上書きの mv が全て EBUSY のまま）。

## 検証（QEMU、amd64）

- native: 512 B・2 KiB・4 KiB cluster の FAT32 それぞれで、有効な swap file の隣の file の作成・1 MiB の書き込み・読み戻し・mkdir・rename・
  ls・rm・sync が通り、swap file は読めるが変えられない、swapoff・rm、host の `fsck.fat -n` clean（`plan/ws073/tests/p015-native.sh`・`fat-claim.sh`）。
  ESP での `swapon boot0:swapfile` の後も隣の file を書ける（`boot-slots.sh native`）。UFS の root で `dir-grow.sh` の make・verify（buffer cache は共有）。
- hybrid: BOOT（2 KiB cluster、rootfs.img・data.img の loop と swapfile）に新しい file を作って消せ、fsck clean（`p015-hybrid.sh`）。

## 残り

- 別の性能の問題: 512 B cluster の ESP への 16 MiB の `dd` が約 30 秒（未調査）。
- swap の prepare の `buf_invalidate(..., BUF_INVALIDATE_DISCARD)`（`src/kern/swap.c`）は claim の extent に一部だけ重なる line も捨てる。直前の
  mount の sync で通常は dirty でないが、その間に隣の file が書かれると失われうる（未確認）。
