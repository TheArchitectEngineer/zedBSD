# BUG-073: swap・loop の claim のある FAT で cluster が buffer cache の line（4 KiB）より小さいと volume 全体が EBUSY で固まる

Bug ID: `BUG-073`
Reproduction: reproduced（QEMU、amd64 native の ESP（FAT32、512 B cluster）と hybrid の BOOT（2 KiB cluster）、WS073 の agent）
Disposition: scheduled（ws073-p015）
Date: 2026-09-27
Source: ws073-p015（backing claim の試験）
Owner: WS073

## 期待と観測

期待: swap file・loop の claim のある FAT で、claim の外の file の作成・読み・mkdir・swapoff ができ、claim の file だけが書けない。

観測: `swapon boot0:swapfile` の後に `echo > /boot/boot0/new.txt` が EBUSY、以後その FAT の ls・cat・mkdir・swapoff が reboot まで EBUSY。

## 原因（agent の読み）

`buf.c` の writeback_line が line 全体を書き戻し、その line が claim の file の cluster も含むので `mutation_reserve` が拒む
（range this claim already covers）。dirty な line が BUF_ERROR に残り、後の全てを止める。ws073-p014 の 300 秒の timeout と、p009 以降の
pcat の `/boot` にも関係する見込み。

## 次の手

ws073-p015 で buf.c の line の書き戻しを claim の外の sector の連なりだけにする（kernel、HAL の変更なし）。別に、512 B cluster の ESP への
16 MiB の dd が約 30 秒（性能、未調査）。
