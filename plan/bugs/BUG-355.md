# BUG-355: native の UFS への大きい書き込みが約 1 MB/s と遅い（2 GiB の swap file の 0 書きに約 30 分）

- 状態: open（2026-10-29 Q1 が登録）
- 発見: 2026-10-29 P4（q1665-i07・i08、WS307 p009・p010 の QEMU、SATA の disk）。installer が UFS の root に swap file 2 GiB を作る段。
- 観測: 0 書きが約 1 MB/s。installer は 1 MiB の write と最後の fsync 1 回で書いており、installer の側に直す所は無い（P4 の読み）。WS307 p006 の制限（UFS の 16 MiB の dd が同じ桁）と同じ見込み。
- 期待: 媒体の速さに近い書き込み（少なくとも数十 MB/s）。
- 未確認: QEMU だけか実機（NVMe・SATA）でも同じか、FAT・block device への直の書き込みとの比べ、原因（UFS の block の割り当て・buffer cache・同期の書き込み・driver の queue の深さ）。

## 追加の観測（2026-10-29 23:0x、WS307 p011 の 4 回目、P4 の報告）

- QEMU の 4096 byte の logical sector の NVMe に native UFS で全体の導入（既定の項目 165 MiB、小さな file の多い unit）が 22 分で約 50 MB（目算 30〜40 KB/s）。同じ導入は 512 の NVMe で約 9 分。p006 の 16 MiB の dd の比（4096 は 512 の約 2.7 倍遅い、plan/ws307/ws.md の制限）より大きく遅い。小さな file の書きで 4096 の差が広がる見込み（未確認）。
- WS307 の試験は 4096 の導入を base・OpenSSH・OpenSSL（約 45 MB）だけ・timeout 3600 s に縮めて回避した（ae125c7d4）。
