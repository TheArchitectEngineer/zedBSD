## q782-i01（P1、2026-10-06）: 切り分け（原因は取得。libbrowser の engine でも shell でもない）

Status: 判断待ち（User-Agent の方針。Q1 経由でユーザーへ）

- host の headless（`plan/ws074/tests/host-build.sh plain` の `browser --dump=dom --async https://www.amazon.co.jp/`）は `<html><head><body>` だけ。
  libbrowser の User-Agent（`userland/desktop/libbrowser/net/net.h` の `NET_USER_AGENT`）は Chrome 153 の UA
  （`Mozilla/5.0 (X11; Linux x86_64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/153.0.0.0 Safari/537.36`）。
- curl で同じ UA・同じ header（`Accept: */*`、`Accept-Encoding: identity`）: **HTTP 202、本文 0 byte、`x-amzn-waf-action: challenge`**（AWS WAF の JS の
  challenge。CloudFront）。白い画面はこの空の本文。
- UA ごとの答え（2026-10-06 の curl）: `browser/0.1 (Kei)` → 200・約 900 KB（desktop の版）。`Mozilla/5.0 …` で始まる UA は全部 202・0 byte
  （Chrome の UA、それに `Kei/0.1` を足した物、`Mozilla/5.0 (X11; zedBSD x86_64) Kei/0.1`、Firefox の UA）。
- `NET_USER_AGENT` を一時的に `browser/0.1 (Kei)` にした host の build（commit していない）では、同じ headless の `--render --async` が 3 秒で
  Amazon のトップを描いた（header・検索欄・商品の card・footer。host では日本語の font を渡していないので豆腐。Uncaught は `customElements` の 1 件）。
- 経緯: [amazon-goal.md](../ws074/amazon-goal.md)（2026-09-28）の決定は「目標は私たちの UA の版」。その後の比較の Phase（p096・p097）が固定の
  Chrome の UA を使い、engine の UA も Chrome の物になっている。

直しの案（要る判断: どの UA を送るか。Google など他の site の返す版も UA で変わる）:
1. `NET_USER_AGENT` を `browser/0.1 (Kei)` に戻す（1 行。navigator.userAgent も変わる）。Amazon は desktop の版を返す。
2. Chrome の UA のまま、Amazon は諦める（WAF の challenge の JS を通すのは範囲外）。
3. site ごとに UA を変える（今は仕組みが無い。範囲が広がる）。
