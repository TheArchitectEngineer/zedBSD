# BUG-060: guest の `mkfs -t ufs FILE` が write cached の UFS の mount の上で EBUSY で終わり、その volume の umount と sync も EBUSY

Bug ID: `BUG-060`
Reproduction: reproduced（QEMU、WS063 の agent）
Disposition: resolved（ws072-p001、2026-09-27、QEMU）
Date: 2026-09-27
Source: WS063-p002 の試験（base の image でも同じ、既存）
Owner: [WS072](../ws072/ws.md)

## 観測

format は正しく書かれるが mkfs は EBUSY で終わり、以後その volume の umount と全体の sync が EBUSY を返す（lease が漏れたと見る）。`-o writethru` の mount では起こらない。

## 次の手

ws061-p006 の format の reserve の lease と write cached の関係を調べる。

## 解決（ws072-p001、2026-09-27）

原因: formatter の lease（inode の key 付きの backing claim）がある間、volume への持ち主の無い raw の書き込みは全部拒まれる。write cached の volume では
書き込みが buffer cache に残り、flusher・`buf_sync` が guard の無い thread から書き戻すので EBUSY になり、journal の commit の失敗で volume が
書けなくなっていた（lease の漏れではない）。

修正: 遅延した書き戻しを filesystem の guard の中で行う（`buf.c`）、lease の下の書き込みは遅延させない（I/O context に lease、`file.c`・`buf.c`）、
lease の前に file を fsync する（`file.c`）、journal の中身の書き込みに I/O context を渡す（`ufs.c`）。詳細と試験は
[ws072-p001](../ws072/phase001/phase.md)。write cached の root で `mkfs -t ufs` が成功し、sync・書き込みも正常。
