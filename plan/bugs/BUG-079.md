# BUG-079: App Home から起動した application が zdesktop の環境変数を受け継がない

Bug ID: `BUG-079`
Reproduction: reproduced（Venus の guest、ws035-p090 の作業中、決定的）
Disposition: tracking（libc・rtld の候補、WS073 の再開時）
Date: 2026-09-28
Source: ws035-p090（デモの磨き）
Owner: 未定（libc・ld.so）

## 観測

ssh の shell で `export HOME=/tmp/dhome FOO=bar` の後に zdesktop を起動。Home から起動した terminal の `env` は XDG_RUNTIME_DIR・WAYLAND_DISPLAY・
TERM・PATH・PWD だけで HOME・FOO が無い。command が `env` だけの Home の項目は PATH だけを出す（zdesktop が子で `execl("/bin/sh", ...)` の前に行う
`setenv()` も失われる）。同じ shell から直接起動した zdesktop-terminal、`env FOO=1 sh -c ...` では受け継がれる。

## 見込み（desktop の agent）

zdesktop に clearenv・unsetenv・environ の操作は無く、libc の execl → exec_varargs は environ を正しく使う。zdesktop の process の中で libc の
`environ` が空か初期化し直されている（Vulkan・Venus の経路の library による 2 度目の libc の初期化など）と疑う。未調査。

## 影響

Files と terminal が passwd の home（/root）へ戻る。デモは session の script で /root の通常の folder を作って回避。

## 次の手

zdesktop の process で environ を gdb で追う（どの library の読み込みで変わるか）。libc・rtld の修正。
