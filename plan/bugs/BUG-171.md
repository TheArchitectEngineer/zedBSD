# BUG-171: 窓の透明度を opaque にしても窓が不透明にならない

Reproduction: reproduced（実機）
Disposition: scheduled（2026-10-05 夜、決定 B で修正済み・T1 の試験待ち）
Discovery: 2026-10-04 UAT（実機 Latitude 5330、素の起動、image sha256 f03920c3…、main 52e15c0 の CI の構成＋[config-uat.mk](../uat/config-uat.mk)）、[UAT 2026-10-04](../uat.md)
Handling: WS089（Settings）／compositor
Evidence: [plan/uat/2026-10-04/](../uat/2026-10-04/)（dmesg・/var/log・session.log・ps・sysctl・Shut Down の間の log）

## 観測

E2: Settings で窓の透明度を opaque にしても窓が透けたまま。session の log に `ZWL PREFERENCES key=window.opacity applied value=86`（[zmon-and-session.txt](../uat/2026-10-04/zmon-and-session.txt)）。opaque の時の値（100 か）と compositor の合成（glass の効果）を確かめる。

## 調べ（2026-10-05 P1 generation17 / q725、読み。source は変えていない）

- 経路: Settings の Appearance の slider（`page-look.c` の `se_look_drag`、離した時に `se_look_set_opacity`）→ `kl_settings_set("window.opacity", "100")` → compositor の store（chosen）→ `settings_apply_opacity` → `server->window_opacity = 1.0`、log `ZWL PREFERENCES key=window.opacity applied value=100`。QEMU の `plan/ws089/tests/settings-p004.sh` は slider を右端まで drag して `applied value=100` を確かめ、T1-011 で PASS している。読みの限り、この経路に不具合は見つからない。
- UAT の証拠: session の log には起動時の `applied value=86`（desktop.conf の値）だけがあり、opaque に変えた後の `applied value=100` が無い。考えられる理由は 2 つ。
  1. 変更が compositor に届かなかった: 当時の入力は PS/2 の touchpad で、slider の drag（tap-drag）の release が届かないと値が保存されない（同じ UAT の BUG-170 の音量の slider のフリーズ、BUG-166・178 の touchpad の drag の問題と同じ系統）。touchpad は WS159 で native になったので、次の UAT で確かめ直す。
  2. **届いても「透けて見える」**: `window_opacity` 1.0 で窓の本体の画は不透明になるが、Keiland の app の glass panel（Settings・Files などの sidebar、`panels.c` の `panels_glass`）は opacity に依らず、ぼかした壁紙を 34%（`GLASS_WHITE`）白くした frosted glass のまま描く（shader の `mix(under, color, color.a)`）。窓の title bar も glass。Settings で「Opaque」を選んでも Settings 自身や Files の sidebar の向こうに壁紙が見えるので、「不透明にならない」と見える。
- **人間の判断が要る点（Q1・ユーザー）**: 「Opaque」の意味。
  - (a) 100% では glass panel と title bar も不透明（solid の白に近い色）にする。注意: opacity の既定は 100 なので、既定の見た目から frosted glass が消える（Keiland の glass の見た目が変わる）。
  - (b) 100% を「窓の中身が不透明」とし、glass panel は frosted のまま。Settings の表示を「Opaque」から実態に合う言葉（例: 「Window contents opaque」）にし、glass も止めたい人には別の選択肢を足す。
  - (c) Appearance に「Glass effect」の on/off を別に足す（off で panel・title bar を solid に）。
- 判断の後に実装する（(a) なら `panels_glass` と title bar の glass で `window_opacity >= 1.0` の時に `color[3] = 1.0`、(c) なら新しい key と Settings の行）。次の UAT で 1 の経路（slider で opaque にした後に `applied value=100` が出るか）も確かめる。


## 決定と直し（2026-10-05 夜、P2 g16）

- ユーザーの決定（Q1 の伝達）: **B** = 明示に 100 を選んだ時だけ窓の glass panel を不透明にする。既定は今の frosted のまま。title bar は対象外。
- 直し（compositor）:
  - `userland/desktop/wayland/zwl.h`: `server->panels_opaque`。
  - `userland/desktop/wayland/settings.c` の `settings_apply_opacity`: `window.opacity` が chosen で 100 以上の時だけ `panels_opaque = 1`（既定・reset は 0）。opacity が同じでも panels が変われば描き直す。log `ZWL PREFERENCES key=window.opacity applied value=N panels=opaque|glass`（`value=N` までの既存の試験の照合はそのまま一致）。
  - `userland/desktop/wayland/panels.c` の `panels_glass`: `panels_opaque` の時は glass の色の alpha を 1（light は白、dark は暗い glass の色で、壁紙が透けない）。title bar・bar・Home 等の他の glass は変えない。
- 試験: `plan/ws089/tests/settings-p007.sh` に 3b（`set window.opacity 100` → `applied value=100 panels=opaque`、opaque.png）と、reset の後の `value=100 panels=glass` を足した。
- 確かめ（host）: zedBSD の `bin/wayland`（config-amd64-osk-predict.mk、BUILD=build/ws140-p002）と `make keiland-linux` とも warning 0。style-check: panels.c・zwl.h 0、settings.c は既存の 1 件のまま。
- 未実施: QEMU（T1: `plan/tools/guest/test-image.sh plan/tools/settings/config-amd64-settings.mk BUILD`（settings-p007 の image）→ `plan/ws089/tests/settings-guest.sh start IMAGE` → `plan/ws089/tests/settings-p007.sh OUTDIR`。合格: status 0、opaque.png で Settings の sidebar に壁紙が透けない、removed.png で frosted に戻る）。実機は次の UAT（slider で 100 にした後に `applied value=100 panels=opaque` が出るか、元の経路 1 も）。
