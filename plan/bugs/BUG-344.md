# BUG-344: libc の fscanf・vfscanf・scanf が 1 行しか読まず、行の残りを stream に戻さない

- 状態: reproduced（2026-10-21、VF2 の gpu-selftest の present の段）/ tracking
- 発見: WS269 q1487〜q1489（P1）。gpu-selftest が vkdemo の frame の header `"P6\n320 240\n255\n"` を `fscanf(f, "P6 %u %u %u", …)` で読むと 1 しか返らず、正しい 320x240 の PPM を「PPM でない」と判定した（板 83）。
- 原因: `src/libc/stdio-extra.c` の vfscanf が `fgets`（4096 byte の buffer）で 1 行を読んで `vsscanf` に渡すだけ。書式の空白は改行を跨いで読み飛ばさず、変換が使わなかった入力は `ungetc` で戻されず捨てられ、4095 byte を超える行は切れる。
- 期待: 書式の空白は改行を含む任意の空白を読み飛ばし、使わなかった入力は stream に残る（C の標準。glibc では上の例で 3 が返る）。
- 再現: 上の 3 行の file を `fscanf(f, "P6 %u %u %u", …)` で読む → zedBSD は 1、glibc は 3（glibc の値は標準からの推定、未実行）。
- 影響: 複数行の入力を fscanf で読む program 全般。gpu-selftest は q1489（b70559027）で fscanf を使わず header を自前で読む形に回避済み。
- 関係: WS269 p010q。libc の修正は別の WS（libc の stdio）で。
- 再調査の条件: libc の stdio の WS で vfscanf を stream から直接読む実装に直した時に、上の再現で 3 が返る事。
