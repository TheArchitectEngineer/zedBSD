# BUG-352: DHCP の interface が 2 つあり両方が default route を入れると、次からの net の commit が全部 `route: Device or resource busy` で失敗する

- 状態: open（2026-10-29 Q1 が登録）
- 発見: 2026-10-29 P3（q1664-i03、WS221 p004 の QEMU の試験）。MTU と無関係に、MTU の設定無しでも再現。
- 再現: QEMU で ue1 を dhcp にして commit（ue0 も dhcp）→ 次の net の commit。
- 観測: reconcile の DEFAULTROUTE_CLEAR の `route delete default` が EBUSY を返し、commit が失敗、rollback も degraded。
- 期待: default route が 2 つあっても、net の commit が通る（default route の扱いを決めて消せる・置き換えられる）。
