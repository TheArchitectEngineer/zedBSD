# BUG-347: disk image の system の file が group-writable になり、wheel（kei）が /lib/libc.so などを書き換えられる

- 状態: resolved（2026-10-28 Q1 の判定: b0cc18f2f、merge a79ce5edb。QEMU の guest で /lib/libc.so が -rwxr-xr-x、/tmp だけ 1777。実機・他 arch・package 入りの image は未実施）
- 決定: 2026-10-28 ユーザー「BUG-347は推しで解決します。担当はP4で、現在の仕様検討が終わった後にスケジュールします。」 → 直しは推しの案 1（root の tree を作る所で umask 022 を固定）。担当 P4、ws307-p001 の後の Queue で。
- 発見: 2026-10-28 ws307-p001（P4）の design-reviewer の観察、P4 が build の tree で確かめた。
- 観測: `find build/aat-0505a/rootfs -perm -g+w ! -type l` が 531（dir を含む）。`/lib/libc.so` は `-rwxrwxr-x`。`tools/build/zedimage-host.c` の `add_tree`（:72 付近）が staged の tree の `st_mode & 07777` をそのまま inode に書き、`write_inode`（:59-60）は uid・gid を 0 にする。gid 0 は wheel で kei が入る（`userland/base/etc/group:1`）。build する人の umask（002）がそのまま image の mode になる。
- 期待: image の system の file・directory は build の umask に依らず決まった mode（意図した setuid・sticky・group の書き込みだけを残す）。
- 影響: image で起動した system で、wheel の利用者が root の権限なしに system の library・道具を書き換えられる（security）。
- 確かめ: guest で `ls -l /lib/libc.so`、image の UFS を check-ufs-image で読む。
- 直しの候補: staged の tree を作る所で umask 022 を固定する、または zedimage-host.c で group・other の書き込みの bit を、意図して付ける path（/tmp の 1777 など）を除いて落とす。

## 直し（2026-10-28 P4、q1647-i01、b0cc18f2f）

- 原因の所: root の tree を作る `ZEDBSD_ROOTFS_TREE_RULE`（`Makefile`）。`cp -f`・`mkdir`・`printf >`・sysroot の `cp -R` は build する人の umask で file を作り、`--subtree` の `cp -RPp` は stage の mode をそのまま写していた。`zedimage-host` の `add_tree` は staged の mode をそのまま inode に書く（uid・gid は 0）。directory は規則の最後の `chmod 0755` で直っていたので、残っていたのは file（と `/.stamp`）。
- 直し（ユーザーの決定の推し、umask 022 の固定）:
  - `Makefile` の `ZEDBSD_ROOTFS_TREE_RULE`: file を作る全ての行（mkdir、`lib/arch.id`・`etc/zedbsd-root` の printf、`--file`/`--subtree`/`--mode` の loop、link の loop、`.stamp` の touch）と `ZEDBSD_ROOTFS_INSTALL_DEVELOPMENT` の mkdir・cp を `umask 022` で。`--subtree` は `cp -RPp` → `cp -RP`（`-p` は mode を写して umask を効かせないため）。group・other の書き込みは明示の `--mode` と sticky の directory の `chmod 1777` だけから付く。
  - `tools/build/make-arch-overlay-ufs.noct`（試験の overlay の UFS の image、`ZEDBSD_ARCH_UFS_IMAGE_RULE`）: 同じ不具合（`cp -p`・`cp -RPp`・`FileUtil.writeText`）を同じ形で（`umask 022 &&`、`-p` を外す、root の印の 2 つの file を `chmod 0644`）。
  - 意図して group・other の書き込みを付ける path は `/tmp`・`/shm`（1777、`ZEDBSD_ROOTFS_STICKY_DIRECTORIES`）だけ。`--mode` の値に group・other の書き込みを付ける物は tree に無い（`git grep` で 0644・0755・0600・0400・0700・4755 と試験の 1 つの 0777 だけ）。set-user-ID は `--mode` の段で付くので保たれる。
- 確かめ（umask 002 の shell、`BUILD=build/bug347`、`ZEDBSD_CONFIG=plan/tools/gnu-utils/config-amd64-base.mk`）:
  - `make … build/bug347/rootfs/.stamp` と `make … disk-image`: exit 0。変えた所の build の出力の warning 0（最初の build の warning は外部の OpenSSL の package の perl の locale と OpenSSL の source の物）。
  - staged の tree: `find build/bug347/rootfs -perm /022 ! -type l` は `tmp`・`shm`（1777）だけ（直す前の main の `build/aat-0505a` の image は 531）。`/bin/ping`・`/bin/newgrp` は 4755、`/etc/shadow` は 0400。
  - image の root の UFS（`build/bug347/arch-images/amd64-native-root-1024m.ufs`）を `tools/build/check-ufs-image.py` の reader で全 inode を読み、group・other の書き込みのある inode（symlink を除く）は `/tmp`・`/shm` だけ。`/lib/libc.so` 0755・`/bin/sh` 0755・`/etc/shadow` 0400・`/bin/ping` 4755、全て uid 0・gid 0。`check-ufs-image.py` も OK。
  - QEMU（`plan/tools/boot-test.sh`、uefi-nvme、`build/bug347/hdd-image.img`）: login prompt、kei で login して `ls -l /lib/libc.so /bin/sh /etc/passwd; ls -ld /tmp /usr/include` → `-rwxr-xr-x root wheel /lib/libc.so`・`/bin/sh`、`-rw-r--r-- /etc/passwd`、`drwxrwxrwt /tmp`、`drwxr-xr-x /usr/include`（PASS、PNG `build/tmp/bug347/boot2/login-after.png`）。
  - overlay の tool: umask 002 で `--file`（0775・0664 の元）・`--subtree`（0664）・`--mode /etc/data=0600` の 16 MiB の image を作り、`/bin/sh` 0755・`/etc/data` 0600・subtree の file 0644・`/lib/arch.id` 0644、書き込みは `/tmp`・`/shm` だけ。
- 未実施: `--subtree` を使う package（python3 など）を含む image の build（base の config には無い。同じ `cp -RP` の動作は overlay の tool の試験で確かめた）、実機、他の arch（同じ規則を使う）の image の build。
- 別件の観察（直していない）: staged の tree の `.stamp`（make の stamp）が image の `/.stamp` として入っている。
