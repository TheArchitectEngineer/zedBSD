## 観測

実機の run で wltest を kill（wlkill）した client の CLEANUP の直後に、compositor の最後の frame（st1: 194、bisect1: 163）で描画が
止まり、後の場面（egltest）が始まらない。hang・fault・device lost の報告は無い。stencil・multisample の変更の有無に関係なく出た。
BUG-077（close の job の予約の循環の待ち）と同じ系統の可能性がある（未確認）。

## 次の手

再現の率を測り、止まった時の compositor の thread と GPU core の session の状態（予約・fence・待ち）を gdbstub か log で読む。

## BUG-091 との関係（2026-09-28、ws075-p014）

BUG-091 の原因（i915 が割込み許可のまま spin lock を持ち、preempt されて別の CPU で解放する）は、起きれば必ず `ud2` の trap（fatal の報告、
BUG-091 の形）か、同じ CPU の再取得の trap になる。別の CPU の待ち手は持ち主が再び走るまで回るだけで、止まり続けはしない。BUG-085 の停止は
fault・fatal の報告が無いので、**同じ原因の可能性は低い**。ただし `request-queue.c` の retire の `device->irq_lock` も同じ形だった（ws075-p014 で
修正）ので、修正の後の kernel で BUG-085 の再現を試す価値はある。未確認。
