# BUG-331: RDNA 機の desktop が App Home を閉じる animation の途中で固まり（mouse も止まる）、機械が reset して Debian に戻る

- 状態: reproduced 0 回（ユーザーの観察 1 回）/ tracking
- 発見: 2026-10-16 19:1x ユーザー「お、RDNA機を操作したらフリーズしました。」「App Homeから戻るときにアニメーション中にフリーズしました。マウスも止まり、同じ画面のままフリーズです。」
- 前提の訂正（P3）: main の f2ed268e4 系の image ではなく、P3 の p017 の 2 段目の試験の kernel（vmunix a7b2cab8: BAR0 を 0x4200000000 に動かして 8 GiB、1 GiB の窓、kernel が console の framebuffer を WC で自分で map）で起きた。
- 経緯: 19:08:18 に P3 の script がユーザーの操作中に zedBSD を再起動した（P3 の誤り、ユーザーの session が切れた）。19:09:30 ごろ同じ kernel で再び desktop（boot 19）。起動の記録は「20 s after boot」（19:09:32）で終わり、60 s の印も停止の行も無い → 19:09:40〜19:10:10 に異常停止、19:10:29 に Debian（firmware の BootOrder）。reset の引き金の記録は無い。証拠: USB の sda2 log/boot-000019.txt。
- 候補（未確認）: (a) BAR の移動と console の WC の map の組み合わせ（HAL の固定の VA は古い物理を UC で指したまま、GOP の surface に WC と UC の別名）、(b) 広げた窓（256 MiB〜1 GiB の blob）、(c) 前からある不具合が App Home の animation の負荷で出た（1 段目の kernel では未再現）。
- 扱い: p017 の 2 段目はこれが分かるまで merge しない。P3 が同じ kernel で再現を試み、出なければ 1 段目の kernel と比べる。実機の再起動は Q1 に知らせてから。
