# BUG-316: SV7 の実機で /boot/boot0 が mount されない（WS238 の native の layout）

- 状態: reproduced（実機、ユーザー）/ tracking（2026-10-15 Q1、bug-analyzer が source から解析中）
- 発見: 2026-10-15 ユーザー UAT「/boot/boot0がマウントされていないです。」「boot0がマウントされなかったのはSV7で、mainです。」
- 環境: Let's Note SV7（Gen9.5）、main の image（build/uat/sv7-gen9/hdd-image.img: ESP 64M に BOOTX64.EFI だけ、ZEDBSD FAT32 256M、UFS、swap）。zedbsd.cfg に boot0= は無く、loader が zedbsd.cfg のある FAT の UUID から作る設計。
- 対照: QEMU（OVMF）では PASS（T1-638）。実機の log は未入手（SV7 は network に無い）。
- 影響: 5330（Beta 2 の主な機種、同じ layout）も同じかは未確認。
- 関連: WS238、BUG-312。
- 2026-10-15 SV7 の log（ユーザーが 10.0.30.3 で起動、Q1 が ssh）: **動いていたのは WS238 の image ではなく**、kernel 8e2115b（2026-10-14）、旧い 3 区画の layout（sda1 FAT 64M＝ESP に全部、sda2 UFS、sda3 swap）。`boot: parameters: boot0=UUID=F2F2-5003 rootpart=PARTLABEL=zedBSD-root swap0=… kmsg=console login=console`、`vfs: boot0 UUID=F2F2-5003 -> /dev/sda1 (private FAT)`、しかし `published at /boot/boot0` の行も失敗の行も無く、/boot は空。`gpt: sda protective MBR extent mismatch`（大きい USB に書いた）。内蔵 disk は sdb（3 区画）。→ 8e2115b の時点で slot 0 が公開されない穴がある。今の main（WS238）でも同じかは解析中（QEMU の T1-638 は PASS）。
