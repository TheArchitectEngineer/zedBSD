# BUG-310: 第 8 世代 Core（Gen9.5、Let's Note SV7）を素で起動すると、compositor が Vulkan の display の失敗で終わり desktop が出ない

- 状態: reproduced（実機、ユーザーの写真）/ scheduled（2026-10-14 ユーザー「i915の実機の問題です。第8世代Core i5です。P2で直しましょう」、P2）
- 発見: ユーザーの実機の UAT（2026-10-14 夜）。Let's Note SV7（Core i5 第 8 世代、UHD 620、WS229 の Gen9.5、既定 on）を release の候補の image で USB から素に起動し、console で `wayland` を起動。写真: build/review/bug310-sv7-wayland.webp。
- 観察（写真の文字）: `i915: resident shim: context sw_id=2 … engine=rcs0`、`sw_id=3 …` の後に `KWL VULKAN_ERROR operation=display result=-3`、`KWL COMPOSE unavailable errno=5`、`KWL STARTUP step=compose ms=177`、`KWL EXIT frames=0 error=5`。
- 推測（Q1）: Gen9 の i915 は engine と Vulkan だけを動かし display は GOP の framebuffer のまま（WS229 の設計）。compositor は i915 の Vulkan の device を見つけて Vulkan の display（VK_KHR_display 相当）で出そうとし、display の口が無いので失敗し、framebuffer の道に戻らずに終わる。T1 の試験（SV7 の Linux の上の QEMU の passthrough）では guest の画面が QEMU の側だったので見えなかった。
- 回避: 起動の設定に `i915.gen9=off`（手引きの手順）。
- 関連: WS229（i915 Gen9）、BUG-303。

## 2026-10-14 P2: 原因と直し（commit 9cdd5689c、未試験）

### 原因

- compositor（`userland/desktop/wayland/compose.c` の `compose_device()`・`compose_display()`）は最初の Vulkan の physical device を取り、その
  VK_KHR_display の display を必須にする。display が 0 個なら `VK_ERROR_INITIALIZATION_FAILED`（-3）→ `KWL VULKAN_ERROR operation=display result=-3`
  → `KWL COMPOSE unavailable errno=5` → 終了。
- Gen9 の i915 は N0-lite（`display/takeover.c`）で `display->absent = 1`（WS229 の設計どおり display controller に触れない）。`drv_i915_display_bind_ops()`
  は panel の無い node に display の op を bind しないので、libvulkan の `vkGetPhysicalDeviceDisplayPropertiesKHR` は 0 個を返す。
- compositor にも libvulkan にも、display の無い時に software の合成や `/dev/graphics` へ出す道は無い（GPU の無い機械では `operation=device` で終わる）。
  WS229 p001 の D3「display の無い GPU node で Keiland を動かす経路は作らない」の結果。**`i915.gen9=off` でも desktop は出ない**（GPU が無いので
  compositor は device の段で終わり、console だけ。source から読んだ事実で、実機では未確認）。手引きの「回避」は desktop の回避にならない。

### 直し（候補 (a) を kernel の側で: Vulkan で描き、GOP の framebuffer へ出す）

- 新しい `src/drivers/gpu/i915/display/bootfb.c`・`bootfb.h`: Gen9 の node（`gt.graphics_ver == 9` かつ `display->absent`）にだけ、loader が渡した
  framebuffer（`pcat.framebuffer` の handoff）の上の display を 1 つ bind する。試験用の capture display（`capture.c`）と同じ形（1 output、connected、
  FIFO、BLOB/copy、1 plane、BGRA/RGBA、lease 1 つ、mode は framebuffer の解像度 @60 Hz、名前 `i915 bootfb`）。
  - present: GPU が frame を連続の staging（RAM、uncached の PPGTT の map）へ copy → clflush → CPU が行ごとに framebuffer へ写す
    （framebuffer の stride を使い、RGBX/BGRX と frame の BGRA/RGBA が違えば赤と青を入れ替え、framebuffer より大きい frame は左上で clip）。
  - CPU の view は write-combining: framebuffer が i915 の aperture（GMADR）の中なら device の WC の aperture の view（実機の iGPU）、外なら
    自分で `hal_space_map_device(..., HAL_SPACE_WC)`（QEMU の passthrough の guest の GOP は QEMU の VGA）。
  - lease の claim で `kern_text_suspend()` と framebuffer の黒の消去、lease の終わり（release、および compositor の終了・crash の
    session close）で `kern_text_resume()`。
  - log: bind の時 `i915: bootfb: WxH on the firmware's framebuffer at 0x… (stride …, BGRX|RGBX, aperture|own view)…`、
    `i915: bootfb: lease N claimed; the text console is suspended`、最初の frame で `i915: bootfb: frame 1 WxH gpu_copy_us=… cpu_copy_us=…`、
    以後 600 frame ごとに平均、`… lease N released after … frame(s) …; the text console resumes`。
- `display/display.c`: `drv_i915_display_bind_ops()` で display が live でない時に `drv_i915_bootfb_bind_ops()`（Gen9 以外は何もしない）、
  session close・fini を bootfb へ。scanout の op は capture の物（同じ id 1・generation 1・形式）を使う（`scanout.c`・`.h` の注釈だけ）。
- compositor・libvulkan・HAL の API・toolchain は変えていない。Gen12（5330）は display が live なので今の道のまま。Gen12 で N0 が STOP した
  absent の node も `graphics_ver != 9` で今のまま（display 無し）。
- 制限: vsync 無しで scanout 中の framebuffer に直に書くので tearing があり得る。1 frame ごとに GPU の copy と全画面の CPU の copy（1920x1080 で約 8 MB）。
  greeter → session の引き継ぎの間に text console が一瞬戻る。cursor plane 無し（compositor の software の cursor、capture と同じ）。

### ユーザーへの実機の確かめの手順（SV7、USB）

1. 直しを含む release の候補の image を USB に書く。`zedbsd.cfg` に `i915.gen9=` の行は足さない（既定 on）。
2. SV7 で USB から素に起動する。期待: Kei の logo の後に login の画面か desktop が、firmware の解像度で出る（明るさの変更・外部 display は不可、tearing はあり得る）。
3. 出なければ、console で `grep -e 'i915: bootfb' -e 'KWL' /var/log/kernel.log`（または `wayland` を手で起こした時の画面）を撮る。
   正しい時の行: `i915: bootfb: 1920x1080 on the firmware's framebuffer at 0x… (stride 7680, BGRX, aperture view)`、`i915: bootfb: lease 1 claimed; …`、
   `i915: bootfb: frame 1 1920x1080 gpu_copy_us=… cpu_copy_us=…`。

### 文書の直しの案（Q1 が直す、docs/release/zedbsd-1.0.0-beta2-guide.md の「Older Intel graphics」と known-issues の Gen9 の行）

- 事実（source から、実機では未確認）: `i915.gen9=off` では GPU が無いので desktop は出ず、text console だけになる（直しの前も後も）。
- 案（guide）: 「On computers with a 6th to 10th generation Core processor (Gen9 and Gen9.5), Kei drives the GPU's engines and Vulkan and shows the
  desktop on the framebuffer the firmware set up, but does not drive the display yet: … Each frame is copied to that framebuffer, so moving
  pictures may tear and be slower than on the Latitude 5330.」「If the GPU driver gives trouble, turn it off … Kei then has no GPU: the desktop does
  not start, and only the text console is shown.」
- 案（known-issues の Gen9 の行）: 「… the desktop is shown on the firmware's framebuffer (each frame copied, so it may tear) …」を足し、回避の欄の
  `i915.gen9=off` に「(the desktop does not start without the driver)」を足す。
