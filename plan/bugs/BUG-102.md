# BUG-102: 利用者 kei が ping できない（raw socket が superuser だけ）

Bug ID: `BUG-102`
Reproduction: reproduced（ユーザー、素の 5330、demo-lcd3、2026-09-29）
Disposition: resolved（2026-09-29、[ws073-p029](../ws073/phase029/phase.md)、QEMU で確認。実機は未実施）
Date: 2026-09-29
Source: ユーザー「ユーザkeiがpingできません。ネットワーク権限がないようです。」
Owner: WS073（Bug Board）

## 観測

graphical の session の利用者 kei（uid 1000、`network` の group の member: `userland/base/etc/group` の `network:x:69:kei`）で `ping` が失敗する。

## 原因（コード）

`src/kern/syscall.c` の socket の生成（1372 行付近）は `AF_PACKET` と `SOCK_RAW` を `cred_is_superuser()` の process にだけ許し、
それ以外は `EPERM`。`userland/base/ping/main.c` は `socket(AF_INET, SOCK_RAW, IPPROTO_ICMP)` を使う。`network` の group は
この検査に関わらない（2026-09-28 の「セッションユーザはnetworkグループに追加してOK」は networkd の操作の権限のためのもの）。

## 直し方の案（決めること）

1. ping を setuid root にする（BSD と同じ。raw socket を開いた後に権限を落とす）。
2. ICMP の datagram socket（`SOCK_DGRAM` + `IPPROTO_ICMP`、Linux の `ping_group_range` と同じ考え）を kernel に足し、ping をそれに移す。
3. `network` の group に ICMP の raw socket を許す（kernel の検査に group を足す）。

決定（2026-09-29 ユーザー）:「pingをsetuidにします。これはBSD系OSだからです。」→ 案 1。ping の package の install の mode を 4755 にし、
`socket()` の後に `setuid(getuid())` で権限を落とす。kernel は exec で setuid を扱う（`src/kern/exec.c:312`）。

## 修正と確認（2026-09-29、[ws073-p029](../ws073/phase029/phase.md)）

- `userland/base/ping/Makefile`: install の mode 4755（newgrp と同じ仕組み）。image で `-rwsr-xr-x root wheel /bin/ping`。
- `userland/base/ping/main.c`: main の最初に `socket(AF_INET, SOCK_RAW, IPPROTO_ICMP)` を開き、直後に `setuid(getuid())`。失敗なら終了 1。
  引数の解析・名前の解決は権限を落とした後。socket の失敗は保存した errno で従来の位置に報告。kernel は変えていない。
- QEMU（amd64、`plan/ws073/tests/ping-user.sh`、`PING-USER:PASS`）: kei（uid 1000）で `ping -c 3 127.0.0.1`・`ping -c 3 10.0.2.2` 各 3/3。
  set-user-ID の無い複写は `ping: socket: Operation not permitted`（症状の再現）。同じ手順の probe（`tests/setuid-drop.c`）で権限を落とした後
  euid=1000、raw socket・`setuid(0)`・`seteuid(0)` は拒まれる。boot test PASS。
- 未実施: 実機（素の 5330・demo-lcd3）、graphical の session の terminal からの実行。
