# BUG-291: libc の memcpy・memmove・memset が 1 byte ずつの loop で遅い（uncached の map で 12 MB/s）

- 状態: reproduced（Pi 4 の実機の計測、2026-10-12 P3） / scheduled（P2）
- 発見: 2026-10-12 P3（ws141-p013）。Pi 4 で Settings の title bar の hover が重い件の内訳: libkeiland の present-copy.c が canvas の行を map した memory へ memcpy する所で 1180x800x4＝3.8 MB に 305 ms（約 12 MB/s）。
- 原因（source）: `src/libc/string.c` の `memcpy`・`memmove`・`memset` が 1 byte ずつの loop。canvas の map は Normal non-cacheable（`render-device.c` の render_map → `DRV_GPU_MAPPING_UNCACHED_RAM`）なので 1 byte ごとに uncached の store になる。kernel の `kern_memcpy` は word 単位で別。
- 影響: 全 platform の全 userland の memcpy・memset・memmove（特に uncached・write-combined の map への写し）。
- 直す案: word（できれば 16 byte）単位の memcpy・memmove・memset（alignment の前後の端を byte で、重なりの向き、`-fno-builtin` の下で compiler が自分を呼ばない形）。amd64・arm64（i386 は今は build しない、guardrail）。host の試験（長さ・alignment の組み合わせ、重なり）と速さの比較。
