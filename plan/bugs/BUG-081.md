# BUG-081: 既定でない BUILD で、新しい checkout の package の build が失敗する（cross の wrapper が build/amd64/dynamic を固定で参照）

Bug ID: `BUG-081`
Reproduction: reproduced（新しい worktree、WS073 の agent）
Disposition: resolved（WS073、2026-09-28）
Date: 2026-09-28
Source: WS073（BUG-079 の後の desktop の image の build）
Owner: WS073

## 観測

新しい checkout で `BUILD=build/ws035-sq`（build-zdesktop-image.sh）だけで build すると、cross の wrapper
（`build/amd64/packages/toolchain/bin/zedbsd-clang`、gen-cross-toolchain.sh が `userland/packages/external.mk` の ZEDBSD_EXTERNAL_DYNAMIC から作る）が
既定の BUILD の `-L build/amd64/dynamic` を常に使い、それが無いので sysroot の非 PIC の libc.a に落ち、libcxx の cmake の試験の link が
R_X86_64_32S の再配置の誤りで失敗する。main の tree は以前の既定の build で build/amd64/dynamic があるので通っていた。clang/Makefile にも同じ問題の注記がある。

## 次の手

WS073 で修正（wrapper が BUILD の dynamic の directory を使う。規約 §12（環境変数で設定しない）に合わせ、可能なら BUILD ごとに wrapper に焼き込む）。
新しい worktree からの desktop の image の build で確認。

## 解決（2026-09-28、WS073）

wrapper は BUILD ごとの directory ではなく、wrapper の隣の共有の link の directory（`build/<platform>/packages/toolchain/lib`）を焼き込む。
package は全 BUILD で共有されるので、BUILD ごとの wrapper は BUILD が変わるたびに package（clang を含む）を configure し直させる。
link の directory には package が link する共有 library（libc.so、amd64 では OpenSSH の openpty の libutil.so）の複写を置き、
top-level の make では build 中の `$(BUILD)/dynamic` から、package 単独の make では従来の既定の build の dynamic から取る。
複写は source が変われば更新され、wrapper の stamp の order-only の前提なので、新しい libc で package が configure し直されることはない
（`userland/packages/external.mk`。gen-cross-toolchain.sh は変えていないので、既存の tree の wrapper は次の sysroot の更新で新しい path になる）。
環境変数は使わない（規約 §12）。

検証: 新しい worktree（build/amd64/dynamic が無い）で `plan/ws035/tests/build-zdesktop-image.sh build/ws073-desk`: libcxx・openssl・openssh・clang が
build でき（R_X86_64_32 の誤り 0、sshd の DT_NEEDED は libutil.so・libcrypto.so・libc.so）、image の check が OK、
`plan/tools/boot-test.sh build/ws073-desk/hdd-image.img` PASS。最初の試み（libc.so だけの複写）で OpenSSH の依存の契約（libutil.so）が落ちたので
libutil.so を加えた。
