# BUG-090: libc の qsort が二次の時間（1 byte ずつ交換する挿入の sort）

Bug ID: `BUG-090`
Reproduction: reproduced（ws079-p006、guest で密な page の描画が 351 ms。rasterizer を自前の merge sort にして 11 ms）
Disposition: resolved（ws073-p026、2026-09-28。QEMU と host で確認、実機は未実施）
Date: 2026-09-28
Source: ws079-p006（PDF Viewer の agent）
Owner: WS073（[ws073-p026](../ws073/phase026/phase.md)）

## 観測

`src/libc/stdlib-extra.c` の `qsort` は byte ずつ swap する挿入の sort で、要素の数の二乗の時間がかかる。libpdf の reader の xref の sort、
PDF Viewer の file の chooser、glob 等が使う。

## 次の手

O(n log n) の sort（例: introsort か、安定を要らないので heapsort と挿入の組み合わせ）に替え、要素の大きさに応じた swap（word 単位）にする。
libc の既存の試験と大きな配列の試験で確かめる。

## 解決（ws073-p026、2026-09-28）

- 新しい `src/libc/sort.c`: `qsort`・`qsort_r` は introsort（median of three、65 要素以上は ninther、Hoare 型の分割、深さ 2⌊log2 n⌋ を超えたら
  heapsort、16 要素以下は挿入）。交換は `(address | size)` の許す最も広い単位（machine word、32 bit、byte）。`heapsort` は in-place の heapsort、
  `mergesort` は安定な bottom-up の merge sort（写しを確保できないと ENOMEM）。`stdlib-extra.c` の旧実装は削除、`libc.mk` の 2 つの一覧に追加。
- host 試験 `plan/ws073/tests/qsort-host.sh`: plain・ASan・UBSan PASS（要素 1〜24 byte、8 つの pattern、n = 0〜1e6、host の qsort と key の並びと
  要素の集合が一致、mergesort の安定、ずらした配列、乱数の比較関数、McIlroy の adversary で 3.8 n log2 n の比較）。
- 時間: host の n=30000 × 8 byte random 1987 ms → 4.6 ms、reverse 3947 ms → 5.2 ms（glibc 4.2・1.6 ms）、1e6 random 226 ms（glibc 187 ms）。
  guest（QEMU、`plan/ws073/tests/qsort-guest.sh`、旧 libc.so と `LD_LIBRARY_PATH` で比較）: n=20000 random 1819 ms → 11 ms、reverse 3591 ms → 6 ms、
  1e6 random 431 ms。
- amd64 の image の build（zedBSD の source の warning 0）と boot test PASS。i386・arm64 は sysroot の compile だけ。
- 残り: libpdf の raster の自前の merge sort と comment（WS079 の判断）、qsort の安定を暗に頼る呼び手の監査、実機。
