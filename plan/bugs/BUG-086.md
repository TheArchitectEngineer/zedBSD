# BUG-086: 同期の signal（SIGSEGV 等）が block されていると fault が同じ命令へ戻り続ける

Bug ID: `BUG-086`
Reproduction: reproduced（BUG-082 の fork の frame の誤りで、子が 0xa38 で約 7 億回 fault した。`fault-blocked.c` で決定的）
Disposition: resolved（ws073-p022、2026-09-28）
Date: 2026-09-28
Source: ws073-p020・p021（WS073 の agent の報告）
Owner: WS073（[ws073-p022](../ws073/phase022/phase.md)）

## 観測

`src/kern/user-probe.c` の `kernel_user_fault_handler` は、fault が起こした同期の signal が block されていると pending にするだけで同じ命令へ戻る。process は永久に fault し続ける（spin）。

## 次の手

block・ignore されている同期の fault の signal は既定の動作（終了）を強いる（Linux と同じ）。fault の試験で確かめる。

## 解決（2026-09-28、ws073-p022）

原因: `kernel_user_fault_handler()` は fault の signal を process に送るだけで、ignore なら捨て、block なら pending のまま同じ命令へ戻った。
修正: `signal_send_fault_info()`（signal.c）が fault の signal を thread に送り、SIGSEGV・SIGBUS・SIGILL・SIGFPE が ignore・block なら SIG_DFL に戻して
unblock する（Linux の force_sig_info）。検証（QEMU、amd64 full guest、KVM）: [fault-blocked.c](../ws073/tests/fault-blocked.c) が修正前 7 件 FAIL
（SIGALRM で死ぬ）、修正後 10/10、handler の 3 件は正しい siginfo。boot test PASS。実機は未実施。
