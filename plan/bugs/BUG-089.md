# BUG-089: 新しい worktree で desktop の image を build すると host の LLVM を作り直し、共有の build/llvm へ install しようとする

Bug ID: `BUG-089`
Reproduction: reproduced（2026-09-28、agent の worktree で 3 回。どれも install の前に止めた。ws073-p026 で `make -n` と実 build で再現）
Disposition: resolved（2026-09-28、[ws073-p026](../ws073/phase026/phase.md)）
Date: 2026-09-28
Source: ws079-p004・p010・libtruetype の agent の報告
Owner: WS073（ws073-p026）

## 観測

agent の worktree で `plan/ws035/tests/build-zdesktop-image.sh` を走らせると、guest の config が host の LLVM（lldb 付き）の configure と build を始め、
install の先が worktree の `build/llvm`（main の共有の `build/llvm` への symlink）になる。worktree には `build/llvm-source` と LLVM の distfile の
検証の stamp が無く、`toolchain/llvm/patches/*` の mtime が checkout で新しくなるため、make が source の取り出しと build をやり直すと見られる。
共有の `build/llvm` は今のところ書かれていない（agent が止めた。timestamps は 2026-09-27 のまま）。

## 回避（今）

agent は `build/llvm-source` と distfile の stamp を read-only の symlink にし、patch の mtime を戻すか、`<BUILD>/dynamic/<lib>.so` の target だけを build する。

## 次の手

worktree の build が既存の toolchain を再利用できる形（toolchain の stamp を内容の hash で判定する、または `ZEDBSD_TOOLCHAIN_DIR` を make の変数で渡す）にし、
共有の toolchain への install を拒む guard を足す。

## 原因（ws073-p026）

- `llvm.mk` の source の stamp が `$(ZEDBSD_LLVM_PATCH)` の mtime に依存し、order-only で `toolchain/llvm/distfiles`（tree の中、worktree に無い）の
  archive の record を要る。新しい checkout の patch は stamp より新しいので、sysroot の builtins と libcxx・clang の package の経路で、archive の
  取得（180 MB）と展開が走る（build/llvm-source が link なら「unrecognized source tree」で止まる）。
- clang の package の `| $(ZEDBSD_LLVM_NATIVE_STAMP)` が、worktree に build/llvm-build が無いと LLVM（clang;lld;lldb）の configure と tblgen の
  build を始める。configure は `CMAKE_INSTALL_PREFIX=<worktree>/build/llvm`（共有の toolchain への link）を焼き込む。この経路は install しないが、
  その build tree からの `install-distribution`（tool の repair、非 accepted の install）は共有の toolchain に書く。main の build/llvm-build の
  install prefix も main の build/llvm なので、それを link して install を走らせれば同じ。
- configuration の identity が FORCE の target のため、`make -n` は main でも毎回 configure を表示していた（偽陽性）。
- `external.mk` の `cp -al build/llvm-source copy.tmp` は link を link のまま複写し、package の patch が link の先の共有の source に当たりうる
  （main の source は無傷を確認）。

## 修正（ws073-p026）

source・configuration・host の tblgen・install を、make が読む時に identity の内容（source は patch の SHA-256 を含む）で受け入れ、受け入れた tree は
mtime を見ずにそのまま使う。build/llvm・build/llvm-source・build/llvm-build が tree の外を指すとき（`realpath -m`、tree の中の link は所有）、
その tree への書き込みは全て拒否の rule になり理由と対処を出す。上書きは `ZEDBSD_LLVM_ALLOW_FOREIGN=yes`。package の source の複写は
`cp -al <source>/. copy.tmp`。

## 検証

`plan/ws073/tests/bug089.sh`（修正前 8/9 FAIL、修正後 9/9 PASS）。新しい worktree（三つの tree を scratch の複写へ link）の `make toolchain` と
`build-zdesktop-image.sh` が rc 0、scratch と main の三つの tree の全項目（path・size・mtime・inode）が前後で同一。main の LLVM の状態での
`make -n` に LLVM の作り直しは無し。詳細は [ws073-p026](../ws073/phase026/phase.md)。

## 残り

Noct の host の source（build/NoctLang）も patch の mtime で「refusing to replace existing source tree」になり、新しい worktree の `make toolchain` が
止まる（拒否なので共有の tree は書かれない）。別の bug の候補（ID 未割当）。
