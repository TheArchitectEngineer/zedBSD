# BUG-330: framebuffer の console のスクロールが遅い（1920x1080 で 1 秒に約 4 行）

- 状態: reproduced（ユーザーの観察）/ scheduled
- 発見: 2026-10-16 ユーザー「もしかしてフレームバッファのスクロール、全部書き直してたりしません？1920x1080だと1秒に4行しか出力できず、めちゃくちゃ遅いみたいです。」
- Q1 の読み: kernel の text console（src/drivers/platform/pcat/graphics/text.c の scroll_locked）は cell の配列を 1 行ずらした後に redraw_locked で全部の cell を描き直す。HAL の early console（src/hal/amd64/bsp-pcat/cons.c の scroll_locked）も全部の cell を framebuffer_draw_cell_locked で描き直す。1920x1080・8x16 で約 16000 cell、約 8 MB を 1 行ごとに書く。framebuffer の map の memory type（UC か WC か）は未確認。
- 修正の方向: 変わった cell だけ描く、または RAM の shadow から行をずらして写す（framebuffer からは読まない）、framebuffer を write-combining で map する。
- 関連: WS039 p017（P3 が kernel の console の framebuffer の map を自分で持つ形に変える）と同じ file の別の部分。
