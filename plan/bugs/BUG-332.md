# BUG-332: app の起動の fork の直後に compositor が GPU の memory を解放すると EBUSY で device lost になる

- 状態: reproduced（RX 5600 XT の実機 1 回）/ tracking
- 発見: 2026-10-16 21:2x P3 の WS039 p019 の実機の r3（/home/awe/zedBSD-worktrees/p3/build/tmp/p5-ab2/r3/）。3 つ目の app の起動の後、compositor が `VULKAN kernel error errno=17 device lost` → `KWL VULKAN_ERROR operation=submit result=-4` で落ち、session が作り直された。kernel に space lost・reset の行は無し。
- 原因（P5 の読み）: compositor の GPU_RESOURCE_DESTROY が gpu.c の gpu_destroy_ioctl で `mapping_count != 0` の EBUSY。kwl_spawn（userland/desktop/.../home.c）が fork() を使い、子が親の GPU の mmap の region を exec まで持ち続ける（vmspace.c:4147、device の region は fork で共有）。その間に compositor が map 済みの VkDeviceMemory を解放すると EBUSY、libvulkan が device lost にする。GPU の driver に依らない共通の code の競合（i915・nvrtx でも起きうる）。
- 修正の方向（案）: fork の子に device の region を引き継がない（または exec までの間の mapping を数えない）、spawn を posix_spawn・vfork の形に、destroy の EBUSY を遅延の解放に。
