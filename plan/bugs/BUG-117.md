# BUG-117: 窓の多いとき、executor が「set 0 binding 0 に image view と sampler が無い」draw を拒み、compositor の描画が止まる

Bug ID: `BUG-117`
Reproduction: reproduced（5330 の passthrough、約 20 run 中 2 回、2026-09-30）
Disposition: resolved（ws075-p025、2026-09-30。実機の passthrough の stress で確認、素の 5330 は未確認）
Date: 2026-09-30
Source: ws075-p024 の途中報告
Owner: WS075（i915 の executor）、必要なら WS099（compositor）

## 観測

- 10 app を開く途中（Model viewer を開いた辺り、p023 の実験では X terminal の後）に compositor の描画が止まる。
- kernel log: `i915: vk: draw refused: set 0 binding 0 has no image view and sampler` → `draw 99652 failed` → command buffer が止まる → lease の解放 →
  画面が止まる。
- p024 の select の変更の前の版でも起きる（p023 の実験 (a) の 2 回目の停止も同じ行）。

## 見立て（推測、未調査）

executor（`render/state.c`）が、sample する set 0 binding 0 の view か sampler が NULL の draw を拒んでいる。compositor の descriptor の更新・
view の破棄と、記録・提出の順序の問題（使用中の descriptor の中身が先に破棄される、または更新の前の set で記録される）か、executor の
descriptor の追跡の誤り。

## 影響

デモ（fg010 の S11: 窓 10 個の操作）で画面が止まる。最優先で直す。

## 原因と修正（ws075-p025、2026-09-30）

詳細は [ws075-p025](../ws075/phase025/phase.md)。

- 原因: executor の Vulkan の object の表（`src/drivers/gpu/i915/render/object.c`、device に 1 つで全ての session が共有）を、複数の
  process の command stream が lock 無しに同時に（複数の vCPU で）変えていた。insert・配列の拡張・remove が重なると、ある session の
  descriptor set・view・sampler が表から消える。compositor の set が消えると update が捨てられ、draw が「no image view and sampler」で
  拒まれて compositor が終わる。VkDeviceMemory の list（`render/memory.c`）も同じ前提で共有されていた。
- 修正: 表と allocation の list に mutex を持たせ、全ての操作をその下で行う（commit ef0f3e94）。拒む所に、欠けたもの（set・view・sampler）を
  言う診断の log を足した。
- 確認（5330 の QEMU の VFIO passthrough）: 10 app の上で Model viewer の開閉を 100 回繰り返す stress（`plan/ws075/tests/hdmi/stress-117.sh`）で、
  修正の無い版は set の消失が 2 件（うち 1 件は `draw refused: set 0 binding 0 has no image view and sampler (no set bound)`、この bug と同じ形）、
  修正の版は 0 件。test-hw vkx・vke1・vke2・vkc PASS、measure-apps 2 回で compositor の 1 run・C6 は前と同じ。素の 5330 は未確認。
- 別の制限（この bug ではない）: 30 窓まで開くと GPU の object の 128 の枠が尽き（`gt memory: object pool exhausted (128 slots)`）、作れない物が出る。
