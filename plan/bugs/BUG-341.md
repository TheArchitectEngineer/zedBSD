# BUG-341: VF2 の自前の表示の点灯で DC8200 の model が 0 と読め、画面が点かない

- 状態: reproduced（2026-10-20 ユーザーの VF2 の実機）/ scheduled
- 発見: ユーザーの VF2 の UAT（`build/uat/vf2/native-dtb.img`、main bb116a057）。「画面はつかなかった。でも、ログインはきっと出てるね。」serial の log（手がかり、判定には使わない）: `dc8200: no-go (power domain off, loader removed its output at exit)` → `vf2-pmu: domain 4 on, state 7 -> 17` → `dc8200: own mode: unknown model 0` → `visionfive2: display not lit (13)`。power_display の clock・LCD の親・pixel の親・reset の各段は失敗の行を出していない。
- 見込み: PD_VOUT を入れ VOUT の clock と reset を放した後も、DC8200 の register が 0 と読める。U-Boot の sf_vop_remove が止めた物のうち、zedBSD が入れ直していない物（SYS の CRG の側の表示の bus の clock（noc の disp の axi・vout の src など）と reset、VOUT の top の reset、DSS の syscon の bit の順）がある見込み（未確認）。
- 同じ log の良い事: BUG-340 の fallback で `dw-mmc: no sample phase reads at 49500000 Hz` → `card clock down to 24750000 Hz` の後、init が起動し `init: system running`、`getty_console`、Ethernet が `1000 Mbps`、DHCP で `10.0.30.2/16`。
- 関係: WS277 p005、BUG-340、BUG-339。

## 修正（2026-10-20 P1 q1360-i01、実機で未確認）

- 原因の見込み: power_display が VOUT の CRG の gate（DC8200 の axi・core・ahb・pix0、LCD、HDMI）を、SYS の CRG の `SYSRST_VOUT_TOP_SRC`（43）・`NOC_BUS_DISP_AXI`（26）を放す前に開いていた。VOUT の CRG 自体が reset 43 に保たれているので、その間の gate の書き込みは効かないか、解除で既定（閉）に戻り、DC8200 の register が 0 と読める。vendor の U-Boot（sf_vop.c `vout_probe_resources_jh7110`）は disp_axi → noc_disp の解除 → vout_src・top_vout_axi・ahb → rst_vout_src の解除 → VOUT の gate → DC8200 の reset の順。あわせて vendor が開く `dc_pix1`（VOUT 8）を zedBSD は開いていなかった。DSS の syscon の bit・PD の後の待ちは vendor の probe に無く、変えていない。
- 直し（`src/kern/platform/visionfive2.c`）: power_display を SYS の gate → SYS の reset（26・43）→ VOUT の gate（`dc8200_pix1` を追加）→ LCD・pixel の親 → VOUT の reset の順にした（`start_display_gates`・`release_display_resets`）。own mode が ENODEV（model の不一致）の時、`dc8200: display power:` の 1 行に各 gate と reset の状態（`+` 開・解除、`-` 閉・保持、`?` 読めない）を出す（`describe_display_power`）。
- 確かめ: build `make ZEDBSD_CONFIG=config/ci/config-visionfive2.mk BUILD=build/bug341-vf2 -j16 vmunix` rc 0・warning 0。host 試験 `plan/ws256/tests/vf2-soc/run.sh build/bug341-soc` → 0 failure、`plan/ws277/tests/p005/run.sh build/bug341-p005` → mode 100・own 23・own 20 PASS。QEMU・実機: 未実施。実機で `own mode: unknown model` が出なくなり画面が点くことを確かめるまで resolved にしない。出た場合は `display power:` の行が次の手がかり。
