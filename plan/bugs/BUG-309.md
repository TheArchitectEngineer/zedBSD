# BUG-309: PC-9821 Ra43 の BIOS が zedBSD の pc98 の disk を起動の disk と認識しない（0x55AA の印の疑い）

- 状態: reproduced（実機、ユーザーの UAT）/ scheduled（2026-10-14 Q1、P1）。修正を入れた（partition を cylinder の境に、`07727be4d`）。QEMU（T1）と実機（V13・Ra43）の確かめ待ち
- 発見: ユーザーの UAT（2026-10-14）「PC-9821 V13では起動OKでした。PC-9821 Ra43では、起動ディスクとしてBIOSから認識されませんでした。55 aaのマーカーがあるとRa43では認識されないと記憶してます。直せますか？」
- 手がかり（Q1、source の grep だけ）: `tools/build/zedimage-host.c` は MBR の sector の 510・511 に 0x55・0xAA を書く所が 2 か所（389 行・644 行付近）と、stage1 にその印を求める検査（330 行）がある。pc98 の image でどの経路を通り、sector 0 に 0x55AA が残るかは未確認。PC-98 の IPL は sector 0 にあり、PC/AT の MBR の印は要らない。
- 次（当初、2026-10-14 Q1）: P1 が pc98 の image の sector 0 の作り方を調べ、pc98 では 0x55AA を書かない形に直す。→ 調査で 0x55AA は原因でないと分かり、partition を cylinder の境に合わせる修正に変えた（下の「調査」）。
- 関連: WS232（pc98 の build と QEMU の起動）、platform/pc98。

## 調査（2026-10-14 P1、host で image を読んだだけ。実機・QEMU は未実施）

### 0x55AA を書いている所

- sector 0 の IPL は `bootloader/pc98/disk-ipl.S` の 512 byte で、末尾 `.org 0x01fc` に `09 00 55 aa`（boot menu の版の byte と 0xAA55）を自分で置く。
  `platform/pc98/vmunix.mk` の stage1.bin の規則が末尾の `55aa` を検査し、`tools/build/zedimage-host.c` の `disk_create` は全機種で stage1 の
  510・511 に 0x55AA を求め、pc98 では sector 0 を素のまま書く（0x1BE の PC/AT の partition table は pc98 では書かない）。
  `zedimage-host.c` の 389 行・644 行付近の `mbr[510]=0x55` は PC/AT・UEFI の経路で、pc98 は通らない。`check-bios-hdd-image.noct` は image の 0x55AA を求める。
- 比べた image の sector 0 の末尾:
  - zedBSD（修正前・後とも）: `... 09 00 55 aa`、先頭 `eb 0a 90 90 "IPL1" 00 00 00 1e`。
  - Ra43 で起動する Linux の PC-98 の image（ユーザーが示した linux-pc98 v0.13.0 の `linux-pc98-i386sx-busybox-ide.img`、Q1 が先頭 4 KiB を抜いた）: 同じ `09 00 55 aa`、先頭も同じ形。
  - FreeBSD 8.4 の pc98 の `/boot/boot0`（`~/FreeBSD/FreeBSD-8.4-RELEASE-pc98-disc1.iso` から読んだ。fdisk が sector 0 に入れる IPL）: `eb 09 00 00 "IPL1" ...` 末尾 `01 00 55 aa`。
- 結論: Ra43 で起動する Linux の image にも 0x55AA があるので、0x55AA は原因でない。**0x55AA は消さない**（disk-ipl.S・vmunix.mk・zedimage-host.c の stage1 の検査はそのまま）。

### V13 で起動して Ra43 で起動しない差の候補（可能性の高い順）

| # | 候補 | zedBSD（修正前） | Linux の image（Ra43 で起動） | 扱い |
| --- | --- | --- | --- | --- |
| 1 | partition が cylinder の境から始まり、cylinder の境で終わるか（8 head・17 sector の geometry） | BOOT の IPL と開始が C15/H0/S8（LBA 2048、cylinder の途中）、終わりが C2665/H3/S4（image の最後の sector、cylinder の途中）。image の大きさ 362496 sector も cylinder の倍数でない | BOOT が C1/H0/S0 から C1928/H7/S16。LINUXROOT・LINUXSWAP も cylinder の境 | **入れた**（下の「修正」） |
| 2 | 最初の partition が cylinder 1 から始まるか（NEC の FDISK の慣習） | 修正後は C16（LBA 2176） | C1（LBA 136） | 残る。1 で直らない時の次の候補。stage2（LBA 2..15）は cylinder 0 に収まるので、C1 に寄せることはできる |
| 3 | Ra43 の IDE の BIOS がその媒体に与える geometry が 8 head・17 sector と違う | IPL・LBA2 の selector は int 1Bh の CHS の mode で partition table の CHS をそのまま読む | 同じ方式の IPL で起動する | 残る（低）。BIOS が起動の disk と認めない症状とは合いにくい。媒体の大きさ・種類（CF の adapter など）は未確認 |
| 4 | partition の mid・sid（bootable の bit 0x80、active の bit 0x80、system の種類） | BOOT が `a1 91` | BOOT が `a1 91`（LINUXROOT・LINUXSWAP は `21 83`・`21 82`） | 除外（同じ） |
| 5 | sector 0 の先頭の jump と "IPL1"、0x1FC の `09 00`、0x55AA | `eb 0a 90 90 IPL1 00 00 00 1e` … `09 00 55 aa` | 同じ | 除外（同じ） |
| 6 | partition table の entry の数 | 1 つ（BOOT） | 3 つ | 残る（低） |

推測の部分: Ra43 の BIOS が partition table（sector 1）を読んで cylinder の境を確かめる、という仕組みは資料で確かめていない。根拠は「Ra43 で起動する Linux の image との差が 1 だけ」ということだけ。

### 修正（P1、commit `07727be4d`）

- `tools/build/zedimage-host.c`: pc98 の image で `pc98_cylinder_layout` を通す。BOOT の partition は 2048 以上で cylinder の境かつ 4 KiB の整列の最初の LBA（8 head では C16 = LBA 2176、4 head でも 2176）から始まり、要求の FAT の大きさ以上の whole cylinder で終わる（FAT は partition を埋める）。native UFS root の partition も whole cylinder にし、image の大きさを cylinder の倍数に切り上げる。FAT の BPB の hidden sectors（`mformat -H`）を 2048 から partition の開始に直す。PC/AT・UEFI の経路は変えない。
- `tools/build/check-bios-hdd-image.noct`（build が使う checker）: pc98 では partition table の生きた entry がすべて H0/S0 から始まり最後の head・S16 で終わること、IPL と開始の cylinder が同じこと、image が cylinder の倍数であることを検査し、FAT の位置を 1 MiB の固定でなく table から求める。native UFS root は partition が UFS より最大 1 cylinder 大きいことを許す。
- loader（disk-ipl.S・lba2.S・partition-pbr.S・BOOTZBSD.EXE）は変えていない。LBA2 の selector は table の IPL の CHS を、PBR は BPB の hidden sectors を、BOOTZBSD.EXE の native の経路は table の開始の CHS を読むので、開始の移動に追従する。
- `tools/build/check-bios-hdd-image.py` と `make-bios-hdd-image.py` は直していない。どこからも呼ばれず（build は `.noct` を使う）、pc98 では修正前から PC/AT の active partition を求めて通らない。削除の候補として Q1 に送った。

### host の確認（P1、2026-10-14）

- `make ZEDBSD_CONFIG=config/ci/config-pc98.mk disk-image`: exit 0、`zedimage-host.c` は `-Wall -Wextra -Werror` で build。
- 新しい `build/pc98/hdd-image.img`: 185708544 byte = 362712 sector = 2667 cylinder。sector 0 は `09 00 55 aa` のまま。sector 1 の BOOT は `a1 91 00 00 | 00 00 10 00 | 00 00 10 00 | 10 07 6a 0a`（C16/H0/S0 から C2666/H7/S16）。LBA 2176 の BPB の hidden sectors は 0x880 = 2176、総 sector は 180268（1024 byte）= 360536 sector = partition の全体。
