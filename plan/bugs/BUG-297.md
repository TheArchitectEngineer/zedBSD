# BUG-297: AAT apps.phone.message の step 7「Again with no backend」で PHONE RESULT・PHONE STATUS failed=1 が出ない

- 状態: reproduced（QEMU、T1-567 で 2 回） / scheduled（直しは agent/p3、T1 の再実行の待ち）
- 発見: T1-567（QEMU x86_64 Venus、標準の AAT image）。step 1〜6 は通り、step 7 だけ 10 秒待っても `PHONE RESULT request=N error=[1-9]…` と `PHONE STATUS request=N state=0 failed=1` が出ない。
- 影響: AAT `apps.phone.message` が FAIL になる。Phone の動作の不具合ではない（下の原因）。
- 担当: P3（Q1 の依頼、2026-10-13）。
- 証拠（T1 の worktree、読むだけ）: `/home/awe/zedBSD-worktrees/t1/build/review/t1-567/out3/`（`logs/apps.phone.message.log`、`png/apps.phone.message-no-backend.png`）。

## 観測

- log は `KWL PHONE backend=0` → `PHONE LINK backend=0 messages=0 send=0 notify=0 owner=0 why=no-record` → `PHONE REQUEST action=send contact=0 length=5` で止まり、`PHONE SEND`・`KWL PHONE send` の行も無い（compositor へは何も行っていない）。
- PNG では「Again」が入力欄に残り、timeline に送信中・失敗の message が無い。notice は写っていない（notice は 4 秒、撮影は 2 つの 10 秒待ちの後）。

## 原因（source の読み、確度 高）

- 試験の期待が古い。BUG-287 の直し `cc6078aa0`（2026-10-10）で、Phone は backend が無い（`phone.backend` 0、compositor の link を知っていて `backend == PH_BACKEND_NONE`）時に、**compositor へ送らず・保存せず**、notice「No phone is set up: …」を出し、書いた文を欄に残すようにした（`userland/desktop/phone/main.c` の `ph_send` の先頭の判定、直した後の 1621〜1626 行）。BUG-287 の ticket の「直し 3」がこの意図した動作。
- 試験（`plan/tools/aat/scenarios/helpers_phone.py` の step 7、`tests/scenarios/apps/phone/message.md` の 3）は、それ以前（ws170）の「compositor が ENODEV で断り、`PHONE RESULT error=`・`PHONE STATUS state=0 failed=1`、message は Not delivered」を期待したままだった。
- 加えて、この断りは log に何も書かず、試験が log で確かめる手段が無かった。
- いつから: `cc6078aa0`（2026-10-10 09:58）から。その少し前の `778c1e377`（ws197-p004、2026-10-10 03:18）が `PHONE SEND` の行に `paired=` を足したため、step 1 の pattern が合わずに試験は step 7 の手前で必ず止まっていた（pattern は後に直された）。step 7 が新しい動作で走ったのは T1-567 が初めて。

## 直し（2026-10-13 P3、agent/p3）

- `userland/desktop/phone/main.c` の `ph_send`: compositor へ送る前の 3 つの断り（backend 無し・paired の phone が未接続・paired の phone が送信を受けない）に、長さだけの log の行 `PHONE REFUSED action=send contact=N length=N why=no-backend|not-linked|no-send` を足した（番号と本文は出さない）。動作は変えない。
- `plan/tools/aat/scenarios/helpers_phone.py` の step 7: `PHONE REFUSED action=send contact=0 length=5 why=no-backend` を待ってすぐ撮影（notice の 4 秒の中）、mark 以後に `PHONE SEND `・`KWL PHONE send ` の行が無い、`~/Documents/Phone/messages/aat-ben/*.txt` に「Again」が無い、を確かめる。人の目の確認は「欄に Again が残り、notice No phone is set up」。
- `tests/scenarios/apps/phone/message.md` の 3: 正解を同じ内容に直した。

### 確かめた事（build と静的な確認だけ。QEMU は T1 への依頼）

- build: amd64（`make -j16 ZEDBSD_CONFIG=config/current-uat.mk BUILD=build/amd64 build/amd64/bin/phone`）・rpi4（`make -j16 ZEDBSD_CONFIG=config/ci/config-rpi4.mk BUILD=build/arm64 build/arm64/bin/phone`）とも exit 0・warning 0。
- `plan/tools/style-check.py userland/desktop/phone/main.c`: 2 件で、直す前と同じ（838・841 行、今回の変更の外）。`git diff --check` 問題なし。helpers_phone.py は構文の確認（`ast.parse`）だけ。
- Phone の host 試験（`plan/ws170/tests/run-host-phone.sh`）は view.c だけを試し、`ph_send`（main.c）を含まないので流していない。
- QEMU での AAT の再実行: **未実施**（T1 に依頼）。
