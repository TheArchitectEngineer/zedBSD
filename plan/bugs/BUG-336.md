# BUG-336: amd64 の HAL の IRQ の 3 つの競合・状態の不具合（set_wake と suspend、失敗した削除の mask、同じ IRQ の同時実行）

- 状態: unreproduced（source の読みで確認）/ scheduled
- 発見: ユーザーが外部のレビューの指摘を持ち込み（2026-10-19 15:04）、Q1 が src/hal/amd64/irq.c を読んで確かめた。
- 中身:
  - A: `hal_irq_set_wake()` は `irq_suspension` を IRQ の lock の外で見てから lock を取る。その間に別の CPU の `hal_irq_suspend()` がこの IRQ を処理し終えると、wake の変更が効かない（立てても masked のまま、外しても届き続ける）。直し: 判定を IRQ の lock の中へ（suspend は flag を立ててから各 IRQ の lock を取るので順が保たれる）。
  - B: `irq_set_handler()` の削除は `masked=1` と hardware の mask の後に task mode を見て HAL_ERR_BUSY で戻り、mask を戻さない。MSI の解放（940・1076 行付近）から通りうる。直し: task mode の判定を状態を変える前に。
  - C: `in_handler`・`in_flight` が 1 つの値で、同じ IRQ が同時に入ると先に終わった方が flag を消し、削除の drain が走っている handler を待たない。interrupt gate の IF=0 と、affinity の変更が in_handler・in_flight の間は BUSY なので、まず起きない見込み（推測の隙は残る）。守り: dispatch の前に in_handler を見て、立っていれば mask して EOI で落とす。
- 決定（2026-10-19 15:04 ユーザー、クリック）: 「A・B を直し C も守る」。
- 担当: P1（q1280）。試験: build warning 0、短い host 試験、T1 で amd64 の起動と suspend の回帰。
