# BUG-336: amd64 の HAL の IRQ の 3 つの競合・状態の不具合（set_wake と suspend、失敗した削除の mask、同じ IRQ の同時実行）

- 状態: unreproduced（source の読みで確認）/ scheduled（修正済み・T1 の試験待ち）
- 発見: ユーザーが外部のレビューの指摘を持ち込み（2026-10-19 15:04）、Q1 が src/hal/amd64/irq.c を読んで確かめた。
- 中身:
  - A: `hal_irq_set_wake()` は `irq_suspension` を IRQ の lock の外で見てから lock を取る。その間に別の CPU の `hal_irq_suspend()` がこの IRQ を処理し終えると、wake の変更が効かない（立てても masked のまま、外しても届き続ける）。直し: 判定を IRQ の lock の中へ（suspend は flag を立ててから各 IRQ の lock を取るので順が保たれる）。
  - B: `irq_set_handler()` の削除は `masked=1` と hardware の mask の後に task mode を見て HAL_ERR_BUSY で戻り、mask を戻さない。MSI の解放（940・1076 行付近）から通りうる。直し: task mode の判定を状態を変える前に。
  - C: `in_handler`・`in_flight` が 1 つの値で、同じ IRQ が同時に入ると先に終わった方が flag を消し、削除の drain が走っている handler を待たない。interrupt gate の IF=0 と、affinity の変更が in_handler・in_flight の間は BUSY なので、まず起きない見込み（推測の隙は残る）。守り: dispatch の前に in_handler を見て、立っていれば mask して EOI で落とす。
- 決定（2026-10-19 15:04 ユーザー、クリック）: 「A・B を直し C も守る」。
- 担当: P1（q1280）。試験: build warning 0、短い host 試験、T1 で amd64 の起動と suspend の回帰。

## 修正（2026-10-19 P1、q1280-i01）

- A（`src/hal/amd64/irq.c` の `hal_irq_set_wake()`）: `irq_suspension` の判定を IRQ の service lock の中へ移した。suspend は flag を立ててから各 IRQ の lock を取るので、lock の中で 0 を見れば suspend はこの IRQ をまだ処理しておらず、新しい wake の値を見る。
- B（`irq_set_handler()` の削除）: task mode の判定を `removing`・`masked`・`hardware_mask()` より前に移し、HAL_ERR_BUSY の時に状態を変えない。呼び手の `hal_irq_msi_free` 系（2 か所）は自分で立てた `removing` を失敗の時に 0 へ戻すだけで、これは従来どおり正しい（irq_set_handler 側の `removing = 0` は不要になり削った）。
- C（`irq_handler()`）: service lock を取った直後に `in_flight`・`in_handler` を見て、どちらかが立っていれば（同じ IRQ の別の配送が所有中）flag に触れずに EOI だけして落とす。mask はしない: kernel の `masked` を立てずに line を閉じると開ける者がいなくなるため。in_flight は realtime の handler の間も 1 のままなので、realtime・task・未所有のどの道でも同じ守りになる。
- 他の arch: 同じ形を探した。
  - i386（`src/hal/i386/irq.c`）: 削除の道で `i386_interrupt_mask()` が task mode の判定より前にあり、BUSY でも mask が残った（B と同じ形）。判定の後へ移した。set_wake・suspend は無い（`idle-suspend-unsupported.c`）。in_handler は CPU ごとの配列なので C の形は無い。
  - m68k virt（`src/hal/m68k/bsp-virt/irq.c`）: `hal_irq_unregister()` が handler の一致を確かめる前に mask し、INVALID でも source が mask のまま残った（B と同じ形）。一致の確認の後へ移した。
  - arm64・riscv32/64・ppc32/64・m68k x68k・sparcv9: task mode・suspension・単一値の in_flight を持たず、同じ形は無い（読みのみ。sparcv9 はユーザーの担当なので触れない）。
- build（`make ZEDBSD_CONFIG=config/ci/config-<c>.mk BUILD=build/bug336-<c> vmunix`、-Werror）: amd64・pcat（i386）・m68k-virt とも rc=0、warning 0。host 試験は該当する物が無く未実施。QEMU は未実施（T1 へ）。
