# BUG-326: 起動の後に DHCP の lease が取れても dhcpc が失敗する（/etc/resolv.conf.tmp.<pid> が前の起動から残る）

- 状態: reproduced（5330 の実機で 3 回）/ resolved（Q1 の修正、実機での確認は未実施）
- 発見: 2026-10-16 P1（i915 の表示の書き直し p016 の 5330 の回帰）。05:03・05:24・06:08 UTC の 3 回とも `dhcpc: lease obtained, but /etc/resolv.conf could not be written: File exists`。zedBSD の /etc に前の起動の `/etc/resolv.conf.tmp.38` が残っていた。
- 原因: userland/base/dhcpc/main.c が `/etc/resolv.conf.tmp.<pid>` を O_EXCL で作る。起動ごとに dhcpc の pid は同じ（38）になりやすく、前の起動が電源断などで残した temp に当たると失敗する。基準の kernel で通り p016 で通らなかったのは pid の巡り合わせで、kernel に依らない。それまでの 5330 の「DHCP 不良」（169.254 の割り当ての件を含む）もこれの可能性がある。
- 修正: O_EXCL で作る前に、同じ名前の古い temp を unlink する（同じ pid の生きた process は自分だけ）。warning 0 の compile を確認。
- 未実施: 実機での確認（次の 5330 の image に入れる）。
