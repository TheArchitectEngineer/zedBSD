# BUG-078: libc の libm（src/libc/math.c）の精度と正しさ（pow・fmod・exp・log・sin ほか）

Bug ID: `BUG-078`
Reproduction: reproduced（QEMU の guest、ws074-p025 の試験、決定的）
Disposition: resolved（2026-09-28、WS076）
Date: 2026-09-28
Source: ws074-p025（ブラウザの JS の `14 ** 2`）
Owner: WS076

## 期待と観測

期待: `pow(14, 2)` が 196（整数の冪は正確、一般に正しく丸めた結果に近い）。
観測: guest で `14 ** 2` が 195.99999999999994（host と Chromium は 196）。`src/libc/math.c` の pow が `exp(y * log(x))`。

## 影響

pow を使う全てのプログラム（ブラウザの JS の `**`・`Math.pow`、数値の書式ほか）の精度。ブラウザの `plan/ws074/tests/js/operators.js` の guest の結果 1 行が host と違う。

## 次の手

整数の冪の正確な経路（二乗の繰り返し）と、一般の場合の正しい pow（誤差 1 ulp 以内の実装、ライセンスを確認して）を libc に。

## 範囲の拡大（2026-09-28、ws074 の agent の計測）

guest と host の glibc・Chromium の比較:

- `fmod` が `x - trunc(x/y)*y`（math.c:372）で大きな x で誤り: JS の `1e17 % 7` が 0（正しくは 5）、`2**60 % 7` が 0（正しくは 1）。**値の誤り**。
- `exp`・`log`・`sin` が最後の桁で違う: `Math.exp(1)` 2.7182818284590446（2.718281828459045）、`Math.log(10)` 2.3025850929940455（2.302585092994046）、
  `Math.sin(1)` 0.841470984807901（0.8414709848078965）。他の関数も同じ作りの見込み。
- `remainder`・`remquo`・`fma`（融合しない）・`erf`（約 1.5e-7 の近似）も素朴（未計測）。

ブラウザは libm を回避しない（`%` と Math.* は libc を呼ぶ）。数値の文字列化は engine の自前の正確な実装（vm/number.c）で libm に依らない。
直し方は 2026-09-28 にユーザーが決定:「libmは独自に書いてください。libcのツリーに入れてください。」→ [WS076](../ws076/ws.md)。

## 解決（2026-09-28、WS076）

libm を `src/libc/math/` に自前で書き直した（[WS076](../ws076/ws.md)）。fmod・remainder・remquo は整数の長い除算で正確、pow・exp・log・
sin ほかは double-double で求めて 1 回丸める（MPFR との照合で全件 0.5 ulp 以下）。証拠:

- host: `plan/tools/libm/host-test.sh`（MPFR）で `pow(14, 2)` = 196、`fmod(1e17, 7)` = 5 を含む全表が PASS。
- guest（QEMU、amd64）: `plan/tools/libm/guest-test.sh` PASS。`plan/tools/libm/browser-js.sh` で ws074 の operators.js が
  `GUEST_KNOWN` の除外なしで Chromium と一致（`compound 196 22 2`）、`js/libm.js` の `1e17 % 7` = 5、`2 ** 60 % 7` = 1、
  `Math.exp(1)` = 2.718281828459045、`Math.log(10)` = 2.302585092994046、`Math.sin(1)` = 0.8414709848078965 が一致。
- `plan/ws074/tests/run-js-tests.py` の `GUEST_KNOWN` の BUG-078 の行は不要になった（WS074 の file、削除は main か WS074）。
