# BUG-028: 誰も listen していない loopback ポートへの connect が返らない

Bug ID: `BUG-028`
Reproduction: reproduced
Disposition: resolved（2026-09-27、ws073-p005）
Date: 2026-09-22
Source: WS032 p009（ターゲット上の lldb）で、終了した lldb-server のポートへ `gdb-remote 127.0.0.1:1234` した lldb が戻らなかったことから観測。
Owner: none（未割当）
Queue: none。

## 期待と観測・影響

`127.0.0.1:1234` で listen するプロセスがいない状態で TCP `connect()` すると、`ECONNREFUSED` で即座に失敗するべきところ、呼び出しが返らない（90 秒以上待っても戻らない）。lldb では `(lldb) gdb-remote 127.0.0.1:1234` の後、ログに "Connecting to connect://127.0.0.1:1234" が出たまま止まる。

loopback の SYN に対して RST が返っていないか、RST を受けても connect を起こしていないと考えられる。

## 次の条件

`src/kern/net` の TCP で、listen ソケットのないポートへの SYN に RST を返すこと、および RST 受信で SYN_SENT の connect を `ECONNREFUSED` で起こすことを確認する。小さな C プログラム（閉じたポートへ `connect()` し、戻り値と errno を出力）で再現できる。
[bug-board](../known-bugs.md)に索引を保持。

## 解決（2026-09-27、ws073-p005）

- 再現: 修正前の kernel で `127.0.0.1` の閉じた port への connect は待たずに返るが errno が ECONNRESET。自分の ue0 の address（`10.0.2.15`）への
  connect は返らない（listener があっても届かない）。
- 原因: SYN_SENT の RST を ECONNRESET にしていた。自分の interface の address 宛ての packet を wire へ ARP して送ろうとしていた。
- 修正: SYN_SENT の RST（SYN を確認する ACK 付き）を ECONNREFUSED に。自分の address 宛ては lo0 を回して届ける。ICMP の echo の reply は宛先の
  address から。
- 試験: `plan/ws073/tests/connect-refused.c 127.0.0.1 10.0.2.15` 10 件 PASS（修正前 8 件 FAIL）。[ws073-p005](../ws073/phase005/phase.md)。
