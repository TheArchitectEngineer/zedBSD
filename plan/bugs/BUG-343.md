# BUG-343: VisionFive 2 の SD からの起動で、root の file system が 60 秒たっても live にならない事がある

- 状態: reproduced（2026-10-20、電源の入れ直し十数回のうち 3 回ほど）/ tracking
- 発見: WS269 の UAT の電源の入れ直し（SwitchBot）で、3 分たっても SSH に戻らない起動があった。ユーザーのシリアルの log: `powervr: firmware: still in file after 5 s` … `still in file after 55 s` → `powervr: firmware: file failed (42) after 60003 ms`（firmware の file の読みは root が live になるのを 60 秒待つ。`firmware-file.c` の wait_root）。
- 観測: 正常な起動でも `dw-mmc: read of 32 blocks at 153392 failed (5, status a4), try 1`・`dw-mmc: no sample phase reads at 49500000 Hz`・`dw-mmc: data errors at high speed, card clock down to 24750000 Hz` が出る（WS256 p005・p013 の高速の読みの退避）。読みの失敗が root の mount の前に重なると mount が終わらないか、retry が足りない見込み（推測）。
- 環境: VF2 v1.3B、SDXC SA128（manufacturer 02）、image build/uat/vf2-gpu/native.img（main 1512e79cd）、kernel d851a8783。
- 関係: WS256 p013（SD の clock）・p005。GPU とは無関係。
- 再調査の条件: 起動の失敗の時のシリアルの log（ユーザーの手元）で、`vfs:` の行がどこで止まるかを見る。

## 2026-10-21 06:20 の追加の観測（Q1、同じ部品の疑い、同一とは断定しない）

- 起動の後に長く動いた板（kernel main 06f1ba788、電源の入れ直しから数十分〜、その間に gpu-selftest・vkmatrix・vkcoherency を 13 回、各回 SSH で）で、root（`/dev/mmcblk0p4` の ufs）からの program の実行が全部 `Input/output error` になった（`ls`・`cat`・`cp`。shell の組み込みと既に動いている program は動く）。dmesg は GPU の行で ring が溢れ、dw-mmc の行は残っていない。その起動の早い所には `dw-mmc: read of 16 blocks at 188672 failed (5, status 84), try 1`・`read of 64 blocks at 211632 failed (5, status a4), try 1` があった。
- 電源の入れ直しで戻った（SD は読める）。GPU の試験は影響を受けていない（その直前まで 13/13）。
- 影響: 板の kernel の入れ替え（`plan/tools/vf2/run.sh`）が cp の段で止まる。`run.sh` は失敗で止まり電源を入れ直さないので、boot の kernel は壊れなかった。
- 次: WS256 の SD の driver で、retry の後の失敗が block の層に EIO を返し続ける状態（card の state・clock の下げの後の戻り）を見る。
- 2026-10-21 板 100 の電源の入れ直し（P2 の診断の kernel）で 3 分たっても SSH に戻らず、2 回目の入れ直しで戻った（`plan/tools/vf2/run.sh` の「no ssh after 3 min, cycling again」）。シリアルの log は無いので原因は未確認（同じ症状の 4 回目の見込み）。
- 2026-10-21 08:5x: desktop の試験の間に SD の I/O の失敗が重くなった。d18 で root が書き込みを止め（`ufs: mmcblk0p4: the volume refuses writes … error 5`）、同じ address の segfault が複数。d19 の後に `tail: Input/output error`（kernel の入れ替えの cp が止まる）。d20 の 1 起動で `dw-mmc: read of … failed` が 86 回。SD の card の劣化か driver か未確認。板の試験の結果を読む前に確かめる。
