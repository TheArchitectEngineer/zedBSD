# BUG-103: /bin/sh で上下の矢印キーの履歴の呼び出しが効かない

Bug ID: `BUG-103`
Reproduction: reproduced（ユーザー、素の 5330 の Terminal、2026-09-29）
Disposition: scheduled（WS087）
Date: 2026-09-29
Source: ユーザー「/bin/shが上下キーでヒストリーをたどれないようです。たどれるようにしたいです。」
Owner: WS087

## 観測

対話の `/bin/sh` で上下の矢印キーを押しても前の命令が出ない。

## 分かっていること

`userland/base/sh/history.c` の冒頭の説明には「line editor が矢印キーで行を呼び出すための履歴を持つ」とある。line editor が有効になる条件
（vi mode だけ、端末の種類、Terminal が送る escape の形）のどこで外れているかは未調査。WS087 p001 で調べる。

## 調査（ws087-p001、2026-09-29、QEMU amd64）

詳細は [ws087-p001](../ws087/phase001/phase.md)。

- line editor（`userland/base/libedit`）は `isatty(0) && isatty(2)` の対話の shell で常に有効（emacs mode、`set -o vi` で vi mode）。
  Terminal（`/bin/terminal`）は上下左右に `ESC [ A/B/D/C` を送り（QEMU の Terminal で `dd` に受けて確かめた）、editor はそれを解する。
- **同じ shell の中の上下の矢印の呼び出しは、QEMU の Terminal（QMP の key、画面は worktree の `build/ws087/shot2.png`）・ssh -tt の pty・serial console で動く。**
- **新しい shell は履歴が空から始まる。** sh は履歴を file に保存しない（`HISTFILE`・`~/.sh_history` が無い）。新しい Terminal の窓・tab・ssh の
  session で上を押すと何も出ない（ssh -tt で再現）。これを有力な原因とし、WS087 p002 で `HISTFILE`（既定 `$HOME/.sh_history`）の読み込みと追記を足す。
- 未確定: 5330 の実機で「同じ窓で命令を打った直後でも上が効かなかった」のか（そうなら実機の key の経路の別の不具合）。実機の確認は未実施。ユーザーへの質問を main に依頼した。
