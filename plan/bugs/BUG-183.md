# BUG-183: WiFi をオンにする操作で、switch が青くなるまで約 1 秒かかる（オフは一瞬）

Reproduction: reproduced（実機）
Disposition: tracking（優先度: 標準）
Discovery: 2026-10-04 夜 ad-hoc UAT-3（実機 Latitude 5330、image `build/uat-3/hdd-image.img` sha256 ada4492e…、main efe846a、[uat.md の uat-3](../uat.md)）
Handling: WS089（Settings の Wi-Fi）・WS131（system bar の network、libkeiland の kl_system_*）・networkd

## 観測

ユーザー「Settingsでも画面右上でも、WiFiをオフにする動作の反応は一瞬なので許容範囲だが、再度オンにする動作はボタンが青くなるのに1秒かかっている。」

## 次

オンの時は UI が networkd の結果（radio の起動・AX211 の open）を待ってから switch を描いている疑い。押した時点で「オンにしている途中」の見た目を即座に出し、失敗したら戻す（楽観的な更新）か、待ちの表示を出す。Settings と system bar の両方。 修正は P3（Bug の修正の担当）の Queue（q700）で。QEMU の確認は T1（AX211 が無い QEMU では networkd の模擬か RTL8822BU の USB passthrough）、実機は次の UAT。

## 保留（2026-10-05 未明、q703-i01 P2 generation14。ユーザーの方針「既存BUGはいったん保留して、新規実装を進める」）

- 未着手（差分なし）。読んだこと: switch は Settings（`page-network.c` の `se_toggle_draw(..., on, ...)`）も system bar（`network.c` の `network_draw_switch`）も networkd の報告した状態（`state.wifi`）だけで描く。on は networkd の WIFI_ENABLE が radio の準備（`wifi_request_prepare`）の後に答え、その後に状態が通知されるので約 1 秒かかる。
- 再開点（設計）: 押した時点で求めた値（on/off）を switch に描き、状態がそれに一致するか、要求が失敗で答えられる（元に戻して理由を出す）まで保つ（答えが成功で状態が来ない時は数秒で状態に戻す）。Settings と system bar の両方。
