# BUG-110: shared library の TLS の参照（`__tls_get_addr`）が毎回 syscall で遅い

Bug ID: `BUG-110`
Reproduction: reproduced（QEMU、ws073-p037 の計測）
Disposition: resolved（2026-09-29、[ws073-p038](../ws073/phase038/phase.md)、WS035 のエージェント）
Date: 2026-09-29
Source: ws073-p037（BUG-109）のサブエージェントの報告
Owner: WS073（実施は WS035 のエージェント）

## 観測

`feraiseexcept` → `__libc_fenv_location`（`_Thread_local`、global-dynamic の TLS）→ `src/rtld/rtld.c` の `__tls_get_addr` が、呼ぶたびに
`thread_self`（`KERN_THREAD_SELF_GET_TLS`）の syscall で thread pointer を取る。1 回約 205 ns。不正確な結果を返す libm の関数（sin・exp 等の
ほぼ全て）が毎回払い、`errno` など他の shared library の global-dynamic の TLS も同じ経路なら影響はもっと広い。

## 直し方（案）

amd64 は `%fs:0`（TLS の variant II の self pointer）、arm64 は `TPIDR_EL0` を読めば syscall は要らない。rtld・libc の pthread・kernel の
thread の TLS の約束（FS base の設定、self pointer の置き場）を確かめてから直す。HAL の API は変えない。

## 解決（2026-09-29、[ws073-p038](../ws073/phase038/phase.md)）

- `src/rtld/rtld.c` の `thread_pointer()`: amd64 は `%fs:0`（control block の先頭の `self`）、arm64 は `TPIDR_EL0`。`__tls_get_addr`・TLSDESC の resolver・
  `__rtld_pthread_private` で使う。static の libc（`static-tls.c`）の `__rtld_pthread_private` も、main thread の attach の後は同じ。i386 等は syscall のまま。
- 約束の確認（FS base・`TPIDR_EL0` は SET_TLS・switch・signal で保たれ、全ての block の先頭が自分の address）は p038 の表。
- 証拠（QEMU amd64）: errno 1 回 199〜204 → 7.5 ns、`feraiseexcept` 201.5〜215 → 7.5 ns、static 237 → 5.0 ns。複数 thread と signal の中の TLS の試験
  （dynamic・static）PASS、dyntest PASS、libm の試験 PASS、`sqrtf` 220.5 → 16.5 ns、desktop の login・Log Out PASS、boot test PASS。arm64 は build だけ。
