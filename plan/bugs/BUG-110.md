# BUG-110: shared library の TLS の参照（`__tls_get_addr`）が毎回 syscall で遅い

Bug ID: `BUG-110`
Reproduction: reproduced（QEMU、ws073-p037 の計測）
Disposition: scheduled（WS035 のエージェント）
Date: 2026-09-29
Source: ws073-p037（BUG-109）のサブエージェントの報告
Owner: WS073（実施は WS035 のエージェント）

## 観測

`feraiseexcept` → `__libc_fenv_location`（`_Thread_local`、global-dynamic の TLS）→ `src/rtld/rtld.c` の `__tls_get_addr` が、呼ぶたびに
`thread_self`（`KERN_THREAD_SELF_GET_TLS`）の syscall で thread pointer を取る。1 回約 205 ns。不正確な結果を返す libm の関数（sin・exp 等の
ほぼ全て）が毎回払い、`errno` など他の shared library の global-dynamic の TLS も同じ経路なら影響はもっと広い。

## 直し方（案）

amd64 は `%fs:0`（TLS の variant II の self pointer）、arm64 は `TPIDR_EL0` を読めば syscall は要らない。rtld・libc の pthread・kernel の
thread の TLS の約束（FS base の設定、self pointer の置き場）を確かめてから直す。HAL の API は変えない。
