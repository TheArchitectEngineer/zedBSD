# BUG-358: 4096 byte の logical sector の disk で native UFS への書き込みが極端に遅い（小さな file の多い導入で 30〜40 KB/s）

- 状態: open（2026-10-29 Q1 が登録。ユーザー「4096バイトセクタで遅いことはバグとして記録して、先に進んでほしい」）
- 発見: 2026-10-29 P4（q1665-i10、WS307 p011 の 4 回目 `p011.hfdv7fqg`、QEMU の 4096 の NVMe）。
- 観測: installer の全体の導入（既定の項目 165 MiB、小さな file の多い unit）が 22 分で約 50 MB（目算 30〜40 KB/s）。同じ導入は 512 の NVMe で約 9 分。
  WS307 p006 の測り（16 MiB の dd が 512 で 23 秒、4096 で 63 秒、約 2.7 倍）より差がずっと大きい。
- 見立て（未確認）: 512 byte の journal の record の read-modify-write（plan/ws307/ws.md の制限）、小さな file の metadata の書きが 4096 の read-modify-write になる。
- 関係: [BUG-355](BUG-355.md)（UFS の大きい書き込みが約 1 MB/s、512 でも遅い）。
- 回避: WS307 の試験は 4096 の導入を base・OpenSSH・OpenSSL（約 45 MB）だけ・timeout 3600 s に縮めた（ae125c7d4）。
- 未確認: 実機の 4Kn の disk、原因の切り分け（journal・metadata・buffer cache・driver）。
