Bug ID: `BUG-099`

Disposition: tracking

Source: main の検証（ws081-p012 の merge の後、batch120 の pen の image）

## 観測

main の checkout（4e850cdd）の pen の image（`build/main-pen`、QEMU Venus、1280x800）で `plan/ws081/tests/p012-guest.sh build/main-pen build/main-ws081-p012b`
を流すと、段 3（page mode の左への flick）の `replay swipe.script` が「touchinject swipe.script: FAILED」になった。`replay` は guest で
`/bin/touchinject /tmp/swipe.script; echo replay=$?` を走らせ、SSH の出力に `replay=0` の行が無いと失敗にする。
同じ段の効果の検査（the finger swiped・the swipe turned forward・page 2 is shown）は全部 ok で、swipe は届いていた。
touchinject が非 0 で終わったのか、SSH の出力が失われたのか（`guest.py run` の timeout 等）は分からない。log: `build/main-ws081-p012b.log`。

## 調べたこと

- 同じ guest を起こし直し、同じ `swipe.script` を単独で 2 回: どちらも `replay=0`。
- 試験の全体をもう 1 回（`build/main-ws081-p012c.log`）: PASS。
- 未調査: touchinject の終わりの経路（`hold` の後の close、注入の device の teardown）の誤りの返し方、`guest.py run` の timeout と SSH の出力。

## 次の手

touchinject の各 exit の経路で理由を stderr に出す（どの段で非 0 か分かるように）、`replay` が `replay=` の行の無いときに SSH の rc と出力を残す。
再び出たらその出力で原因を決める。
