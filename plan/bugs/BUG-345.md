# BUG-345: Pi 5 のデスクトップでマウスのクリックが時々効かない（入力は届いているのに画面が変わらない疑い）

- 状態: unreproduced（2026-10-23、再起動の後は 0 件）/ tracking
- 発見: 2026-10-22〜23 ユーザーの Pi 5（kei@10.0.30.5）のデスクトップ。ユーザー「システム全般で、マウスクリックがイベントとして伝わらないことがあるのを確認しました。なんでしょうね？」。手掛かり「TerminalのShellメニューの上で連続で2回クリックすると、2回目が認識されず、Shellメニューが閉じないです。」。調査は P3（WS278 の板、2026-10-23）。
- 期待: 押した click の全部が画面の反応になる（Shell の menu が開く・閉じる）。
- 観測: 実演（Terminal の Shell の menu の開く・閉じるを 3 回、計 6 click）で「3回目のクリックが認識されませんでした。（Shellを開く2回目のクリックですね）」。

## 調べた事（2026-10-23 P3）

- kernel（板の debug kernel v1、`dbg-click` の記録: usb-hid の report、hid-input の BTN_LEFT の evdev、rp1-usb の割り込みと poll の回数）:
  - 自由な 20 click の試し: 21 組の press/release が hid と evdev の両方に揃って出た。report の取りこぼし・合体は無し、completion から再 arm までの遅れは最大 1 ms、xHCI の event は全部 MSI-X（vector 31・36）の割り込みで取られ、safety poll が拾った分は 0。
  - 失敗した 6 click の実演: 6 組とも hid と evdev に出た（ms=5052661/714、5056163/231、5061782/879、5064759/827、5067054/122、5069522/604）。
- compositor（`/run/user/1000/session.log`）: その 6 click に対し `KWL MENU open → close → open → close → open → close` の 6 行が出た。1 秒ごとの `KWL SYSTEM result` の番号で時刻を当てると、行の間隔（約 4・5・3・3・2 s）は click の間隔（3.5・5.6・3.0・2.3・2.5 s）と 1 対 1 で合い、「効かなかった」3 回目の click でも menu は compositor の中で開いた。各 menu の出来事の 5 秒の窓に `KWL PERF compose frames=1`（open の窓は `large n=1` の描画）があり、frame も 1 枚ずつ組まれていた。この時は画面が静止していて、frame はその 1 枚だけだった。
- 表示（板の debug kernel v2、hvs6-flip の record と vblank の adoption の時刻、V3D の job の時間）: 再起動の後の実演（6 click）は「今回は6回とも認識されました。」。この時は frame が 16〜17 ms ごとに続けて record・adopt されていて（serial 1124〜1178、record から adoption まで 0〜17 ms）、静止した画面ではなかった。その後もユーザー「再起動後はクリックの取りこぼしがゼロになったようです。」。
- 結論（今の所）: 入力（USB・HID・evdev・compositor の menu の処理）は失敗した回も含めて全部届いている。症状は「組んだ frame が画面に出ない（次の frame まで出ない）」窓の疑い。静止した画面で frame が 1 枚だけの時にだけ見え、連続で描いている時は次の frame が 16 ms で上書きするので見えない。長く動いた後（失敗は uptime 約 1 時間 20 分、最初の報告は debug の無い kernel）にだけ出た可能性がある。

## code から見た候補（未確認、直しは入れていない）

1. `src/drivers/gpu/bcm2711/display/hvs6-flip.c` の `publish_locked`: list が 2 つ出ている（`pending_count == 2`）間の record は出さず（`perf.coalesced`）、次の vblank の adoption（`bcm2711_display_flip_vblank_locked` の最後の `publish_locked`）が運ぶ。adoption は pixel valve の VFP_START の割り込みで HVS の `DL` を読んで、出した list と一致した時だけ起こる（`device_vblank_service`、`hvs6.c`）。静止した画面で最後の record が coalesce された時に、その後の vblank で一致が見つからない（DL がどちらの pending の list とも合わない、割り込みが来ない）と、最後の frame は次の record まで出ない。
2. 失敗した回は flip の記録が無かったので、frame の record（`bcm2711_display_flip_record`）がその click の時刻に来たか（libvulkan の present の worker の fence 待ち・`output_present` の前で止まっていないか）は分かっていない。
3. GPU の書き出し: native pass は `clean_output = true` で L2T を clean し、compute は毎回 clean するので、GPU の cache に frame が残る窓は code の上では見つからなかった。

## 再調査の条件

- 再発した時に、板を再起動せずに `dmesg` と `/run/user/1000/session.log`（`KWL MENU`・`KWL PERF` の行）を取り、hvs6-flip の record・adoption の時刻を出す debug の kernel（2026-10-23 の v2 と同じ記録: record の serial・ms・phys・pending、adoption の serial・ms・phys）に替えた上で、静止した画面で同じ実演（Terminal の Shell の menu の開く・閉じるを 3 回、2〜3 秒おき）をする。失敗した click の後に record が来ているか、record の後に adoption が来ているかで、上の 1（表示の adoption）か 2（present の前）かを分ける。
