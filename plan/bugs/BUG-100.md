# BUG-100: Remacs の host Noct の古い CMake cache と bytecode 名で make が失敗する

Bug ID: `BUG-100`
Reproduction: reproduced（amd64 host の `make -j16`）
Disposition: resolved（ws073-p028、2026-09-29）
Source: ユーザーの「makeするとtoolchainのnoctが失敗する」報告
Owner: WS073

## 観測と原因

`build/host-noct-package/CMakeCache.txt` は旧 `build/sources/noct` を source として記録している。Remacs の rule は現行の `userland/base/noct/noct` を同じ build directory へ CMake configure しようとして、source の不一致で停止した。別の host Noct を作る設計自体が重複している。さらに Remacs の取得した `tools/build-nap.sh` は `.nb` を探すが、現行 Noct は `.nbc` を生成する。

## 解決と確認

Remacs は既存の canonical host Noct (`NOCT_HOST_ARTIFACT` と `NOCT_HOST_BUILD_STAMP`) を使う。取得した Remacs の source には `.nbc` を扱う patch を stamp 付きで適用する。`make noct-toolchain-smoke` PASS、`make -j16 build/amd64/packages/editors/remacs/remacs.nap` PASS（Noct で bytecode を再生成）。全体の `make -j16` は clang package の大規模な再 build に進み、完了前に中断した。QEMU と実機は未実施。

2026-09-29 の再発（q497）: すでに `.nbc` の source に stamp の rule が patch を再適用し、reverse patch と `.rej` で停止。script の出力名で未適用・適用済みを分けるように修正した。両方の状態の host 試験は PASS。全体の `make` は未実施。

2026-09-29 の q498: `make toolchain-cache` は既存のホスト用 LLVM の cache を受け入れた。ゲスト用 clang の build を続け、`make -j16` と通常の `make` が image の検査まで PASS。`toolchain` の smoke 依存を除去した。外部 source と未追跡の別 tree の warning は残る。
