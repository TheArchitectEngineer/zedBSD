# BUG-243: フルサイズの OSK で窓が縮むと、app の表示が縦に圧縮される（app に resize が届いていない）

- 状態: reproduced（ユーザーの UAT、2026-10-07） / disposition resolved（2026-10-07 T1-332: Terminal・Text Editor の docked と floating で潰れない、`KWL OSK work docked … height=404` の後に同じ client の `KWL IMPORT … height=404`。zgears は X の display が無く未実施）
- 発見: 2026-10-07 ユーザーの ad-hoc UAT

## ユーザーの報告（原文）

「フルサイズのオンスクリーンキーボードを起動すると、ウィンドウが小さくなってくれますよね。それは期待通りの挙動になっており感謝です。ただ、ウィンドウサイズが縮小されたとき、表示が縦方向に圧縮されています。たぶん、ウィンドウリサイズがきちんとアプリに届いていなくて、アプリの思っているウィンドウサイズは大きいままで、コンポジタの内部サイズが変わっただけになってます。」

## 期待と観察

- 期待: full の OSK が出て窓の領域が縮む時、compositor が app に新しい大きさ（xdg_toplevel の configure か keyboard の inset）を送り、app がその大きさで描き直す。表示は縦に潰れない。
- 観察: 窓は小さくなるが、中身が縦に圧縮されて見える（app は古い大きさの buffer のままで、compositor が縮めて合成している疑い）。

## 調べること

- compositor の OSK の full の時の窓の配置（keyboard.c・layout.c・inset.c、ws102-p015 の `keiland_keyboard_inset_v1`／kl の inset）: configure を送っているか、buffer を scale しているか。
- inset を受けない app と受ける app で違うか、maximized・docked の窓と floating の窓で違うか。

## 関連

- [WS102](../ws102/ws.md)（画面の keyboard、p015 inset）

## 2026-10-07 P2: 調べと直し（未確認、T1 の撮影待ち）

- 読みで分かったこと: full（QWERTY）の panel が開く時、compositor は docked の窓に新しい大きさの configure を送る（`keyboard.c` の `keyboard_work_area`、
  log `KWL OSK work docked surface=… height=…`）。floating の窓は大きさを変えず、panel の下に掛かる時だけ位置を動かす。一方、docked の窓の本体は
  `shell.c` の `docked_rect`（panel の slide に合わせて縮む docked の space）に描かれ、`draw_body` は app の image をその矩形に**引き伸ばして**描いていた。
  app が新しい大きさで描くまでの間（slide の間）、または configure に応じない app では、image が縦に圧縮されて見える。libkeiland の app（16 個）は
  `KL_WINDOW_RESIZE` で描き直す。ユーザーの見た app は未確認（Q1 がユーザーに聞いている）。
- 直し（Q1 の ACK）: `draw_body` で、docked の窓（animation・pull の最中でない）の image の大きさが docked の space と違う時は縮尺しない。image をそのままの
  大きさで space の左上から描き、space の縁で切る（uv を切る）。panel・sub-surface も等倍。入力は前から body の原点からの等倍なので、表示と入力が合う。
- 確認: zedBSD の build（`build/p2-ci/bin/wayland`）warning 0、style-check 0。QEMU の撮影は T1（docked・floating × inset を受ける・受けない app）。
