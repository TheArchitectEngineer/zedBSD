- 形は毎回 `pending-events=2 iman=3 usbsts=8`、completion=1（Success）。event は ring に届き割込みも pending なのに、guest が 1 秒の間
  取っていない（guest の側の取りこぼし）。BUG-030 の形（`pending-events=0`、completion 26、QEMU の flush の待ち）とは違う。
- keyboard の attach の失敗は修正の前の kernel でも 40 回中 6 回あり、BUG-030 の修正の退行ではない。

## 次にすること

`iman=3`（IE=1・IP=1）で event が 2 つ溜まったまま 1 秒取られない理由を調べる。割込みの配送（MSI/MSI-X と CPU の割り当て）、handler が
走っているのに event ring を読まない条件、EP0 の待ちが割込みに頼り poll しない経路を見る。

## 2026-09-30 追記（main、ws073-p041 の KVM の受け入れの試験から）

- **bulk の endpoint でも起きる**: KVM の 40 回中 1 回、usb-storage の READ の data の段（8192 byte）が 30 秒の timeout に掛かった（`BOT data dir=in error=42`）。
  診断は `pending-events=1 iman=2 usbsts=8`、completion=1（Success）residual=0。転送は終わり event も ring にあるのに、guest が 30 秒取らなかった。
  IMAN=2（IE=1、IP=0）で、EP0 の形（iman=3、IP=1）とは IP の値が違う。再試行で回復。dmesg: worktree ws073-bugs の
  `build/ws073-p041-accept/kvm/g2-b12/dmesg-1.txt`。
- 同じ試験で EP0 の `xhci: cancel` は 7 回、keyboard の attach の失敗は 3 回。
- BUG-030 の形（flush の待ち、pending-events=0・completion 26）ではないので、BUG-030 は resolved にし、この 1 回はここへ移した（main の判断）。

## 原因と修正（2026-09-30、[ws073-p042](../ws073/phase042/phase.md)）

- 原因: driver が command（Address Device・Configure Endpoint など）の poll の間 IMAN.IE を 0 にし、終わると 1 に戻していた。QEMU 10.0 の xHCI は
  IE=0 の書き込みで MSI-X の vector を `msix_vector_unuse()` し、IE=1 の書き込みでは「IP が立っていれば `msix_notify()`（IP を 0 に）→ その後 use」の順。
  `msix_notify()` は vector が use されていなければ黙って捨てる。poll の間に来た event（EHB=1・IP=1）の割込みはこの復帰で捨てられ、ring に event が
  残ったまま EHB=1 なので以後の event も割込みを起こさず、次の command が poll するまで止まる。bulk の形（`iman=2`、IP=0）はこの直後、EP0 の形
  （`iman=3`、IP=1、pending 2）はさらに次の event が「EHB 立ち」で IP=1 のまま止まったもの。診断の `erdp` の bit 3（EHB）は全て 1。
- 修正: `src/drivers/pci/pci-xhci.c` で command の poll の間も IE を落とさない（`command_polling` を削除。poll と handler は `event_lock` と
  `command_event` で元から共存できる）。根の修正で、安全網は入れていない。
- 確認: phase.md（build、少数回の再現の試験、boot test）。受け入れの本数の試験は試験の担当。
