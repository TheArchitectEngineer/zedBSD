# BUG-246: 整列の popup の開く animation と、整列した窓の入れ替えの animation が、pointer の事象が無いと進まない（5320 実機）

- 状態: reproduced（実機 5320、ベアメタル、ユーザーの UAT 2026-10-07） / scheduled（P2、UAT 優先）
- 発見: 2026-10-07 ユーザーの ad-hoc UAT（5320、i915、zedBSD を USB から起動）。QEMU（Venus）の T1-349 では menu-settled まで進んだ。

## 観察（ユーザーの文）

「Arrangement Popupは、最初の1コマが表示されたあと、マウス入力のイベントがないと続きが描画されないようです。しかも、最初にクリックするまで、マウス移動のイベントのたびにアレンジされたウィンドウが再描画されるのかちらついています。」
「アレンジしたウィンドウを入れ替える操作のとき、マウス移動がないと移動のアニメーションが完了しないようです。上記バグと関連すると思います。」
「これらは5320実機でベアメタル起動での結果です。」

## 疑い（Q1、未確認）

- i915 の表示では、compositor の animation の次の frame を pointer の事象だけが起こしている（animation 中に再描画を予約する口、または i915 の present の完了・vblank の事象が compositor を起こさない）。Venus では別の経路で frame が回るので QEMU では出ない。
- 最初の click までの「ちらつき」は、pointer の移動のたびに整列の窓の層を描き直している疑い。
