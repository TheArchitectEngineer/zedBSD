# BUG-098: 新しい pty の slave が常に root の所有で、root 以外の利用者が forkpty できない

Bug ID: `BUG-098`
Reproduction: reproduced（QEMU Venus、demo の利用者 `kei`、ws035-p118）
Disposition: scheduled（ws035-p118 の agent が main の許可で `src/kern/tty.c` を直す）
Date: 2026-09-28
Source: ws035-p118
Owner: WS035（kernel の変更は main が許可）

## 観測

`kei` で Terminal が「ZTERM FAILED operation=forkpty errno=25（EACCES）」で起動しない。`posix_openpt`・`grantpt`・`unlockpt`・`ptsname_r` は成功し、
`/dev/pts/0` が mode 0620・uid 0・gid 0 で、slave の open が `kei` では EACCES。`src/kern/tty.c` の `pty_master_open` が新しい組を常に
owner_uid=0・owner_gid=0 にし、libc の `grantpt()` は TIOCGPTN の ioctl だけ。POSIX の grantpt・Linux の devpts・FreeBSD は slave を
呼び出し側の実の uid に渡す。sshd は root で chown するので影響がない。

## 修正の方針（main の指示）

slave の owner の uid は呼び出し側の実の uid（ruid）。gid は呼び出し側の group にしない（同じ group の他の利用者が書けてしまう）: `tty` の
group があればそれ、無ければ 0。mode 0620。
