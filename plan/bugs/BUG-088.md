## 観測

`src/hal/amd64/space.c` の `AMD64_CURRENT_SPACE` は per-CPU の pointer と field を 2 回の load で読む。BUG-082 の `running_task` と同じ形で、呼び出し側（TLB shootdown の送り手）が preempt されうるなら別の CPU の値を読む。

## 次の手

呼び出し側が preempt されうるかを調べ、されうるなら 1 回の %gs の load にする（HAL の実装の修正、hal.h は不変）。

## 結果（2026-09-28、ws073-p023）

読み書きする所は全て割り込みを禁止した中にある: 起動の初期化（CPU 1 つ）、`hal_space_switch()`（呼び手は `hal_task_context_switch()`（sched が禁止）と
`hal_task_exec_current()`（exec.c が禁止）だけ、store は自分か `space_lock_enter()` で禁止）、`shootdown()`（先頭で禁止）。preempt も CPU の移動も
起きないので、2 回の load は同じ CPU を読む。修正は不要で code は変えていない。将来の割り込みを許した `hal_space_switch()` の呼び手への備え
（1 回の `%gs` の load、または hal.h の契約の明記）は [phase](../ws073/phase023/phase.md) の残りに。

予防の変更（2026-09-28、main の決定、[ws073-p024](../ws073/phase024/phase.md)）: `current_space` の読み書きを 1 回の `%gs` 相対の access に
（`space.c` の `current_space_load()`・`current_space_store()`、`percpu.h` の `AMD64_PERCPU_CURRENT_SPACE`）。build warning 0、boot test PASS、bug082.sh 30/30。
