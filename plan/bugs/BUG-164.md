# BUG-164: crash の後に orphan の inode（nlink 0・size 0 の通常の file が allocated のまま）が残ることがある

Reproduction: reproduced（決定的、ws073-p054 の tests/p054-orphan.sh: 開いたまま消した file と crash）
Disposition: scheduled（ws073-p054、P2）
Discovery: ws073-p053（BUG-163）の p053-fsync.sh の 8 回のうち 1 回（partition の開始 63、名前の churn の中で gdbstub で切る）

host の check-volume が `orphan allocated inodes: [300]` を報告（通常の file、nlink 0、size 0）。churn が消した名前の inode の解放が、切った時に disk に無かった見込み（unlink と free が別の transaction）。他の 7 回（直した kernel の 4 回を含む）は UFS OK。直した kernel で再現するかは未確認。disk の image: P2 の worktree の `build/p2-b135/p053-before63-u1/disk.img`（使い捨ての場所、残っている間に調べる）。

次: unlink と inode の free が同じ transaction に入るか（あるいは replay で nlink 0 の inode を回収するか）を読む。

## 原因と直し（2026-10-04、P2、[ws073-p054](../ws073/phase054/phase.md)）

- 原因: mount の回収 `orphan_recover` が tail journal（v2）の volume でしか走らず、batched journal（v3）と journal の無い volume では
  nlink 0 の inode を回収しなかった。unlink と解放は別の transaction になりうる（開いたまま消した file は close まで解放されない）ので、
  その間の crash の後に残る。
- 直し: tail journal の無い書ける volume も、前の session が clean に終わらなかったとき（clean byte 0）に scan し、順序の経路で回収する。
- 確かめ: 直す前は orphan が mount の後も残る（決定的）、直した後は `UFS OK`。元の image（inode 300）も直した kernel の mount で回収。判定は Q1。
