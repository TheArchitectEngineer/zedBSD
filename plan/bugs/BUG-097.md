# BUG-097: 既にある名前への mkdir が、親に書けない利用者で EEXIST でなく EACCES になる

Bug ID: `BUG-097`
Reproduction: reproduced（QEMU Venus、demo の利用者 `kei`、ws035-p118）
Disposition: resolved（2026-09-28、ws035-p120。作業中の報告では ws035-p118）
Date: 2026-09-28
Source: ws035-p118
Owner: WS035（kernel の変更は main が許可）

## 観測

`src/kern/syscall.c` の `sys_mutation_common` が、名前がもうあるかを調べる前に `vfs_may_create`（`inode_creation_request_user`）を行うため、
`kei` の `mkdir("/home")` が EACCES になる。Notes の journal.c・main.c の「ここまでの folder を作る」loop は EEXIST 以外で止まるので、Notes が
「Could not keep the stroke」になり `~/Documents/Notes` に保存できない。`mkdir -p $HOME/Documents` も同じく失敗する。

## 修正の方針

mkdir では先に `inode_lookup` し、見つかれば EEXIST、ENOENT なら権限の検査と作成へ（FreeBSD・Linux と同じ）。約 15 行。

## 修正（2026-09-28、ws035-p120）

`src/kern/syscall.c` の `sys_mutation_common`: mkdir は先に `inode_lookup`、あれば EEXIST、ENOENT なら `inode_creation_request_user`（権限の検査）と `inode_mkdir`。
