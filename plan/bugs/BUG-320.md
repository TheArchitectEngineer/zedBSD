# BUG-320: Pi 4 で browser が起動しない

- 状態: reproduced（ユーザー、Pi 4 実機）/ scheduled（P1、2026-10-15）
- 発見: 2026-10-15 ユーザー「Piでブラウザが起動しませんでした。PiではなくQEMUで確認できますか？P1を割り当てます。」
- 環境: Pi 4（kei@10.0.30.2）、kernel main 5afbaa4d5（T2 の T1-657）、userland はユーザーの build（main 2597b86 の頃、Bluetooth の driver off）。
- 未確認: 症状の詳細（窓が出ない・すぐ終わる・固まる）、log。QEMU の raspi4b（`plan/tools/boot-test.sh` の BOOT_MODE=raspi4b、TCG、V3D の GPU は無い）で再現するか。
- 関連: WS074（browser・libbrowser、B1）、WS141（Pi の GPU）。
- 2026-10-15 P1 の調べ（Pi 実機、読むだけ）: 原因は 3 つ。(1) Pi に RTC が無く時計が 2026-01-01、既定の https://www.google.com/ が `certificate is not yet valid` で失敗。(2) shell が最初の頁の失敗で窓を開かずに rc=1 で終わる（shell.c）。(3) GPU: Pi の V3D の Vulkan が libbrowser の paint の pipeline を断る（`vkCreateGraphicsPipelines failed (-8)`）: frag の gl_FragCoord、texelFetch、instance rate の頂点の属性、SRC_ALPHA の blend。QEMU の raspi4b には V3D が無く (3) は再現できない（host で bcm2711 の compiler に通して決定的に再現できる）。
- 2026-10-15 ユーザーの判断（クリック）: (3) は「A: browser の描き方を合わせる」→ B1 が libbrowser の paint を Pi の driver が受ける形に（p238）。(1) は「ntpdate を既定で有効に」→ P1 が Pi の image で起動時の ntpdate を有効に（server は pool.ntp.org、Q1 が決めた既定）。(2) は P1 が shell を直す（失敗しても窓を開き表示する）。CPU で描く案 C は guardrail の「画像の処理は GPU で」に反するので取らない。
