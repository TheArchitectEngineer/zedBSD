# BUG-114: 全画面で起動した窓（Notes）の全画面を解くと、title bar が system bar に重なり動かせない

Bug ID: `BUG-114`
Reproduction: reproduced（ユーザー、2026-09-30、どの環境かは未確認）
Disposition: resolved（ws035-p138、2026-09-30）
Date: 2026-09-30
Source: ユーザーの報告
Owner: WS035（zdesktop）

## 観測（ユーザー）

「Notesをスワイプでフルスクリーン起動したあと、Escキーでフルスクリーンを解除すると、タイトルバーがスクリーン上部のバーにかぶってしまい、
移動操作ができなくなります。スクリーンサイズを求めて、画面の中央に配置するのがいいかも。」

## 見立て（main、未確認）

右上の角の swipe（`corner.c`）は `/bin/notes --fullscreen` を起こすか、既存の Notes の窓を全画面にする。窓として置かれたことの無い窓は、
全画面を解くときに戻す位置が無く、(0, 0) 付近に置かれて title bar が system bar の下に隠れる。

## 直し方（ユーザーの案に沿う）

- 全画面・最大化を解くとき、戻す窓の位置が無ければ、画面（system bar を除いた作業の領域）の中央に置く。
- どの場合も、浮いた title bar が system bar に重ならないように、窓の位置を作業の領域の中に収める。

## 解決（ws035-p138、2026-09-30）

- 原因: 全画面で始まった窓は窓として置かれたことが無く、戻り先が (0,0) のままだった。
- 修正: 全画面を解くとき、置かれたことが無い窓は作業の領域の中央に置く（client が窓の大きさで描き直した時点で置き直す）。戻り先がある窓も、
  最大化を解くときも、作業の領域の中に収める（title bar は system bar の下）。
- 確認（QEMU の Venus、Notes の image）: `plan/ws035/tests/zdesktop-p138.sh` PASS（swipe → Esc で中央、title bar の drag で動く、2 回目の swipe → Esc で
  戻り先へ）。回帰 p052・p053・p076・boot test PASS。実機は未実施。
