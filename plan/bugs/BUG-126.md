# BUG-126: toolchain の lock の中で libcxx の source の複写に patch が当たらない（`cp -al` が読み取り専用の directory を写す）

Bug ID: `BUG-126`
Reproduction: reproduced（2026-09-30、main の checkout、`make -j16 BUILD=build/amd64 disk-image` で libcxx の source を作り直すとき）
Disposition: resolved（2026-10-01）
Date: 2026-09-30
Source: ws103-p003 の準備（別の checkout を指していた CMake の cache を消して作り直した時、ユーザーの許可「消して作り直してOKです」）
Owner: main（2026-10-01 ユーザー「BUG-126を修正してください」が toolchain の範囲の変更の許可）

## 観測

- `userland/packages/external.mk` の `ZEDBSD_EXTERNAL_LLVM_COPY` は、共有の LLVM の source（`build/llvm-source`）を `cp -al` で
  `build/packages/libcxx/src.tmp` に写してから patch を当てる。
- `plan/tools/toolchain-lock.sh lock` で `build/llvm-source` の directory は読み取り専用。`cp -al` は directory の権限も写すので、複写の directory も
  読み取り専用になり、`patch` が一時 file を作れず失敗する（`Can't create temporary file libcxx/include/__locale_dir/locale_base_api.h.orslWmt : Permission denied`）。
- 失敗の後に残った `src.tmp` は、次の実行の `rm -rf` でも消せない（`Permission denied`）。`chmod -R u+w` の後に消す必要があった。
- 回避: main が `toolchain-lock.sh unlock` → build → `lock`（2026-09-30 に実施、libcxx は作り直せた）。

## 別に見つけたこと（同じ日、解消済み）

この checkout（`/home/awe/zedBSD-claude1`）の Noct の build directory（`userland/base/noct/noct/build-zedbsd-amd64`）、7 つの package の build
（clang・curl・expat・libcxx・openssh・openssl・zlib）、package の cross の wrapper（`build/amd64/packages/toolchain`）が、別の checkout
（`/home/awe/zedBSD-rpi4`）の path を持っていて、新しい build directory と既定の `config.mk` の build が失敗していた。消して作り直し、既定の image の
build が通った。共有の toolchain の tree（`build/llvm-build`・`build/NoctLang`）の CMake の cache も同じ path を持つが、install 済みの toolchain は
使えるので触れていない（LLVM を作り直すときに問題になる）。

## 修正（2026-10-01）

- `userland/packages/external.mk` の `ZEDBSD_EXTERNAL_LLVM_COPY`: `cp -al` の後に複写の **directory だけ** を `u+w` にする（`find -type d`）。
  file は toolchain の file への hard link で mode を共有するので触らない。前の複写・失敗の残り（`$copy`・`$copy.tmp`）も、`rm -rf` の前に
  directory を書けるようにする（symlink は辿らない）。
- `plan/tools/toolchain-lock.sh` の注釈の誤り（「複写の directory はその package のもの」）を直した。

## 確かめ（2026-10-01、main の checkout、toolchain は lock のまま）

macro を切り出して、lock した `build/llvm-source` から libcxx の patch を当てる複写を `build/bug126/`（作業用、後で削除）に作った。

| 場合 | 結果 |
| --- | --- |
| 前の macro（HEAD） | 失敗: `Can't create temporary file libcxx/include/__locale_dir/locale_base_api.h.oV36AzG : Permission denied`（再現） |
| 新しい macro | patch が当たり `src` ができる |
| 新しい macro の 2 回目（前の複写がある） | 成功 |
| 前の macro の失敗の残り（読み取り専用の `src.tmp`）がある所へ新しい macro | 残りを消して成功 |

- toolchain の側は変わらない: `toolchain-lock.sh status` は 4 つの tree とも書ける directory 0、patch された file の元（`build/llvm-source/…/locale_base_api.h`）は
  inode・link 数 1・mtime（2026-09-28）が変わらず、複写の側は別の inode、patch の無い file は同じ inode の hard link のまま。
- `make -n BUILD=build/amd64 disk-image` が通る（Makefile の構文）。libcxx・clang の package の実際の作り直しは行っていない（同じ macro を使うので未実施）。
