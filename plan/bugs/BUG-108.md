# BUG-108: unix socket の blocking の connect が backlog の満杯で待たずに EAGAIN（多数の client の一斉の起動で失敗）

Bug ID: `BUG-108`
Reproduction: reproduced（QEMU の Venus の desktop、ws073-p034）
Disposition: resolved（2026-09-29、[ws073-p035](../ws073/phase035/phase.md)、QEMU で確認。実機は未実施）
Date: 2026-09-29
Source: ws073-p034 のサブエージェントの報告
Owner: WS073

## 観測

- `src/kern/net/unix-socket.c` の listen は backlog を 16 に clamp し、backlog が満ちると `connect` は blocking でも待たずに EAGAIN を返す
  （Linux の AF_UNIX の blocking の connect は空きを待つ）。
- 40 の Wayland の client（wlshm）を間隔なしで一斉に起こすと `setup errno=5` で失敗した。
- 同じ時に wltest（EGL）の 4 本が `errno=24`（EMFILE）で窓を開けなかった（単独では開ける、原因は未調査）。
- デスクトップの起動の直後に多数の app を開く時に効く。試験は 0.3 s おきで回避していた。

## 修正と確認（2026-09-29、[ws073-p035](../ws073/phase035/phase.md)）

- `src/kern/net/unix-socket.c`: blocking の connect は backlog の空きを listener の `connect_waitq` で待つ（accept と close が起こす）。nonblocking は EAGAIN、
  listener の close は ECONNREFUSED、signal は EINTR。backlog の上限を 16 から 128 に。
- wltest の「errno=24（EMFILE）」は読み違え: zedBSD の errno 24 は EAGAIN（EMFILE は 46）。wlshm と同じ backlog の満杯が原因。
- QEMU: `STAGGER=0` の socket-desktop（40 ＋ 4 の client を一斉に）3 回とも全て描画。`plan/ws073/tests/unix-backlog.c` PASS。
