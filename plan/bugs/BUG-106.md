# BUG-106: `ssh -tt` で最後の命令の出力が空か途中で切れることがある

Bug ID: `BUG-106`
Reproduction: reproduced（QEMU、ws086-p002 の guest の比較、8〜25 回に 1 回）
Disposition: tracking
Date: 2026-09-29
Source: ws086-p002 のサブエージェントの報告
Owner: WS073（[ws073-p032](../ws073/phase032/phase.md)、uncleared）

## 観測

`ssh -tt` で guest の `ls` が最後の命令のとき（shell が exec する形）、出力が 8〜25 回に 1 回ほど空か途中で切れる。後ろに `; true` を
置くと 25/25 回とも完全で、ls の終了状態は 0。pty の slave を閉じた時に未読の出力を捨てるか、sshd-session の子の終わりと channel の
EOF の順の問題と思われる（未調査）。ls の変更とは無関係（ls の外）。

## 調査（2026-09-29、[ws073-p032](../ws073/phase032/phase.md)、WS081 のサブエージェント）

- kernel の pty（`src/kern/tty.c`）: slave の close は ring を捨てず、master の read は ring が空になってから EOF。ring を空にするのは TCFLSH（TCOFLUSH・TCIOFLUSH）だけ。
  session の leader の終わりも出力に触れない。読んだ範囲に出力を捨てる経路は無い。
- OpenSSH 10.5p1: 子の終わりで `chan_write_failed` だけを呼び、master を EOF まで読む。順の問題は見つからない。
- 再現の試み（QEMU、WS081 の pen の image、今の main の ls を `/tmp/ls` に置いた）: ws086 と同じ形の command を約 500 回。途中の欠けは 0。
  0 byte の 1 回は、sshd の listener（pid 12）の SIGSEGV（`at 0x100300c64, address 0x38`、共有 library の中）と同時。その後 25 回は connection reset だった。
- 仮説: ws086 の欠けは sshd-session の子の SIGSEGV（[BUG-051](BUG-051.md)）の現れの可能性がある（子が落ちれば出力は途中で切れ、ssh の終了状態は 255）。
  ws086 は失敗した回の終了状態と guest の `dmesg` を記録していない。
- 次: 再現する image（`config-amd64-ssh.mk`）で、失敗の回ごとに ssh の終了状態と guest の `dmesg | grep 'killed by signal'` を取る。
  SIGSEGV が伴えば BUG-051 の duplicate にする。rc 0 で欠けるなら pty の順を gdbstub で見る。
