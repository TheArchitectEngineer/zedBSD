# BUG-065: 同じ block device を 2 か所に read-write で mount できる（volume を壊す）

Bug ID: `BUG-065`
Reproduction: reproduced（QEMU、WS072 の agent、native の guest image。base の image でも同じで既存）
Disposition: resolved（2026-09-27、[ws073-p002](../ws073/phase002/phase.md)、QEMU で確認。実機は未実施）
Date: 2026-09-27
Source: WS072 の agent の guest の操作（main から WS073 へ転送）
Owner: WS073

## 期待と観測

期待: mount 済みの device の 2 度目の mount は EBUSY（少なくともどちらかが書き込み可能なとき）。

観測（root が `/dev/nvme0n1p2` の guest）:

```
mkdir /w; mount -t ufs /dev/nvme0n1p2 /w     # 0 で返る
mount
/dev/nvme0n1p2 on / type ufs (rw)
/dev/nvme0n1p2 on /w type ufs (rw)
```

1 つの volume に独立した UFS の状態（cylinder group の cache、journal）が 2 つでき、volume を壊す。

## 解決（2026-09-27、ws073-p002）

原因: `mount_filesystem_on_disk()` は backing claim（swap・loop・format）との衝突だけを調べ、他の mount が同じ disk を使うかを見ていなかった。
修正: `mount_disk_reserve()`（`src/kern/mount.c`）が namespace の lock の中で全ての mount の disk と blocks の重なりを比べ、どちらかが書き込み可能なら
EBUSY、そうでなければ同じ critical section で disk を記録する。read-only 同士は共有できる。`plan/ws073/tests/double-mount.sh` 17 件 PASS、
同時の 2 つの mount 10 回で毎回 1 つだけ成功、boot test PASS。

副作用（判断が要る点）: kernel が private に rw で持つ boot の FAT（ESP）の公開の mount も EBUSY になった（phase の記録）。
