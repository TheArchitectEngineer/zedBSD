# BUG-298: networkd の DHCP の最中に `net static` で付けた address が、DHCP の失敗の後に 169.254（link-local）で上書きされる

- 状態: reproduced（QEMU、T1-569 で 3 回） / resolved（2026-10-13 ユーザー「解決済みです。」、実機で確かめ済み）
- 発見: T1-569（QEMU x86_64、image は `plan/tools/guest/test-image.sh plan/ws220/tests/config-amd64-tcp.mk`、script は `plan/ws220/tests/tcp-stream-series.sh`）。
- 関係: [BUG-293](BUG-293.md)（同じ networkd の link-local の扱い。あちらは `net down` で 169.254 が外れない不具合で、仕組みが別。BUG-293 の直し (C) で `net up` が DHCP を再試行するようになったので、`net up en0` の直後の `net static en0` でもこの不具合に当たる）。
- 担当: P4（Q1 の依頼、2026-10-13）。
- 証拠（T1 の worktree、読むだけ）: `/home/awe/zedBSD-worktrees/t1/build/review/t1-569/`（run の log）と、その symlink の先 `/home/awe/zedBSD-worktrees/t1/build/ws220-series-{0,01,1}.run.*/`（`setup.txt`・`series-down.txt`・`transfer-*.txt`）。

## 観測

- guest の 2 枚目の USB の網の口 ue1（net.conf に無い、QEMU の usb-net を host の tap に bridge、相手は 10.77.0.1、DHCP の server は無い）に、script が root で `net static ue1 ipv4 10.77.0.2 netmask 255.255.255.0 || ifconfig …; ifconfig ue1 up; sleep 2; ping -c 3 10.77.0.1` を流した。`net` のエラーは出ていない（remote は 2>&1 で setup.txt に入る）ので `net static` は成功している。
- ping は 3 個のうち 2 個が返った（3 個目で address が消えた）。起動から約 19 秒の最初の sample（`series-down.txt`、`time_ms=19405`）で ue1 は `inet 169.254.1.8 netmask 255.255.0.0` だけ。TCP は 10.0.2.15（ue0）から 10.77.0.1 に出て返らず、upload は `No route to host`。3 回とも同じ。

## 原因（source の読み、2026-10-13 P4）

1. networkd は net.conf に無い有線の口を DHCP（10 秒）で設定する（`userland/base/networkd/managed-lan.c` の `policy_for` の fallback、`NETWORKD_LAN_DEFAULT_DHCP_SECONDS`）。ue1 は起動の後に `lan_configure`（`userland/base/networkd/main.c`）で `dhcpc -t 10 ue1` を流す。dhcpc は始めに口の address を記録してから 0 にする（`userland/base/dhcpc/main.c` の `prepare_interface`、記録は 0.0.0.0）。
2. networkd は 1 本の thread で、子の command を待つ間（`run_command_until` の loop）に `wifi_wait_pump`＝`service_wifi_wait` を回し、Wi-Fi の仕事が無ければ届いた要求をその場で `dispatch_request` する。DHCP の最中に届いた `net static ue1` はこうして入れ子で実行され、`ifconfig ue1 inet 10.77.0.2` と `lan_note_configured`（CONFIGURED）まで済んで成功を返す。ping はここで通る。
3. dhcpc は offer が来ないまま 10 秒で諦め、失敗の後始末 `restore_interface` で記録した address（0.0.0.0）・netmask・broadcast を書き戻す。10.77.0.2 が消える。
4. `lan_configure` は戻ってきた dhcpc の後に `lan_address_usable(ue1)` を見て address が無いので、`lan_assign_link_local` で 169.254.1.8 を付け、`networkd_lan_configured(…, 0)` で状態を UNCONFIGURED にする（2 で付いた CONFIGURED を上書き）。
- kernel が address を置き換える経路は無い（169.254 を付けるのは networkd の `lan_assign_link_local` だけ。USB CDC ECM の carrier は device の NetworkConnection の通知にだけ従い（`src/drivers/usb/usb-cdc-ecm.c`）、bmRequestType が 0xA1 でない物は `usb-cdc-notification.c` が捨てる）。ifconfig で直に付けた address を networkd が「管理の外」として消す処理も無い。消したのは dhcpc の rollback。
- 試験の script の使い方の誤りではない: `net static` は正しい使い方で、製品の側で通らなかった（script の `|| ifconfig` の逃げ道も同じ経路で消える）。
- Pi 4 で: en0 が net.conf で `dhcp`（または未記載）の時、networkd の DHCP の最中（起動・cable の挿入の後の DHCP の 10 秒、BUG-293 の直しの後は `net up en0` の後も）に `net static en0 …` を打つと同じことが起きる（source から。実機は未確認）。net.conf で en0 を static にしてあれば networkd は dhcpc を流さないので起きない。`net dhcp en0` を同じ時に打つと dhcpc が 2 本同じ口で走る。

## 修正（2026-10-13 P4、worktree p4 branch agent/p4）

- networkd（`userland/base/networkd/main.c`）:
  - `lan_configure` を、設定中の口の名前（`lan_configuring`）を立てて `lan_configure_steps` を呼ぶ形にした。
  - 設定中に届いた要求のうち、その口の address を決める物（UP・DOWN・DHCP・STATIC・LAN_CONFIGURE、権限と confirmed の検査を通る物、`lan_request_supersedes`）は、その場で実行せずに 1 つだけ脇に置く（`lan_pending`）。2 つ目と、入れ子の要求の中で届いた物は EBUSY「the interface is being configured; retry」。
  - 脇に置いた時、policy の command が止めてよい所（`ifconfig up` と dhcpc／static の `ifconfig inet`、`lan_configure_stoppable`）なら、pump が ECANCELED を返し、`run_command_until` は子に SIGTERM を送って最大 3 秒待つ（`stop_child`、残れば SIGKILL）。止められた子が 0 で終わっていれば（lease を確定した後に聞いた dhcpc）成功として扱う。
  - 止められた `lan_configure_steps` は、address が無ければ link-local を付けず状態も変えずに戻る（PENDING のまま。syslog に `configuring stopped for a request`）。link-local・route の段で届いた要求は何も止めず、設定が終わるのを待つ。
  - `run_lan_work` は `lan_configure` が戻った直後に脇の要求を実行して答える（`dispatch_pending_lan`）。STATIC なら CONFIGURED になり policy はもう触らない。
- dhcpc（`userland/base/dhcpc/main.c`）: SIGTERM を timeout と同じに扱う（`timed_out`）。読みは最大 1 秒で切れるので、聞いてから 1 秒以内に失敗の後始末（口を見つけた時の形に戻す）をして終わる。ACK の後の確定は途中で止めない。
- 試験の script（`plan/ws220/tests/tcp-stream-series.sh`）: `|| ifconfig` の逃げ道を外し（`net static` の失敗を隠さない）、ping の 10 秒後に `ifconfig ue1` を読んで 10.77.0.2 が残っていることを確かめる（FAIL は `lost 10.77.0.2 (BUG-298)`）。実行の権限を付けた（mode 100755）。
- build: amd64（`ZEDBSD_CONFIG=config/ci/config-amd64.mk`）・rpi4（`config/ci/config-rpi4.mk`）の `bin/networkd`・`bin/dhcpc` が warning 0（-Werror）。
- host 試験: 無し（変えたのは networkd の main.c の要求の受付と子の扱いで、`make managed-lan-host-test` の対象の managed-lan.c は変えていない）。
