# BUG-175: Terminal を多数開くと errno=8（ENOSPC）で新しく起動しなくなる

Reproduction: reproduced（実機）
Disposition: resolved（2026-10-05 Q1: pty の上限を 64（64-bit）に、P1 8caf1c79、T1-149 で 40 個を同時に開いて ENOSPC 無し（QEMU）。実機で Terminal 20 以上は UAT、再発なら reopen）
Discovery: 2026-10-04 UAT（実機 Latitude 5330、素の起動、image sha256 f03920c3…、main 52e15c0 の CI の構成＋[config-uat.mk](../uat/config-uat.mk)）、[UAT 2026-10-04](../uat.md)
Handling: [BUG-120](BUG-120.md) の関連を調べる
Evidence: [plan/uat/2026-10-04/](../uat/2026-10-04/)（dmesg・/var/log・session.log・ps・sysctl・Shut Down の間の log）

## 観測

G4: Terminal を多く（30 前後）開くと `errno=8` で起動しなくなる。zedBSD の errno 8 は ENOSPC（`include/uapi/errno.h:29`）。資源の枯渇の候補: GPU の object の枠（BUG-120 の系統）、共有 memory・tmpfs の容量、pty の数。

次: QEMU で Terminal を 30 個開いて再現し、どの syscall が ENOSPC を返すかを見る（ktrace 相当か strace の道具、または compositor・terminal の log）。

## 原因と修正（2026-10-05 P1 generation17 / q725）

- 原因（読み）: kernel の pseudo terminal の数が `PTY_MAX` 8 で固定だった（`src/kern/tty.c`）。`/dev/ptmx` の open は空いた pair が無いと `ENOSPC`（zedBSD の 8）を返す（`pty_master_open`）。Terminal の窓・tab ごと、SSH の session ごとに 1 つ使うので、Terminal を多く開くと 9 つ目からこれで起動しない。報告の「errno=8」と一致する（「30 前後」は数え方の目安と見る）。BUG-120（GPU の object の枠）とは別の根。
- 修正: 上限を `include/kern/tty.h` の `TTY_PTY_MAX` にし、64-bit の kernel は 64、32-bit の小さな board（PC-98・X68000・i386）は 16（1 pair 約 7 KiB の static の memory）。`/dev/pts` の一覧と statvfs の配列（`src/kern/devfs.c` の `indices[8]`）と、`/dev/pts` の directory の entry の容量（`DISK_MAX + 10` だけで、64 の terminal が入らなかった）も `TTY_PTY_MAX` に合わせた。
- 確認: amd64 の vmunix（CI の config）warning 0・kernel include check PASS（`pty_pairs` は 0xe800 → 0x74000 byte）、PC/AT（i386）の vmunix warning 0・contract OK。style-check は増えていない。
- QEMU の試験 `plan/ws073/tests/bug175-guest.sh`（SSH の guest で `/dev/ptmx` を 40 同時に開き、`/dev/pts` に 40 以上、ENOSPC が無い、終われば返る）。T1 に依頼（Q1 経由）。実機は次の UAT（Terminal を 20 以上開く）。
