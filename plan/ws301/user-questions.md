# WS301 ユーザーへの問い（用語と概念から）

2026-10-29 P5。WS301 は「CPU の速さと電力を OS が調べ・変える仕組み」を作る WS。答えてもらった Q301-3・4・5・7 は [ws.md](ws.md) に原文で記録した。残りは 3 つ。

## 前提の用語

- **core**: CPU の中の、命令を実行する単位。5330 の CPU は 10 個の core を持つ。
- **P-core と E-core**: 5330 の core は 2 種類ある。P-core（Performance core、2 個）は速く電力を食う。E-core（Efficient core、8 個）は遅いが省電力。この形を **hybrid** と呼ぶ。
- **周波数（clock）**: core が 1 秒に進む歩数。高いほど速く、電力と熱が増える。5330 の P-core は最大 4.4 GHz、E-core は 3.3 GHz。
- **DVFS**: 周波数（と電圧）を負荷に合わせて変える事。
- **HWP**: Intel の CPU（2015 年の第 6 世代以降）の機能。OS は「最低・最高・性能寄りか省電力寄りか」を伝え、細かい周波数は CPU が自分で決める。5330 は持つ。
- **HAL**: zedBSD の中で CPU の register に直に触る層。HAL の関数の宣言を変えるにはユーザーの承認が要る。
- **1 clock あたりの仕事**: 同じ周波数でも core の設計で 1 歩に進む仕事が違う。P-core は E-core より 1 歩の仕事が多い。

## Q301-1 HAL の追加を承認するか

- 何を決めるか: WS301 が要る HAL の関数（CPU の並びの表 1 つ、HWP の操作 6 つ）を `include/hal/hal.h` に足してよいか。
- 説明の資料: [hal-review.md](hal-review.md)（用語、目的、足す型と関数、機種ごとの扱い、安全の仕組み、判断の点）。
- 決まると変わる事: 承認すれば p003 で HAL を実装し、5330 で設定と読みの試験まで進める。承認しなければ、HAL の要らない部分（表の組み立て・計算の host 試験）だけを進め、5330 の試験はできない。
- 選択肢: (A, 推し) 第 3 版をこのまま承認。(B) CPU の並びの表だけ先に承認（HWP の操作は後）。(C) 今は承認しない。
- 推しの理由: CPU の並びの表だけでは、要求 (1)(3)(4) の「ステップ・設定・取得」ができない。安全の仕組み（拒まれても止まらない、試験が通るまで既定で無効、仮想機械では触らない）を差分の契約に入れてある。

## Q301-2 「一番速い core を 100」の速さを何で測るか

- 背景: 要求 (5) は「一番速い core を 100 としたときの core ごとの性能」。速さの測り方が 2 つある。
  - **最大の周波数の比**: CPU が報告する最大の周波数（P 4.4 GHz、E 3.3 GHz）で比べる。5330 は P-core = 100、E-core = 75。いつも同じ値。1 clock あたりの仕事の違いは入らない（実際の E-core はこれより遅い見込み）。
  - **HFI**（Hardware Feedback Interface）: CPU 自身が「今この core はどれだけ速く動けるか」を表にして memory に書く仕組み。1 clock あたりの仕事も入るが、熱や電力の状態で値が刻々と変わり、熱い時は「一番速い core」が入れ替わることもある。5330 は HFI を持つが、Debian（Linux）はこの機械で HFI を有効にしておらず、値はまだ見ていない（zedBSD が有効にして初めて分かる）。
- 決まると変わる事: WS302（thread をどの core に置くかの判断）が使う値の性質。A なら安定した値、B なら今の状態を映す値。
- 選択肢: (A, 推し) 最大の周波数の比で 100 を決め、HFI の値は「今の使える性能」として別の欄で出す（両方を見られる）。(B) HFI だけで 100 を決める。
- 推しの理由: 「100」の基準が熱で入れ替わると、利用者（WS302・表示）が混乱する。HFI の値も別の欄で失わずに出せる。

## Q301-8 HWP の無い CPU をどう扱うか（ユーザーの問い「HWP は必ずあるのか」への答え）

- 答え: 必ずはない。無いのは、2015 年より前の Intel の CPU、AMD の CPU（AMD には似た別の仕組み CPPC があり、無い機種もある）、仮想機械の中（QEMU は HWP を見せない見込み）、arm64・riscv64（HWP は Intel の機能）。
  手元の Intel の機械（5330、SV7）は持つ（SV7 は世代からの推定）。
- HWP が無い時に OS が何もしないと: 周波数は firmware（BIOS）が残した設定と CPU の自動の制御のまま。壊れはしないが、OS からの省電力の制御が効かない。
- 他の道:
  - **legacy の P-state**: HWP の前の Intel の方式。CPU の register から選べる周波数の段（例 0.4〜2.5 GHz の 100 MHz 刻み）を読み、OS が段を選んで書く。register は CPU の model ごとに違いがあり、HAL の関数が増える。
  - **ACPI の `_PSS`**: firmware の表に「選べる周波数の段」が書いてある規格の道。AMD にも効く。ただし 5330 のような firmware は `_OSC`（OS と firmware の取り決めの呼び出し）を呼ばないとこの表を出さず、`_OSC` はユーザーの決定（Q301-3）で WS310 に回した。
- 選択肢: (A, 推し) この WS は枠だけ（HWP の無い CPU では表は出すが設定は「対応外」）。(B) legacy の P-state をこの WS に入れる（約 +5 LW、HAL の追加が増える、試す機械が手元に無い）。(C) `_PSS` の段を WS310 の後の別の WS で作る。
- 推しの理由: この WS の対象の機械は全部 HWP を持つ。B は試せる機械が無く、C は WS310 が先に要る。要る機械が来た時に別の WS で足せる形（provider の口）にしてある。
