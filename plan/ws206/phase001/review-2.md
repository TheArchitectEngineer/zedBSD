# WS206 p001 第 2 版 review（design-reviewer）— 要点
判定: このままでは p002 に進めない。条件: (1) R1 をやめ 0xfe300000 の SDIO host を別の file に（F1）、(2) WS215 と共有の GPIO・mailbox の helper の Phase と関数の形を今決め両方の Phase 表に依存（M5）、(3) p008 の前に W6 の補遺（core の WPA2 engine との結びつきの全部と FullMAC での扱い、S1）。p003 は E4 の回答待ち、p004・p005 は S2〜S4 の後。
F1 致命: R1（rpi4-sdhci.c を register の層に分ける）が並行の BUG-295（p4、rpi4-sdhci.c +318/−71、transfer_blocks・restore_card・transfer_run_recovering・d_max_transfer_blocks 128）とぶつかる、instance の flag を 0xfe300000 に結ぶと QEMU の SD（src/kern/platform/rpi4.c:82-91）の待ちと clock が変わる、QEMU では rpi4-pcie.c:172 の drv_rpi4_firmware_init まで進まず mailbox が未初期化（ENODEV）、共有で減るのは約 200 行（rpi4-sdhci.c:96-128 の global を全部 instance に）→ SDIO の host を独立の file（例 rpi4-sdio-host.c）、rpi4-sdhci.c は触らず「SD が使った base」を返す小さな関数（例 drv_rpi4_sdhci_base()）だけ共有し claim に使う、SPI 126 の振り分けは小さな共通の dispatcher（M1）、R1 を外し BUG-295 を危険に。
S1 重大: W6 は core と WPA2 engine の結びつき（wlan.c に engine・station->wpa2 の参照 117）を小さく見ている: station_link_lost_controlled は engine IDLE で ENOTCONN（wlan.c:3660）、station_sync_wpa_locked が controlled_port = wpa2.authorized 等を毎回上書き（:2955-2969、report_frame・tx_complete・timer から）、wlan_station_transmit と report_frame が wpa2.authorized を見る（:1166、:1025）、30s の期限は engine の timer だけ（:5149）、retire は engine_stop_needed と connect_driver_active（:2143、:3087）、wlan.h の「Drivers cannot publish AUTHORIZED directly」と plan/master-design-policy.md:191（core が WPA2 と controlled port を持つ）が変わる（Q1 が記録）→ wlan_wpa2_engine_* と同じ面の「FullMAC の engine」を足し station は分岐だけ、またはすべての箇所の表を p008 に。p008 は 6〜8 LW。
S2 重大: scan で report_scan_channel_ready が抜け（core は TUNING で ready が無いと complete を ESTALE wlan.c:713-719、結果も ready の前は受けない :578-588、AX211 は ready intel-ax211.c:4235）→ escan の ioctl が成功したら ready、status 0 で complete、chanspec の control（primary）の channel を解く。
S3 重大: W12 で接続の event の ring が満杯の時の deadlock（bus thread が満杯を待ち F2 の control の応答も読めず、op は control gate を持ったまま応答を待つ）→ 接続の event は generation ごとの latch、fullmac_connect の中の約 8 個の ioctl の 500ms の同期の待ちは ETIMEDOUT で半端な設定と PMK が残る → connect は要求を入れてすぐ返し結果は event で。
S4 重大: 失敗の errno の写し（networkd は EACCES で profile を store が変わるまで再試行しない networkd/main.c:8136、:4659、PSK_SUP の途中の status、4-way の timeout は鍵の誤りか電波か）→ event・status・reason から errno の表を W7 に、鍵の誤りの証拠がある時だけ EACCES、host 試験に。
中: M1 SDIO の IRQ と register（ISR は mutex 不可、INT_ENABLE の bit 8 は instance の irqsave の spinlock、SOFTWARE_RESET_ALL は enable を 0 に戻すので設定し直し、IRQ の番号は DT から（SPI 126 は GIC 158）、card interrupt の取り落としの保険に長い間隔の poll、BUG-295 の次の段で eMMC2 も SPI 126 を登録すると EBUSY → dispatcher に 2 slot）。M2 drv_rpi4_firmware_init が SMP で安全でない（rpi4-firmware.c:130-168、lock 無し、message を公開してから mailbox を公開する間に barrier 無し、WiFi・BT・GPU が同時に呼ぶと壊れる）→ platform の初期化で 1 回だけ呼ぶか lock、GPIO の helper の map も boot で。M3 後から公開する thread と shutdown の取り合い（wlan_station_attach は net_device_gone・shutdown と直列、最大 300s の待ちの間の shutdown の中止の手順、firmware の package が無い時は claim・IRQ・電源を返す）。M4 firmware の file（INODE 60 等）は driver の lock（NETWORK 120 / DISK 130 付近）の前に読む、新しい lock の rank。M5 helper の形の不一致（WS206 W3 は drv_rpi4_firmware_gpio_set(line,state)、WS215 B12 は drv_rpi4_firmware_set_gpio(gpio,state)、line か 128+n か）、作る側が決まっていない。M6 boot の probe が同期（kern_platform_refresh_devices の中で電源の pulse、CMD5 の最大 1s、mailbox）→ thread へ。M7 43455 の save-restore・KSO・clock の要求 → v1 は force HT と記録し p004 で確かめる（推測）。
軽微: NVRAM の位置（長さの語が RAM の最後の 4 byte）を明記、SDPCM の credit に (max−seq)&0x80 の guard、idsup は cap の iovar でも確かめる、set_clock は 2 の冪の分周だけで base clock によって 25MHz にならない恐れ（250MHz なら約 15.6MHz、未確認）、mmcnr の node の status（disable-wifi の overlay）と QEMU の emulated_board の guard、PMK の消去を slot・BCDC・SDPCM の送りの buffer・timeout の経路の全部に、長い待ちは sleep、rpi4-audio.c の GPFSEL4 の移動は不要（範囲外）、userland/firmware/README.md と Kconfig の名前、MAC が NVRAM の仮の値と同じ時は断る。
E2 賛成（.wifi は T1 が試験の時に読み passphrase は SSH の stdin、log・plan に出さない、2.4 と 5 GHz の両方）。E4: DEP-5 の「最後に一致した stanza が勝つ」で debian/copyright の Files: debian/*（GPL-2+）との順序が未確定、どちらの NVRAM でも package に GPL-2 の text と出所の記録を同梱が安全、firmware の bin と CLM は Cypress EULA で可、判断はユーザー（推しは代案 (a) か両方の license を記録）。E6 firmware の既定に賛成、JP は RPi の CLM に JP と rev があるか確かめるまで反対。
段の分け: p002a（GPIO・mailbox の helper、WS215 と調整）、p002b（SDIO の host を独立の file と SDIO の層、CMD5・CCCR・CIS を Pi で、QEMU の起動の回帰）。p008 は S1 の補遺の後、見積りを増やす。
