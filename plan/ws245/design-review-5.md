## 確かめられなかった事

- survey の読みが DC6 の中で安全か: ADL-P の DC_off の domain は PIPE_A を含まない（`power.c:2146-2165`）ので、eDP が pipe A で灯っていても DC_STATE_EN は DC6 になり得る。PSR を使わず pipe が scan out している間は DMC が DC5/DC6 に入らない（推測: PRM・Linux の DC の入る条件を読んでいない）。survey は picture up の後に読むので実害は小さいと見るが、p041（resume の後）や pipe が消えた後に読む形に広げる時は確かめが要る。
- CRC の enable が DC state・DMC・underrun に影響するか（Linux の `crc_enabled` は PSR と FBC を止めるだけ、`intel_pipe_crc.c:306`）。5330 で走らせていない。
- `kern_logf` の console への写し（`klog.c` の mirror）が 5330 の素の起動で serial か framebuffer の console に出るか、出るならどの速さか（B1 の起動の遅れの大きさ）。
- p037 の xd-takeover が GOP の crtc を止めた後、readout（`drv_i915_n1_readout`）が取った power domain の reference を誰が返すか（今は Linux の `intel_crtc_disable_noatomic` の側。`drv_i915_n1_release` の中身は読んでいない）。
- `N0`・`N1` が guardrail の「開発の段の符号」に当たるか（M10）。
- `opregion.c` の SWSCI の通知（`takeover.c:4691`）が今の 5330 で実際に何もしないか（M2。backend "NONE" と check の失敗までは読んだが、走らせていない）。
- build・host 試験・QEMU・5330 の起動は一つも流していない。この review の指摘は全部 code と文書の読みによる。
