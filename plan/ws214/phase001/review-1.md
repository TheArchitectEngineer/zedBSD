# WS214 p001 第 1 版 review-1（design-reviewer）— 要点（全文は Q1 の会話の handback、ここは直しに要る所）
判定: p003 以降に進めない。致命 F1、重大 H1〜H6。第 2 版（F1 を直す、H1〜H6 に設計の答え、直した UAPI の案）を再 review。
F1 1 回の vkQueuePresentKHR で plane ごとに違う srcRect・dstRect を渡せない（VkDisplayPresentInfoKHR は 1 つ、VUID-VkPresentInfoKHR-sType-unique、wsi-swapchain.c:1866-1882 は 1 つを全 chain に当てる、cursor の chain は srcRect=extent でないと INITIALIZATION_FAILED :1906-1917、対象 2 つ以上の present は ordinary の lane present_lane :3648-3651 で B-u・WS213 の前提が壊れる）→ present は plane ごとに分け、原子性は libvulkan の規則と kernel の commit で（例「同じ display の primary の present が kernel に届く前に出た overlay の present は、その primary と同じ 1 つの commit にまとめる」、R は primary を先に続けて overlay、C の窓と cursor は別 present で「同じ refresh」は努力目標として測る）。
H1 core の session の gate（gpu.c:1412-1466・1635 gpu_session_enter、PRESENT_SYNC は settle と採用の待ち最大 2×100ms の間 busy gpu.c:5940-5953、connection は device と node に 1 つで fd 共有、lease は open をまたげない、B-k2 は controller->mutex だけ plan/ws141/phase016/phase.md:502-506）→ overlay だけの COMMIT と CURSOR の op を core の session の gate から外す（handle の表は短い lock）、p003 の範囲に。
H2 settle と EBUSY が mutex を取らない overlay の commit と両立しない（display-flip.c:316-360 settle の前提、採用の IRQ が次の list を publish し続ける :519、100ms で uncertain=true、submit_frame は pending で EBUSY :585-588）→ primary の present も状態に入れて coalesce、settle と EBUSY をやめ、待ちは「自分の primary の世代以上を含む list が採用されるまで」。B-k2 にも同じ穴（WS141 p016 に伝える）。
H3 plane を隠す操作を標準の Vulkan で表せない（透明の画像でも HVS は読む、1080p で 498MB/s）→ 隠し方を決める（例 1×1 の透明な srcRect・dstRect を libvulkan が「隠す」と解釈、swapchain は壊さない）、帯域の予算もそれに。
H4 位置だけの fast path に入らない（transfer_only wsi-swapchain.c:937-939・3697、R が COLOR_ATTACHMENT で直に描くと why=usage、place17 の再発）→ R は焼きを専用の offscreen（p007 の KWL_LAYER_WINDOW の memory を流用可）に描き swapchain の画像（TRANSFER_DST だけ）へ copy、試験は compositor と同じ usage の chain で（p016 u16 の教訓）。
H5 R と C の swapchain の受け渡しが WS213 の不変条件（C は自分専用の swapchain だけ plan/ws213/phase001/phase.md 3.2、park は R と C の両方 4.8）に反する、drag→dock の C→R の返しの手順が無い → 窓の plane の持ち主を移す専用の message（C だけを止めて ack）、WS213 の不変条件の変更として WS213 の Phase に comment。
H6 非同期の採用と画像の解放の経路が無い（GPU_DISPLAY_WAIT は眠らず ETIMEDOUT、同期の primary だけ数える display-device.c:947-977、libvulkan は WAIT の間 display_mutex wsi-display.c:1256-1261、display_image_available は libvulkan の holds だけ :1173-1193、kernel の holds は slot に 1 つで解くのは mutex の下の retire_holds display-device.c:76-77・1592-1628）→ IRQ で採用した commit の sequence を記録し waitq で起こす、holds の解放は thread の文脈、WAIT の意味の変更は UAPI の承認の対象。
中: M1 帯域 1.5GB/s は Linux の load tracker（BCM2835 の頃、BCM2711 に当てはまるか未確認）、1024x600 で約 0.74GB/s（縦の縮小の倍は ceil で 2 を超えうる）→ p003 で underrun を実測してから未決 5。M2 UAPI: fence（wait・signal）が無い（gpu-fence.h:99-105、gpu.c:5925）、gpu_display_present を入れると lease・generation・sequence が二重、cursor が commit に入らない、plane ごとの serial・ticket が無い、ENOSPC を OUT_OF_DATE にすると primary も作り直し（overlay を外して再 commit し overlay の chain にだけ失敗）、overlay_info の flags の bit 未定義、src_x は uint32。M3 C の位置の計算に M の制約（y の下限 lowest、double click の slop BUG-265、shell.c:10133-10146）が無い → 写すか M の値を受け箱に。M4 GPL の出典（WS141 規則 5、HVS5 の scaled の plane の word の GPL でない出典が無い）→ 値ごとに出典、p003 の終わりにも監査、規則の当てはめは Q1。M5 試験: overlay の present に why= の log と本当の usage の fixture、受け入れは kernel の採用の cadence（BCM2711_FLIP_CADENCE）で、「drag の間の submit 0」と時計・帯の描き直し、HVS の重ねと GPU の合成の画素の比較（premultiplied の影）。M6 非同期の経路で clock・cache を触らない（mailbox は眠る、500MHz の下限 display-flip.c:722-731、overlay の画像は uncached、IRQ で clean 不可）。M7 依存: p003 と B-k2 は担当 1 つ、p004 は B-u の Pi の受け入れ、p005 は WS213 p004 の clear に whole-Phase 依存、p015 の UIF の制約は WS141 に comment。
