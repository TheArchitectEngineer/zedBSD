# WS214 p001 第 2 版 review-2（design-reviewer）— 要点
判定: 条件付きで p003 に進める。致命なし。重大 N1・N2 は libvulkan と compositor の規則の誤りで p004・p005 の前に直す（p003 の kernel は止めない）。ユーザーに 9-1（UAPI）を聞く前に N3〜N8 と軽微の UAPI を本文に入れる。B-k2 の部分は UAPI の承認と切り離す（N9）。
N1 重大「次の primary」が kernel に届く順の次（phase.md:145、:364、vkQueuePresentKHR は worker に公開で返る wsi-swapchain.c:687-725、primary の job は GPU を待つ）→ 前のコマの P1 が lane に残る間の切り替えで 2 重・消える。直し: 保留に「保留した時の primary の ticket＋1」を付け、その ticket 以上の primary の job だけが取り込む。p004 の fixture に「primary が lane に残っている時に切り替え」。
N2 重大 保留中の plane への後続の present・保留の寿命・primary が来ない時の期限が無い（:146、:385、:446、:449）: (a) entered の後の C の present が fast path で直に commit → 2 重。直し: 保留がある間はどの present も保留に入れて置き換える。(b) 置き換えられた保留の画像、vkDestroySwapchainKHR、vkQueueWaitIdle・vkDeviceWaitIdle（present_drain）の時の保留の扱い（壊れた chain の保留が後の primary の commit で ESTALE、:369 で primary も失敗）。(c) park で M が plane を隠す（:449）は primary を伴わず保留が残る、出力を閉じる時も。直し: 「primary を伴わない flush」（park・close・破棄・WaitIdle）と期限（例 2 refresh、過ぎたら単独で commit し log）。
N3 中 番号（sequence・adopted）の意味（:225-231、:322）: commit が fence を待ってから記録するので入口で振ると後の番号の fast path が先に採用され WAIT(前) がすぐ返り scanout 中の画像を再利用 → 番号は guard の下の記録の時に振る（state_serial）、adopted は「その番号以下が全部採用済み」、completed は controller 全体（display-device.c:931-934）なので lease ごとか controller ごとかを決める。
N4 中 lease の失効と mutex を取らない commit（display-device.c:811-835、:404-432、:298、:335）: release の始めに guard の下で「失効中」の印、記録の時点で lease・generation・失効を guard の下で再確認、眠る COMMIT_WAIT・WAIT を起こして EBUSY か ENXIO、UAPI の「the output is then recovered as after a fault」（:230）は回復の主体が無いので文を直す。
N5 中 pin が長い・table_lock は waitq の条件の lock に使えない（:296、waitq.h:47 は spinlock、gpu.c:2250-2280、DESTROY は gate を持って待つ、display_destroy_image は display_mutex の下 wsi-display.c:1218-1222）→ fence は core が lookup の前に待つ（gpu.c:5925 と同じ）、pin は retain か記録まで、pin の数と DESTROY の待ちは spinlock、session->resources を歩く所は全部表の lock。
N6 中 clock を下げる競争（:329、display-flip.c:694-702）→ 今の方針（lease の間は下げず console に戻る時だけ）を保つ、または下げる値を mailbox の前に guard の下で公開し記録は clock の mutex の下。
N7 中 3 slot の直し漏れ: cursor の画像 DISPLAY_CURSOR_IMAGES=4（display-device.c:52）→ 5 枚、cursor_named を 3 slot で数える。check_pipeline（display-flip.c:881-882）は next == active を求める。publish_list（display-flip.c:964-968）の PV の status（0x28）の書き込みが未処理の vblank を消す → 差し替えでは触らない、underrun は採用まで止め採用の時に消す（:513）ので drag の間数えられない → 止めずに数える（W1C だけ）。attach の大きさの確かめ（display-flip.c:89 の 0x42c4）を 0x5000 以上に。
N8 中 C の window の acquire（cursor-thread.c:443 は timeout 0 で RETRY、phase.md:392）: 2 枚の FIFO で前の present の採用まで空かない、入力が止まると最後の位置に着かない → RETRY を次の vblank に立てる規則（最後の位置まで必ず出す）。
N9 中 Phase の分け方（ws.md の p003、phase.md:493）→ p003a（gate、3 slot、coalesce、IRQ の採用の記録、既存の op、B-k2、承認不要）と p003b（COMMIT・OVERLAY_INFO・WAIT の変更・scaled・hvs-load、承認後）に分ける。WS141 p016 の受け入れ B は B-k2 が要る時に p003a に依ると Q1 が記録。
N10 中 ENOSPC の再 commit で窓が消える（:369）→ 窓入りの primary を R が描くまで前の状態を保つ（保留ごと捨て primary も出さない）案を検討。
N11 中 copy の経路の PRESENT（:310、display-device.c:76 copies[2]）: 今かもしれない list が 2 つで copy 先の一方は scanout 中でありうる → copy の経路は mutex を残して採用を待つか 3 枚。
軽微: drv_gpu_display_ops に flags が無い（include/drivers/gpu/gpu-display.h:23-61）→ 足す欄と gpu_ops_validate の「optional の組」。「lock を持たずに waitq で眠る」（:308）→ adopted_serial と waitq_sequence を flip.guard の下で読み waitq_sleep(&wq,&guard,...)、WAIT は WAITQ_INTERRUPTIBLE。UAPI の不足: signal_fd を COMMIT_WAIT 無しで EINVAL、同じ plane を 2 回で EINVAL、SHOWN で IMAGE 無し・前の画像も無しで EINVAL、1 つの commit で一部 DROPPED（原子性の例外）。5.1 の srcRect＝dstRect＝窓の矩形（:385）と copy 先の offset（画像の (0,0) なら srcRect は (0,0,w,h)）。8-4（:512）は C0 の間引きで一致しない → 「M の最後の位置との差が 1 回の間引きの分以内」。8-1 の cadence の中央値 ≤17ms は pointer の速さ次第 → 入力の時刻から採用までの遅れか動いている区間だけ、pair は採用の時に数える。scaled の LBM を幅 2048 固定なら 4K で max_src ≤ 2048。
review-1 の判定: F1 部分（N1・N2）、H1 概ね（N4・N5）、H2 解決＋中（N7）、H3 概ね（N2c）、H4 解決、H5 部分（N2a・N8）、H6 部分（N3・N4）、M1 部分（N7）、M2 部分（N3・軽微）、M3 解決、M4 解決、M5 部分、M6 部分（N6）、M7 部分（N9）、軽微 解決（lease の戻しは N4）。
