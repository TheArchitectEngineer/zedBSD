## 目標（2026-09-29 夜 ユーザー）

「IMEですが、基本辞書ができあがったあとで、単語を番号にして、ニューラルネットワークを使い、単語の出現順で漢字変換の同音異義語を学習して、
変換精度を向上させたいです。これは最後の仕上げですね。同様に、形態素解析のニューラル化もやりたいです。日本語の形態素解析では、各文字の間に
単語の境界があるかを予測し、続けて各語の品詞を予測する方法があります。BiLSTMや小型のAttentionモデルで両方を扱った研究では、モデル本体を
15MB未満に収めています。」「IMEの場合は、入力が漢字かな交じり文ではなく「ひらがなの連続」なので、区切りがさらに曖昧です。そこに特化し、
RNNで前後の文脈を見ながら語の境界と品詞を推定する研究もあります。」「zedBSD向けには、辞書で変換候補を作り、小型モデルで区切りと文脈上の
自然さを評価する構成が考えやすいです。形態素解析だけで漢字表記を決めることはできないため、かな漢字変換の候補生成と一緒に設計するのが重要です。」

- WS095 の engine（辞書による候補の生成、`ja-segment.c` の分割、`ja-engine.c`）はそのまま候補を作る側に置き、その上に小型のモデルで
  候補の区切りと文脈の自然さを評価する層を足す。
- 1. **同音異義語の選択**: 語を番号（辞書の見出しと候補の組）にし、語の並び（前の語の列）から次の語の候補の順を決める小型の言語モデル。
- 2. **ひらがな列の形態素解析**: 各かなの間に語の境界があるかと、各語の品詞を、前後の文脈から推定する（BiLSTM か小型の Attention）。
  今の規則（費用の段・助詞の表・活用の automaton）による分割の評価と置き換えるか、併せて使う。
- 大きさの目安: モデル本体を 15 MB 未満（ユーザーの挙げた研究の規模）。

## 設計で決めること（p001）

- 候補の生成（辞書）とモデルの評価の分け方: 分割の lattice を辞書で作り、モデルが境界・品詞・語の並びの点を付けて最良の経路を選ぶ形か。
- 推論: zedBSD の userland で動く自前の C の推論（行列演算、float32 か int8 の量子化）。外部の framework は使わない。入力 1 回の遅れの上限。
- 学習: host で行う（学習の道具と再現の手順、seed、学習物の hash）。学習物（重み）の file の形と置き場所（`/usr/share/kei/ime/ja/`）。
- 学習の data（corpus）の出所と license、重みの license（**ユーザーの判断が要る**）。
- 評価: WS095 の 100 文と held-out の文、分割の正しさと第一候補の正しさ、辞書だけの engine との比較。
- 利用者の学習（WS095 の `ja-user.c`）との関係。
