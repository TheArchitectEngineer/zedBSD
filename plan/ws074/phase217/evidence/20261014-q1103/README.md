# q1103-i01 — vertical-lr inline text layout boundary

The fixed [q1102 reports](../../../phase189/evidence/20261014-q1102/README.md) leave style-changes 007/008 at 0/6 subtests. Each first assertion compares the width of a vertical-lr item containing one Ahem `É`: expected 20/40/30px for the three `font-size` values, observed 100px for each. The WPT parent is a horizontal inline-grid with a 100px column, 50px rows, `justify-items:baseline`, `text-orientation:sideways`, and `line-height:1`. q1092's independent `XXXX` host case observed 100×13 for the in-flow Grid child with a horizontal 24px text fragment.

The current path in `layout/grid.c` forces all non-horizontal children to `justify=stretch`; `grid_lay_item` then gives an auto-width item the 100px physical column. `layout/inline.c` uses a horizontal `cutter.width`, packs fragment advances along x, stacks lines down y, and stores only `line.y`/`fragment.x`. `layout/paint/list.c` creates horizontal `PAINT_TEXT` with x pen advances. Layout bounds, hit-testing and dumps also interpret fragments horizontally. `writing-mode` is inherited in CSS cascade, but `text-orientation` is not represented in the CSS property table. Thus changing Grid stretch alone cannot supply a vertical line width, its height, baseline, rotated glyph paint or coherent geometry.

[CSS Writing Modes §3](https://drafts.csswg.org/css-writing-modes-3/#vertical-typesetting) defines vertical inline progression and [§5](https://drafts.csswg.org/css-writing-modes-3/#text-orientation) specifies sideways glyph orientation. The next design should introduce a vertical line/fragment geometry representation shared by inline layout, paint, bounds/hit/dump, then map an orthogonal Grid item's logical inline/block sizes to physical height/width. The first implementation Queue can be restricted to a single unwrapped text run with `vertical-lr` and `text-orientation:sideways`, explicit height, no floats/atomic descendants; verify 20/40/30px physical widths and 50px height in a non-Grid block before Grid alignment. Follow-up Queues handle Grid auto width/baseline group, wrapping, mixed orientation, and absolute children. Avoid treating the narrow first stage as full vertical-writing conformance.
