# q1179-i01 — orthogonal positioned Grid failure split

[Classification](classification.json) reads the unchanged q1177 fixed Grid502 raw callbacks for `positioned-items-with-margin-border-padding` 006–010 and `non-static-positioned-items` 007–012, 11 whole FAIL files. In all 11, the first horizontal parent callback fails on a vertical child's width: expected 10/40/26 px versus actual 60/90/76 px, respectively, always a 50 px content-width excess. The next horizontal callback has the same width pattern. The vertical-lr callback instead first fails on offsetTop, and vertical-rl first fails on offsetLeft. Every file has four FAIL callbacks in q1177.

The WPT originals vary child margin, border and padding, and the final file of each series also frames the parent. The split appears before those variations: `non-static-positioned-items-007` has no frame and already fails width10→60. Its horizontal Grid has direct vertical-lr/rl absolute children; its vertical Grid has horizontal and opposite vertical absolute children. `margin-border-padding-006` begins with child margins and the same orthogonal pattern. Explicit physical insets are used in the non-static series, while the margin/border/padding series has all-auto insets.

Source inspection identifies three relevant paths:

1. `layout/inline.c` `inline_vertical_absolute_grid` accepts only a parent with the same or opposite vertical writing mode. A horizontal Grid's vertical absolute child therefore misses vertical text geometry and is measured as horizontal width60 instead of width10. `inline_vertical_room` also reads vertical Grid column tracks only; an orthogonal horizontal Grid requires definite row-track height as inline room.
2. `layout/grid.c` `grid_static_vertical_start` accepts same/opposite vertical child modes, so a vertical Grid's horizontal absolute child retains the container corner instead of its definite area. The first vertical callbacks consequently have top/left differences. The horizontal Grid path in `grid_static_position` already supplies a definite explicit area.
3. `layout/position.c` `position_place` calculates shrink-to-fit width and offsets from the area supplied by Grid. It can retain this common path once the appropriate text geometry and static area are provided; no separate WPT-specific offset is justified by current evidence.

Next bounded implementation candidate: a horizontal fixed 2×2 inline Grid with a direct vertical-lr absolute ASCII child, explicit row/column span1 and one physical inset.
