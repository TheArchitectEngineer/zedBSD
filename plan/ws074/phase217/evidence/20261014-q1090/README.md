# q1090-i01 — RTL Grid absolute static position design

The fixed WPT `grid-column-axis-alignment-positioned-items-001.html` has a 400px RTL grid with columns 100px/150px. Its first four absolute children use explicit `grid-column` and `grid-row`; the first column's inline-start edge is the grid's right edge. WPT expects offsetLeft 340 for a 60px child in that column, and 230 for a 70px child in column 2. The q1089 result still reports offsetLeft 0 for the RTL subtest. The row-axis representative has the same RTL failure. These are WPT relative offsets, not viewport coordinates.

The [minimal fixture](rtl-static-cases.html) has two 400px RTL grids with direct absolute children in row 1/column 1, once with 20px fixed width and once with auto width (`XXXX`, measured 24px). [Host layout output](rtl-static-cases.layout.txt) gives both children the grid's physical left edge x=8 (second grid y=178). Their expected x positions under inline-start alignment are 8+400−20=388 and 8+400−24=384 respectively. The fixture confirms that the width is available only after the out-of-flow child's layout; text auto width is measured as 24px in the dump. This is a minimal geometry diagnosis, not a WPT result.

`layout/grid.c` initializes all out-of-flow children to static_x/y=0, then q1089's `grid_static_position` assigns track origins only for horizontal LTR. The in-flow RTL path computes physical track x from the tracks after the item's column; it also applies `justify-self` after item sizing. `layout_absolute` adds the grid content origin to the child's static_x. Later `position_place` lays out/shrink-to-fits the absolute child, then uses `static_x + margin-left` when both horizontal insets are auto. Its current static_x represents a left edge. For RTL inline-start the required left edge is `area_right − used outer width`, unavailable when `grid_static_position` runs. Encoding this by pretending a right inset is explicit would change containing-block/sizing semantics and explicit-inset behavior.

The next finite implementation should retain the area's inline-start edge as private layout metadata on the direct child, including a flag for right-edge origin, while Grid still excludes it from sizing/auto placement. For valid definite explicit tracks in positioned horizontal RTL Grid and both axes auto insets, Grid computes the physical area right edge from sized tracks/gaps/content distribution. `layout_absolute` translates that edge with the grid content origin. `position_place`, after the existing width calculation, derives the border-box x by subtracting the used border/padding/content width and right margin from the right edge. Explicit insets, invalid/auto lines, other writing modes, and non-Grid boxes retain their current path. The first implementation should cover start alignment only; other `justify-self` values and vertical writing need separate scope and tests. Care is needed to avoid double-applying margins and to keep the Grid content width and containing-block width distinct when tracks use only 250px of a 400px container.

Proposed q1091 bounded scope: implement this private RTL right-edge static position for direct absolute children with valid definite explicit Grid row/column, horizontal writing, start inline alignment, and both axis insets auto; verify fixed/auto-width minimal cases, the two fixed WPT horizontal RTL subtests, the q1089 LTR/explicit-inset/invalid-line fixture, old PASS sentinel, classic JS, warning0 host build, and fixed Acid3/Acid2 pixel non-regression. No full Grid recensus or vertical/other alignment claims. The existing q1087 Grid502 **103 PASS/399 FAIL** remains the latest uniform result.
