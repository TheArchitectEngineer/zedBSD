# q1100-i01 — vertical Grid style-changes boundary

The [fixed q1099 reports](../../../phase219/evidence/20261014-q1099/README.md) leave four vertical-writing IDs. In vertical-rl 003/004, explicit width and height assertions pass; failures are `offsetLeft`. In vertical-lr text 007/008, all 12 callbacks first fail width: expected 20/40/30px, actual 100px. The [official WPT sources](https://github.com/web-platform-tests/wpt/tree/2d66b9b7998bb58c336138c178323ddee857b586/css/css-grid/alignment) show 003/004 empty children with explicit widths and 007/008 Ahem text with auto widths. These are distinct layout paths.

| Case | Fixed failure pattern | Relevant current path |
| --- | --- | --- |
| 003/004 vertical-rl empty items | In the baseline group, border left x40 before exclusion of the 50px item with 10px horizontal margins; remaining 20/30px items move to x70 when that item changes to `justify-self:end`. That excluded item then sits x40. | `layout/grid.c` first sets `justify=stretch` for any non-horizontal child. Explicit widths avoid size corruption, but the later x alignment block ignores baseline for vertical children and positions their left margin edge at the grid area's start. |
| 007/008 vertical-lr text items | Every width expected 20/40/30, actual100; x assertions are never reached. | `layout/grid.c` forces stretch for non-horizontal children, then `grid_lay_item` sizes auto width against the physical 100px column. `layout/inline.c` formats text horizontally; q1092 host fixture observed a 24px horizontal line. |

The 003/004 offsets imply a baseline-sharing group whose common border-left x leaves room for the widest participating item through its right margin: before, x=100−(50+10)=40; after excluding that item, x=100−30=70. The `justify-self:end` item's own border-left x is 100−(10+50+10)+10=40. This is an inference from these fixed assertions, not a general vertical-writing algorithm. [CSS Align §9](https://drafts.csswg.org/css-align/#baseline-export) defines grid-item synthesized baselines from border edges and groups items in the same column for justify-axis alignment. A bounded next implementation can support a horizontal Grid container with one definite pixel column, vertical-rl empty direct children of explicit pixel width, column span1 and baseline preference, while preserving excluded/end placement. It must retain horizontal old PASS and Acid3 exact. Text 007/008 requires a separate vertical inline formatting path and logical sizing; the empty-item fix cannot make them PASS.
