Source trace: `layout/inline.c` still rejects every out-of-flow root in `inline_vertical_simple`, so the new vertical inline geometry never reaches these absolute children. `layout/position.c` calls `layout_max_content` and then lays out the auto-width absolute box at its measured width. The fixed Grid column heights can supply bounded vertical inline room, but only after the out-of-flow restriction is narrowed for a suitable absolute child. Separately, `layout/grid.c:grid_static_position` returns immediately for every non-horizontal Grid, leaving vertical absolute area origins at defaults. These are separate prerequisites: fixing text width alone will expose or leave static x/y errors. Row-axis017's RTL horizontal offset requires its own evidence-based decision.

It should verify the physical 10×60px text box, bounds/hit/paint and first width assertion, while preserving horizontal and non-positioned behavior. Vertical Grid static area placement and whole WPT clearance then require a separate Queue.
