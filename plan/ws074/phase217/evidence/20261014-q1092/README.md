# q1092-i01 — vertical Grid failure boundary

After q1091, both fixed positioned-item WPT files have horizontal LTR and RTL subtests PASS but their vertical-lr/vertical-rl subtests FAIL. In both files the first failure is the first absolute child's width: expected 10px, observed 60px. The official WPT source declares `writing-mode: vertical-lr`/`vertical-rl`, columns 100px/150px, rows 150px/100px, and Ahem text `X XX X`. Its expected first child is 10px wide and 60px tall; its expected grid offsets also show that logical columns run vertically and rows horizontally.

The [minimal vertical-lr fixture](vertical-grid-cases.html) uses a 250×250 positioned grid and `XXXX` in both an in-flow child and an absolute child at column 1/row 1. Its [host dump](vertical-grid-cases.layout.txt) shows an in-flow child 100×13 at (8,8), an absolute child 24×13 at (8,8), and a horizontal text line of width24 in both. The text uses the fixed 10px monospace font. The in-flow child is stretched to the physical 100px column width; the absolute child remains a horizontal line. This fixture isolates three missing behaviors rather than claiming one Grid-specific fix.

`layout/grid.c` always sizes `grid.columns` against physical width, `grid.rows` against physical height, and computes column x/row y. For any non-horizontal writing mode, it forces in-flow `justify` to stretch. Its `grid_static_position` deliberately skips vertical writing. `layout/position.c` lays out absolute text in physical horizontal width and has no vertical inline-size mapping. A source scan of `libbrowser` found `writing_mode` use in CSS inheritance, Grid and part of Flex/position, but no use in inline text layout. [CSS Grid](https://drafts.csswg.org/css-grid/#grid-concepts) defines columns along the inline axis and rows along the block axis; [CSS Writing Modes](https://drafts.csswg.org/css-writing-modes/#vertical-typesetting) specifies vertical typesetting. The current implementation therefore needs a cross-layer vertical inline layout path, Grid track axis mapping, and absolute static-area alignment. Removing only the forced-stretch line would change one symptom while leaving the text and track axes wrong.

Next bounded vertical work should begin with a separate horizontal-vs-vertical inline text layout design and a minimal text/line test, then map Grid tracks/placement and absolute area; each part needs its own finite implementation and old horizontal/Acid regressions. The two positioned WPT whole files cannot clear until all layers work. Meanwhile Grid shorthand and other independent failure groups can progress without this prerequisite. The `grid.c` file header still describes absolute static origins as horizontal LTR only after q1091; correct that documentation with the next code edit.
