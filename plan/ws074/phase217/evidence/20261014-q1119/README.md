# q1119-i01 — inline-grid auto width diagnosis

The fixed q1118 column-axis 012–016 reports share a horizontal RTL failure: `offsetLeft` expected190/actual948. Their WPT source uses `display:inline-grid`, 100px+150px explicit columns, auto width and no in-flow items. A [host layout dump](host-layout.txt) of 012 shows both horizontal `.grid` boxes at **1008px** wide, with the first RTL absolute child at physical x987 (fallback fonts differ from WPT Ahem). The WPT expectation instead uses a 250px intrinsic Grid width. The browser's viewport-filling auto width explains the large RTL offset; the first LTR Grid's left-side placement hid it.

The source path confirms the cause: `css/values.c` maps `grid` and `inline-grid` to the same `CSS_DISPLAY_GRID` enum. `layout/box.c` marks only inline-block/inline-table as atomic, so inline-grid enters block layout. `layout/block.c` resolves its auto width against the containing block (1008px here). The existing atomic path uses `layout_shrink_to_fit`, and `layout_content_width` already reports `grid_content` as the explicit tracks' width. `layout/box.c`, `layout/block.c` and `layout/position.c` compare `CSS_DISPLAY_GRID` in Grid-specific handling; a distinct `CSS_DISPLAY_INLINE_GRID` would have to be included in those checks while retaining inline-level/atomic behavior. The `offsetLeft` binding subtracts a positioned offset parent's box and does not itself account for the width change.

The next bounded implementation can preserve `inline-grid` as a distinct display enum, mark it atomic, route it through Grid item/layout/intrinsic-width paths, and verify a minimal auto-width 250px case against block-grid controls. Recheck the fixed 012–016 RTL callbacks, old Grid PASS sentinels, CSSOM display values, host build and Acid. This diagnosis does not assert that every remaining RTL case will pass until measured. [Direct-file load errors](host-errors.txt) are limited to `/resources` scripts absent under a file URL; the dump is only layout evidence, while the fixed HTTP WPT reports remain authoritative for callbacks.
