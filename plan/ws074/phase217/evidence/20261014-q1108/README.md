# q1108-i01 — positioned Grid self-alignment boundary

The fixed [q1105 Grid502 raw reports](../../../phase189/evidence/20261014-q1105/README.md) contain 17 whole FAIL files each in column-axis and row-axis positioned-item series. [Horizontal matrix](horizontal-matrix.json) pairs their first two horizontal LTR/RTL subtests and two vertical subtests with exact assertion messages. In the column-axis series, 20/34 horizontal subtests fail; in the row-axis series, 26/34 fail. All 68 vertical subtests first fail physical width expected10/actual60 and depend on [p220](../../../phase220/phase.md) and vertical Grid axes.

Column-axis files 002/005/007/009/011 form a bounded first candidate: `align-self:end`, `center`, `flex-end`, `self-end` all fail only `offsetTop` in horizontal LTR and RTL, at expected140/70 against actual0. Files 012–016 combine other direction/position cases and are left separate. In `layout/grid.c`, `grid_static_position` sets `static_y` to the area's top for every horizontal absolute child. In `layout/position.c`, `position_place` uses that y after it computes the child's shrink-to-fit width/height, without consulting `align-self` or the area's height. Therefore end/center needs the definite area's vertical extent and the final child margin-box height at placement time. A private Grid-only static area height/alignment flag can carry this; explicit top/bottom insets must continue to win. The first implementation can limit to horizontal Grid parent/child, definite explicit area, both vertical insets auto and end/center values in files 002/005/007/009/011. It should keep q1089/q1091 start placement, RTL x, and old PASS cases.

The row-axis series requires a separate inline-axis alignment design, including RTL physical edges and the q1091 right-edge static metadata. Neither series can whole PASS until its vertical subtests work. The classification is a causal design boundary, not a claim that all 34 files share one fix.
