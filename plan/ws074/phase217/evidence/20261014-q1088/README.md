# q1088-i01 — Grid alignment failure diagnosis

The [fixed q1087 Grid census](../../../phase189/evidence/20261014-q1087/README.md) has 206 whole FAIL IDs under `css/css-grid/alignment/`. [Classification](analysis.json) groups file names and normalizes failure messages. The labels overlap: 64 failed IDs contain `positioned`, 45 `vertical`, 43 `baseline`, and eight `style-changes`. Across these IDs, 1,109 failed subtests mainly report width (465), `offsetLeft` (363), `offsetTop` (203) or height (64) mismatches. Those counts identify symptoms, not one shared cause.

Three representative cases show separate general defects:

1. `grid-column-axis-alignment-positioned-items-001.html` expects its second-column absolute child at `offsetLeft=100`, but reports 0. The [minimal fixture](minimal-abspos-grid.html) specifies a 250px positioned grid with 100px/150px columns, 80px/80px rows and a 20px absolute child in column 2, row 2. Its [layout dump](minimal-abspos-grid.layout.txt) places the grid at (8,8) and the child at (8,8); the grid area begins at (108,88). In `layout/grid.c`, out-of-flow children receive `static_x=static_y=0` and `grid_collect` skips them. `layout/position.c` uses those static coordinates when both corresponding insets are auto. This explains the minimal failure and is a likely contributor to the positioned family. [CSS Grid Level 1](https://drafts.csswg.org/css-grid-1/#abspos-items) and [CSS Align Level 3](https://drafts.csswg.org/css-align/#staticpos-terminology) define the specified grid area as the relevant rectangle when the grid container establishes the absolute containing block.
2. `grid-self-alignment-stretch-vertical-lr-001.html` expects its first child width 10 but reports 100. `layout/grid.c` explicitly changes `justify` to `CSS_ALIGN_STRETCH` whenever the grid or child writing mode is not horizontal. This matches the oversized physical width. Vertical writing needs axis mapping and sizing rather than that unconditional override; one WPT result does not establish all vertical cases.
3. `grid-alignment-style-changes-001.html` expects 50px tracks but reports a 1008px child width. The test sets `grid: 100px / 50px 50px 50px`; `css/values.c` recognizes `grid-row`, `grid-column` and `grid-template-*` but has no `grid` shorthand property. The [minimal shorthand fixture](minimal-grid-shorthand.html) and [layout dump](minimal-grid-shorthand.layout.txt) reproduce three 1008px items instead of three 50px tracks. This is a parsing gap separate from the absolute-placement and vertical-writing gaps.

Next finite implementation candidate: for a positioned grid container with a direct absolute child, both physical insets auto and valid definite grid line placements in horizontal LTR writing, derive its static area origin from the final track offsets without allowing the child to size or auto-place tracks. Verify the minimal fixture, the horizontal WPT positioned representative, explicit-inset preservation, classic/Acid regressions, then measure the affected fixed IDs. RTL/vertical axes, auto/invalid lines and broader alignment stay as separately bounded work unless the general algorithm covers them safely. No claim that all 64 positioned IDs share this one cause.
