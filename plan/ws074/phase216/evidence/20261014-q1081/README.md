# q1081-i01 — module graph implementation boundary

The fixed Grid 32 no_output IDs all import the same `runTests` function from one support module ([q1078](../../../phase189/evidence/20261014-q1078/README.md)). After [q1079](../20261014-q1079/README.md) and [q1080](../20261014-q1080/README.md), a standalone source with `export function` executes, but the engine does not retain a module instance or resolve imports.

## Source constraints

- `js/compile.c:js_compile` currently turns a parsed program into a closure with a NULL environment; `compile_prologue` creates a fresh environment only when nested functions capture bindings. `scope.c` places uncaptured module declarations in temporary registers. A live exported binding must instead have a stable slot retained after evaluation.
- `vm/bytecode.h:vm_env` has GC traced parent and slots; `vm/function.c:vm_env_create` initializes slots and retains its parent. `vm/code.c:code_trace` traces constants, so an import instruction can keep its target environment as a code constant. `VM_OP_GET_ENV` already reads a named slot through an environment register. This avoids a new VM opcode for an indirect import read. Import writes must reject assignment, and lexical reads must preserve the existing uninitialized check.
- `js/parse_stmt.c` already yields import specifiers, module URL string, and export declaration/specifier nodes. `js/compile.h:js_binding` has kind, location and captured state. Link information can be added as an internal binding kind plus target module environment/slot; resolving names by copying export values would fail live-binding semantics.
- `page/script.c:script_type_runs` skips module elements. `page/page.c:page_load_document` finishes parsing and immediately calls `page_fire_load`. A deferred module queue must evaluate after `html_parser_finish` and before DOMContentLoaded, while classic scripts keep their parser behavior. `page_resolve_location` and `page_fetch` already resolve and fetch relative resources; each dependency must resolve relative to its own module URL. Page-owned entries and GC roots must survive network callbacks and be removed on page teardown. The module map must key canonical URL and evaluate each module once.

The indirect immutable import binding and uninitialized error are specified in [ECMAScript 2025 modules](https://tc39.es/ecma262/2025/multipage/ecmascript-language-scripts-and-modules.html); the non-async HTML module script waits for parsing to finish, according to the [HTML Standard](https://html.spec.whatwg.org/dev/scripting.html). This design follows those semantics; the code above is existing implementation evidence, not yet a proof of conformance.

## Finite implementation sequence

1. **Export environment (next Queue):** keep a module program's top-level exported bindings in a stable `vm_env` owned by an internal module instance. Reuse that environment as the compiled program closure's outer environment rather than allocating an inaccessible one in its prologue. Expose read-only internal export name → slot resolution after parsing/linking. Verify exported closure captures the same mutable slot and GC retains it after the module returns. Keep plain `--js --module` behavior and classic scripts intact. No HTML or imports in this step.
2. **Linking/imports:** parse the graph and allocate each module environment before evaluation, resolve named exports and imports, and compile import reads against the target environment/slot through the existing `LOAD_CONST` + `GET_ENV` operations. Reject writes and unresolved/duplicate bindings, preserve TDZ, evaluate dependencies once with cycle handling. Verify a module mutation is observed by its importer, cross-module errors and GC stress. Add `export {}`/re-export/default only in separately bounded scopes if needed.
3. **HTML loader:** queue parser-inserted non-async module scripts and fetch their graphs using each module URL as base; execute before DOMContentLoaded, preserve classic order, same-origin/MIME/error behavior, and page teardown roots. Then run fixed `positioned-grid-descendants-001.html` and the remaining 31 IDs under the existing WPT callback runner. A callback with FAIL is coverage progress, not a PASS.

Open architecture risks for implementation: module namespace property access is needed for namespace imports and dynamic `import()`, and top-level await needs asynchronous graph evaluation; neither is exercised by the 32 fixed Grid files. Those features remain p216 residual work for broader Interop 2025. The next Queue should select only export environment work and its own verification, without treating the full 32-ID outcome as achieved.
