# q1149-i01 — vertical-lr implicit auto Grid diagnosis

All eight fixed Interop 2025 [`grid-self-alignment-stretch-vertical-lr-009`–`-016`](analysis.json) were remeasured through the same WPT checkout `2d66b9b7998bb58c336138c178323ddee857b586`, selected manifest, localhost HTTP, three host fonts, 5 s settle and 20 s process bound. All eight remain whole FAIL after q1148. `analysis.json` retains the exact ID hash, expected item rectangles from the WPT source, and first actual failure. Cases 009–012 use vertical-lr children; 013–016 use horizontal-tb children. 010–012 and 014–016 add physical margins. All have a 250×250 definite vertical-lr inline Grid with implicit auto rows and columns.

The first failure in each case is physical width: 009 expects 20 and gets 125; 010–012 expect 20 and get 115; 013 expects 80 and gets 125; 014–016 expect 80 and get 115. The 20px width is vertical text's line width; 80px is horizontal Ahem text's inline width. The 125px value is the auto track share, which the item incorrectly stretches across even when `align-self:start` specifies its block-axis intrinsic size.

The independent [2×2 minimal page](auto-grid.html) has the same logical row/column placement and self-alignment without WPT scripts. zedBSD [reports](browser.txt) `a=0,0,125,20|b=125,0,125,20|c=0,20,125,20|d=125,20,125,20`. Host Chromium 153 [reports](chromium-measure.txt) `a=0,0,20,125|b=0,125,125,48|c=125,0,20,48|d=125,125,125,125`. Fonts differ, so 48px is not used as a zedBSD acceptance number; the x/y track mapping and stretch axis differ independent of font. WPT's fixed Ahem expectations supply exact acceptance geometry.

`layout/grid.c:grid_vertical_fixed` handles only explicit fixed px tracks and auto physical height; the 250px/implicit auto cases enter the old horizontal path. That path sizes logical columns from physical `box->width`, puts columns along x, then forces `justify` to stretch for non-horizontal writing mode; `grid_size_rows` grows physical y. `layout/inline.c:inline_vertical_room` also requires fixed parent columns or a definite child height, so vertical text inside an auto-grid item falls back to horizontal line geometry. This is a shared axis/sizing defect, not eight unrelated alignment exceptions.

Next finite implementation should first support 009 and 013 (no margins): vertical-lr/LTR 2×2 implicit auto tracks, definite 250×250 content box, gap0, span1, in-flow nonreplaced auto-size children, start/stretch alignment. Size logical columns on physical y and rows on physical x from appropriate content contributions; distribute positive free room to auto tracks; provide the resolved column height to vertical text layout before measuring/placing it; keep the child's own writing mode for intrinsic size. Verify minimal page against Chromium for axes and both WPT whole PASS, then old 001–008, horizontal WPT, host, Acid. Margin variants 010–012/014–016 require a later scoped extension. Avoid using the hard-coded 125px expected share: margin variants have 120/130px splits.
