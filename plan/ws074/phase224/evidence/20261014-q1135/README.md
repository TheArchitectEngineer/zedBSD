# q1135-i02 — Grid track animation regression diagnosis

The fixed q1134 raw reports show 178 `grid-template-rows-composition.html` and 238 `grid-template-rows-interpolation.html` subtests changed PASS→FAIL. Example composition expectation `120px calc(130px + 4%)` gets the underlying `50px 10%`. The WPT helper `css/support/interpolation-testcommon.js` computes the expected value by setting a separate target's inline style, then compares it to the actual target's `getComputedStyle(...).getPropertyValue(property)`. Its CSS animation method creates `@keyframes` and sets animation name/duration/delay/timing; its Web Animations method requires `Element.prototype.animate`.

Git commit `7a5a135b3` added `COMPUTED_GRID_TEMPLATE_ROWS` serialization in `bind/computed.c`. Before that, `getPropertyValue('grid-template-rows')` returned empty for both actual and expected targets, making the earlier PASS a false positive for animation behavior. Source search found no CSS `animation-*`/`transition-*` parser or keyframe cascade and no Element.animate binding. The [minimal probe](animation-probe.html) prints [plain=50px, animated=50px, elementAnimate=false](probe-output.txt). The current nonempty computed value exposes the missing animation behavior. Replacing the current computed value with empty would hide failures and is not a repair.

Finite next implementation must add real CSS Animations/Transitions and Web Animations support through the general animation/style computation path, beginning with a narrowly selected property and fixed WPT subset. Grid track-list interpolation and composition need typed track values and discrete behavior where lists are incompatible. This requires a separate design and validation scope; q1135-i02 was read-only diagnosis. It is partial cleared; p224 whole and p189/p173 all-focus targets remain uncleared. Shared projection/GitHub publication pending with Q1; no push.
