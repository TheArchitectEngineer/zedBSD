# q1144-i01 — bounded vertical-lr inline geometry

The bounded `layout/inline.c` path maps nonwrapping Latin text in vertical-lr/LTR text-only blocks to physical coordinates. It accepts one line or explicit `<br>` lines only when each line fits a definite physical inline room: a pixel height on the block or the shortest fixed column of the bounded inline-grid parent. Floats, atomic/replaced descendants, markers, other writing modes, and overflowing runs retain the prior path. `position.c` derives physical intrinsic width from the stacked line widths; bounds, hit testing, and layout dump interpret logical line/fragment coordinates in physical axes.

The [minimal fixture](vertical-inline.html) changed from [before](before.txt) span `single-text=9,8,36,13` and `multiple-text=9,110,36,23` to [after](after.txt) `single-text=9,9,10,36` and `multiple-text=9,111,20,36`. [Layout dumps](before.layout.txt) and [after](after.layout.txt) show one 10px wide line and two 10px wide lines. [Hit checks](hit.txt) return `single-text` at (14,14), `multiple-text` at (24,120), and the enclosing `single` block at (50,50). The [20px height overflow fixture](vertical-inline-overflow.html) [falls back](overflow.txt) to the old horizontal geometry, so this partial path does not claim wrapping support.
