# q1067-i01 — GC crash during CSS Grid WPT completion

Pinned WPT `/css/css-grid/grid-items/grid-minimum-size-grid-items-021.html` crashed the plain browser with SIGSEGV in all three normal runs under q1066/q1067 (return -11, 144 result callbacks, no completion). Two gdb runs changed the symptom to normal completion, so the first gdb result was not accepted as a fix. The pre-fix ASan run (`asan-report.json`) found a heap-buffer-overflow in `vm_heap_mark` at `vm/heap.c:322`, reading 24 bytes before a manually allocated realm record. The GC assumed that every pointer outside small-cell blocks referred to one of its large allocations. The Window global retains its manually managed realm pointer in `internal` for named-property lookup; tracing that pointer as a GC large cell caused the invalid read.

The fix checks the heap's registered large-allocation table and exact cell address before marking an external pointer. It leaves manual realm ownership with the page. No WPT, runner or public ABI changed. The fixed WPT now exits 0 and returns completion in three plain runs and one ASan run; each test outcome is correctly `FAIL` because CSS Grid assertions still differ. The post-fix ASan stderr contains no sanitizer error. The original q1066 process-error row remains historical and is not rewritten.
