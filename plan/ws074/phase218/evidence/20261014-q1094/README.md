# q1094-i01 — CSS `grid` shorthand diagnosis

The [fixed q1093 Grid502 census](../../../phase189/evidence/20261014-q1093/README.md) still has 399 whole FAIL files. A [literal source scan](literal-scan.json) finds a `grid:` text pattern in 90 selected files: 83 FAIL and seven PASS. This is an **upper bound on possible affected files**, not 83 proven shorthand-caused failures: a text match may be in a selector, script, attribute or comment, and files often have other unsupported features.

Three fixed WPT examples separate the missing behaviors:

- `/css/css-grid/alignment/grid-alignment-style-changes-001.html` has `grid: 100px / 50px 50px 50px` in a stylesheet. Its q1093 raw report says the first three items each have width1008 instead of expected50. The [minimal static fixture](grid-shorthand-cases.html) gives the shorthand grid two 1008px wide children stacked in separate 16px rows, whereas equivalent longhands produce two 50px columns in one 80px row; [host dump](grid-shorthand-cases.layout.txt).
- `/css/css-grid/grid-definition/grid-shorthand-001.html` tests `grid.style.grid = "100px / 200px"` while gap remains 10px/20px. Its first subtest already fails because an unspecified computed `grid-template-*` serializes as empty rather than `none`; after assignment it gets `none` instead of expected200px for columns. Parsing and computed-style defaults both matter.
- `/css/css-grid/parsing/grid-shorthand-serialization.html` uses `auto-flow`, dense, repeat, `grid-template-areas`, CSSOM round trips, and shorthand serialization. Its raw report gets `undefined` for many properties. This is broader than a two-track static parser.

`css/values.c` has property names and parser branches for `grid-template-columns`, `grid-template-rows`, `grid-column`, `grid-row`, and `grid-area`, but no `grid` or `grid-template` shorthand name. The existing shorthand parser expands tokens into longhand declarations in source order before cascade. Neither `grid-template-areas` nor `grid-auto-flow`/`grid-auto-rows`/`grid-auto-columns` is an implemented longhand, so a complete shorthand requires those properties and CSSOM serialization as later work. [CSS Grid Level 1 §7.8](https://drafts.csswg.org/css-grid-1/#grid-shorthand) specifies that `grid` sets three explicit and three implicit grid longhands and leaves gutter properties unchanged. Unsupported values must be rejected as one declaration; accepting a valid-looking prefix would create incorrect computed styles.

Next bounded implementation scope (q1095): recognize only the explicit rows/columns form `grid: <supported track-list> / <supported track-list>` or `none / ...` where both sides are already valid `grid-template-rows`/`columns` grammar; expand atomically into those two longhands in the existing order/cascade path. Preserve row/column gaps; reject `auto-flow`, named areas and malformed input as an entire declaration. Verify static shorthand-vs-longhand geometry, preceding/following longhand precedence, an invalid declaration, the fixed static WPT representative's width subtests, existing Grid and CSS parser tests, warning0 build and Acid pixel non-regression. This is deliberately partial because the engine has no implicit-grid longhands to reset yet. A follow-up must implement all six longhands and CSSOM behavior before p218 whole can clear. Correct `grid.c`'s stale file header during that code edit (it still says horizontal LTR static origins only).
