# ws141-p016 (b) 第 2 版「0 埋めの見直し」review（design-reviewer、7f2a15f0e）
結論: このままでは不可、H1・H2・M1 を書き足せば可。今すぐ実装してよいのは overflow・tile の pool・upload の chunk・shader の code の 4 つ。canvas の変換先と snapshot の pixels（TFU が書く物）は H1 の後。
H1 storage の cache は controller 全体で 1 つ（render-device.h:73、render-device.c:70）、cache_take は大きさだけで選び種類も session も見ない（native-storage.c:551-573）→ 前の中身に別 client の窓の画素・頂点・uniform が入る。CPU の変換は padding まで 0 にする（native-texture.c:239-243）が TFU の経路（vulkan-native-draw.c:505-506、459）は storage の memset（native-storage.c:85）に頼る（:516 も）。UIF の padding は最後の column の右端・最後の block row の下端（native-texture.c:45-47、1180 幅で 4px）。TFU が padding を書くか・TMU が読むかは未確認。Mesa の BO cache は process の中だけで kernel の新しい BO は 0（記憶）。直し: (a) cached view に前の使用者の session の印、同じ session の時だけ埋めない（熱い経路は compositor の 1 session）(b) TFU が書く物は padding の部分だけ CPU で 0、または実機で目印の pattern → TFU → padding を読んで確かめる。安全の文を種類ごとに「読み得る全 byte をこの使用の中で書く」の証明に。
H2 defaults の storage（vulkan-native-draw.c:679-685、256B、w だけ 1.0 で x・y・z は 0 頼み）が表から漏れ、同じ allocate_storage（:271-307）を通る → 埋めるかは呼び出し元ごとに明示の引数、defaults は埋める。表に全部の呼び出し: native-storage.c:220（code）・:443（snapshot）、vulkan-native-draw.c:296（呼び出し元 :495 変換先・:638 code・:679 defaults・:1236 大きい upload と独立の draw）、:1256（chunk）、vulkan-native-pass.c:593（呼び出し元 :628/632/636/640/645/671）。meta の draw（pool が NULL）の upload は埋める。
M1 埋めない種類も GPU に渡す前に全体を clean することを明記（失敗の途中で dirty な line が残る: vulkan-native-draw.c:530-548 の prepare_sampler の ENOTSUP、:750-765 の attribute_encode の失敗、view は native-storage.c:288 で cache に戻る）。今は vulkan-native-pass.c:679-683、vulkan-native-draw.c:461・517・1263、native-storage.c:234 で clean。省くなら cache_put で dirty な line が無いことを不変条件に。
M2 1 pass の固定の埋めは overflow 1MiB（vulkan-native-pass.c:671）と pool 約 0.53MiB（native-pass.c:99-101）。代案: overflow は binner の OOM の時だけ（v3d-job.c:599-603 feed_overflow）→ controller に 1 つの reserve を worker が持つ（pass は 1 つずつなので共有可）。clean の費用も見る。計数: bcm2711_buffer_zeroed（native-storage.c:88、buffer.c:267-275）は使い回しの回数・bytes・時間を一緒に数える → 埋めない使い回しは別の計数。
M3 計測（vulkan-stream.c:170-175、render-runtime.c:310-325）は「合計の hold が最大の request の中で一番長い command」→ request の command の数を足し、全体で一番長い 1 command の opcode と時間を別に。preempt・IRQ で wall の時間が膨らむ外れ値に注意。
L1 list の image を埋める理由が誤り（native-bin.c:82 は draw->bin の CPU の配列、encoder は bin の全部を書く native-pass.c:174・vulkan-native-pass.c:658・native-pass.c:180、大きさ :105、render と tile は全体を memset :183-184）→ 根拠の文を直す。L2 tile state は v3d-job.c:349、約 64KiB で埋めるままでよい。L3 upload の chunk の枠の 24〜31B は古いまま、uniform 0 個の 4B の placeholder（vulkan-native-draw.c:653-656）は書かれない → placeholder に 0 を 1 word、native-storage.c:233 の注記を直す。
安全で実装してよい: overflow と pool（bin が失敗すると render を投入しない v3d-job.c:358-363、654-655）、upload の chunk と code（M1 の clean を残す前提）。HAL 不要。
試験: host で cached view を 0xA5 で埋めて draw・pass を作り、GPU が読む範囲に目印が残らない・defaults の x・y・z が 0、Pi（T1）で TFU の padding を読む試験（線形 filter と REPEAT・CLAMP）。
