# ws141-p016 (B) 第 3 版 review（design-reviewer、85f1c32c6、phase.md:214-234）
結論: 方向は妥当（kernel が中身の同じ cursor を写さない、libvulkan が中身の変化を自分で知る）。ただし C1・C2 で目的に届かない。実装可否: kernel の (3) は M3 を直せば先に実装可。libvulkan の fast path は C2・H1・H2・M1・M2 を入れた版を再 review の後。受け入れ B は C1（(b)・A3・compositor の直し・測り方）が済むまで判定不可。

致命的
C1 fast path の前に compositor の main loop が render の mutex を待つ。(1) cursor-plane.c:416-419 は copied が 1 の間毎回 vkGetFenceStatus（sync.c:211-213→890-901、device->mutex の下で GPU_OP_GET_FENCE_STATUS の同期の往復、(b) の待ち 113〜168ms と全 session の FIFO の後ろ）。copied は :475 で 1 にした後 open・close 以外で 0 に戻らない → Q1 が main で直した（10ae7a26e: SUCCESS を一度見たら copied=0）。(2) main loop は cursor の更新（display.c:192）の前に adopt_commit、その import・shm（import.c:353、shm.c:392・882）が vkQueueWaitIdle、frame の描画（display.c:208）の vkBegin/EndCommandBuffer も同期（commands.c:416・465）。(3) 受け入れ B の input_us（damage.c:68）は compositor が入力を処理した時刻で main loop の停止を検出できない。直し方: 段の表に B の前提として (b) と A3、import・shm の WaitIdle の扱いを入れる。受け入れ B は evdev の timestamp と present の時刻の差・present の間隔で測る。
C2 条件 (d) と queue ごとの worker（wsi-swapchain.c:2685、primary と cursor が同じ compose->queue cursor-plane.c:464・496、primary の job は fence を UINT64_MAX で待つ :2779）。像の変化の後に copy の job が残ると (d) で位置だけの present も通常経路 → 10ms ごとに job が足され drain より速い → pointer が止まるまで fast path に戻らない（icon の point・drag の場面）。直し方: (a) cursor の lease ごとに present の受付で ticket を振り、display の層は適用済みより古い ticket の SET・MOVE を捨てる（F6 を解く）か (b) cursor の chain の job を他の chain を待たない別の worker に。加えて (b)(c) が成り立ち (d) だけが不成立の時は通常経路でも GPU の copy を記録しない。追い越しが安全な理由（M1 の不変条件）を書く。

重大
H1 判断の位置と lock。present_record（:1857）は vkResetFences（:2061）・GPU_FENCE_QUERY（:2097）・Begin/End（:1907・1928）を含む → 判断は present_prepare の検証（ACQUIRED、cursor の rect :1716-1725、results）の後・present_record の前。display_present_cursor は display_mutex（wsi-display.c:1780）、worker は primary の PRESENT_SYNC の間 display_mutex を持つ（:1079-1150）、kernel の output_present は adoption 待ちの間 controller の mutex（display-device.c:843-921）、CURSOR_SET・MOVE もその mutex（:1637・1714）。device->mutex の下は status・payload の消費・serial の比較だけ、外してから ioctl。後始末は present_finish(job,...,submitted=TRUE)。SET の失敗は chain->error に latch（:2785-2795）。条件に swapchainCount==1、wait の重複なし、results[0]==VK_SUCCESS。
H2 (d) と位置は chain でなく lease ごと（wsi-display.c:64-79 の lease は旧と新の swapchain で共有、pending_jobs は chain ごと :1846）。display_position（:1804-1824）と display_present_cursor の位置の読み（:1782-1783）が別の区間。直し方: 位置と像を 1 つの op（present_cursor_at(lease, image, x, y, ticket)）で 1 回の display_mutex の区間、worker も同じ op。(d) と ticket は lease に。

中
M1 serial の置き場・初期値・更新の時点・lock。group の image は oldSwapchain で共有（:796-808）、native の image は chain ごと（presentation[] :1293-1327）→ content_serial は group の image、copied_serial は chain の presentation。copied_serial の初期値は「未コピー」。更新は fence の待ちが成功した後。控えは copy の受理と同じ device->mutex の区間。submit の受理で進める方式は正しい（native の image に書くのは WSI の copy だけで、image が再 acquire 前に退役 present_finish :2425-2426）— この不変条件を明記。
M2 hook の範囲。api-commands.tsv に Copy/Blit の「2 版」は無い（:95-138・184-192）。vkQueueSubmit2KHR は vkQueueSubmit に変換（sync2.c:155〜）、WSI の内部の submit（wsi-swapchain.c:2220）、WaitIdle の空 submit（queue.c:218）も queue_attempt を通る → 加算は queue_attempt の受理（queue.c:461-473、device->mutex の下）の 1 か所。「分からない」は device ごとの epoch、fast path は serial と epoch を比べる。ExecuteCommands の溢れは epoch で閉じる。hook は表の列で dstImage を宣言。書き込みの経路は usage の制限で塞がる（attachment は COLOR_ATTACHMENT vulkan-target.c:443・vulkan-native-pass.c:401、STORAGE は不可 vulkan-resource.c:23、BindImageMemorySwapchain・export は無い）。
M3 kernel の鍵（F7）。書き込みは「書いてから generation++」（v3d-memory.c:333-334、vulkan-buffer-copy.c:285-291、render-device.c:445、display-device.c:582-591）→ CURSOR_SET の memcpy（display-device.c:1673-1677）の前に guard の下で generation を読む。鍵は memcpy の後に flip の結果に関わらず更新。vulkan-buffer-copy.c:284-291 は resource_backing の失敗で memory_written を呼ばない（書かないか進める）。UAPI の注記（include/uapi/gpu-display.h:237-248）に「変わらない storage は写しを省くことがある、host_mapped は常に写す」。「各 image は最初の 1 回だけ写す」（phase.md:231）は保証されないので記述を直す。
M4 試験: libvulkan の WSI の host fixture が無い（偽の render・display の kernel の見積もり）。場面: 負荷の下で像の変化の後も fast path に戻る（C2）、oldSwapchain と lease の共有（H2）、fast path が ioctl の間 device->mutex を持たない（H1）、copied_serial の初期値と新しい chain（M1）、generation を memcpy の前に読む（M3）。
M5 段: B の行に (b)・A3・compositor の直しへの依存を。kernel の (3) は別の小段。

軽微
L1 primary の present の間、cursor の SET・MOVE と acquire（wsi-display.c:1166）が 1〜2 refresh 待つ見込み、計測項目に。L2 CURSOR_SET が native の image の run を CPU で読む、cacheable で V3D の書き込みの後に invalidate が無いと古い line（写しの省略の後に残る）— run の cache 属性を確かめる。L3 i915・Venus は影響なし（HAS_CURSOR は bcm2711 だけ display-device.c:655）。
