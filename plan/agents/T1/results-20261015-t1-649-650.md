- raw の結果（ユーザーが中央と四隅を tap、時刻 777〜803 s）:
  - **release は報告されている**: 各 contact に `ABS_MT_TRACKING_ID -1` と `BTN_TOUCH 0`（`KEY 0x14a 0` 24 回、down 25 回、最後の 1 つは buffer の欠け）、続けて SYN。tap は 約 0.07〜0.15 s、move 3〜14 回。slot は 0 と 1 を使う（指 1 本の tap は slot 0）。tracking id は 232 から単調増加（260 まで 29 個、すべて対で release あり）。
  - **座標が端で飽和して 0 / 16383 になる**: 左端で X=0（id 234〜240 ほか）、右端で X=16383（id 232・242〜248・256・258・259）が多数。
  - **Y の最大が 6446 までで、9599 にならない**: 下の隅の tap は Y 5000〜6445（id 249 15751,6373、250 2528,5848、260 15785,6445）。declared 9599 に対し、実際の panel の Y は約 0〜6450 の範囲に見える。中央付近の tap は (7449,5261) など。つまり座標の正規化に declared の Y 最大 9599 を使うと画面の下 1/3 に届かない。
  - 上端は Y=1〜78（id 238〜240）。上端からの swipe は Y が 1 から増える形で始まる（edge 判定の入力は正しく上端に見える）。
  - 左端・右端に飽和しているのは、X の実範囲が 16383 を越えているか、端の tap が clamp されているためで、どちらかは raw では区別できない。
- 判定は P2 へ: (1) event4 が残る件（keyboard の collection）、(2) Y の実範囲と declared の差、(3) X の飽和。
