# WS213 p001 第 2 版 review-2（design-reviewer）— 要点
結論: S1 条件付きで可（op の list・同じ所での再生・等価の試験・walk の費用の計測・遅延作成の open への移動に絞る、shm の memcpy の持ち主・host image の書き込みの規則・写しの目標は S1 の op の形に固定しない、WS211 P3 との順は Q1）。S2 今は不可（K1・H-a〜H-e を入れ M-a・M-b・M-f を直して再 review）。HAL・UAPI 不要。
K1（Critical）写しを捨てる経路が残る: walk（4.1 の 2）が acquire（4.1 の 3）より先、acquire の OUT_OF_DATE・SURFACE_LOST（compose.c:561-582）や park（表示が取り上げられ acquire が成功しない）で描かれない写しが生まれる。巻き戻らない副作用: layer の decided_anim・keys・valid・inflight（layer-cache.c:262,279,626-627）、shot の SHOT_RECORDED（shot.c:339）、import の layout の list（import.c:186-197）、shm の写しと release、dirty・pointer_moved・home_start_pending、damage の履歴。直し（推奨）2 段の pull: M は「描く物がある」の印だけ → R が出力と heads を上限付きで acquire し「image k と取れた heads の mask」を付けて「次をくれ」→ M はその image を前提に walk。acquire の失敗・park で写しが生まれない、heads の条件の区間が不要、damage は今の buffer age、時刻のずれも消える。採らないなら abandoned の完了の記録と副作用ごとの巻き戻し。
H-a walk の中から R へ同期の依頼をすると deadlock（3.2 の backdrop）。walk の間 R は待っていて Vulkan を呼ばないので M が作ってよい → 不変条件「R は待ちの間 Vulkan を呼ばない、walk の中の M の作成・破棄は許す」を明記し同期の依頼をやめる。walk の外の同期の依頼（kwl_shot_tick）は R の 1 コマ全体（最大 533ms）止める。
H-b p004 の host image（staging）の書き手: IME の tick（main.c:801 → input-method.c:307 → ime_current :2621 → kwl_home_field_state home.c:1236 → glass_text_width glass.c:1847 → glass_cache_glyph、kwl_host_image_written glass.c:2983）、色の emoji（glass.c:3234）、壁紙の loader（glass.c:648→821/1091）、landscape（:451）、resize（:493）は vkDeviceWaitIdle の後に CPU で書く。kwl_host_images_record と kwl_host_image_written は atomic でない競合、書き途中の staging を GPU が写す。Mesa では walk の外の vkDeviceWaitIdle が外部同期の違反 → host image への書き込みは walk の中か park の中だけ、glass_text_width を metrics だけにする変更を p004 に前倒しか walk の外の raster を禁じる、壁紙・landscape・resize は p004 では park、R が写す list は walk の時に写しへ取り込んだ物。
H-c R の shm の memcpy と client の pool_resize（shm.c:521、munmap :542）が競る、release を完了まで遅らせると 2 枚の shm の client が待たされる → memcpy は M の walk の中に残す（推奨）、release は写した直後。
H-d cursor の plane（M）が wl_shm の cursor の staging を直に読む（cursor-plane.c:310、:678、:532）→ cursor の surface の shm（64×64 以下）は作成も書き込みも M が同期で、退役は plane の fence も待つ。
H-e 「この WS が単独で保証するのは main の止まりが無くなること」（ws.md:34）と食い違う（M の cursor の present は R の vkQueueSubmit の device->mutex の区間 queue.c:422〜、End の decode の context->mutex 11〜19ms を待つ、recorded→queued 最大 24ms）→ 受け入れを「M の止まりは R の 1 transaction 以内、present_max が閾値以下」に、または cursor の plane の present を専用の小さな thread に。
M-a H4 未解決: park は fence 次第、libvulkan に上限の無い待ち（queue.c:345-363、sync.c:1103-1108）、M の park の ack の待ちに上限が無い → 上限を付け超えたら device lost・failed、acquire の途中の park は K1 の形で。
M-b 完了の記録と「次をくれ」の順 → 1 つの順序付きの通り道、次をくれは完了の記録の後。
M-c H2 の表の漏れ: output-switch.c:98-104（hotplug の fence）、:441、kwl_heads_sync（output-switch.c:89-91,149）、cursor-plane.c:534 の vkWaitForFences 等、shot.c:359 の vkMapMemory、shot_finish の解放（shot.c:414-415）、shm.c:387-392、scene.c:41-67、layer-cache.c:807。
M-d §6「plane が無い出力（Linux・FreeBSD）」は未確認（kwl_cursor_plane_open は platform で分けない cursor-plane.c:43-100）→ Mesa の build の queue_lock は WaitIdle 系と M の cursor の経路も。
M-e p005 の glyph の待ちの上限切れ → 待ち切るか「glyph が未着」で layer を無効。
M-f 試験に K1・H-a・H-c・H-d・H-b・M-b の場面、thread を使わない手順の試験で交互の順を 1 歩ずつ。
