# WS213 p001 第 3 版 review-3（design-reviewer）— 要点
結論: S1（p003）条件付き可（cursor の形の起動時の作成は host image の batch shm.c:354-392、p004 に進む walk の費用の閾値を数値で、p003〜p006 の phase.md に受け入れの条件 L-7）。S2（p004）今は不可（H-1〜H-3、M-1〜M-4 の後に再 review）。HAL・UAPI 不要。
H-1「ready を受けたら必ず walk」が frame pacing（display.c:224-235、compose.c:725-731）と食い違い、want が古いまま残る（client の絵が 1 コマ遅れ、変わらないコマを余分に描く、不要な焼きを先に）→ ready は「描いてよい」の知らせに留め walk を強制しない（M は自分の schedule で walk、R は k を持って待つ、M は取り消しでも答えられる）、want に番号、試験 (b) に pacing・古い want・種類の食い違い。
H-2 R の heads の acquire が M の状態を読み書き（heads.c:316-361 kwl_heads_acquire → heads_needs_frame 1111-1140、kwl_heads_present 459-496 の head->dirty=0・lost=1）、park で slot が再利用されると mask の bit が別の head を指す、出力だけ作り直しで head の image が漏れる（heads.c:499-503）→ M が want の時に要る head の slot と世代を want に入れ、R はそれだけを timeout 0 で取り結果を返す、dirty・lost・missed は M が当てる、head->dirty は M が walk の時に下ろし失敗の時だけ立て直す、park の後は世代が変わった slot の bit を落とす。
H-3 H-d の「cursor の shm を commit の時に同期で作成」が H-a を破る（image_create shm.c:786-819、image_layout 831-886 の compose->pool・vkQueueSubmit＋vkQueueWaitIdle、host_images の list shm.c:796-797、set_get :801、vkQueueWaitIdle queue.c:108-127 が R のコマ全体最大 533ms を待つ、host image の copy compose.c:2790-2800 と staging の競り）→ cursor 用の shm の画像（plane の大きさ以下）を R の起動前か park の中で固定数用意、commit では memcpy だけ、書く前に plane の copy と出力のコマの両方の完了を確かめるか 2 枚を交互、大きさの変わる作成は次の walk の中。
M-1 acquire の失敗で R が空回り（wsi-swapchain.c:3060-3064）→ 失敗の時 R が want を下ろし M が立て直すまで acquire しない、want の持ち主・立てる・下ろす規則を 4.2 に。
M-2 park の失敗の後始末（compose.c:443・815、cursor-plane.c:121）と同期の park での M の止まり → park の失敗は後始末せず log と _exit、同期は session の pause と終了だけ、他は非同期で parked を FIFO で受けてから。
M-3 H-e の判定が自分の数字で満たせない（recorded→queued 最大 24ms、End の decode 11〜19ms、acquire の signal の device->mutex sync.c:429、plane の vkWaitForFences 100ms cursor-plane.c:534、timeout で vkDeviceWaitIdle :121、import の context->mutex）→ 判定は plane の全段の最長と walk の外の M の Vulkan の最長、cursor の専用 thread は最初から p004 に入れるか別 Phase にして共有する物を設計してから。
M-4 試験で競合を見つけられない → Linux の build の ThreadSanitizer を p004 の受け入れに、H-1・H-2・M-1・M-2 の場面を足す。
M-5 park の後の同じ k と Mesa の acquire の semaphore の再利用（compose->acquired は一度だけ compose.c:1386-1390、zedBSD は software_signaled sync.c:436-438）→ park で image を手放したら acquired（と head の acquired）を作り直し、k の有効性は swapchain の世代で。
M-6 p003 の前提: cursor.c:378-382 は起動時の全部の作成で READY が遅れるので遅延作成（10 枚 24×24、kwl.h:73、cursor.c:84、1 枚ごとに vkQueueWaitIdle shm.c:879-881）→ batch でまとめる、p003 の受け入れに数値の基準。
Low: L-1 walk・park の中の vkQueueWaitIdle・vkDeviceWaitIdle は WSI の worker の present の drain を待つ（queue.c:108-155 → wsi-swapchain.c:617-647、2715-2790）、M の止まりの見積もりに。L-2 shm の memcpy を walk の中だけにすると release が遅れる、output_lost の間 client が待つ → 飛んでいる copy の list に無い surface は walk の外でも memcpy と release 可（作成は walk の中）。L-3 3.2 の shot の行の文言。L-4 未着の glyph は cell の割り当ての順に書く。L-5 plane の失敗の経路（cursor-plane.c:121・126）の close も park に。L-6 output_lost・switch_proving（compose.c:2826-2853）を M が知るのは完了の記録の時、KWL LAT の定義に。L-7 p003〜p006 の phase.md に受け入れの条件・確認の上限・コマンド。
