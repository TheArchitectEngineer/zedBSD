# WS213 p007 K-1・K-2 review-1（design-reviewer）— 要点
判定: K-1 はこのまま実装しない（K1-1 を直し再 review、K-D の Pi で候補 1 が出た時）。K-2: (a) は (b) に含める、(b) は「範囲の確かめを fault より前に locks の下で」の形なら K-D を待たずに実装可、(c) は前提が成り立たず落とす、(d) は仕様を書き直して再 review（K-D で waits 多・hold 短の時だけ）。順の推し: (1) K2-1 の mutex_lock の直し → (2) K-D の報告の重さ（report_us）を足して Pi の 1 boot → (3) K-2 (b)（(a) を含む）と 1 CPU で mutex_spin_take を飛ばす → (4) 直した K-1 → (5) 直した (d)。
K2-1 重大（既存の欠陥）: mutex_lock（src/kern/lock.c:350-352）は mutex_lock_interruptible を EINTR の間繰り返し、mutex_sleep_take(WAITQ_INTERRUPTIBLE)（lock.c:324）は signal の保留・terminate_requested・stop で眠らずに EINTR（waitq.c:107-134）→ 256 回の見直し→guard→EINTR を忙しく回る、1 core で quantum 10ms まで CPU を握り持ち主が走れない（client の終了時の vmspace の後始末、signal の届いた thread の copyin）。直し: mutex_spin_take の後に guard を取り mutex_sleep_take(mutex, 0, &error)（割り込み不可）で眠る（mutex_wait の再取得と同じ形）。
K1-1 重大: 持ち分が実時間でなく次の tick で尽き、尽きた thread は sched_preempt の queue_prepend（sched.c:830-832）で run の頭に LIFO → I が走り始めた直後の tick で降格し他の woken の quantum の後になり得る。直し: 持ち分は走り始めの counter からの実時間（例 1ms 以上）か「走り始めてから 2 回目の tick」、降格は preempted の区間の尾に FIFO。host 試験に「走り始め直後の tick」「降格が 2 つ以上」。
K2-2 重大: (d) の handoff の仕様不足（exchange(FREE) lock.c:382・mutex_wait lock.c:429・mutex_sleep_take の exchange(CONTENDED) lock.c:526 が HANDOFF を消す/無視、HANDOFF を立てる時の競合 FREE|HANDOFF、消す規則が無い、取り損ねた待ち手は waitq の尾に戻る waitq.c:149-157、waitq_wake_one が void で頭を取り出し owner を書く API が無い、起きた待ち手は waitq_sleep の全部の戻り waitq.c:166-218 で exchange の前に owner==self）→ 状態の表と CAS の遷移を書いて再 review、KERN_TEST_CHECKPOINT で guard を外す窓 waitq.c:110-112・206-208 の場面。
中: K2-3 (c) の前提不成立（vmspace_destroy vmspace.c:6871-6911 が metadata だけで regions を書く）→ 落とす。K2-4 (a) で確かめを外すと pin の fault（vmspace.c:1919-1928）が先に起き副作用が変わる → (b) に含め locks 1 回で vmspace_check_locked→全 page の準備の確かめ→pin、準備が無い時だけ外して fault（metadata の入りは N page で N+2 回、vmspace_pin_mapping_ready vmspace.c:5381-5440）。K1-2 K-1 は mutex を持つ thread の tick の横取りを増やす（sched.c:1066-1114）→ K2-1 と (b) の後に、host 試験に mutex を持ったまま横取り。K1-3 古い印で同じ優先度の run の thread を選ぶ（sched.c:819-822）→ 自分以上の woken の頭か厳密に高い run だけ。KD-1 K-D の報告が user へ戻る任意の thread で同期に kern_logf（1 文字ずつ、klog.c:120-147、rpi4.c:221-228）→ 次の行に report_us=、または報告と重なる CURSOR_LAG に印。K2-5 (d) の優先度と SMP（USB_BT_SCO_PRIORITY usb-bt.c:1787）。
軽微: K1-4 持ち分は woken に入れる時だけ、steal（sched.c:2443・2553）と sched_set_cpu（1698・1724）で消すか I1 を直す。K1-5 (a)+3 と比べていない。K1-6 印を使う所は kern_preempt_enable（sched.c:661-672）を入れて 4 か所、i386・m68k・sparcv9 は HAL_TIMER_FREQUENCY 100 で K-1 は効かない。K2-6 触る file（uaccess.c・vmspace.c・lock.c・waitq.c）を範囲に。K2-7 trylock の利用者（file.c:717,1200,1268,2699,3150、readahead.c:285,294、unix-socket.c:1677、vm.c:4166,10292）。K2-8 1 CPU で mutex_spin_take の 256 回を飛ばすのは正しい、K2-1 と一緒に。
確かめた: WS208（agent/p2）は MI の kernel を変えていない、K-D は main。未確認: Pi の kernel_putc の費用、signal 保留中・終了中の metadata lock の競合の頻度、poll_notify の herd の N。
