# VF2 の PowerVR の driver の速さ: 分かっている事のまとめ（2026-10-21 夜）

ws270-p007 の一日分の調べを、外部の目で読み直してもらうための要約。詳しい経過は [phase.md](phase.md)、
[notes-p1.md](notes-p1.md)（job・firmware・DDK との register の比較）、[notes-p2.md](notes-p2.md)（compiler・Mesa pco との比較・pairing）。

## 1. 構成

- 板: StarFive VisionFive 2（JH7110、RISC-V U74 ×4）、GPU は Imagination PowerVR BXE-4-32（BVNC 36.50.54.182、Rogue）、display は Verisilicon DC8200。
- zedBSD 独自の driver: kernel の中に Vulkan の executor と SPIR-V → USC の compiler（`src/drivers/gpu/powervr/`）。firmware は Imagination の
  rogue の firmware（mainline の linux-firmware と同じ物）。user mode driver（Mesa 流）は無く、libvulkan が ioctl で kernel を呼ぶ。
- compositor は Keiland（`userland/desktop/wayland/`）、swapchain は LINEAR の B8G8R8A8 を DC8200 が zero copy で scanout（CPU の copy なし、
  確認済み）。Keiland は damage（buffer age・scissor）、不透明な面の下を描かない、opaque region を持つ。
- 比較の相手: 同じ板の Linux（StarFive 6.12.5）で IMG の proprietary DDK 1.19@6345021（libVK_IMG）。同じ vkmatrix（`userland/tests/vkmatrix/main.c`、
  host の gcc で Linux でも build）で計測。

## 3. 一日でやった事と効果（順）

1. Keiland: 64 draw ごとの job の分割（全画面 LOAD 4 回）を driver で 512 draw に、glyph の batch、窓の不透明な所の下を描かない、opaque region → desktop 390 → 300 → 160 ms。
2. compiler: 死んだ代入・copy 伝播・FMAD・.sat・blend の簡約・shared/literal の直読み → Keiland の fragment の group 数が Mesa pco の 0.2〜0.9 倍。flat 15.7 → 9.2 ms（396 MHz）。
3. ALU の phase 0/1 に独立の 2 命令を詰める（pairing）と 12 命令先までの並べ替え: mul4 54 → 36 ms（396 MHz）→ issue 律速を確認。
4. Mesa と同じ PPP（varying base を出さない、pds_tempsize 0、DISABLE_PIXELMERGE）: draws4 19 → 16 ms。
5. 空 tile の skip（ISP の process_empty_tiles を落とす）・background の tag を切る: 効果小。
6. firmware の trace を HWR だけに（全 group の記録で firmware の時間が倍）、firmware（MIPS）の code を cached に: small の job の TA 640→160 us、3D 608→190 us。
7. job の memory の使い回し・shader の code を pipeline ごとに 1 回・draw の buffer の作り直しと clear を無くす: job の build 1.4 → 0.2 ms。
8. GPU の clock 396 → 594 MHz（Linux の vendor と同じ）: ALU 系は 1.5 倍。
9. APM 100 ms、SLC 64-byte interleave、firmware の data cached: 効果なし。

## 4. 否定された仮説

- GPU の memory の read が遅い（perf-read で追加 0）。
- SLC（DDK も TPU・PBE・ISP などは SLC を bypass、`SLC_CTRL_BYPASS 0x00001D1F01000000` を両方で確認）。register（CLK_CTRL・SLC_CTRL_MISC・BYPASS）は DDK と同じ値。
- FBCDC（圧縮）: DDK で LINEAR と OPTIMAL の差は 0.4〜0.6 ms だけ。
- tile の数・三角形の数・parameter buffer・TA（TA は小さな job で約 160 us）。
- temps・occupancy（fragment の temps を 48 に固定しても同じ）、dual-phase、精度（lp の形で同じ速さ、F16 の SIMD は ISA に無い）。
- PDS が texture を読む（Rogue の PDS に DOUTT は無い）。
- shared の DMA の待ち（push・descriptor を PDS の DOUTW で直に書いても flat 4300 のまま）。
- dust の電源の on・off（job の間も入れたままで TA が 140 us 減るだけ）。

## 5. 残る差と今の仮説

- **pixel あたりの shader の費用**: DDK は flat − clear ≈ 0.1〜0.3 ms、texture − clear ≈ 1.0 ms。zedBSD は 2.0 ms と 6.0 ms。
  - 1 group は全画面で約 0.45 ms（594 MHz）＝ 1 clock あたり約 8 lane。BXE-4-32 の 32 FLOPS（8 lane × FMAD 2）と合う、と読んでいる。
  - immediate（2 group）は clear と同じ時間、push4 の flat（4 group、うち PACK rpt4 が 4 slot）は +2 ms。rpt4 の PACK・UNPACK は回数分の issue を使う。
  - 仮説（P1 q1546 で実装中）: DDK は uniform だけで決まる計算（push の色の pack、glass の 1/screen 等）を draw ごとの shared の program に移し、
    pixel ごとの shader はほぼ MOV だけ。
  - texture: zedBSD の texture.frag は約 8 group（iterate、smp、WDF の待ち、pack、blend の unpack と計算）で +6 ms。DDK は +1 ms。
- **小さな job の固定費**: DDK clear-64 348 us に対し zedBSD 1100〜2000 us（GPU の中は TA 160＋3D 190 us、残りは CPU 側と完了の通知）。
- **clear そのもの**: DDK 1219、zedBSD 2200〜2300（同じ background object の clear）。

## 6. 測り方の注意

- 時計: zedBSD の vkmatrix は 1 ms 刻みの時計で平均（min が 1000 の倍数）。外れ値（SD の I/O の止まり）が時々ある。DDK 側は us の時計。
- kernel の switch は compile の define なので、1 つずつの比較は板の再起動が要る（SD の不調で 1 回 5〜10 分）。
- 板の SD の read の失敗（BUG-343）は新しい card でも出る → driver 側の疑い。
