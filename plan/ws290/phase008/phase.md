## 設計の決定（p008 の helper、P3 の判断を頼む）

design §11.4・§14・§18 の p008 の範囲で、design に値の無い所を次のように決めた。p009 が使う取り決めを含む。

- **heap と配置**: executor heap の block は全部 `GHCI_VM_FLAG_EXEC` で map する（`vk-memory.c` の `heap_grow`）。pipeline は heap の 1 つの run: [PSO 128 byte（128 揃え）][VS（か CS）の code（64 揃え）][FS の code（64 揃え）][set 3 の driver の表 32 byte（spill する program が有る時だけ）]。scratch は別の run で、stage ごとに `RESIDENT_WARPS[15:0]` × program の bytes per warp（64 揃え）。表の 0x00・0x08・0x10 に VS・FS・CS の scratch の番地（`pipeline->table_va`、無ければ 0。p009 は 0 でなければ set 3 に bind する）。`RESIDENT_WARPS[15:0]` = 0 の device で spill する pipeline は断る。
- **fragment stage の無い pipeline**: compiler に `ghci_gsi1_empty_fragment()`（`gsi1-compile.c`）を足した。命令は `addi r0, zero, -1`・`exp r0, 0x105`・`end` の 3 つ、used_regs 7（rasterizer が書く r0〜r6）。仕様（§12.10.3）は「movi rT, -1 と exp rT, 0x105 の 2 命令」と書くが、compiler は -1 を addi で作り、どの program も end で終わるので、compiler 自身の終わり方に合わせた。
- **texsz.s**: compiler の program の flag に `GHCI_GSI1_FLAG_SAMPLE_QUERY`（bit 3、PSO の flag ではない）を足し（`gsi1-texture.c` の `emit_texsz`）、CAP_MSAA の無い device では pipeline を断る（p006 の review の L4）。
- **断り方（U8）**: pipeline の作成で分かる不足は全部 `VK_ERROR_OUT_OF_DEVICE_MEMORY` と log（「pipeline refused: 理由」、device の最初の 64 件）: VS と FS の slot の和 > 16・資源の表 > 128 entry/4096 byte・属性 > 60 register（compiler の拒否）、色の attachment > MAX_MRT、SRC1 の blend factor で CAP_DUAL_SOURCE 無し、logicOp で FEATURE[11] 無し、attachment ごとに違う blend で MRT_BLEND 無し（blend しない attachment の factor・op は比べない、enable と write mask だけ）、LDS > LDS_KB、workgroup が device の答える `maxComputeWorkGroupSize`・`maxComputeWorkGroupInvocations`（`ghci_vk_caps_limits`、今は {128,128,64}・128）を超える、texsz.s で CAP_MSAA 無し、属性の format に VERTEX_BUFFER の feature が無い、scratch の和が heap の block（16 MiB）を超える、sample 数が 1 でも（CAP_MSAA の）4 でもない、sampleShading・alphaToOne・depthBounds（feature が false）、adjacency・patch の topology、geometry・tessellation の stage、16 を超える vertex binding・属性、dynamic buffer の配列の element > 0 を使う program（下）。sampler の anisotropy は `VK_ERROR_FEATURE_NOT_PRESENT`。view: format が表に無い・texel の大きさが image と違う → `VK_ERROR_FORMAT_NOT_SUPPORTED`、cube array → `VK_ERROR_FEATURE_NOT_PRESENT`、depth/stencil の format の stencil だけの view → `VK_ERROR_FORMAT_NOT_SUPPORTED`。session に無い object・bind されていない image/buffer・型と payload の合わない write は EINVAL（frame を止める、p007 と同じ「形の違う物」の扱い）。
- **一度に複数の pipeline**: pipeline ごとに作り、失敗した物の identity は 0、結果は最初の失敗の VkResult（libvulkan の `pipeline_batch` は部分の成功を受ける）。record が decode できない時と、作った pipeline を session の object にできない時（identity の重複など）は EINVAL で frame を止め、その command で作った pipeline は全部消す（review の L6）。
- **specialization**: 共有の frontend は spec constant を知らないので、executor が SPIR-V の写しを書き換える: OpSpecConstantTrue/False/OpSpecConstant を SpecId の map の値（無ければ既定値）の OpConstantTrue/False/OpConstant に、OpSpecConstantComposite を OpConstantComposite に、SpecId の OpDecorate を OpNop 4 語に。OpSpecConstantOp は P3 の判断（review の M2）で 32-bit の整数と Boolean の scalar について SPIR-V の順に畳む（specialization の有無に関わらず）: IAdd・ISub・IMul・UDiv・SDiv・UMod・SRem・SMod・ShiftLeftLogical・ShiftRightLogical・ShiftRightArithmetic・BitwiseOr/And/Xor・Not・SNegate・LogicalAnd/Or/Not/Equal/NotEqual・IEqual・INotEqual・U/S の大小比較 8 つ・Select・32-bit の UConvert/SConvert。結果は OpConstant（4 語）か OpConstantTrue/False（3 語）にし、残りの語は OpNop。0 での除算・INT_MIN/-1・32 以上の shift・他の op・32-bit の定数でない operand は断る（log に理由）。WorkgroupSize の BuiltIn を持つ定数（glslc の local_size_x_id は LocalSize 1 1 1 と OpSpecConstantComposite を出す）の 3 値で OpExecutionMode LocalSize の値を（LocalSizeId なら id を）書き換え、置けなければ断る（review の M1）。
- **Vulkan の count と decode した配列**: 共有の codec は配列を wire の自分の count で作るので、executor は `vk.h` の macro で record の decoder の `i915_vkc_array` を `ghci_vk_decode_array`（`vk-object.c`）に替え、配列の直前の scratch の 8 byte に要素数を置く。count の field で配列を読む所は全部 `ghci_vk_decoded_count` と比べ、違えば create を断る（EINVAL で frame を止める。device の create は VK_ERROR_INITIALIZATION_FAILED）。対象: set layout の pBindings・pImmutableSamplers、pipeline layout の pSetLayouts・pPushConstantRanges（64 個まで）、pool の pPoolSizes、allocate の pSetLayouts、module の pCode、specialization の pMapEntries・pData、vertex input の 2 配列、viewport・scissor、blend の attachment、dynamic state、submit の 4 配列（p007）、device の pQueueCreateInfos（p007）。i915 の codec は変えない。
- **session の budget**: executor の object が持つ host の byte を session ごとに `GHCI_VK_BUDGET_BYTES`（64 MiB、`vk.h`）まで数え、超える create は VK_ERROR_OUT_OF_HOST_MEMORY（review の M4）。数える物: shader module の語、pipeline（record と heap の run と scratch）、set layout（binding・immutable sampler、最後の hold が外れた時に返す）、pipeline layout、descriptor set（record と descriptor）、command buffer の記録の room（増えた分、超えれば記録の失敗で end が OUT_OF_HOST_MEMORY）。object の `charged` は destroy で返る。
- **render pass（p009 まで）**: `GHCI_VK_RENDER_PASS` の kind と `struct ghci_vk_render_pass`・`struct ghci_vk_subpass`（色の数と format、depth の format、sample 数、input attachment の format と sample 数）を vk.h に置いた。pipeline は render pass の object が有ればその subpass を、無ければ自分の state（色の数 = blend の attachmentCount、sample 数 = rasterizationSamples、input attachment 無し）を使う。p008 では render pass の object を作る op が無いので、input attachment を読む FS は compiler が format 無しで断る。render pass の release は今は `vk-pipeline.c`（p009 で `vk-pass.c` に移してよい）。
- **descriptor の byte**: sampler・view の descriptor は create の時に作り、set は write の時に descriptor の byte を持つ（draw の時は写すだけ）。番地は memory の mapping から引く（image・buffer は bind 済みが要る）。image view は 2 つ: sampled（view の level 全部、view の最初の level・layer の番地、2D array・cube の depth は layer 数・6、slice pitch は layer の stride、3D は level の depth と plane、swizzle、sRGB の flag）と single（同じ番地で mip_levels 1、swizzle は恒等、cube は 2D の 6 layer。storage image と input attachment の set 2 の写し、design 版 4.10 の取り決め）。uniform texel buffer の view: texture は幅 min(256, 要素数)・高さ ceil(要素数 / 256)・行 256 × texel の byte の linear 2D、buffer descriptor は stride = texel の byte・format。set の uniform buffer・uniform texel buffer の buffer descriptor は flags[0] ReadOnly、storage は 0。
- **dynamic offset**: pipeline layout は set 順・binding 順・element 順に descriptor 1 つに bank の 1 語（c40 + i）。compiler の `dynamic[]` には element ごとに同じ (set, binding) を並べる（compiler は最初の 1 つを使う）ので、dynamic buffer の配列の element > 0 を読む program は作成で断る。
- **draw・dispatch の表**（p009 が呼ぶ）: `ghci_vk_layout_tables(session, pipeline, sets[4], dynamic_offsets, count, push, push_bytes, tables)` が set 0（texture の slot 順に 32 byte）・set 1（sampler の slot 順に 16 byte）・set 2（entry の offset に 16 か 32 byte）・bank（c0〜c23 = push 0〜95、c32〜c39 = push 96〜127、c40〜 = dynamic offset、c24〜c31 は 0 で LOAD しない、`bank_count` = 40 + dynamic の数。push_bytes が 4 の倍数でなければ最後の語の残りは 0 で、push の外は読まない）を作る。slot・entry の set が bind されていない・binding が無い・binding の型が slot・entry の種類の取る型でない（texture の image は combined image sampler か sampled image、texel buffer は uniform texel buffer、sampler は combined image sampler か sampler、set 2 は uniform/storage buffer（dynamic も）・uniform/storage texel buffer・storage image・input attachment をそれぞれ）・descriptor が書かれていない（immutable sampler の sampler slot は書かなくてよい）と ENOENT（p009 は U8 で飛ばして log）、dynamic の数が layout と違うと EINVAL。
- **set ごとの dynamic offset**（p009 のための data だけ）: pipeline layout と pipeline に `dynamic_base[4]`（set i の最初の dynamic offset の番号）と `dynamic_sets[4]`（set i の dynamic offset の数、layout の外の set は 0 で base は全体の数）を置いた。p009 は vkCmdBindDescriptorSets の firstSet からの offset をこれで並べる。
- **pool**: type ごとの数と maxSets を数え、超えれば `VK_ERROR_OUT_OF_POOL_MEMORY`（wire は 1.1）。pool の大きさは同じ type を足して UINT32_MAX で飽和し、set の room は layout の同じ type の binding を合わせて 64 bit で比べる。set layout の descriptor の和は足す前に 4096 との差で比べる（review の H1）。free は FREE_DESCRIPTOR_SET_BIT を見ない。set layout は参照を数え（set と pipeline layout が hold）、layout の destroy の後も set は使える。write と copy は binding を越えて続くが、越えた先の binding も同じ型でなければ EINVAL（review の L4。write の途中の失敗では、それまでに書いた descriptor は残り frame が止まる）。immutable sampler の binding は宛先の sampler を保つ。
- **pipeline cache**: data は 32 byte の header（headerSize 32、version 1、PCI の ID、`GHCI_VK_CACHE_UUID`）だけ。capacity 0 は大きさ、32 未満は 0 byte で `VK_INCOMPLETE`。初期 data は使わず、merge は確かめるだけ。
- **PSO に無い静的な状態（R07）**: pipeline の `state` に dynamic の印（VkDynamicState の bit）、viewport（float の bit 6 語）と scissor、line width（wideLines が false なので常に 1.0）、depth bias（SET_DYNAMIC_STATE 0x01 の順: constant・slope・clamp）、blend constant、stencil の各面の 1 語（compare mask・write mask << 8・reference << 16、0x03 の形）、MRT_BLEND の device だけ attachment ごとの blend の語（0x07 + k、dw11 と同じ形で `ghci_pso_encode` から取る）、rasterizerDiscard。PSO の dw9 の line width は 16（1.0）、dw12 は binding 0〜3 の stride が 255 以下の時だけ（p009 は `pipeline->strides` で bind する）。triangle fan は dw8 = 3 と `pipeline->fan`。
- **vertex 属性**: PSO の attribute slot は location の昇順に詰める。compiler には location ごとの format の成分の数と整数の印（`ghci_vk_format_traits`、`vk-format.c` に足した）を渡す。
