# WS210 p014 review-1（design-reviewer、d2de6e0b1、source は main 9cf242cb7）
可否: F1 今の形では不可（H1・H2、直せば可）。F2 の MOTION の合流は条件付きで可（効果は小）、KL_PACING_FRAME は不可（H3・H4）。F3 は依存の直し（H5・M7）。F4 の Settings の載せ替えは不可（M4）、Music は不要（L1）、Files は可（L6）。F5 可（L2）。HAL 不要。

H1 互換の kl_ui_take_damage が「描く物なし」でも 0 → Music（main.c:552-556、1247-1257）・Phone（656-660、810-818）・Photos（1511-1512）・Calendar（601-616）・Mailer（532-536、689）が窓全体を描く退行（A→B→A や drawn_hot に戻る時）。直し: pending があって NONE の時は 1 と drawn_hot の矩形（無ければ 0 面積）、または 5 つの app を kl_ui_take_frame に移し NONE なら描かない。host 試験に A→B→A の後の互換の口の戻り値。
H2 「F1 だけで軌跡が消える」は不成立: 一方向に速く動かすと drawn_hot と hot の外接は今と同じ箱（ui.c:2286-2301）。2 つの矩形は take_frame の parts と 2 回の clip と present の矩形の list の後。Settings の左ペインは自前の ui_motion/ui_damage_add（settings/ui.c:1029-1056、1844-1875）で kl_ui を通らない、Files の FM_HIT も同じ型（files/ui-input.c:614-642）。直し: 第 1 段は Settings と Files の自前の lit に「描いた時の hover と今の hover」の比べ（se_ui_draw の時に drawn_hover_kind/index を記録、damage を 2 つの部分に、Files の fm_ui_damage は既に 2 部分）、libkeiland の F1 はその次。
H3 KL_PACING_FRAME で commit が来ないと永久に描かない: present の失敗 OUT_OF_DATE・EIO（window.c:678-686、present.c:255-317）、SHM の EAGAIN（present-shm.c:46-74）、resize・configure。直し: 要求は commit が確実な点で、失敗したら callback の proxy を destroy して due に戻す、resize・最初の frame・configure は due を無条件に 1、callback は常に 1 つ、window の破棄で destroy。
H4 KL_PACING_FRAME の待ちの間 timeout 0 の busy-spin（settings の main_timeout、music main.c:1307 mu_wait、calendar main.c:675、Phone、Photos）。直し: 「dirty かつ due でない時の待ちは frame_due の wait_ms（callback 待ちなら -1）と app の他の待ちの短い方」を明記、6 app の timeout の関数を直す、待ちの CPU を試験で。
H5 parts は compositor まで届かない: libvulkan の WSI は VkPresentRegionsKHR を外接 1 つにまとめる（wsi-swapchain.c:3304-3349）、wl_surface.damage も 1 つ（wsi-wayland.c:79、833-842）、keiui_present_frame は 1 つの area・全面の quad（present.c:235-251）、p013 の present-damage.c はまだ無い。直し: p013 E1・E2 と WSI の複数矩形の damage（別 WS、Q1 判断）への依存を明記、p014 の受け入れは「app の描く面積と frame の数」に限る。

M1 窓の canvas に描かない begin/end（settings/widgets.c:745-769 の 1x1 の canvas、textedit/main.c:842、1143、1249、1846）で drawn_hot がずれ lit が残る。直し: drawn_hot は kl_ui_end で「この frame に記録された hot」だけ、描かない frame の口か別の kl_ui、Settings の 1x1 の frame は widgets_ui と別の kl_ui に。
M2 「待つ間も入力を受けて状態を進める」は kl_ui で成り立たない（click は 1 slot ui.c:189-196、key は frame ごと ui.c:1035-1069、scroll・gesture・drag は kl_ui_begin で進む ui.c:852-867、Music の要求も view の描画の中 main.c:600-640・view.c:504-511）。pacing で 2 つ目の click が失われる。compositor は合成しなかった窓の callback を保留（compose.c:3001-3033、display.c:435-454）。直し: 「入力は溜め kl_ui の動作は次の frame」に直す、click・key が待っていれば due にする口、または click の queue。
M3 WSI の commit は worker thread で非同期（wsi-swapchain.c:2698、wsi-wayland.c:774-783）、Linux の compat は 100ms 待って commit（libvulkan-compat/wsi-swapchain.c:1502-1544）。直し: 根拠の節を直し、Pi の perf で worker に並ぶ frame の数と入力→commit を測る項目、要求を present の前に置く理由と呼び出し元の thread が 1 つを明記。
M4 F4 の Settings の左ペインを kl_sidebar_item にすると見た目と入力が変わる（icon・文字の x・半径・focus が無い時の灰色・色、ui_find は pane で切らない ui.c:2195-2220 と Settings の ui_hit_at ui.c:960-974、click が二重）。直し: Settings は自前の描画のまま行を kl_ui_hit（pane と交わる行だけ）で登録し KL_HIT_HOT だけを使う、click は今の経路、または H2 の比べだけで済ませる。
M5 part ごとに描画を回すと全体の走査が part の数だけ（settings/ui.c:415-447、kl_text_draw は clip で先に落とさない ui/text.c:253-296、Files は既に part ごと files/ui.c:400-405）。直し: canvas に複数矩形の clip を足して 1 回の走査、または合流のしきい値を描画の費用で（present の揃えとは分ける）。
M6 F1 は全部の kl_ui の利用者に効く（Mailer、Text Editor、Video Player、PDF Viewer の bar、Notes の box、chooser・picker）→ Mailer を F1 の試験に、他は build と hover の試験か T1。
M7 Phase の分け方: (a) Settings・Files の自前の比べ（H2）(b) F1 と F3 の口と frame ごとに take する app の移行（H1 含む）(c) F2（Linux・FreeBSD の確認を含む）(d) F4（任意）。p013 との依存は Q1 が ws.md に。
M8 試験の不足: H1 の退行、pacing の失敗の経路、待ちの CPU、描かない frame の後の lit の残り。MOTION の合流の判定を純関数に分ける。T1 の PNG では止まり・spin・遅れは検出できない。
