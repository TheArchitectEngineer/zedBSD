# WS210 p014 F2 第 2 版 review-2（design-reviewer、1bc16551a、source main 59c6306ce）— 要点
可否: F2.1 は L1 を直せば可（既定にするかは Pi で）。F2.2〜F2.5 不可（H1、M1〜M4・M6、M5 の事前の計測）。F2.6 不可（F2.2〜F2.5 の後、受け入れの数値を先に）。
H1 申請すると Settings・Files の (a) の効果が消え軌跡が戻る: settle（settings/main.c:549、files/main.c:764）は周ごとに damage を足す（settings/ui.c:457-474 → ui_redraw_region → ui_damage_add 1983-2007、files/ui-input.c:225-240）、drawn_hover は描いた時だけ（settings/ui.c:426-429）。同型: Calendar の animating=0（calendar/main.c:587-588）、Music の lit_changed=0（music/main.c:1252,1258）、kl_ui_take_frame も消費。直し: 「due の判定は描画の関数の最初、settle・take_frame・animating・lit_changed の消費は due の時だけ」、または settle を毎回作り直す形、host 試験に due でない周 2 回の後の部分が 2 つだけ。
M1 urgent の漏れ（POST 13、CONTROL_TEXT 19・CONTROL_DONE 20、TAB 26、POPUP_DONE 35、DRAG_DONE 25、DROP_ENTER/LEAVE 22・23、CONTROL_DROP 34、TABLET_DOWN/UP 27・29、AXIS_STOP 18、RESIZE 11 の立て所 window.c:1873,2730）→ 待たせてよい物（MOTION、LEAVE、AXIS、TOUCH_MOTION、DROP_MOTION、TABLET_MOTION/HOVER、DROP_ACTION）だけを列挙し他は全部 urgent。
M2 kl_window_frame_due に副作用（urgent を 0、watchdog で destroy と要求し直し）があり 1 周に 2 回呼ばれる（待ちの関数と描画）、Music の key（music/main.c:1296-1304）が 1 callback 遅れる → 副作用の無い問い合わせ（kl_window_frame_wait）と、urgent・watchdog の解除は present の時、host 試験に 2 回呼ぶ場合。
M3 zedBSD の非同期の WSI では callback が 1 つ前の commit に乗るのが普通になり得る（推測）: 要求は main で present の前、commit は worker の wayland_commit で 1 つ前の callback を待つ（wsi-wayland.c:774-783、797-845）、vkQueuePresentKHR は積んで戻る（wsi-swapchain.c:576-591）、Linux・FreeBSD の compat は同期で commit（libvulkan-compat/wsi-swapchain.c:1502-1544）→ 定常で 1 frame 先行。OS ごとの期待を書き、F2.6 の受け入れに worker に並ぶ数 ≤1 と kl_present_times の acquire_ms・wait_ms、足りなければ WSI の側（libvulkan、別 Phase、Q1 判断）。
M4 失敗の経路の残り: (a) SHM の EAGAIN（present-shm.c:58-61）で due に戻すと忙しい待ち → shm_release（present-shm.c:213-226）まで due にしない (b) worker の非同期の失敗は vkQueuePresentKHR に返らず次の acquire で（wsi-swapchain.c:567-570）、救いは watchdog、SUBOPTIMAL は commit 済み（present.c:337-338）(c) compositor が callback を保留するのは compose が起きない時だけ（sleep_hold display.c:162、出力の喪失、image が無い window）、重なって隠れた window・別の head の window は compose されて解放（compose.c:1825-1868）。保留中に present すると WSI の worker が前の callback を最大 10 秒待ち（WAYLAND_WAIT_NS wsi-wayland.c:25,776）、3 枚が尽きると vkAcquireNextImageKHR で最大 10 秒（PRESENT_TIMEOUT present.c:31、wsi-swapchain.c:3054-3110）、超えると SURFACE_LOST が残り Settings は EIO→DEVICE_LOST で終了（settings/present.c:101-104）→ watchdog の present は callback が戻るまで 1 回、zedBSD では watchdog を 1 秒程度、urgent も保留中は 1 回。今の WSI の「保留が 10 秒続くと surface を失う」は F2 以前からの問題（Bug の候補、Q1）。
M5 F2.2〜F2.5 の効果がまだ示されていない（描画が compositor より遅ければ pacing は何もしない）→ 着手の条件に「Pi の hover 中の acquire_ms と wait_ms が 0 に近くない」（settings/main.c:582-583 の SLOW-FRAME、kl_window_present_times）。
M6 待ちの関数の規則: request_count（music/main.c:1320、phone/main.c:896、mailer/main.c:777）、Calendar の animating は main loop（calendar/main.c:389-391）→ app ごとに描画の理由と描画以外の理由を表に、wait_ms は切り上げ。callback の done は default queue に届き取りこぼさない（app.c:200-262、wsi-wayland.c:940-1000）。
M7 callback の要求の場所は keiui_present_frame の中（present.c:212-352）で、p013 の E1・E2 と p005 の kl_window_frame_end にも同じ hook → commit を要求する内部の hook を 1 つに、p013 との順序を ws.md に。
L1 F2.1 の細部（keiui_pacing_merge の引数は kl_app_event.window、arrival_us の扱い、keiui_window_wake、同じ slot を返す keiui_window_stamp window.c:2028-2030）。L2 誤った引用（display.c:435-454 は unmap の解放）。L3 Linux・FreeBSD の compat の 100ms と watchdog が重なり約 5fps。L4 文書の古い所（F5 の KL_VERSION 90、Phase の中の順の 3、ws.md の p014 の行、window_push は今 window.c:1632-1670）。L5 KL_PRESENT_NONE の window は ENOTSUP。
